## 设计骨架

### 1. 总体架构（参照 Ossie 两套规范 + GB/T 48000.3 方法论）

| 层 | 职责 | 模块（Maven 结构） | 对应 Ossie 规范/案例 |
|---|---|---|---|
| 本体建模层 | 业务世界：对象/关系/规则/动作/术语 | `data-ops-business/data-ops-business-ontology`（裁减） | ontology 规范 / flights.yaml |
| 语义建模层 | 怎么算：指标口径/函数 | `data-ops-business-semantic/data-ops-business-semantic-modeling`（**新子模块**） | core-spec metrics / tpcds |
| 运行时 | 守卫+编译+执行 | `data-ops-business-semantic/data-ops-business-semantic-compile`（**原 semantic 改名移入**） | — |
| 绑定层 | 本体对象↔语义字段映射 | 现有 `mapping/` 服务重构（仍在本体模块或语义建模层） | Ossie Ontology mappings |

**模块结构调整**：`data-ops-business-semantic` 升级为父 POM（聚合），下挂两个子模块 `semantic-modeling`、`semantic-compile`；原 `data-ops-business-semantic` 目录整体改名迁移为 `semantic-compile`。依赖方向：语义建模 → 本体（单向）；compile → modeling + ontology。

### 2. 本体建模层（业务世界）
- 数据模型：Domain / Object(EntityType, identify_by, extends) / Attribute(数据属性+值域) / Relation(对象属性: roles/multiplicity/verbalizes) / **Rule(业务规则→requires 声明式约束)** / **Action(业务动作)** / Glossary / Axiom(公理校验)。
- 条件语言：`requires`——引用概念/关系/值常量的声明式业务不变量（如"金额≥0"、"起飞<到达"），**不是执行口径**。
- 公理（GB/T §8.2）+ 元数据契约（附录A：IRI/Name/Label/Definition/Domain/Range/Type）+ 独立生命周期（DRAFT→PUBLISHED→DEPRECATED + change order）。
- Agent 契约：**世界地图**；导出 Ossie `ontology:` 产物（flights 形状）。

### 3. 语义建模层（怎么算，新子模块 semantic-modeling）
- 数据模型：Metric(ATOMIC/DERIVED/COMPOSITE，聚合/时间粒度/单位/口径) / **口径条件语言 caliber**（可执行过滤+派生，引用本体属性） / Function(可复用计算)。
- **与规则解耦**：`metric.ruleRefs` 从"口径来源"降级为"审计引用"，`MetricFilterMerger` 规则合并逻辑移除，口径由指标自身定义；`METRIC_APPLIES_TO` 从属性 requiresJson 迁出到语义层（指标适用前提）。
- 独立生命周期（口径高频迭代、metric 独立版本）。
- Agent 契约：**口径字典**；导出 Ossie `semantic_model:` 产物（tpcds 形状）。

### 4. 绑定层（本体 ↔ 语义）
- object.datasetId、attribute.datasetFieldId 即 Ossie Ontology mappings；现有 `DatasetMappingService`/`AnchorConsistencyValidator`/`AnchorInvalidationListener`/`AnchorJoinHitValidator` 归入；其中 **metric 的 base_attribute 校验（MEASURE/可聚合）移入语义建模层发布闸门**。多跳维度路径行为保留。

### 5. 运行时（semantic-compile，职责不变）
- `DefinitionSnapshot` 拆为按两层分别读取（本体快照 + 语义快照）；Guard 用本体层值域校验 + 语义层口径编译。

### 6. Agent 契约改造
- 现 `SchemaSearchReader`/conceptCard 指标混入对象卡——拆成 **WorldView（本体层）** 与 **CaliberView（语义建模层）** 两套发现接口；决策流：世界地图选对象/规则/动作 → 口径字典选指标 → 运行时执行。

### 7. 迁移映射（文档重点章节）
- 14 张表归属拆分（rule/action/glossary/flow 留本体，metric/function 入 semantic-modeling）；
- Maven 重构：semantic 升级父 POM + 两个子模块、原 semantic 改名迁移 semantic-compile；
- Manager 依赖解耦：metric→entity/rule 改为语义→本体单向；`OntologyChangeOrderManager` 跨层级联改为事件订阅；
- `RuleConsistencyAnalyzer` 留本体层、`ValueMappings` 本体层共享、`MetricFilterMerger` 归语义建模层；
- Ossie 导出：单 artifact → 三产物（ontology + semantic_model + mappings）；
- 每项标注影响文件（repo 相对路径）。
