# Agent Requirements

> 本文件只描述**模块需要什么**，不描述怎么实现。历史需求和讨论看 Issue / PR / Git。

## 目标

Agent 提供面向业务人员的自然语言数据分析：以对话方式理解分析意图，在平台数据集上执行结构化查询与统计计算，返回带证据的回答，并支持沉淀为可分享的分析报告。

## 核心能力

- 会话式对话：多轮上下文、SSE 流式输出、会话列表、历史回放、删除会话、会话重命名；首轮提问后自动以对话内容开头作为会话标题（不调用模型）。
- 提交/执行分离：发起推理只做归属校验与落库（QUEUED），立即返回 turnId；推理由后台调度异步执行。同一会话同时至多一个活跃轮次；重新加载或断线后，客户端可按 turnId 重新订阅事件流并携带 Last-Event-ID 增量补发，已执行事件不重复、不丢失。
- 事件可重放：一轮推理的全部事件帧持久化为投递日志（带递增 event_id），SSE 仅是投递通道；进程崩溃后未启动的排队轮次自动被执行，执行中的轮次以明确 INTERRUPTED 终态收尾（事实保留、不伪造续跑）。
- 数据集发现：按名称与描述列出 ONLINE 数据集；查看数据集字段清单（显示名 / 类型 / 维度度量角色 / 业务描述）。
- 结构化取数：由模型产出维度、指标聚合、过滤、排序、行数上限组成的查询参数，经 dataset 查询运行时执行并返回表格证据。
- 结果解释：基于查询证据生成结论、摘要与后续分析建议。
- 统计计算：对查询结果执行相关性、回归、分布检验等 Python 分析。
- 日期推算：相对日期（今天 / 上周 / 本月等）到具体日期区间的换算。
- 人机反问（HITL）：信息不足时向用户提问（问题文本 + 可选选项列表），用户选择或自由输入后继续同一轮推理。
- 分析报告：将完整分析过程与结论保存为 Markdown 报告（图表使用 ECharts 配置块），提供报告分页查询、查看与删除。
- 轮次追踪（turn trace v2）：按轮次查看推理全链路六视图——parent 链树、平铺 spans、归一化时间轴、kind 维度聚合（count/total/max/avg/p95/token）、链路完整性（断链显式化，未观测到 ≠ 成功）、观测类型渲染投影；工具失败详情优先取业务错误结构（失败语义归一），载荷按四档信封解码（INLINE/SUMMARY_HASH/HASH_ONLY/OMITTED）。turn 归属在提交时冻结、读取先校验归属。
- 会话级观测矩阵：按会话查看 turns × kinds 聚合（LLM 次数/重试/工具次数/耗时/token），定位慢轮次与失败集中的工具。
- 观测类型治理：yak_agent_step.kind 以 KindSpec 注册表为单一真相（未注册 kind 拒绝落库），载荷策略（JSON 感知截断/敏感键负清单/摘要指纹）与渲染提示随 KindSpec 声明生效；新增观测维度 = 注册一份 KindSpec（+可选 Middleware），零改表零改渲染。
- 运行时观测治理：观测总开关与 per-kind 开关关闭时步骤记录零写入（读路径不受影响）；载荷 INLINE 上限与 LLM 请求排障升档（SUMMARY_HASH→INLINE）运行时现读生效；步骤表存储量每日聚合日志上报（TTL/归档待量级证据再立项）。
- 查询审计：按当前用户分页查看取数留痕（会话 / 数据集 / 状态 / 行数 / 耗时），支撑“AI 结论用了哪次查询”的追溯。
- 推理可观测：每次模型调用尝试恰好落一条步骤记录（tokens / latency / 重试次数 / 状态 / 分类错误码），失败也记账；单次模型调用受硬超时约束，超时不重试；5xx 与网络类错误指数退避重试，401/403/429 视为用户侧错误直接返回不重试。

## 关键业务行为

一轮典型交互的事件流：

```text
提交 -> turnId 立即返回 -> 后台执行：流式回答(text / thinking / tool_call / tool_result / summary)
需要澄清 -> 反问(pending) -> 用户补充提交(同一 turnId 续跑) -> 同一轮继续
取数   -> run_dataset_query -> 表格证据 + 结论
统计   -> analyze_with_python（数据内联）
沉淀   -> save_analysis_report(markdown + ECharts 块)
订阅   -> GET 事件流按 turnId，Last-Event-ID 断线增量续播
```

允许同时存在：

```text
Session S 的已完成历史 + 排队/进行中的一轮异步推理 + 一份已保存报告
```

此时必须满足：

```text
新一轮 Start            -> 不影响历史消息事实
进程崩溃/重启           -> 未启动的排队轮次自动执行；执行中的轮次以 INTERRUPTED 收尾且事实保留
报告保存                 -> 关联 session，独立生命周期（删除会话不强制删报告）
```

## 运行安全要求

- 提交推理与订阅事件流必须先做会话归属校验：用户只能写入和读取自己的会话（turnId 与 sessionId 绑定归属）。
- 存在 pending 反问时，恢复请求必须携带匹配的 toolCallId 与工具名；一次只允许一个 pending 反问。
- 查询参数必须通过字段白名单校验后才可执行；非法参数以结构化错误回喂模型自纠，不允许直接透传给底层运行时。
- 单次查询行数上限受模块配置约束；模型请求超出上限时按上限截断执行。
- Python 执行默认关闭；启用后受并发信号量与单次超时约束，超时强杀进程。
- 模型 API 密钥只在模型装配边界短暂存在，不入库、不出现在日志与 SSE 事件中。
- SSE 断连仅终止订阅推送，后台继续执行；显式取消停止后续推理，不得伪造或抹除已发生事实。

## 模块边界

本模块负责智能分析对话面，不负责：

- 数据集的定义、版本、上线与字段语义治理；
- 物理数据源连接管理与驱动维护；
- SQL 文本的生成、改写或直接执行；
- 平台登录认证与菜单权限的存储实现（复用 yak-security）；
- 向量检索基础设施；
- MCP Server 编排；
- 通用工作流编排。

## 当前明确未解决

以下能力不是普通需求变更可以顺手加入的内容，需要单独设计：

```text
数据集业务分组 / 标签辅助发现
数据集级可见性授权联动（能对话 != 能查所有数据集）
Ollama 等本地模型 provider 接入
Skill 的项目私有范围与扩展资源加载（现有管理员维护 Skill 正文已接线）
analyze_with_python 沙箱化（容器 / 受限运行身份）
基于模型的会话标题摘要生成（当前为截取首问的零成本方案）
报告分享与订阅
```

## 需求变更规则

如果 PR 引入本文件没有描述的新业务能力或改变已有业务行为：

```text
Requirement Gap
```

先确认需求并更新本文件，再实现代码。Reviewer / AI 不得自行补需求。

本文件只维护**当前有效需求**，不要追加迭代历史。


## 首版治理解读（F-009）

资产/质量详情提供有对象上下文的现有 AI 对话入口；授权读取、引用与回链可核验，部分失败保留其他证据，不可用/权限拒绝/不适用不得归为健康。Quality 的 ERROR / NOT_RUN / NOT_PASSED 不折叠。最终正文在引用检查后发布，工具进度仍流式展示。禁止治理写工具与未校验报告落库。Dataset 目录使用既有 data-development:read，查询使用 dataset:query 和真实 USER / 角色主体，版本发现与取数之间变化则拒绝并要求重读。

## F-010 建议辅助

依照 docs/product/features/F-010-ai-governance-suggestions.md 实施。候选有界、授权读取、原页面人工保存与原子并发保护；不得自动运行、启用调度、修改源域事实或绕过既有权限。真实模型验收与自动化验证分开记录。

## 任务执行约束与回归

按 F-011 实施显式治理工具矩阵、同轮有限调用与累计失败预算、模型输入字符预算、实际配置/工具/Skill 哈希及分层评测。入口预读与 HITL 计入额度，恢复不能无限重置；普通对话仍走 Dataset 原授权查询。模型、Skill 和源注释均不能扩大任务工具范围。

配置面显示已接入动态键的实际值与启动/动态来源，预留未接入项明确不可调整；模型与新执行预算为启动配置，修改需重启。Skill 更新防陈旧编辑覆盖，启停及重启后读取以持久化状态为准。真实模型与用户旅程验收单独待完成，CI 替身不表示准确率或任务收益。

## 历史质量排查指引

按 F-012 为显式历史执行任务提供本次事实、关注规则、待验证假设/缺口、人工检查步骤和原执行页面下一步。用户明确发送，必要时原 HITL 澄清，恢复不切目标或重置预算。源字段缺失与用户口述背景分开；当前证据无样本、错误类别或失败策略时不能确认根因、异常行数或 STOP 因果。

复用当前文本/事实卡/证据协议，最终固定人工核对提示与正文一并保存到同一官方消息。范围仍是所选 execution，不读当前定义替换历史、不扩大工具权力。独立质量题集与旧策略基线分开计数，多步人工验收不因单请求完成而通过；真实语义/源审计仍独立待完成。

## 质量候选人工核对

按 F-013 在原监控编辑器提供当前表单对照与保守重复识别，逐条采纳仍重新经过源校验，只追加停用规则。校验与人工保存互斥；取消/切目标的晚返回不得采纳。表单和候选不成为历史事实或长期采纳库，实际保存/运行继续由 Quality 拥有。

## 历史会话继续

按 F-016 对历史回答使用服务端写入的原轮次引用准确关联执行证据；仅唯一、归属一致且完成的轮次允许附 trace。旧消息/压缩后引用缺失/非法或重复引用保留正文并明确无关联，不按顺序猜测；失败记录保持独立来源。原 history API 形状、continuation/HITL/跟随/停止不变。

按 F-014 用兼容只读 continuation API 恢复最新任务、真实状态和原反问；普通任务不回扫旧治理目标，损坏输入/缺反问/读取失败禁止继续且可重试。历史/trace/continuation 校验当前用户和项目；不暴露原始输入载荷。原页面支持 sessionId URL 与刷新，加载和活动轮阻止重复提交，切换/新会话忽略晚响应并清除旧范围。追问明确发送并重新授权；HITL 恢复同轮同预算，活动轮采用刷新核对而非自动全文重放。

按 F-015 对恢复的活动轮有限自动检查状态：3 秒间隔、最多 20 次、串行、页面隐藏暂停且不重置次数；完成/待答/轮次变化后重新读取历史和上下文。读取失败或耗尽保留历史、禁止发送并可手动刷新；切换/卸载/主动操作忽略晚响应。原页面可按所见 turnId 停止排队/运行，校验用户/项目与 CHAT_RUN 权限、保护认领竞态，不误停后来轮次、不取消 pending。停止后重新读取真实状态，不凭请求应答显示成功。

## 结束后的下一步
按 F-017 提供最新终态说明与显式原问题草稿；填写零推理、不覆盖编辑，新发送经原入口创建新轮并核对陈旧来源。双击保护与提交未确认阻断保持输入，原 HITL/停止/预算不变。

## 治理问题组织
按 F-018 在已有任务入口提供原模板、可选背景/核对重点/期望结果与纯文本预览。填写明确触发且不覆盖编辑、不自动推理；活动/pending/读取失败/无权限禁止填写，切换清除。治理空状态不展示不适用的问数例子。

## 实时轮次核对
按 F-019 将原实时停止统一到精确轮次命令，提交未确认不取消未知轮。停止和断线后核对实际 continuation，失败保留文字/输入并阻止新发送，可手动刷新；旧订阅回调不污染后续任务。

## 编辑器候选轮次核对
按 F-020 将原候选面板纳入精确停止和只读状态核对；完成后只展示唯一关联原轮的历史候选。活动/读取失败禁止另发，原反问同轮继续，提供刷新和原会话路径；同步防重复、晚返回隔离及原人工采纳/保存约束保持。

## 回答证据核对
按 F-021 在原共享证据卡展示五态含义、来源/对象/读取时点与未知更新时间，支持本段回答内筛选和原源页面回链。歧义块/重复 ID 不关联事实，未知/不可用不当健康；原消息与源域真相保持独立。

## 报告安全留存
按 F-022 在原报告页提供静态净化 HTML 与原 Markdown 导出，图表保留配置且说明静态边界；读取/导出重新经原本人权限详情核对。列表/详情只展示最新请求，失败可重试，关闭/卸载/读权限失去隔离晚返回，重复导出同步阻止；原删除权限与确认保持。


## F-023 场景 Skill 标准匹配

F-023 单字段 TYPE 标准匹配：用户从 Modeling 原字段草稿发起现有持久化轮次。源域授权、有界候选、Skill 同轮快照与活版本核验、SDK 结构化 call；候选经源域复核后才发布/带入。待确认项是完成轮次的问题清单，补充后重新生成，不引入新的 HITL 状态。草稿不是事实，AI 不保存业务。

依赖：Agent runtime → toolset → gateway → semantic.api / modeling.api；源域不依赖 Agent，不新增状态机或第二业务真相。合同见 [F-023](../../docs/product/features/F-023-skill-standard-match.md)。


## F-024 模型来源映射 Skill

Modeling 拥有单列来源映射与目标字段，授权 MappingSuggestionQueryApi 读取固定源表的 fresh 元数据并有界交付。Agent 仅 gateway → modeling.api 消费，不直接读取 Datasource 内部实现。复用原轮次、SDK Skill 与结构化调用；候选仅进入原表单，人工 If-Match 保存。映射写路径持有模型行锁，字段及单列映射用 locking read；保留标准字段关联，冲突先于写入。外部 DDL 校验只证明读取时刻，不宣称跨库原子性。详细边界见 [F-024](../../docs/product/features/F-024-skill-model-mapping.md)。


## F-025 指标版本口径 Skill

MetricExplanationQueryApi 是 Metric-owned 授权只读投影：固定当前版本，读取不可变快照并复用 digest；仅白名单有界事实，超界/缺快照不可用。Agent 仅 gateway → metric.api，源域不反向依赖 Agent。复用 SDK 场景执行与原表单，候选仅 businessDesc，人工保存复用 expectedVersion、校验、审计和回读；验证/发布仍独立。引用校验不等于自然语言正确，真实模型验收 PENDING。合同见 docs/product/features/F-025-skill-metric-caliber.md。


## 场景辅助与 J2 原页面交接（F-026/F-027/F-028/F-029）

原轮次与 SDK 状态仍拥有执行/消息。批量是最多五项的客户端顺序选择；每项有独立原轮，提交或终态不确定时停止后续项。类型与说明候选、指标定义草稿均需活权限/源版本/Skill 重查。精确历史指标解释仅阅读，CURRENT 仍拒绝漂移。场景不开放业务写工具。

依赖仍是 Agent runtime → toolset → gateway → 源域 api；Modeling/Semantic/Metric 不依赖 Agent。复用现有保存、权限、项目与审计，无新业务状态机/事实库。精确合同见 docs/product/features 下相应 Feature。

原会话可回看最新完成轮的标准匹配、来源映射、指标解释与定义草稿（F-031），展示候选、依据、待确认项和原页面入口。SSE、旧轮无范围证据、缺失/重复引用、坏回执、范围不符或读取失败保留正文并提示核对；切项目/会话或失去读取权限后旧卡失效。回看不采纳、不保存、不自动调用源，历史快照与新建未保存草稿必须明确标注。
