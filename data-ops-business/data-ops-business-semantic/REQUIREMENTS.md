### 32.1 码值类聚合交互(方案 A,2026-09-15;表结构不变)

- **码集 = 多行 CODE 记录**,以 `code_set_code` 关联;一行 = 一个码值。表单一次录入"码集 + 多行码值"(码值/标签/码值排序,至少 1 行,动态增删)。
- **编码自动生成**:行编码 = `{码集编码}_{码值}`,码值中非 `[A-Za-z0-9_]` 字符清洗为 `_`;与既有编码冲突时自动追加数字后缀(用户不手填行编码)。
- **唯一性**:码集编码项目内唯一(新建时已存在则提示"是否编辑");码值同一码集内唯一(前端实时 + 后端落库校验);编辑时码集编码不可改(legacy 空码集行补全编码除外)。
- **列表按码集聚合(2026-09-16 修订:全部视图与码值分类页均生效)**:统一分页查询以 **SQL GROUP BY** 聚合 CODE 行(分组键 `COALESCE(NULLIF(code_set_code,''), std_code)`),每组返回码集编码/名称(MAX(std_name))/码值数(COUNT)/整组状态(含停用即停用)/预置/版本(MAX)/描述/最新更新时间;其余五类仍逐行返回;搜索与状态筛选作用于码集整体(码值级命中即整组呈现)。
- **码集名称存储**:新建/保存码集时,组内所有行 `std_name` 统一存码集名称,`code_label` 存码值标签;聚合取 `MAX(std_name)` 即码集名称。历史行名称不一致时详情接口标记 `nameInconsistent`,编辑弹窗提示确认,保存后自愈归一(不做强制迁移脚本)。
- **标准字段码值引用下拉(35)**:`GET /standards/code-set/options` 返回启用码集(码集编码+名称),选项 label=`{码集名称} ({码集编码})`、value=`code_set_code`,与 `std_code_set_code` 字符串存储语义对齐(修复此前误绑标准行 id);支持按名称/编码搜索。
- **引用选项按需加载(35,2026-09-16)**:字段编辑弹窗打开时经 `GET /standards/options?kinds=...` 拉取对应类别启用项(类型/单位/口径/安全,只含 id/code/name/stdType),码集走专用 options 端点;标准字段列表页不得预载全量标准、不得以分页接口大 size 兜底全量。
- **码集级版本**:`GET /standards/code-set/{key}/versions` 合并组内各行的修改前快照(按时间倒序),列表"版本"操作对码集生效。
- **编辑/启停/删除均以码集为整体**:一次保存事务原子生效(改标签/排序/增删码值);行级快照仅在行被修改时落(32 快照不变式);不支持单独停用某一码值行。
- **兼容存量**:空 `code_set_code` 的历史行在聚合视图按其 `std_code` 独立成组,编辑时可补全码集编码(采纳进新码集);历史不一致名称编辑保存后归一为码集名称。
- **范围偏差说明**:"码集整体排序"未单独存储——统一表无码集级排序列(违背"不改表"约束),码值排序保留码集内次序。

## Ticket 35:标准字段集(全局字段库 + 业务过程引用)

- 管理员维护**全局标准字段库**:字段编码项目内唯一(创建后不可改),角色为 业务过程(PROCESS)/维度(DIMENSION)/度量(METRIC);类型/单位/口径/码值/安全**必须引用数据标准**(下拉选择对应类别的标准),不允许自由填写。

- 引用校验:标准 ID 必须存在且类别匹配(类型引用必须指向 TYPE 标准等),否则拒绝;字段删除前校验未被任何业务过程引用。

- **data_type 快照策略（收紧 1）**:`std_type_id` 非空时 `data_type` 由服务端从标准同步,用户不可手改;`std_type_id` 为空时可手填。
- **按角色适配表单与校验(2026-09-16;口径选填 2026-09-17 修订)**:引用规则按角色差异化——类型标准引用**三类必填**;METRIC(度量)必填**单位**,**口径选填**(作为该字段的默认推荐口径,指标可覆盖;字段管"是什么"、口径管"怎么算",口径的最终选择在指标层面,2026-09-17 用户决策推翻"度量必填口径");口径非空时服务端校验 kind=CALIBER、存在、ENABLED;不展示码值/安全。DIMENSION(维度)可选**码值+安全**,不展示单位/口径;PROCESS(业务过程)仅类型引用,不展示其余四类。后端按角色校验必填(缺失拒绝,42018),**并归零当前角色无意义的引用**(前端隐藏即清空,服务端兜底),避免脏引用入库。

- **data_type 提示刷新（约束 1）**:关联类型标准变更时不自动级联更新已存字段;字段详情提示"关联类型标准已更新,是否刷新";字段编辑保存时服务端重新从标准同步,保证编辑后一致。

  - `std_code_id`(码行 ID)改为 `std_code_set_code`(码集编码字符串):字段约束整个值域,非某个码值;服务层 `existsEnabledCodeSet` 校验项目内存在 ENABLED 且 code_set_code 匹配的 CODE 行,否则拒绝;
  - 新增 `data_type` 快照列、`status`、`source(PRESET/MANUAL/CAPTURE,替代 is_preset)`、`version`(乐观锁);

## Ticket 39:标准推荐 SPI(规则版,modeling 消费)

- semantic 提供 `StandardRecommendApi`:输入 字段名/字段类型/角色(PROCESS|DIMENSION|METRIC|UNKNOWN),输出:
  - **命名校验**:字段名对照 ENABLED 且 scope 为 FIELD/通用的命名标准 rule_expr;匹配则给出命中的标准,不匹配则给出首个适用标准作为建议(违规提示,可"一键修正"=采纳该标准的引用)。
  - **类型推荐**:dataType 命中类型标准 source_mapping 中登记的源类型(或等于 std_type)时推荐。
  - **码值推荐**(维度):字段名包含码集编码时推荐对应 CODE 标准。
  - **口径/单位推荐**(度量):字段名包含口径编码推荐 CALIBER;度量字段无单位命中时默认建议金额单位。
  - **安全推荐**:字段名包含等级编码关键词(如 PII_PHONE → phone)时推荐 SECURITY 标准。
- 全部规则仅匹配 ENABLED 标准;候选上限 3 条;推荐不阻断任何流程(39/41 消费方语义)。
- 41(推荐 UI/agent)与 38(ODS 套用)复用同一 SPI。

## Ticket 52(跨模块,MDM 消费):StandardQueryApi 扩展

- MDM(主数据管理)属性引用数据标准,经 `api.StandardQueryApi` 消费(不直读本模块表):
  - `labels(Collection<Long> ids)` → 批量标准标签 `名称（编码）`(id → 标签),供 MDM 属性列表展示类型/单位/安全标准名;
  - `existsCodeSet(String codeSetCode)` → 项目内是否存在启用码集(ENABLED 且 code_set_code 匹配的 CODE 行,同 40 决策一),供 MDM 属性码集引用校验。
- 契约边界不变:MDM 只经 `api` 包消费,不 import 本模块内部实现类型;引用仍是松散 ID,展示名经 SPI 解析。

## Ticket 44 字段继承:ProcessApi 只读扩展(2026-09-17)

- 派生(44)需要按"源表角色"决定继承哪些表的字段,并提供"字段 ↔ 标准字段"匹配兜底,故 `ProcessApi` 新增两个**只读**方法(纯新增,无破坏性变更):
  - `listProcessSources(Long processId)` → 过程源表绑定视图(datasourceId、sourceTable、tableRole、joinCondition),取自 36 绑定,不泄漏本模块内部类型(以 api 包内 record 暴露)。
  - `listFields(String keyword)` → 标准字段库(35)清单(关键字可空 = 全量,按过程内顺序/创建顺序稳定排序),供 38 导入与 44 派生的字段匹配与展示名解析。
- 用途边界:modeling 只做匹配与展示,不回写 semantic;匹配命中结果以松散 ID(`std_field_id`)记在 modeling 侧,语义模块不感知调用方。
- 角色语义不变:`MAIN`/`DETAIL`/`DIM` 由 36 维护,44 仅消费;角色缺失/多主表由调用方阻断并提示回 36 配置。
