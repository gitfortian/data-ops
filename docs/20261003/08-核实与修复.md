- Producer / Consumer：原有 Manager、Launcher、Reader 和 API 生产证据；现有页面消费。没有新增业务存储、业务状态机、导航域或第二份业务真相。

- E2E acceptance evidence：Windows 清除预生成 CSS 后启动成功，真实浏览器 1440×900 登录页截图见下方；其他证据明确标记为组件测试、HTTP 契约测试或代码核对。

## 根因与已知限制

1. 长 ID 原来直接按 JSON 数值返回，浏览器 Number 无法精确表示；修复放在 Development 执行响应的序列化边界，没有给后端 ID 增加第二种存储。
2. 空图属于用户输入问题，原来使用状态异常。现在使用定义输入异常，并只在 Workflow Definition Controller 边界映射为 400；其他未预期异常仍是服务器错误。
3. 质量“无执行”与“执行但全未通过”原来共用 0% 展示。现在用执行数/评估次数区分，真实 0% 仍显示。
4. 总览将启动问题唯一归因于目录不存在的推论不充分。现有插件在 Windows 直接启动 JS CLI，没有成功完成编译；显式 Node 调用与等待编译成功解决了已复现超时。原测试中途的自发退出缺少崩溃日志，不能另外断言其原因。
5. `RemoteComponent` 是 Umi 的路由懒加载包装，仅凭栈名称不能认定使用了微前端远程服务。按需入口隔离了无关高亮依赖；当前没有提供登录凭据，S0-21 和 DEV-04 不宣称完成真实浏览器复验。
