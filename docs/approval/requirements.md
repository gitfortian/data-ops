# 通用审批流 —— 需求文档

> 版本: v1(简单版) · 日期: 2026-09-19 · 状态: 评审后修订稿
> 配套设计: [design.md](./design.md)
> 硬性约束沿用各模块 dev-plan 范式(契约先行 / project_id 服务端可信 / 无物理外键 / 查询预算)。

---

## 一、背景

Yak Ops 数据平台多个治理动作需要"先审后生效"：数据标准发布/变更、权限申请、模型发布、
主数据变更等。当前各能力散缺：

| 场景 | 现状 | 差距 |
|---|---|---|
| 模型发布 | `modeling` 直接 `POST /models/{id}/publish`,DRAFT→PUBLISHED 无审批 | 缺审批门槛 |
| 数据标准发布/变更 | `semantic` 标准(Standard)直接生效 | 同上 |
| 权限申请 | `security` 仅管理员直接配访问策略(AccessPolicy),**无"申请单"形态** | 申请语义本身缺失 |
| 主数据变更 | `mdm` **已有自带审批**(`MdmApprovalService`,单/两级,菜单 V2028) | 已实现,不属缺口 |

平台 `workflow` 模块是 Airflow 类**数据加工编排**,与人的审批语义(待办/驳回/意见)不同域,
**明确不复用**；审批也不引入 Flowable/Activiti(过重),自研最简三表实现。

## 二、需求审视结论(对原始需求的修正)

| # | 原始需求 | 问题 | 修订 |
|---|---|---|---|
| R1 | 审批场景含"主数据变更审批" | 与 MDM 既有审批**重复**,双轨会引发真相分裂 | v1 不含 MDM 迁移;通用审批先覆盖其余三场景,MDM 接入列 P2(§六) |
| R2 | "业务模块定义流程(flow_code)" | 语义模糊:若各模块可绕过审批中心自行定义,通用性失守 | 流程**定义统一在审批中心配置**(管理员),业务只**引用** flow_code + 提供回调 |
| R3 | "审批通过后回调业务模块" | 缺失败语义:回调抛错审批单算什么状态? | D5:与审批操作**同事务同步回调**,失败整体回滚、审批人可见可重试;异步+重试列 P2 |
| R4 | 未提审批人规则 | 无法落地"待审批列表" | v1 流程配置=每级静态审批人名单(1~2 级);发起时快照到步骤行 |
| R5 | 未提防重 | 同一业务对象可被重复发起、出现多张在途单 | 同一 (flow_code, 业务对象) 至多一张在途单(唯一约束,49003) |
| R6 | 功能清单缺"撤销" | 申请人只能等死 | 补:申请人可撤销在途单(未终审前) |
| R7 | 未界定范围边界 | 转办/加签/会签/委托/超时提醒/消息通知是否要做不明确 | **v1 明确不做**(§四范围外),清单化列 P2,防蔓延 |
| R8 | "权限申请审批"当作纯审批问题 | 申请单(谁/访问什么/期限/理由)本体归 security,审批中心只跑流程 | 责任拆分:security 建申请单并入参 payload,审批中心通用(§五) |
| R9 | 待审批列表=单一功能项 | 未区分视角,前端无法组织 | 拆:我的待办 / 我发起的 / 我审批过的(历史)三视图,共用分页契约 |

## 三、角色与用例

| 角色 | 用例 |
|---|---|
| 发起人(业务用户) | 在业务页点"提交审批"(或业务动作自动触发)→ 查看我发起的 → 可撤销 |
| 审批人 | 收到待办 → 看审批依据(快照) → 通过/拒绝(拒绝必填意见) |
| 流程管理员 | 配置 flow_code:名称、级数、每级审批人、启停 |
| 业务模块(代码视角) | 发起(`ApprovalApi.submit`)、查状态(`find`)、接回调(`ApprovalFlowHandler`) |

## 四、功能需求

### 4.1 v1 范围内

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 流程定义 | 每项目若干 flow:1~2 级顺序审批;每级静态审批人名单,任一人处理即定级(ANY);可启停;删除仅软删 |
| F2 | 发起审批 | 业务 Java API 或 REST;携带 biz_type/biz_id/标题/审批依据快照(JSON);防重复在途单 |
| F3 | 我的待办 | 按当前级=我 且 状态=PENDING 分页,倒序;带角标计数(固定预算查询) |
| F4 | 审批操作 | 通过:进入下一级,末级通过→单终态 APPROVED;拒绝:必填意见,整单立即 REJECTED |
| F5 | 撤销 | 仅发起人、仅 PENDING;终态 CANCELED |
| F6 | 审批记录 | 单据详情含完整步骤流水(每级谁/何时/结论/意见);按业务对象查最新/历史单 |
| F7 | 业务回调 | 终态时同步回调业务 `ApprovalFlowHandler`;APPROVED=业务生效动作发生点 |
| F8 | 审计 | 发起/通过/拒绝/撤销/流程变更全部走 `BusinessAuditService` |

### 4.2 v1 范围外(P2 迭代候选,只列不做)

转办 / 加签 / 会签(AND) / 或签之外的多选模式 / 委托代理 / 条件分支路由 / 角色动态解析审批人 /
超时提醒与自动升级(可挂 `YakScheduleNamespaces`) / 站内信·消息通知 / 撤回已审级重发 /
表单动态渲染引擎 / MDM 审批迁移。

## 五、与业务模块集成

| 场景 | flow_code(建议) | 级数 | 业务侧职责 | 审批通过后 |
|---|---|---|---|---|
| 模型发布 | `MODEL_PUBLISH` | 1~2 | modeling 把模型快照(名称/分层/字段数)入 payload;注册 handler | 执行既有 `ModelVersionService.publish` |
| 数据标准发布/变更 | `STANDARD_PUBLISH` | 1 | semantic 标准草案入 payload | 标准置生效 |
| 权限申请 | `ACCESS_GRANT` | 2(数据负责人+安全管理员) | **security 先新建"申请单"**(资源/期限/理由),再发起 | 生成访问授权策略 |
| 主数据变更 | — | — | v1 保持 MDM 自有审批 | — |

集成纪律:审批中心**不依赖任何业务模块**(方向反转,业务实现审批中心的 SPI,同 `AssetProvider` 范式)；
审批中心不存业务事实,只存发起时的展示快照。

## 六、非功能约束

1. 契约先行:模块根目录契约文件集(README/DOMAIN/ARCHITECTURE/DEPENDENCIES/REQUIREMENTS/REVIEW)。
2. `project_id` 只取服务端 `CurrentProject`;接口 `@ProjectScope(PROJECT_REQUIRED)`。
3. 无物理外键;Flyway 自持链 `db/migration/yak-approval` V1 起编;菜单注册进 yak-security 链,取 **V2033**。
4. 错误码段 **49001~49099**;权限码 `data-approval:read/create/approve/manage`。
5. 一切列表分页;待办角标等聚合走固定查询预算,失败不伪造 0(home-overview-contract)。
6. 回调异常必须能回滚审批动作 → 同事务;禁止在回调里做跨进程 HTTP。
7. 前端 `data-ops-ui` 下 `.md` 只读;新菜单码登记 `securityMenuCodes.ts` 并过契约测试。

## 七、预期效果

| 维度 | 效果 |
|---|---|
| 治理 | 发布类动作皆有"先审后生效"门槛,留痕完整可追溯 |
| 复用 | 一次建设,后续任何模块加审批=注册一个 flow + 一个 handler,零流程代码 |
| 体验 | 审批人一个入口看全平台待办,不用逐模块翻页面 |
| 演进 | v1 三表最简;范围外项全部清单化,升级不动表结构主干 |
