- 测试时间：2026-10-01 12:00–12:34（视口 1440×900，Edge headless + CDP，前端 :8000 / 后端 :8080 真实链路）

- 环境干扰：走查期间被强制跳回 `/login?returnTo=...` 共 **5 次**（多分区共用同一账号的单点会话互踢）。凡因此产生的现象，本文单列并标注「环境干扰、不计入产品问题」；但由它暴露出的壳层缺陷（S6-04）仍计入产品问题。

## 结论摘要

- **P0 0 / P1 2 / P2 8 / P3 15（合计 25 条）**
- 一句话结论：**核心 CRUD 闭环可用、危险操作二次确认到位，但「功能开关只管菜单不管路由」构成越权可达的 P1，加上平台设置列表页在 1440 宽下的时间列裁切 P1，建议修复后再验收。**

## 交互与共性问题

- **列表页超宽是同一处实现范式的问题**：项目空间、用户、角色三页都在 1440 下把时间列压到不可读（`tiny` 右边界 1420–1508），而 `overflowX` 仍报 false（滚动发生在表格内部）。缺统一的「列宽预算 + `scroll.x` 显式声明 + 操作列固定」约定，建议一次修复覆盖三页。
- **写操作反馈没有统一规约**：用户、部门有成功 toast（且文案准确），项目空间、角色、审批流同类操作全部静默；危险删除倒是有二次确认。**确认有、反馈无**，说明缺失集中在「成功后的提示」这一环。
- **危险操作二次确认做得好的地方要保留**：工作空间删除带前置依赖校验（「检查通过」）、部门删除带「无法恢复 + 仅无子部门无关联用户可删」说明、审批流删除带软删语义说明；`恢复默认设置`、`确认导入` 这类批量/系统级按钮本次按红线未触发。
- **术语与 i18n 混杂是数据层与壳层两类问题**：壳层表现为同对象多名（项目空间/工作空间、消息中心/通知）与引导指向不存在的菜单；内容层表现为种子数据英文描述（部门、角色）和审计日志操作名中英混排。两者修复路径不同，不应合并为一个「加翻译」任务。
- **弹层与路由生命周期解耦**（S6-04）：会话失效重定向只换了主内容，Modal 仍挂载并覆盖在登录页上——并发登录互踢是环境干扰，但「弹层不随路由销毁」是真实壳层缺陷，在任何 401 场景都会复现。
- **抽屉/表单细节的可访问性与陈旧状态**：Select 搜索框无标签（`noLabel`）、关闭的抽屉 DOM 常驻并保留旧值与旧空态、编码字段与名称字段同型可写——三者共同放大了误操作与被误读的概率。
