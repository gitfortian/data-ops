### 交互与共性问题（与 03 分区对照）

1. **ID 精度：工作流侧未复现（正面）**。03 分区 S3-01 的根因是开发侧 `nodeId` 为裸 JSON number；工作流域主键统一为字符串 UUID（定义/调度/节点 id），引用的 `taskAssetId`/`taskRevisionId` 也是带引号字符串，检查器与 URL 全程一致。**遗留风险点：实例 `executionId` 的类型未取到样本**，修好 R3-07 后必须复验这一项。
2. **保存反馈：工作流侧明显更好**。03 分区 S3-06 是"保存 401 静默无提示"；工作流侧 `保存草稿 / 保存配置 / 删除` 三个写操作都有语义化 toast，且调度保存还额外说明"上线后自动启用"。**但失败路径同样烂**：500 时抛 `http error` / `Request failed with status code 500` 这类技术串——成功路径与失败路径两套标准，与 03 分区同形。
3. **操作列/尾部列被裁切：在工侧重现**。03 分区 S3-09（发布中心 1717）、S3-10（运行记录 1607）→ 本分区 R3-15（实例列表 1635），三处同因（列宽按固定总和编写、空表也保留滚动条轨道）。卡片侧另有独立表现：R3-03 时间戳容器 86px 装不下 101px 内容，**切列表视图即正常**，说明是容器宽度分配问题。
4. **"hover 才出现"的入口在工侧重复出现两次**：列表卡片操作栏（R3-01）与画布节点操作按钮（R3-12）。开发侧对应问题是"纯图标工具栏"（S3-13）。**同一类可发现性缺陷跨分区复发**。
