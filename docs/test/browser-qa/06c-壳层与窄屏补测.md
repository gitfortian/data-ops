### 1. 窄屏复核 `/system/projects`、`/system/users`、`/system/roles`、`/system/oplogs`（1280×800 / 1200×800 / 992×800）—— 判定：**可用但窄屏布局需整改（P2×3 + P3×1），无 P0/P1**

12 组（4 页 × 3 档）单会话实测，每档均用 `Emulation.setDeviceMetricsOverride` 设定后测量、测毕清除。

**（a）页面级横向滚动条：三档 × 四页全部「无」**（这是本轮最重要的正向结论，S6 的推断被实测否证了一部分）

| 页面 | 1280 | 1200 | 992 |
|---|---|---|---|
| `/system/projects` | `pageHScroll:false` `docSW/CLW:1280/1280` | `false` `1200/1200` | `false` `992/992` |
| `/system/users` | `false` `1280/1280` | `false` `1200/1200` | `false` `992/992` |
| `/system/roles` | `false` `1280/1280` | `false` `1200/1200` | `false` `992/992` |
| `/system/oplogs` | `false` `1280/1280` | `false` `1200/1200` | `false` `992/992` |

**（b）表格是否被祖先 `overflow-hidden` 裁切导致内容不可达：结论「否」**

- 表格自身带 `scroll.x`：`.ant-table-content` 在每页每档都是可横滚容器（projects `sw1227`、users `sw1139`、roles `sw1249`、oplogs `sw1496`，`cw` 821–863 @992）。
- 把容器 `scrollLeft` 拉到最大后重新测量表头右边界：`maxRightAfter` = 1240（@1280）/ 968（@992），均 ≤ `vw` → **每一列都能被滚进视口**。

### 2. 侧边栏折叠态（真实点击 `aria-label="收起菜单"`）—— 判定：**功能可用、可达性良好，但激活态与持久化有 4 个 P3**

先纠正 S6 的两处记录：① S6-17 认为「折叠按钮易误点、点击落到快速创建」——本轮用 `click '[aria-label="收起菜单"]'`（harness 按元素中心派发真实鼠标事件，命中坐标 `x:272,y:24`）**一次即成功**，侧栏 `240 → 64`，因此 S6-17 属「选择器不精确导致的测试操作失误」，不是产品缺陷；② S6 的 `p57-sidebar-collapsed.png` 确为错标（实为快速创建下拉），本轮已自行重拍并逐张核对画面内容（`s01/s02` 两张均确认为 64px 图标栏）。

**图标可辨识度**：64px 栏内每个图标都保留 `aria-label`（10/11）与原生 `title`，读屏可用；但纯图形语义偏弱（两个圆形线性图标分别代表「数据资产与治理」与「数据消费与服务」），且激活项只差文字色（R7-06）。

### 4. 顶部铃铛 / 消息中心 —— 判定：**「下拉」不存在（点击即跳转），批量已读缺失，跨项目落点错误（P2×2 + P3×3）**

**未读计数与消息页一致性**：消息页状态筛选展开后为 `opts:["未读","已读"]`；选「未读」→ `暂无通知`（`empty:true`），与铃铛角标不显示**一致**。未读数 >0 的场景本轮无法安全构造（需触发后端事件生成消息，属全局生效动作，红线外），故「>0 时两端口径是否一致」记为未覆盖。

**「全部已读」入口**：全文检索 `全部已读 / 标为已读 / 批量` 命中 0；页面按钮枚举无批量动作 → S6-09 的缺陷在本轮仍然存在。

**正面结论**：① 详情抽屉信息层次清楚（类型/级别/所属项目/时间/正文/动作），`destroyOnClose` 生命周期处理正确；② 分类 Tab（全部/系统/安全/任务/质量）+ 状态筛选可用，筛选切换实测生效（未读 → 空态文案「暂无通知」而非「暂无数据」，措辞贴合场景）；③ 未读为 0 时铃铛不显示红点，避免噪声；④ 角标通过 `MESSAGE_COUNT_CHANGED_EVENT` 与消息页联动，读一条后顶栏能即时同步（源码级）；⑤ 列表页在 1414 视口无横向溢出。
