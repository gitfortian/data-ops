## 逐页明细

### 登录页 `/login`
- 状态：**有问题**
- 接口：`POST /yak-security/api/v1/account/login` 正确密码 200；错误密码 401（`code 2003`）；不存在的用户 401（`code 2003` 前的 `Total: 0`，提示语为"密码错误"，见 S0-15 备注）
- 布局：1440 宽下无横向溢出、无文字裁切（`diag.overflowX=false`，`clipped=[]`）；左右分栏 + 居中卡片，整体可用
- 交互：**失败零反馈**（S0-02）；无语言切换（S0-03）；无记住我/找回（S0-04）
- 安全侧好消息：连错 5 次触发 `code 2006 账号被锁定`，锁定时长 15 分钟（`YakSecurityProperties.lockDuration`），防爆破有效；但**锁定提示同样只在接口里，页面不显示**
- 备注（S0-15，P3）：用户名不存在与密码错误返回同一提示语，枚举防护 OK；但 `code 2003` 文案对"用户不存在"场景不准确，建议统一为"用户名或密码错误"
- 截图：`qa-shots/s0/`（登录页在 1414x807 下渲染正常）
- **S0-02 代码路径定位（供修复参考）**：`LoginPanel.tsx:158` 的 `catch (_error)` 里只有一句注释 `Global request handling surfaces HTTP, business and network failures once.`，即完全依赖全局出口；全局出口 `utils/request.tsx:94 handleAuthenticationFailure()` 在 `pathname` 以 `/login` 开头时确实会 `notifyOnce("login-authentication", {title:"登录失败", description: reason})`。**但实测这条通知没有出现**（4 类容器节点均为 0），说明"委派全局"这条链路在登录页失败场景下断了（怀疑点：401 走的是 `errorHandler` 的 HTTP 分支而非 `handleBusinessError`，或 `notifyOnce` 的 1.2s 去重窗口被页面加载时那次 `GET /account/current` 401 占用）。仓库自身规矩 S11「出错必须让用户看见」正是为这类"注释声明委派、实际吞掉"而设，`scripts/backbone/check-silent-catch.mjs` 目前把这一处归入"委派全局（放行）"的 51 处之一 —— 建议把登录页改成表单级 inline 错误（`setFieldsValue` + `Form.Item` 报错），不要只依赖通知。

## 交互与共性问题

1. **错误反馈缺失是本次最严重的模式**：接口层已经返回了明确的中文错误（`密码错误`、`账号被锁定`），前端没有把它呈现出来。建议统一在请求层把 `code/message` 映射到 antd `message.error`，登录页额外做表单级 inline 错误。
2. **文字容器宽度不足导致裁切**：首页快速创建、图表轴标签都是"内容比容器宽 → 省略号"，属于卡片栅格分配问题，建议描述文字允许两行。
3. **空态设计不统一**：首页用 yak 插画、待办用文件夹图标 + 双文案、其他分区（见各分区报告）也各有不同，需要一套空态规范。
4. **i18n 覆盖不完整**：登录页整页英文 + `pages.login.success` key 缺失，说明国际化只做了部分页面。
5. **列表页普遍缺筛选/分页/计数**（待办已确认，其他分区待验证）。
