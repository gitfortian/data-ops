### 1. `/data-lifecycle/policy`（TTL 策略管理）—— 判定：**不通过（存在 P1 数据静默丢失）**

**状态**：页面可正常加载（`errors:[]`、`failed:[]`），列表 / 新建抽屉 / 编辑抽屉 / 版本抽屉 / 四个危险动作确认框全部走查完毕；创建了 1 条 `QAR6-测试策略`（id 7）并**已删除**（列表回到 6 条，API `total:6, qar6:0`）。

**观察**

- 数据分布：当前会话默认落在项目空间「工业制造」(project 3)，该空间 `policies/page` 返回 `total:0` → 页面显示引导型空态「还没有 TTL 策略 / 一键初始化 ODS / DIM / DWD / DWS / ADS 分层默认策略」+ 行动按钮，**空态有明确下一步指引，是本轮目前最好的一个空态**。随后通过工作空间切换器切到「默认空间」(project 1，6 条策略：5 内置 + 1 E2E 自定义) 做有数据走查；project 2 / 4 实测 `PROJECT_NOT_FOUND`。
- 列表实测：容器 `left 280 → right 1364`（可视 1084px），`scrollWidth 1452 > clientWidth 1084`，10 列总宽需 1452px；「更新时间」`1265→1425`、「备注」`1425→1480` 均超出内容视口 1414，首屏不可见，必须横向滚动。「操作」列 `position: sticky`、右缘 1364 = 容器右缘 → **固定列生效，未被裁切**（对比 S4a-22 采集页的同类问题，此页更规范）。「备注」列只分到 55px，长备注靠 ellipsis。
- 表单校验（新建抽屉，实测 6 个字段 + 3 个保留期开关）：`策略名称` 留空提交 → 内联红字「请输入策略名称」+ 抽屉保持打开；填 `热 100 / 冷 10 / 销毁 5` 提交 → **warning toast「热数据保留期不能大于冷数据」**（轮询 3s 捕获）；合法值提交 → **success toast「草稿已保存，发布后对模型生效」**、抽屉自动关闭、列表即时刷新并出现「草稿 / 未发布修改」标签。校验反馈链路是完整的。
- **核心缺陷：保留周期三段「不限 / 永久保留」开关与表单值脱钩**。三段开关的 `checked` 取自 `Form.useWatch('hotPermanent' | 'coldPermanent' | 'destroyPermanent')`（`PolicyEditDrawer.tsx:66-69`），但**这三个 name 在全文件中没有任何对应的 `<Form.Item>`**（只有 `hotDays/coldDays/destroyDays` 注册了，见 `:275/:295/:316`），`useWatch` 恒返回 `undefined` → `permanent={Boolean(undefined)}=false` → 开关永远渲染成「按天数 + 可输入」；而 `handleSubmit` 用的是 `form.getFieldValue(name)`（`:133-135`），拿到的是真实 store 值。实测后果：
  - 新建时 `destroyDays` 输入 90 → 保存后 API 记录 `{"hotDays":7,"coldDays":30}` **完全没有 destroyDays 字段**，列表显示「销毁 永久」，界面当时显示的却是「按天数 90」；
  - 编辑态点一次「热数据」开关 → `aria-checked` 仍为 `false`、文案仍为「按天数」，但 `#hotDays` 输入框由 `7` 变成空串，保存后 `hotDays` 直接被提交为 null（实测两次，稳定复现）。
  - 用户视角：**输入被静默吞掉，且没有任何报错或提示**。
- 危险动作确认：**发布 / 下线 / 停用 / 删除全部有 `Modal.confirm`**，文案带影响面（「正被 N 个模型引用，发布后这些模型将按新版本内容生效 TTL」）；实测「发布策略」弹框文案为「将当前草稿内容发布为新版本，发布后模型绑定按该版本生效。确定发布「QAR6-测试策略」？」，**按要求只观察未确认，点「取 消」后行状态仍为「草稿」**。内置策略的「删除」为 `disabled` + Tooltip「内置分层策略不可删除」（实测点击无任何反应、无 5xx）。
- 版本抽屉（640px）：`共 3 个版本` + `对比版本` 开关 + 每行 `V3/线上/时间/操作人/checksum(8位)`，行内图标按钮为「回滚到此版本」；点 V 号可展开快照。**实测在 V3 行开启回滚 Popconfirm 后，Popconfirm 面板向上溢出到工具条区域，其「确认回滚」按钮与「对比版本」按钮完全重叠**，本轮因此**误触发了一次真实回滚**（详见 R6-02 与「环境事故」节）。ESC 键不能关闭版本抽屉（实测 `drawerOpen:true`），必须点 X 或遮罩。
