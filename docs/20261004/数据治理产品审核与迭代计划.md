## 四、迭代计划

原则：

- **先收口，再新建**：F-007/F-008 IMPLEMENTING 与 Phase 7 验收先完成，不新开大而全的域；
- **治理进入真实行为是主线**：每个迭代至少让一个治理域能力"从配置变成行为"；
- **需要新契约的一律先走 Product Decision**（质量评分/问题生命周期、质量门禁、安全对象映射、生命周期范围），本文只提出候选，不拍板；
- 工程修复类（P0/P1 bug）不占用产品迭代槽位，走 R0 快速通道。

### R0 · 阻塞解除（本周内，纯工程）

| 项 | 内容 | 依据 |
|---|---|---|
| R0-1 | 核验同步使用的 Link-Up、MDM 使用的数据开发 SQL 执行路径、TTL 使用的 Doris/Paimon 目标；分别记录可用性。按实际路径解除阻塞，不把 Link-Up 部署当作全部链路的共同前提 | INT-01 P0；B1；现行领域执行边界 |
| R0-2 | 修复 `/ai-agent` 白屏（RemoteComponent 加载失败 + 错误边界），短期先保证不白屏（可下线入口或渲染兜底） | S0-21 P0；B6 |

**验收**：同步任务可完整执行；/ai-agent 可用；QA P0/P1 清零。

### R1 · 治理基线可验收（目标窗口 2~3 周，按剩余缺口与人员容量校准）

**User / Problem**：治理人员与验收人员缺少一致样本和当前运行证据，无法可靠判断数据身份、可信度和处置入口。
**Capability / Journey / Expected Outcome**：沿 J1/J4/J5，在现有资产治理与专业能力中找到对象、理解真实证据并回链处理；主数据审批值在重跑后保持正确。
**Truth Owner / Producer / Consumer / Reuse**：来源、MDM、Quality、Security、Lineage、Lifecycle 生产并持有自身事实；Asset/Home 只聚合。复用现有 API、Query、数据开发、Approval、Alert、Project Space/RBAC 和专业页面。

| # | 工作 | 优先级 / 依赖 | 退出证据 |
|---|---|---|---|

### R2 · 两类真实消费闭环（目标窗口 3~4 周，按缺口与容量校准）

**User / Problem / Journey**：Dataset 消费者、Data Service 集成开发人员与产品 Owner 沿 J3/J5 完成发现→契约→真实裁决→消费→使用证据→已知影响→回链，解决目录与真实执行证据脱节的问题。
**Ownership**：Dataset/Data Service 拥有来源定义和版本；Security/既有调用机制拥有授权；Consumption 只拥有 Subscription/normalized Usage Evidence；Asset、Quality、Lineage 保持原事实归属。

| # | 必须交付 | 退出证据 |
|---|---|---|
| R2-0 | 校准 F-004-A 已冻结契约与 B/C 当前实现、来源缺口 | 剩余缺口清单；区分实现存在与已验收 |
| R2-1 / B | 两类真实 Provider、owner/visibility、type-specific contract、可解释治理证据、canonical detail 与稳定回链 | 关键治理证据不能全部 UNAVAILABLE；来源 Owner 不由投影猜测 |
| R2-2 / C | 主体+动作+调用平面的 Access；实际 Query/Invoke；Subscription 与可恢复的 Usage Evidence；已知 Consumer/Impact | 显示裁决与真实动作一致；订阅不是授权；成功消费关联稳定证据 identity |
| R2-3 / D | 两条完整真实环境验收 | Dataset 登录查询与 Data Service 真实 Consumer/API Key 调用；拒绝、跨 Project、provider 失败、投递失败恢复、幂等及来源生命周期映射 |

**独立评审项**：

- 安全对象、动作与主体映射：相关真实 Access 实现的前置契约。Dataset 已有物理列路径先验收；API Key/Consumer 不冒充 USER/ROLE。未明确的映射不能宣称不阻塞开发。
- 质量发布/上线门禁：明确作用点、来源版本、证据有效期、缺失/过期/执行失败以及例外。与已有 Workflow 质量任务运行失败语义区分；评分和问题生命周期单独评审。
- 非 Model TTL / 归档范围：独立 in/out 决策，不阻塞两类消费基线。产品 DEPRECATED/RETIRED 由来源域拥有，不等于存储 TTL。
- Usage 驱动健康度/推荐排序与 Metric 新来源类型：不纳入本期，前者需评分/排序契约，后者需独立 Product Decision。现有 published Metric 可回链引用它的 Dataset/Data Service。

**成功信号**：分别观察两类产品的发现→详情→真实消费→证据可见漏斗与覆盖缺口；不以一条 Dataset 路径替代 F-004 总验收，不设未经基线测量的百分比 KPI。

## 五、风险与依赖

1. **Link-Up 部署形态未决**（compose 内嵌 vs 独立安装包）——R0-1 的第一个动作是把这个选择写清楚，它同时影响客户交付方式。
2. **种子数据包的可解释性**：合成样本覆盖正常、失败及敏感字段候选；写清预期结果与对应旅程，候选字段不预设为已完成安全分类。
3. **容量与依赖**：F-004-A 已冻结；B/C 可按契约并行，真实动作与证据联调后进入 D。安全映射只阻塞相关访问路径；质量发布门禁与 TTL 扩展独立评审。2~3/3~4 周是目标窗口，负责人、验收环境与剩余缺口明确后才承诺日期。
4. **验收环境**：历史环境结论不沿用；首批记录了旧进程 JAR 覆盖引起的类加载错误，并以独立产物实例执行 API 验收。部署来源、运行证据与源码测试分别记录，不能互相替代。
