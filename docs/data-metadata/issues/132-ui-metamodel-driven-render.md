# Ticket 132：前端由元模型驱动渲染——零类型常量

**对应需求：** 可扩展性在 UI 侧兑现 | **阶段：** P4 | **模块：** yak-ops-ui

**What to build：** 目录列清单、详情面板、筛选项**一律由 `GET /api/v1/metadata/types` 驱动**。新类型接入后**不改前端代码**即出现在检索面与详情页。这是"加一类元数据 = 插一行、不改代码"这条承诺在前端的兑现，做不到就是假可扩展。

**Blocked by：** 129（接口）、123（挂载点）；**可按契约先行开发**（只依赖 117/118/129 的 API 形状，不必等后端完成）

- [ ] 列表列、表单项、facet 项均不写死
- [ ] **grep 守护**：页面里不得出现 `'table' | 'dataModel'` 这类硬编码类型联合（plan §8 P4、§10 测试 12）
- [ ] 属性展示按 `field_def` 的 `base_type` / `show_in_list` / `ordinal` 渲染；`ENTITY_REFERENCE` 类型的字段渲染成可跳转的实体链接
- [ ] 未知 `base_type` → 降级为只读文本并在控制台告警，**不白屏**
- [ ] `npx tsc --noEmit` 不高于 199 基线；被改文件零新增错误
