# 全站前端商业化升级方案

日期：2026-10-02
性质：浏览器审核证据与设计建议；不是已批准的 Feature Spec。
范围：全站页面，按用户任务与模块逐批升级。
交付状态：本轮完成审核、调整方案和覆盖索引；前端代码改造与升级后验收尚未执行。

## 1. 结论与实施顺序

现有页面已经覆盖较多业务能力，但视觉和交互仍有明显改进空间：公共容器限制窄屏、列表列数与筛选项过多、留白分配不合理、状态和技术标识难读、空状态体系分散、详情首屏缺少明确下一步。

建议按以下顺序实施：

1. **公共框架和组件**：修复窄屏、智能助手白屏、文字对比度和状态表达，建立列表/详情/表单模板。
2. **资产与元数据**：作为首批完整样板，验证“找到对象→理解事实→进入专业治理”的路径。
3. **标准、建模与指标**：调整树表结构、版本信息、验证与发布层级。
4. **接入、开发与运行**：调整连接表单、任务列表、SQL 工作台与工作流画布。
5. **质量、安全与生命周期**：明确证据覆盖、时间窗口、检查结论和阻断原因。
6. **主数据与审批**：呈现实体、来源、变更差异和处理过程。
7. **消费、API 与分析展示**：让用户理解如何获得并使用产品；统一空态与编辑器引导。
8. **平台管理与全站收口**：统一名称、消息、设置、登录/错误页面，再完成全部角色和状态复验。

不建议在全站逐页先加颜色、阴影和动效。公共布局、信息层级与状态可信度应先形成可复用样板，随后每批逐页迁移。

## 5. 全站设计与交互标准

以下数值是建议设计基线，待首批样板确认后逐批采用。

### 5.1 视觉 token

| 项目 | 建议 |
|---|---|
| 背景 | 工作区浅灰（如 `#F7F8FA`），内容白色；通过边界和间距分层，普通卡片少用阴影。 |
| 主色 | 沿用现有品牌；主动作样式在 YakButton 与 Ant Design 中统一。采用当前深色主按钮亦可，但同级动作不能一页深色、一页粉色。 |
| 语义色 | 蓝/中性用于信息，绿用于有证据的成功，橙用于需关注，红用于失败/危险。粉色品牌与删除/异常区分；等级色保留领域定义。 |
| 正文 | 正文 14px，次要信息至少 12px；对象名称 14px/中等字重；标题 24px（窄屏 20px），分区标题 16px，KPI 28px。 |
| 间距 | 4/8/12/16/24/32px；页面内边距桌面 24px、紧凑 16px、手机 12～16px；区域间 24px。避免用大空白填满屏幕。 |
| 控件 | 普通高度 36px，紧凑列表 32px；手机点击区域约 44px；表格单行参考 48px，紧凑 40px，双行对象列约 56px。 |
| 圆角 | 控件约 8px，卡片约 12px；不在表格、按钮、标签、抽屉中任意混用。 |
| 信息密度 | 列表默认适中；可选紧凑密度属于视图偏好。详情优先内容密度；概览优先判断与趋势；编辑器优先空间。 |

对白测试：`#667085` 约 4.97:1，`#475467` 约 7.69:1；深粉候选 `#C51B46` 约 5.80:1。候选值只用于试稿，实施时需检查透明度、浅色背景、hover、选中和错误状态下的实际组合。

普通文字对比度以 [WCAG Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 为依据；大字与普通字分别按标准检查。

### 5.2 五类可复用页面模板

**列表页**

```text
标题 / 一句范围说明                         [主要动作]
标签页（确有不同集合时）
[搜索] [高频筛选] [高级筛选]      [重置] [视图/列设置]
已应用条件 · 结果数
名称+编码 | 类型/来源 | 状态/版本 | Owner | 更新时间 | 操作
分页 / 当前范围
```

**概览页**：标题与时间范围→4～6 个关键指标→最需要处理的事项/证据覆盖→有数据的趋势→可进入的对象列表。没有证据的图表采用明确空态；不绘制看起来正常的零曲线。

**详情页**：返回位置→名称、类型、版本、状态、来源与更新时间→允许的主要动作→概览摘要→专业分区标签。技术 ID、JSON、枚举原值可复制，在详情/诊断中展开。不可用原因要具体到事实来源，不能被整体绿色状态遮盖。

**树+内容页**：左侧只负责选择、检索与层级，右侧负责内容；未选择时把选择动作放在空态附近。已有可拖动分隔条继续复用；不要为每页再造另一套。

**表单/编辑器**：基础→对象与规则→高级配置→调度/通知等现有区块；清楚显示当前对象和必填项，保存区域稳定可见。保存失败定位具体字段；保留已填内容；关闭未保存编辑时沿用现有保护机制。

### 5.3 空态、状态与数据表达

- 首次使用：说明“这里管理什么”，提供符合权限的下一步；有前置条件时直接回链该条件。
- 筛选无结果：展示当前条件及“清除筛选”；避免引导用户重复新建。
- 未选择对象：紧邻选择器说明要选什么，不堆叠多个 320px 空块。
- 无数据：说明查询范围与时间；只有源域确认时才能显示数量 0。
- 资产分区继续保留 `OK / NO_DATA / NOT_APPLICABLE / FORBIDDEN / UNAVAILABLE` 等契约含义；加载和错误由相应组件表达。部分失败、旧证据等按源域已有契约展示，不新增前端业务状态机。
- 禁止把“未上架”“未验证”“未执行”“不适用”“无法查询”全部涂成红色异常。
- 金额区分估算与已采集值；比例保留分母和范围；多个时间窗口必须分别标注。
- 时间格式统一，并检查 API 详情最近调用与调用记录当前存在的小时差异；由源时间及既有时区契约决定显示，不在各页各自猜时区。

### 5.4 响应式

| 视口 | 建议布局 |
|---|---|
| ≥1440px | 主导航 240px，对象树 260～320px；内容自适应，宽表按业务允许局部滚动。 |
| 1080～1439px | 依据真实内容宽度压缩树、筛选和卡片；保持现有折叠行为的一致性，不靠全局最小宽度支撑。 |
| 768～1079px | 主导航可用 64px rail；对象树默认收起、以面板选对象；筛选最多两行常用区，其余展开。 |
| <768px | 主导航改抽屉；工作空间和用户入口仍可达；表单单列；KPI 两列或一列；表格摘要卡或局部滚动；详情标签可横向滚动但页面不被撑宽。 |

抽屉统一参考 500/640/880px 三档，桌面不超过 `calc(100vw - 32px)`，手机使用完整可用宽度；标题和底部操作固定、内容区单一纵向滚动。类型选择卡片根据容器自适应，不能强制三张一行。

编辑器可保留画布局部二维滚动。手机至少支持查看、选择对象、检查结果和处理其支持的待办；复杂创作如确实只支持桌面，需在产品契约中明确支持范围并提供可返回的说明。

验收新增 320 CSSpx / 放大场景：[WCAG Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) 对表格/画布等必要二维内容有例外，但该例外不能扩展到整个业务页面。

### 5.5 微交互、键盘与动效

- hover 参考 120～160ms，抽屉/折叠参考 180～220ms，优先 opacity/transform；避免持续呼吸、闪光和装饰性移动。
- 刷新局部区域时保留当前内容与滚动位置，显示该区域的刷新状态；首次加载使用与最终版式一致的骨架或已有加载组件，避免整页反复遮罩。
- 按钮执行时显示动作名称与进度，防止重复提交；结果说明对象和执行结果。长任务进入原有运行记录，不能靠 Toast 宣称完成。
- 图标动作具备可理解的 accessible name、tooltip 与键盘焦点；常用动作不只在 hover 后出现。颜色不是唯一状态提示。
- 打开面板聚焦适当位置，关闭后返回触发点；检查 Escape、Tab、焦点陷阱及折叠菜单隐藏项不会聚焦。快捷键先检查浏览器冲突。
- 动态计数/加载完成按需要使用可访问通知，避免屏幕阅读器连续重复朗读。
- `prefers-reduced-motion` 下关闭非必要位移/循环效果；保留静态反馈。仓库已有部分 reduced-motion 支持，应扩展同一模式，而不是视为全站从未支持。
- 大屏模板中的演示数据必须明确标识，不用动效和实时标志将其呈现为真实运行证据。

非必要交互动效的关闭能力参考 [WCAG Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)。

### 工程改造建议

1. 优先扩展已有 Yak 组件与 `SecurityQueryTable`，统一 token 和变体，不新建平行组件库。
2. `SiteLayout` 先移除错误最小宽度并校验 flex 子项；随后只对需要的表格设置局部 scroll。不要先对所有表格强制自动换行。
3. 检查 `global.less` 的小屏表格全局 `white-space`/span 规则、输入背景 `!important` 与滚动容器；迁移到具有明确作用范围的组件规则。
4. 页面模板通过薄组合承接布局，不把每页的 Query、权限、版本或状态计算塞入全局组件。
5. 展示字典依据领域/类型定义；枚举未知值有安全 fallback 与诊断入口，不能删除 raw 信息或猜语义。
6. 列设置、密度、面板宽度等可以作为用户/空间范围的视图偏好；不是业务真相，不能影响查询权限。
7. 每批补齐合法样本后再评审隐藏详情。缺失状态用受控 fixture/mock 在测试环境验证，不改生产事实来迎合截图。
8. 纯视觉变更以浏览器证据验收；增加有意义的自动化覆盖给公共布局、状态映射、键盘/权限边界和关键回链。避免为每个颜色/间距写镜像实现的测试。

## 8. 验收与“无明显可提升之处”的结束条件

### 每批必须完成

- [ ] 本批主入口、可到达详情、表单、标签和编辑器均列入清单，未验项说明原因与补验安排。
- [ ] 相同对象、空间、版本、数据与视口的改前/改后截图可对照。
- [ ] 1440、1280、1024、768、390、320 CSSpx 及放大场景检查；全局页面不横滚，必要表格/画布局部滚动。
- [ ] 正常、加载、首次无数据、筛选无结果、失败/不可用、无权限、长文本均有适用证据；状态按各域实际契约表达。
- [ ] 键盘能进入导航、打开/关闭面板、选择与提交；焦点可见、关闭返回触发点；图标动作有可理解名称。
- [ ] 普通文字实际对比度达标；状态不只靠颜色；reduced-motion 下非必要动画关闭。
- [ ] 主要动作、禁用原因和下一步容易找到；固定 footer 不遮挡内容；无重复大空态/告警条挤占主路径。
- [ ] 前后对象 ID、版本、源域事实、权限边界与审计语义一致；无前端新增综合状态或伪造数据。
- [ ] 至少一条真实用户任务完整走通，并保存结果证据与回链；单纯页面能打开不算 E2E 完成。

### 全站收口

**“没有明显可提升之处”作为有限验收条件**：全部当前支持入口和主路径状态有证据；不存在未解决 P0/P1；无公共布局/状态/可访问性重复问题；连续两轮代表用户任务复核不再发现阻断和明显信息层级问题。仍可保留不阻断任务的 P2 优化清单，不能宣称页面永远没有改进空间。

成功指标与验收分开。建议实际用户任务记录：找到正确对象的时间、选对入口比例、找到下一步动作的时间、误读状态次数、任务完成率。可先以“对象定位 ≤30 秒、首个下一步动作定位 ≤10 秒”为试测目标，再由真实用户与任务复杂度校准；本轮没有用户实验，不报告改善百分比。

## 9. 第一批具体工作单

建议直接从下列可复核工作开始，范围足够小且能验证公共规则：

1. 修复 SiteLayout 最小宽度、手机 Header/导航和数据源抽屉，保存响应式前后证据。
2. 修复智能助手 marked 依赖声明、安装解析与导出匹配问题并增加异常可恢复入口。
3. 统一按钮语义、空态字体/色彩/高度变体，修正无快照与无调用展示。
4. 完成资产目录常用筛选、默认列、对象树和操作收敛；同时覆盖元数据实体视图。
5. 完成资产详情与元数据抽屉首屏、分区摘要、类型定义标签及来源/时间呈现。
6. 以“用户信息表”和一个实际物理表实体完成目录→详情→专业治理→返回的浏览器复验；再迁移到其他模块。

本轮成果为上述方案和 94 张页面证据；实施后才能判断这些改动是否达到收口标准。
