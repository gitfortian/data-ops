# PostgreSQL 新库部署验收

验证日期：2026-10-05。范围为新库部署，不包含存量 MySQL 数据迁移。

## 环境与结果

- PostgreSQL 16.15，业务库与 Yak Security 权限库分别使用两个测试专用空库。
- `PostgresqlStorageSmokeTest`：1 项完整应用集成测试通过，失败与错误均为 0；两次启动合计约 72 秒。
- Maven 全 reactor 与最终定向回归完成后，测试报告合计 3,282 项（包含上述 PostgreSQL 实库测试），失败与错误均为 0，16 项因环境条件跳过；已有 MySQL 新库应用验收通过。
- 官方 Agent StateStore 适配后另跑 Agent 模块，160 项报告通过；质量、数据服务和任务目录模块最终定向回归共 196 项通过。

## 实库证据

1. 完整 Spring Boot 应用启用 PostgreSQL profile 与 Agent，30 个 Flyway 实例完成迁移及校验；首次管理员登录成功，并通过项目请求获取元数据类型。
2. 工作流与质量 UPSERT 可重放，数字型布尔字段读写正确，事务回滚恢复原值；软删除与生成列约束可用。
3. Metadata 与 Lineage 共享目录分别维护自身字段；无变化采集保留更新时间。中文、空格 OR 和 `%` / `_` 字面量搜索可用，行与分面一致，其他项目不可见。
4. 工作流 2 秒运行时长聚合为 2,000 毫秒；质量、离线同步小时聚合以及数据服务 15 分钟桶查询可执行；实时租约保持 owner CAS。
5. MDM 来源 SQL 重放不增加版本；审批属性覆盖在来源更新后保留，有效变化只增加一次版本，来源加工没有向其他项目写入记录。
6. 第二个工作流 Master 获取锁失败；首实例关闭后完整应用再次启动。Quartz durable job、MDM 版本、管理员及默认项目保持，官方 Agent 状态按用户/会话隔离并恢复。
7. 使用真实发布包、其 Bash 启动脚本与外置 PostgreSQL 配置，在另外两个空库上启用 Agent 并启动应用；首次管理员登录和项目元数据请求成功。发布脚本在未提供外置日志文件时使用 Spring Boot 默认日志配置。

## 验证边界

Docker Compose 和发布配置做静态校验；本机未安装 Docker，因此不宣称完成容器启动验收。外部 Flink、Link-Up、用户自定义 SQL 与外部数据源不属于本次平台存储实库测试。测试使用临时数据库，没有搬迁或修改现有业务数据库。
