## 〇、开始前的三件事（缺一不可）

1. **权限**：你的账号需要本体建模权限（读 `MODEL_READ` / 写 `MODEL_MANAGE`）。
2. **一个"已上线"的数据集**：本体锚定只认已上线数据集。还没有的话，先去数据集管理完成"建数据集 → 录字段 → 上线"。本文样例假设你有一个**销售订单明细**数据集（下表 9 个字段，每行 = 一笔订单明细）。
3. **当前选中状态**：建模台的很多下拉只列"当前选中对象"的数据（指标页签尤其明显），每一步开始前先确认左树和中栏选对了。

### 样例数据集字段（去数据集详情页核对你自己的真实字段）

| fieldId（示例） | 字段名 | 数据集类型 | 说明 |
| --- | --- | --- | --- |
| `order_id` | 订单ID | NUMBER/整型 | 主键 |
| `order_no` | 订单号 | STRING | 业务单号 |
| `order_date` | 下单日期 | **DATE** | 时间字段（必须 DATE/DATETIME 类型） |
| `order_status` | 订单状态 | STRING | PAID/UNPAID/CANCELLED |
| `customer_name` | 客户名称 | STRING | 维度 |
| `product_name` | 商品名称 | STRING | 维度 |
| `quantity` | 数量 | NUMBER/整型 | 度量 |
| `amount` | 金额 | NUMBER/小数 | 度量 |
| `unit_price` | 单价 | NUMBER/小数 | 普通属性 |

> 你数据集里每个字段的 **fieldId** 在数据集详情页的字段列表中查看，第 5 步抄它。

## 一、全景图：你要做的十一步

```text
①建域 → ②建ENTITY对象 → ③建PROCESS对象 → ④锚定数据集 → ⑤录属性(含字段锚)
      → ⑥发布对象 → ⑦建指标(4个,有依赖顺序) → ⑧建流程(可选) → ⑨注册函数(可选)
      → ⑩登记动作(可选) → ⑪发布后修改=走变更单
```

两条硬顺序，违反必然被拒：

- **先锚定数据集，再录"字段锚"**（属性上填 fieldId 时，对象必须已绑定数据集）；
- **DERIVED/COMPOSITE 指标引用的原子指标必须已发布**（下拉只列已发布指标）。

## 二、逐步操作（每步：入口 → 填什么 → 自检点）

### 第①步 建业务域

**入口**：建模台左侧"业务域"卡片 → 新建域。

| 字段 | 填 |
| --- | --- |
| 编码 | `order` |
| 名称 | `订单域` |
| 父域 | 不选（顶级域） |
| 描述 | `电商订单主流程：销售单-指标` |

建完左树出现"订单域（order）"，**点选它**再进行后续步骤。

### 第②步 建 ENTITY 对象"销售订单"

**入口**：中栏"业务对象"卡片 → 新建对象。

| 字段 | 填 | 说明 |
| --- | --- | --- |
| 编码 | `sales_order` | 全域唯一，建后不可改 |
| 名称 | `销售订单` | |
| 概念类型 | `ENTITY 实体` | 主数据/单据选 ENTITY |
| 标识属性 | 先跳过 | 对象还没有属性，此处禁用是正常的；第⑤步录完属性后再回来选 |
| 负责人 | `订单组` | |
| 描述 | `客户下单产生的订单记录` | |

### 第③步 建 PROCESS 对象"销售行为"（为什么要建它）

**原子指标只能挂在 PROCESS 类型对象上**（"业务过程 × 度量"），所以除了单据对象，还要建一个代表"发生了什么业务过程"的对象：

| 字段 | 填 |
| --- | --- |
| 编码 | `sales_event` |
| 名称 | `销售行为` |
| 概念类型 | `PROCESS 业务过程` |
| 负责人 | `订单组` |

> 判据：问"这个对象的每一行是不是一件发生的事、且要算数？"——是 → PROCESS；是"一个东西/一份单据" → ENTITY。

### 第④步 锚定数据集（两个对象各锚一次）

**入口**：中栏对象行 → "锚定"按钮（仅 DRAFT 可点）。

| 字段 | 填 |
| --- | --- |
| 数据集（须已上线） | `销售订单明细` |
| 锚定粒度 | `DETAIL`（明细级） |
| 锚定用途 | `日汇总用于 GMV 看板（AI 按用途选集）` |

`sales_order`、`sales_event` **都**锚到同一数据集。**此步之后才能在属性里填字段锚。**

### 第⑤步 录属性（核心步骤，照抄两张表）

**入口**：选中对象 → 右栏"编辑属性集合" → 弹窗内"添加属性"。
"数据集字段锚"一列填数据集详情页字段列表里的 **fieldId**（照第④步锚定的数据集）。

**sales_order（销售订单）的属性：**

| 逻辑名 | 业务名 | 类型 | 角色 | 时间 | 主键 | 可空 | 字段锚 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| order_id | 订单ID | bigint | ATTRIBUTE | | ✓ | | `order_id` |
| order_no | 订单号 | string | ATTRIBUTE | | | | `order_no` |
| order_date | 下单日期 | date | DIMENSION | ✓ | | | `order_date` |
| order_status | 订单状态 | string | DIMENSION | | | ✓ | `order_status` |
| customer_name | 客户名称 | string | DIMENSION | | | ✓ | `customer_name` |
| product_name | 商品名称 | string | DIMENSION | | | ✓ | `product_name` |
| quantity | 数量 | bigint | MEASURE | | | ✓ | `quantity` |
| amount | 金额 | decimal | MEASURE | | | ✓ | `amount` |

录完保存。**回到对象表点"编辑"→ 标识属性选 `order_no`**（下拉已可选），保存。

**sales_event（销售行为）的属性**（在中栏点选 sales_event 后再开弹窗）：

| 逻辑名 | 业务名 | 类型 | 角色 | 时间 | 主键 | 字段锚 |
| --- | --- | --- | --- | --- | --- | --- |
| order_id | 订单ID | bigint | ATTRIBUTE | | ✓ | `order_id` |
| order_date | 下单日期 | date | DIMENSION | ✓ | | `order_date` |
| order_status | 订单状态 | string | DIMENSION | | | `order_status` |
| quantity | 数量 | bigint | MEASURE | | | `quantity` |
| amount | 金额 | decimal | MEASURE | | | `amount` |

**角色怎么判断**（判据见附录 B）：能加能减的数 → MEASURE；用来分组筛选的文本/日期 → DIMENSION；其他（外键、编号、单价快照）→ ATTRIBUTE；参与"按时间看"的时间列 → 勾"时间"。

### 第⑥步 发布对象（发布前自检）

**入口**：对象行 → "发布"。发布前逐条自检（后端会拦）：

- [ ] 每个属性都填了字段锚（有一个空着就会被拒："属性未完成映射"）
- [ ] 至少一个属性勾了主键
- [ ] PROCESS 对象：至少一个属性勾了"时间"、至少一个角色是 MEASURE
- [ ] 对象还是 DRAFT 状态

两个对象依次发布，状态变 PUBLISHED。

### 第⑦步 建指标（4 个，注意顺序和坑）

**关键坑：先在中栏点选 `sales_event`，再进指标页签新建**——"度量属性"下拉只列当前选中对象的属性，选错对象会导致"度量属性不属于统计主体"被拒。

按此顺序建（有依赖）：

| 顺序 | 编码 | 名称 | 类型 | 填法 |
| --- | --- | --- | --- | --- |
| 1 | `gmv` | 成交额 | ATOMIC 原子指标 | 业务过程对象=`销售行为`，度量属性=`金额`，聚合=`SUM`，单位=`元` |
| 2 | `order_count` | 订单数 | ATOMIC | 业务过程对象=`销售行为`，度量属性=`数量`，聚合=`COUNT`，单位=`单` |
| 3 | `aov` | 客单价 | COMPOSITE 复合 | 组件指标=`gmv`、`order_count`（下拉多选），公式=`gmv / order_count`，单位=`元` |
| 4 | `gmv_yoy` | 成交额同比 | DERIVED 派生 | 原子指标=`gmv`（下拉只列已发布 ATOMIC），时间周期=`同比`，修饰=`增长率` |

1、2 建完**先发布**，3、4 的下拉里才会出现它们；每个建完点"发布"。
负责人默认已填 `system`，别清空——指标发布强制要求 owner。

### 第⑧步 建业务流程（可选）

**入口**：右栏"业务过程流"页签 → 新建流程。

| 字段 | 填 |
| --- | --- |
| 流程编码 | `order_to_pay` |
| 流程名称 | `下单到支付` |

步骤（"添加步骤"逐行加，业务对象下拉选域内对象）：

| 序号 | 业务对象 | 说明 |
| --- | --- | --- |
| 1 | 销售订单（sales_order） | 客户下单 |
| 2 | 销售订单（sales_order） | 支付完成 |

保存后发布。

### 第⑨步 注册函数（可选，在"注册面"页面）

**入口**：导航进入注册面 → 函数注册表 → 登记函数。函数 = 聚合表达不了的过程计算，**只读 SQL 模板**。

| 字段 | 填 |
| --- | --- |
| 编码 | `order_amount_by_no` |
| 名称 | `按单号查订单金额` |
| 参数声明 JSON | `[{"name":"orderNo","type":"string","required":true,"description":"销售订单号"}]` |
| SQL 模板 | `SELECT order_no, amount FROM t_sales_order WHERE order_no = :orderNo`（表名换成你数据集背后的真实物理表） |
| use_rule | `需要按订单号查询订单实付金额时调用` |

发布闸（后端强制）：SQL 只读（含 INSERT/UPDATE/DELETE/DDL 即拒）；模板里每个 `:xxx` 占位符都必须在参数声明里；use_rule 必填。

### 第⑩步 登记动作（可选）

**入口**：注册面 → 动作登记 → 登记动作。动作 = 一切写语义的唯一通道。
样例：编码 `remind_unpaid_orders`，名称 `催付未支付订单`，风险级 `MED`，效果描述 `对超时未支付订单发起催付提醒`。
**注意**：发布后它会被 Agent 发现，但"执行验证"被拒绝（`ACTION_NOT_EXECUTABLE`）是**预期行为**——治理三件套上线前一切写语义无出口。

### 第⑪步 发布之后想改？走变更单

已发布对象的属性**不能直接编辑**（直接改会被拒）。路径：中栏上方"登记变更" → 在弹窗里改属性集 → 生成 DRAFT 变更单 → 变更单列表里"生效"（属性原子替换，受影响指标的口径版本自动 +1）。

## 三、常见报错对照表

| 报错（关键词） | 原因 | 怎么修 |
| --- | --- | --- |
| 对象未绑定数据集，不能按字段锚定 | 没做第④步就填了字段锚 | 先锚定数据集，再编辑属性 |
| `[ANCHOR_ROLE_MISMATCH]` | 本体角色与数据集字段角色错位（如 MEASURE 锚到文本字段） | 按第⑤步表对齐角色；或该数据集字段未标角色时不会触发此项 |
| `[ANCHOR_TIME_MISMATCH]` | 勾了"时间"但字段不是 DATE/DATETIME | 换时间类型字段，或去掉"时间"勾选 |
| `[ANCHOR_AGG_UNAVAILABLE]` | ATOMIC 指标的度量属性没锚到 MEASURE 字段 | 检查该属性的字段锚与角色 |
| 属性未完成映射，禁止发布 | 有属性的"字段锚"为空 | 补齐每个属性的 fieldId |
| 对象缺少主键属性，禁止发布 | 没勾主键 | 任一属性勾"主键"（如 order_id） |
| PROCESS 对象缺少时间/度量事实属性 | PROCESS 缺 isTime=1 或 MEASURE 角色 | 按第⑤步 sales_event 表补 |
| 仅 DRAFT 状态可发布 / 直接改被拒 | 对象已发布 | 走第⑪步变更单 |
| base_attribute_id 不属于该统计主体对象 | 建指标时"度量属性"下拉对象与所选业务过程不一致 | **先中栏点选 PROCESS 对象，再新建指标** |
| 指标缺少 owner，禁止发布 | 负责人被清空 | 表单负责人保持非空（默认 `system`） |
| `[FUNCTION_PARAM_UNDECLARED]` | SQL 里的 `:xxx` 没在参数声明中 | 补 paramsJson 或删占位符 |
| `[FUNCTION_TEMPLATE_NOT_READONLY]` | SQL 含写操作关键字 | 平台函数只读；写语义走动作 |
| `[FUNCTION_USE_RULE_REQUIRED]` | use_rule 为空 | 填"什么场景该调用我" |

## 附录

### A. 角色与勾选的判断口诀

| 项 | 判据 |
| --- | --- |
| MEASURE | 会做 SUM/COUNT/AVG 的数值列（金额、数量、次数） |
| DIMENSION | 用来分组/筛选的列（状态、类别、日期） |
| ATTRIBUTE | 其余（主键、外键、编号、单价） |
| 勾"时间" | 这一列是"什么时候发生的"（date/timestamp 类型才可勾） |
| 勾"主键" | 业务唯一键（发布强制至少一个） |

### B. 本指南已被纸面预检覆盖的校验点

样例数据逐条过了：SEC-4 角色交叉（MEASURE↔MEASURE、DIMENSION↔DIMENSION、isTime↔date/timestamp）、ATOMIC base 属性 MEASURE 闸、发布四闸（属性全锚/PK/PROCESS 时间+度量/DRAFT）、指标 owner 与归属校验、函数只读+参数对齐+use_rule。数据集字段若由平台标注了角色，与本表不一致处以后端报错为准（对照第三节修）。

### C. 确认你的构建包含批次 0 修复

打开建模台 → 选对象 → 右栏"编辑属性集合"：
- 弹窗里有"添加属性"按钮、有"可空"列 → ✅ 新构建；
- 没有 → ❌ 旧构建，重新构建 `data-ops-ui` 并重启后端，否则第⑤步会卡死（旧版无法新增属性行）。
