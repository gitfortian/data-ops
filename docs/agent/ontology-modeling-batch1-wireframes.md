## 4. 向导 · 第 3 屏 字段含义卡片（重头戏）

```text
┌──────────────────────────────────────────────────────────────┐
│  ← 上一步    ① 提问题 ─ ② 选数据 ─ ③ 认字段 ● ─ ④ 怎么算 ─ ⑤ 上线   │
│                                                              │
│  帮你先按常见情况选好了,逐张看一眼,不对就换:              8 张卡片    │
│                                                              │
│  ┌─────────────────────────────┐   ┌─────────────────────┐  │
│  │ pay_amount · 金额             │   │ order_status·订单状态 │  │
│  │  用来【累加的数】            ▾  │   │  会【变化的标记】   ▾  │  │
│  │ ──────────────────────────  │   │ ┌─────────────────┐ │  │
│  │ 给 AI 的话:                  │   │ │待支付→已支付→已发货│ │  │
│  │ 订单实付金额,不含运费;         │   │ │→已完成            │ │  │
│  │ 退款单不计入            ✎     │   │ │用户付款后,状态变成  │ │  │
│  └─────────────────────────────┘   │ │已支付         ✎   │ │  │
│  （点卡片可换:用来累加的数 /          │ └─────────────────┘ │  │
│    用来分类的 / 一般说明）           │  这段话已帮你拟好 ✎   │  │
│                                    └─────────────────────┘  │
│  ┌─────────────────────────────┐   ┌─────────────────────┐  │
│  │ order_id · 订单号             │   │ order_date · 下单时间 │  │
│  │  每行数据的【身份证】  🔒自动   │   │  记录【什么时候发生的】│  │
│  └─────────────────────────────┘   │  🔒自动               │  │
│                                    └─────────────────────┘  │
│                                                              │
│                          [ ← 上一步 ] [ 下一步 → ]            │
└──────────────────────────────────────────────────────────────┘
```

【交互】卡片右上 `▾` 换说法（用来累加的数 / 用来分类的 / 一般说明），系统内部映射为对应角色，**界面永不出现角色词**；`🔒自动` 卡片默认收起不可改（身份证/时间由系统认），点开可见并允许人工纠正。【幕后】"给 AI 的话"由规则预拟（字段名+取值样例模板），状态类字段用内部三问拼装流转说明。【状态】某字段预拟失败（取值采样为空）→ 卡片显示"这段话还没想好,你来写一句" + 空文本域（全向导唯一可能要写的场景）。

### 上线自查（有问题时，同一屏展开）

```text
│   [ 上线 ]                                                │
│   ┌────────────────────────────────────────────────┐    │
│   │ 上线前帮你检查了一遍,有 2 件小事:                   │    │
│   │ ⚠ 有 2 个字段还没说明对应哪里的数据    [ 去补 → ]     │    │
│   │ ⚠ 还没有能当"身份证"的字段             [ 去指定 → ]  │    │
│   └────────────────────────────────────────────────┘    │
│   （逐条修复后此清单自动重查,全绿即放行）                      │
```

【交互】"去修复"跳转携带上下文，修复后自动回到本屏重查；【幕后】自查=发布校验的人话映射（字段绑定缺失/缺主键/事件记录缺时间或缺算数），**后端规则不变，只换说法**。

### 8.1 字段含义分区（卡片同向导第 3 屏 + 物理对应下拉）

```text
│ pay_amount · 金额                                                 │
│  用来【累加的数】 ▾      对应数据位置: [ 订单明细.pay_amount ▾ ]      │
│  给 AI 的话:订单实付金额…                              ✎           │
```

【交互】"对应数据位置"为下拉（本记录绑定数据集的字段列表）——终结手抄编号；换绑数据集时全量重选并触发重查。

### 8.2 关联关系分区

```text
│ 它连着谁:                                                          │
│  · 用户 —— "用户 下单 产生 订单"        连通性 98% ✓                  │
│ 谁连着它:                                                          │
│  · （暂无）                                                        │
│  [ 登记一条关系 ]                                                   │
│   ↳ 登记引导(三步): ①选一个东西 ②它们怎么连(两侧各选一个字段)          │
│                     ③系统试连:"抽 100 行,98 行能连上" ✓ [ 保存 ]      │
```

【交互】登记向导式三步；试连结果即 ANCH-1 校验的人话呈现，命中率过低给出提示"这两边好像连不太上，看看字段选对了没"。

### 8.3 变更单分区

```text
│ [ 发起变更 ]                                                       │
│   ↳ 在字段含义区直接改 → 系统识别"这是已上线的记录" →                  │
│ ┌──────────────┬──────────────┬──────────────┐                    │
│ │ 字段           │ 改动前         │ 改动后         │                    │
│ │ 订单状态        │ 待支付→已支付…  │ 新增:已退款     │                    │
│ └──────────────┴──────────────┴──────────────┘                    │
│ 影响哪些分析: 沉睡用户消费金额 等 2 个                                │
│ 变更说明: [ 为什么改:运营侧新增退款状态                ]              │
│ [ 提交变更单 ] → 确认后生效,受影响分析自动标注新版本                    │
```

【交互】已上线记录上直接改 → 系统自动转入变更单流程（而非拒绝）——**拦截变引导**。

## 10. 关键状态与异常设计

| 场景 | 界面表现 |
| --- | --- |
| 无已上线数据集（向导第 1 屏） | 整屏引导："还没有上线的数据。先去数据集页面上线一份，再回来。[ 去上线数据 → ]" |
| 字段说明预拟失败 | 卡片显示"这段话还没想好，你来写一句" + 空文本域（唯一可能要写的场景） |
| 上线自查不通过 | 第 5 屏展开人话清单 + 去修复跳转，自动重查 |
| 数据绑定异常（源头变化） | 详情顶部进度条红显"数据绑定 ⚠ 对不上了 [ 去修复 ]" |
| 已上线记录上直接改 | 自动转入变更单流程（拦截变引导，不报错拒绝） |
| 删除/危险操作 | 统一二次确认，文案说后果不说术语（"删除后这个记录的分析都不能用了"） |

## 11. 落地备注（给开发）

- 线框组件映射：步骤条=Steps、字段卡=Card+Segmented（说法切换）、自查清单=Result+List、变更对照=Table diff、旅程=Timeline+拖拽排序；
- 角色枚举/编码生成/字段锚自动写入均在**前端服务层**完成映射，界面层无术语常量；
- 本线框覆盖批次 1 设计全部屏；字段下拉、搜索分页、变更对照复用 shared 组件（见设计文档落地备注）。
