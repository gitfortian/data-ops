# 指标登记 · 三件套设计（登记在画布 · 角标在节点 · 家底在抽屉）

> 日期：2026-09-05 | 视角：**产品与交互设计**——只描述用户看到什么、做什么、得到什么。
> 上位文档：`ontology-canvas-workbench-design.md`（画布主界面）、`ontology-modeling-batch1-ux-design.md`（批次 1 总设计，其第 4 屏"这个数怎么算"由本文承接落地）。
> 产品决策（产品主确认）：**指标不做成画布节点**——它是"从某条记录身上算出来的一个数"，离开记录无从谈起；画布保留给业务骨架（名词节点 × 动词边）。

---

## 一、一句话定位

> 画布负责"业务里有什么、怎么连"；数的登记跟着记录走（检查器）；数的家底有专门的汇总抽屉。三层各管各的，互相跳转。

## 二、三个时刻

### 时刻一 · 登记（在画布里，不跳出）

**入口**：点开一条记录，检查器里"能算的数"分区。空状态一句引导："这条记录还说不清能算什么数"，下方"登记一个数"按钮。

**表单只问四件事，答案能生成的都生成**：

| 问题 | 形态 | 默认 |
| --- | --- | --- |
| 这个数叫什么？ | 输入框 | 选完"怎么算+算哪个字段"后自动拼一个建议名（如"下单记录·订单金额"），可改 |
| 怎么算？ | 三个单选：**求和（默认）/ 数个数 / 平均** | 求和；记录身上没有"用来累加的数"的字段时默认"数个数" |
| 算哪个字段？ | 下拉，只列这条记录里"用来累加的数"的字段 | 预选唯一候选；**选"数个数"时整问消失**——一行算一个，不需要选字段 |
| 什么情况不算进来？ | 一两行开放文本 | 空。占位："比如：退款单不算；只下单没付款的不算" |

用户全程见不到：编码（自动生成）、类型（系统内部各司其职）、制定人（自动取当前登录人）。

**口径例外本批的边界**：那句"不算进来"登记进这个数的说明，处处可见（卡片、家底、导出）；把它变成机器可执行的结构化规则是后续批次的事——先让规矩被记下来，再让规矩被执行。

### 时刻二 · 查看（轻存在感）

- **节点上**：记录卡片一个角标"N 个数"。扫一眼就知道哪条记录身上有数、哪条还没有。
- **检查器里**："能算的数"分区逐张卡片：名字 + 一句话算法（"求和 · 订单金额"/"数个数 · 每行算一个"）+ 状态（草稿/已上线/已下线）+ 口径例外原文（有则展示）。卡片上就地"上线"：先过一遍检查，不通就用人话告诉差什么；已上线的卡片给"下线"。
- 已上线的数不能改内容（口径要稳定）——要改就下线后重新登记一个，界面上不做编辑入口，避免用户误以为可以悄悄改口径。

### 时刻三 · 家底（"这个模型里的数"抽屉）

画布顶栏入口，打开一个抽屉回答全景问题："我们到底定义了哪些数"。

- 全部数一页看全：搜索（按名字）、按所属记录分组、状态可见；
- 卡片同检查器（算法一句话 + 例外原文 + 上线/下线）；
- **派生/复合数的登记入口在这里**（不是画布动线）：它们要基于已上线的数加工（如"环比""占比"），依赖性强、使用频率低，用稍专业的表单正合适——但文案仍走业务话改造，编码等仍自动生成或隐藏；
- 从这里能看到每个数挂在哪条记录上，点击跳回画布定位该记录。

## 三、文案对照（本模块新增部分）

| 不出现 | 取而代之 |
| --- | --- |
| 指标 / METRIC / ATOMIC | 数 / 一个能算出来的数 |
| 聚合方式 SUM/COUNT/AVG | 怎么算：求和 / 数个数 / 平均 |
| 度量属性（MEASURE）/ base_attribute | 用来累加的数的字段 |
| 口径例外（结构化规则） | 什么情况不算进来？（一句话说明） |
| DRAFT / PUBLISHED / DEPRECATED | 草稿 / 已上线 / 已下线 |
| 指标制定人（owner） | （不出现，自动取当前登录人） |

## 四、这一批明确不做的（及去向）

- **口径例外的结构化规则**：本批一句话承载，后续做"字段+条件"的规则编辑并接执行链路；
- **派生/复合数的图形化血缘**：本批用文字+跳转表达"基于哪个数、怎么加工"，不出图；
- **数的版本与变更单**：已上线即冻结，下线重建承载变化；版本流程按治理规划后续批次；
- **建模向导第 0 屏（提问题）**：待画布动线稳定后以轻入口形式接入（带着问题跳画布）。

## 五、落地备注（给开发，不影响上文产品语义）

- **后端小改（三处）**：① 发布闸放宽——"数个数"（COUNT）允许不挂基数（一行算一个），其余聚合仍强制挂 MEASURE 字段；② 新增按域列指标端点 `GET /api/v1/ontology/metrics?domainId=`（项目隔离，供家底抽屉与节点角标一次取全）；③ Ossie 导出对无基数的 COUNT 输出 `COUNT(数据集)`，不再静默跳过。
- **前端组件**：`MetricRegisterModal`（四问业务表单，编码/制定人/建议名自动生成）、检查器"能算的数"分区、`MetricsDrawer`（家底抽屉，内嵌派生/复合登记=现有 MetricFormModal）、节点角标（node data 加 metricCount）。
- **联动现有能力**：上线失败复用 formatStructuredError 呈现后端人话（后端报错已带 solution）；发布预检的镜像清单本批不重复实现——数的检查项少且都在闸上。
