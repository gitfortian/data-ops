> 日期：2026-09-03 | 状态：计划 v1 待评审
> 定位：本体**页面交互演进**专项计划（`pages/ontology` 工作台 + `pages/ontology-registry` 注册面 + AI 协同建模入口）。上游依据：`ontology-modeling-workbench-design.md`（MW 设计稿，当前实现的载体）、`ontology-mvp-next-steps.md`（语义层二期/三期路线）、`pending-issues.md`（完成登记）。

## 一、现状诊断（2026-09-03 双端源码核对）

### 1.1 前后端能力对齐盘点

| 能力 | 后端 | 前端 | 结论 |
| --- | --- | --- | --- |
| 关系建模 | ✅ 保存/删除/按源查询，保存带 ANCH-1 join 命中率校验（`OntologyRelationController`）；`RelationView` 已预留 `confidence` 字段 | 仅接 `listBySource` 只读 | **缺编辑 UI**（批次 1 接线） |
| 术语表 | ✅ 按域过滤列表 + upsert + 删除（`GlossaryController`） | 未接任何接口 | **缺整块 UI**（批次 1 接线） |

| Agent ↔ 本体工具桥 | ❌ agent 模块源码无任何 ontology 引用 | — | 批次 2 新建（复用 `POST /chat/turns` + SSE 基础设施） |

### 1.2 断点清单（用户走不通或极易困惑，任何 UX 升级前必须修）

| # | 断点 | 证据 |
| --- | --- | --- |
| B-1 | 注册面新建函数/动作保存后提示"已保存（DRAFT）"，但列表只回已发布，**草稿从列表消失，UI 上无任何发布路径** | `pages/ontology-registry/index.tsx:58-67`（`reload()`→`listPublished`）；`OntologyFunctionController.listPublished` 无 status 过滤 |
| B-2 | 属性批量编辑弹窗**没有添加/删除行**——新对象属性为空时用户被卡死；行内输入全是 `defaultValue` 非受控 + 按行序回写，状态易漂移 | `pages/ontology/index.tsx:1168-1306`（`AttributeBatchModal`） |
| B-3 | 域模型支持 `parentId`，但域树平铺渲染，层级能力在 UI 上丢失 | `pages/ontology/index.tsx:645` |
| B-4 | 引用类字段全靠盲输：`identifyBy` 手打逻辑名、DERIVED 指标 `atomicCode` 手编码、COMPOSITE 组件指标手编码、`datasetFieldId` 手填内部字段 ID | `pages/ontology/index.tsx:960,1049,1061,1282` |
| B-5 | 治理代号直接暴露给业务用户（"SCEN-1""PIL-1 唯一编辑入口""GOV-6"等字样出现在表单标签与提示中），分析师无法理解 | `pages/ontology/index.tsx:782,968,1290` 等多处 |

### 1.3 战略判断

- 分析师最痛的不是表单难看，而是**要填的字段多且需要专业知识**（aiContext、role 推断、join 条件、指标口径）——这正是 AI 该接的；
- 人的界面应变成"**引导 + 审核台**"：AI 产草稿包，人做 diff 审核与批量确认。工作台的打磨方向随之从"更精致的新建表单"转向"更高效的审核体验"。

## 二、演进总路线

```text
批次 0 断点修复（≈3.5 PD）
   │  修通"新建→可见→发布"与"属性录入"两个基本闭环
   ▼
批次 1 分析师主线工作流（≈12 PD）
   │  对象详情主线 + 关系/术语 UI 接线 + 发布预检 + 语言层改造
   ▼
批次 2 AI 协同建模（≈12 PD，可按场景拆分）
   │  Agent↔本体工具桥；A1 DDL→属性草稿包先打样，验证"AI 起草+人审核"模式
   ▼
批次 3 全局理解（按需）
      本体检视图 / 健康度面板 / Ossie 导出入口
```

排序原则：批次 0 修通流程，否则一切体验无从谈起；批次 1 建立"对象详情 + diff 审核"这两个**批次 2 的 UI 载体**（AI 草稿要落到关系编辑器和 diff 审核视图上）；批次 2 复用批次 1 的组件，只加工具桥与起草流；批次 3 不进排期，按需求触发。

## 五、批次 2 · AI 协同建模（≈12 PD，场景可拆）

### 5.1 架构：工具桥 + 草稿包 + 审核台

```text
分析师（工作台）
   │ ①贴 DDL / 需求描述 / 选数据集                ④diff 审核·逐条勾选·确认应用
   ▼                                                    ▲
POST /api/v1/agent/chat/turns（复用既有会话+SSE 基础设施）
   ▼
Agent 轮次：新增"本体建模"工具集（decision：绑定建模场景工具集的会话场景，非通用闲聊）
   ├─ 只读工具：get_domains / get_objects / get_attributes / search_published_metrics（供上下文）
   └─ 起草工具：产出【草稿包】= 结构化 payload + 与现状的 diff
   ▼
落库形态：一律 DRAFT / 变更单（GOV-6），绝不直接 PUBLISHED —— 人工确认是唯一生效路径
```

- **工具桥是唯一后端增量**：agent 模块新增 ontology 工具注册（当前 agent 模块无任何 ontology 引用）；
- **审核台复用批次 1 组件**：U1-2 的关系编辑器承接 AI 提议关系，U1-6 的字段级 diff 组件承接草稿审核；
- **关键约束（护栏，对齐 next-steps A5/A6 与二期 E3）**：默认草稿/dry_run、AI 不可覆盖人工 display_name、全程留痕、token 计量复用 `KIND_LLM_CALL` 底座。

### 5.2 场景优先级（按分析师痛点排序）

| # | 场景 | AI 做什么 | 人做什么 | 前置 | DoD | 工作量 |
| --- | --- | --- | --- | --- | --- | --- |
| A1 | **DDL→属性草稿包**（最高频，先打样） | 解析建表语句/字段清单 → 生成属性草稿（role 推断 MEASURE/DIMENSION/ATTRIBUTE、isTime/isPk、aiContext 初稿） | diff 审核视图逐条勾选/改后应用 | 工具桥 + U1-6 diff 组件 | 贴 10 字段 DDL → 草稿包生成 → 审核后属性落 DRAFT 对象；全程无直接 PUBLISHED | 3 PD |
| A2 | aiContext 批量补全 | 对缺字段说明的属性批量生成描述初稿 | 逐条/批量确认 | 工具桥 | 空白 aiContext 覆盖率 0→≥80% 仅经人工确认路径；护栏留痕可查 | 2 PD |
| A3 | AI 提议关系 | 基于两侧锚定字段与采样 join 生成候选关系（带 confidence，字段已预留） | 审 join 条件后保存进关系编辑器 | A1 + U1-2 | 候选关系带 confidence 展示；未经确认不落库 | 2.5 PD |
| A4 | NL→指标草稿 | "上月各区域成交额环比"→ ATOMIC/DERIVED 草稿（过程对象/度量/引用均为选择器约束） | 审核后登记 | 工具桥 + U0-4 指标选择器 | NL 生成草稿指标并经预检发布；口径引用全为下拉值非自由文本 | 2 PD |

工具桥本身 ≈1.5 PD（工具注册 + 草稿包契约 + 留痕）；审核交互复用批次 1 ≈1 PD。

**批次 2 验收**：A1 场景完成一个真实业务域属性建模，人工耗时较纯手工减半（next-steps 二期验收口径一致）；所有 AI 产出可追溯（哪次会话生成、谁确认、何时生效）。
