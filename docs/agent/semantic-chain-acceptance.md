# 语义链路贯通 · 验收说明(规矩可执行 / 一致性引擎 / 多跳路径)

> 日期:2026-09-06 | 状态:后端已实现并全量测试;本文给出验收路径与边界。
> 关联:`ontology-rule-design.md`(规矩)、`ontology-metric-registration-design.md`(数的三件套)。

## 一、这条链路打通了什么

之前的系统:规矩/指标/关系全是"描述"——说得清,不算数、不拦错、不执行。本次之后:

| 能力 | 之前 | 现在 |
| --- | --- | --- |
| 规矩可执行 | 规矩只是存起来的文字 | 指标引用的规矩在查询编译时展开为 WHERE 过滤条件,**真正滤行** |
| 建模时一致性 | 只查字段/发布状态 | **五类逻辑矛盾 + 冗余**在规矩保存、指标保存、指标发布三个口子被拦下(人话+定位) |
| 多跳路径 | 维度 JOIN 只支持单跳 DIRECT | 自动找 ≤3 跳路径(如 订单→用户→用户组),链式 JOIN 编译 |
| 数据安全 | 连接可能一行变多行(口径翻倍) | 每跳必须**多对一/一对一**,一对多跳被放大护栏显式拒绝 |

## 二、矛盾检测在判什么(原理速览)

每条规矩 = 若干"对数据行的要求"(字段+运算符+值)。指标引用的规矩 AND 叠加。检测 =
**按字段把这些要求收敛成允许范围,任一字段范围为空即矛盾**——不是穷举数据行,是
闭式推理(判断次数=提及的字段数,结论覆盖全部数据空间)。五类矛盾:

1. 点 vs 点(`状态=已退款` 且 `状态=待支付`)
2. 点 vs 区间(`金额=50` 且 `金额>1000`)
3. 区间 vs 区间(`金额>1000` 且 `金额<50`)
4. 挖空挖穿(`≠` 掉值域声明里全部取值)
5. 越出值域(`状态=已取消`,值域没有)

外加冗余提醒(被更强条件覆盖,WARNING 不拦截)。值域基准来自属性
`requires_json` 的 `ATTR_VALUE_DOMAIN` 声明(`op=in`+取值数组,或边界约束)。

## 三、手工验收路径(后端重启后)

前置:执行 `scripts/repair-ontology-rule.sql`(存量库);重启后端。

1. **规矩拦截矛盾**:
   - 画布选订单对象 → ⋮ → 管理规则 → 新增「退款单不算」(条件:订单状态 不等于 已退款)→ 保存成功;
   - 再新增「只统计退款单」(条件:订单状态 等于 已退款)→ **保存被拒**,提示两规矩矛盾 ✓
2. **规矩进入编译(过滤生效)**:
   - 登记/发布引用该规矩的指标(如 下单金额,求和);
   - `POST /api/v1/semantic/query/dry-run`,body:
     `{"objectCode":"<订单编码>","dimensions":[],"metrics":[{"code":"<指标编码>"}]}`
   - 返回的 `sqlText` 中应含 `order_status <> ?`(绑定值=已退款)——规矩变成了 WHERE ✓
3. **多跳维度**:
   - 订单→用户(M:N→多对一)、用户→用户组(多对一)建模并发布;
   - dry-run:`{"objectCode":"<订单>","dimensions":["group_name"],"metrics":[{"code":"..."}]}`
   - 返回 SQL 应含两级 `LEFT JOIN ... j1 ...` `LEFT JOIN ... j2 ... ON j1.xxx = j2.xxx` ✓
4. **放大护栏**:
   - 对 1:N 的跳(订单→订单明细)建关系,再按明细字段提问 → 报
     `[DIMENSION_PATH_UNSUPPORTED]` 且消息含"放大" ✓

## 四、值映射(人话值 ↔ 存储值)

数据里存码、建模说人话的场景(订单状态存 `5`,建模说 `已退款`)由
`ATTR_VALUE_MAPPING` 约束承载,在属性 `requires_json` 中声明:

```json
[{"type":"ATTR_VALUE_MAPPING","attr":"order_status",
  "mappings":[{"stored":"5","display":"已退款"},{"stored":"2","display":"已支付"}]}]
```

同一份声明在三处生效:**规矩条件**里写"已退款",提交时前端翻译成 `5`;
**查询编译**时用户过滤/口径过滤的值经映射归一为存储值;**一致性检测**里
规矩(display)与值域(存储值)比较前先归一。前端规则弹窗会自动按映射翻译。

## 五、边界(本版明确不做)

- 条件语言没有跨字段蕴含(`金额>0 蕴含 状态≠待支付`)——需要时再引入约束求解;
- 指标"适用维度矩阵"(哪些维度能看哪些指标)依赖路径推导,已具备基础,矩阵化展示后续做;
- 数据符合度抽样检查(实际数据 vs 值域)是运行期另一道防线,后续批次。
