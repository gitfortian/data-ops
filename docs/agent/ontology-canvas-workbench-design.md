## 一、设计主张

**画布 = 方法论"概念层白板"的产品化。** 过去概念层六步发生在纸面上，系统里只有表单；现在：

| 白板动作 | 画布动作 | 规则 |
| --- | --- | --- |
| 抽实体/抽事件（写名词） | 放节点 | **节点 = 名词**：用户、订单、优惠券、商品；带🔵事件徽标的节点 = 动作留下的记录（一行=一次发生，金额/时间/状态长在它身上，所以能被统计） |
| 抽关系（连动词） | 拉线 | **边 = 动词**：下单、领取、核销、售出——动词是边的标签，边的落点是一个节点 |
| 建层级/看结构 | 看图走查 | 节点上的字段预览、边上的试连命中率，让结构问题当场可见 |

分工铁律：**画布管结构与关系；检查器/详情管单记录的字段；向导管问题驱动的第一份记录。** 任何字段表单都不出现在画布节点上。

## 二、建模全流程（促活案例串讲 · 九个时刻）

> 每个时刻四段：【用户做什么】【界面发生什么】【产生什么】【有什么用】。案例数据：`analysis` 库 promo_ 六表已就绪。

### 时刻 1 · 建域（拿到一张空白画布）

【用户做什么】进入本体建模，新建"营销域"。
【界面发生什么】一张空白画布 + 左侧空的记录清单。
【产生什么】业务域（锚定 Agent 检索范围与权限）。
【有什么用】画布以**域为单位**——一个域一张图，图就是这个域的业务结构。

### 时刻 2 · 放名词（登记一种记录）

【用户做什么】双击画布空白处（或点工具栏"+ 登记一种记录"）→ 系统问"这件事/这个东西的数据在哪份数据表里？"→ 选 `订单明细` → 给记录起个名："订单"。
【界面发生什么】画布上出现一个**事件节点**（徽标：事件 · 一行=一笔订单），系统按数据集字段自动预拟好字段含义卡片（字段名/说法/给 AI 的话），节点下半部实时长出字段预览；同时左侧记录清单多一行。
【产生什么】事件对象（DRAFT）+ 与数据集的绑定 + 预拟的字段说明。
【有什么用】"抽事件"从纸面动作变成放节点；字段含义被系统预拟，用户从"填表"变成"核对"。

### 时刻 3 · 放更多名词

【用户做什么】重复时刻 2：`用户主数据` → 实体节点"用户"；`券信息表` → 实体"优惠券"；`券发放明细` → 事件"用券记录"；`商品信息表` → 实体"商品"。
【产生什么】五个节点（3 实体 + 2 事件），字段含义均已预拟。
【有什么用】概念层"抽实体 + 抽事件"完成——全程没有表单，只有"选数据 + 起名字"。

### 时刻 4 · 拉线（动词登记关系）

【用户做什么】从"用户"节点边缘拉线到"订单"节点 → 气泡确认："**用业务话说说它们的关系**"（输入"下单 产生"）+ 数量关系（1:N）→ 保存。
【界面发生什么】边生成，标签"下单 · 1:N"；系统自动试连两侧数据，边下挂出绿标"试连命中 98%"；试连失败则挂红标"未试连/连不上，看看字段选对了没"。
【产生什么】一条关系（join 条件由两侧"身份证"字段自动推荐，可改）。
【有什么用】关系是 AI 跨对象查询的 join 路径；试连命中率把"关系建得对不对"从猜变成看。继续拉：用户—领取→用券记录、优惠券—核销→用券记录、商品—售出→订单。
【本屏的克制】边的编辑（join 条件/删除）v1 只做"删除"，其余走点开节点/边的侧栏。

### 时刻 5 · 点节点精修（检查器）

【用户做什么】点"下单行为"节点 → 右侧检查器展开。
【界面发生什么】检查器自上而下：建模进度条（字段含义 n/m · 数据绑定 · 身份证 · 给 AI 的话 x/y，点击定位）→ 基本信息摘要 → **字段含义卡片**（说法切换/对应数据位置下拉/给 AI 的话——均已预拟，用户只核对）→ 数据绑定摘要 → "打开完整详情"。
【产生什么】核对后的字段含义与 aiContext——语义层给 AI 的唯一真相。
【有什么用】节点让结构可见，检查器让含义准确——用户最贵的动作是"判断对不对"，不是"填空"。

### 时刻 6 · 上线（自查前置）

【用户做什么】点工具栏"上线自查"（或节点上的"上线"）。
【界面发生什么】自查清单逐条人话："✅ 已登记 9 个字段 / ⚠️ 有 2 个字段还没说明对应哪里的数据（去字段含义）"——逐条修复，全绿放行。
【产生什么】已上线的事件/实体节点（角标变绿）。
【有什么用】事后报错在这个产品里不存在；上线闸的后端规则不变，前端只换说法。

### 时刻 7 · 登记指标

【用户做什么】点事件节点"订单" → 检查器"登记指标" → "怎么算？求和/数个数/平均" + "什么情况不算进来？"
【产生什么】原子指标（口径唯一源头）。
【有什么用】"沉睡用户消费金额"这类口径从此有了唯一出处，看板/AI/接口全部引用它。

### 时刻 8 · 串旅程

【用户做什么】左侧"用户旅程" → 新建"领券到支付" → 把画布上的事件节点按顺序拖进旅程，每步写一句"发生了什么 → 什么变了"。
【产生什么】业务流程（Flow）——AI 理解业务来龙去脉的叙事材料。
【有什么用】三层表达的旅程层：节点是单句，旅程是段落。

### 时刻 9 · 回放与变更

【用户做什么】对着问题清单逐条提问（"哪些沉睡用户该发券"）；已上线的记录要改字段 → 检查器直接改 → 自动转入变更单（字段级对照 + 影响面 + 确认生效）。
【产生什么】答案 + 受控的口径演进。
【有什么用】**建模完成的唯一定义 = 问题回放全绿 + 对数通过**；变更不失控。

## 三、画布工作台逐区交互设计

### 3.1 布局总览

```text
┌ 顶栏:产品导航 ────────────────────────────────────────┐
├ 副栏:域选择 ▾ | +登记一种记录 | 自动整理 | 🔍 | 上线自查 | 图例 ┤
├────────┬──────────────────────────────┬──────────────┤
│ 左:记录 │ 画布(节点/边/提示胶囊/小地图/缩放) │ 右:检查器      │
│ 清单+旅程│                              │ (点节点展开)   │
└────────┴──────────────────────────────┴──────────────┘
```

### 3.2 节点（名词）

- **结构**：头部（图标 + 名称 + 类型徽标 + 生命周期角标）+ 字段预览区 + "共 N 个字段 · 给 AI 的话 x/N"脚注；
- **类型徽标**：🔵事件（动作留下的记录，一行=一次发生）/ 🟢实体（名词主数据）/ 🟣值对象；徽标文案带粒度短语（"一行=一笔订单"）；
- **字段预览规则**：显示前 4 个字段，每行 `字段名 + 说法小标`（累加/分类/时间/身份证/变化标记），超出折叠进脚注；**身份证字段绿标、时间字段标"时间"**——发布闸的关键项在节点上直接可见；
- **生命周期角标**：已上线（绿）/ 草稿（黄）/ 绑定异常（红："对不上了 [去修复]"）；
- **选中态**：蓝边 + 投影 + 右侧检查器展开。

### 3.3 边（动词）

- **标签**：动词短语（"下单""领取""核销"）+ 基数（1:N）；
- **试连徽标**：ANCH-1 命中率绿标（≥80% 绿 / 60~80% 黄 / <60% 红"连不上"）/ 未试连灰标；
- **弱关联**：经中间记录的间接关联画虚线（如"下单—用券"经订单号）；
- **交互 v1**：点边选中（显示标签详情）+ 删除；join 条件编辑走点边后的侧栏（v1 不在边上做表单）。

### 3.4 拉线登记关系

1. 从节点边缘拉线到目标节点；
2. 气泡确认三件事：用业务话说关系（必填，示例引导"用户 下单 产生 订单"）· 数量关系（可空）· 连接字段（两侧下拉，默认推荐两侧"身份证"字段）；
3. 保存 → 系统试连 → 边上挂命中率徽标；
4. **字段选不上的表现**：试连 0% 时边标红并提示"这两边好像连不太上"，不阻断保存（允许先建后修）。

### 3.5 新增名词（双击空白 / 工具栏）

1. 问句一："它的数据在哪份数据表里？"（已上线数据集列表，含"这行代表什么"一句话确认）；
2. 问句二："叫什么？"（名称；编码自动生成）；
3. 生成节点 + 自动预拟全部字段含义卡片 + 自动绑定；
4. 无合适数据集时：允许"先建概念，数据后补"（节点标"未绑定"，不阻断画布思考）。

### 3.6 检查器（点节点展开，可收起）

自上而下：名称+徽标 → 建模进度条 → 基本信息摘要 → 字段含义卡片（同向导第 3 屏：预拟+确认）→ 数据绑定摘要 → [打开完整详情]（跳转对象详情页精修指标/变更单）。宽度可拖拽调节。

### 3.7 工具栏

`+ 登记一种记录` · `自动整理`（一键布局）· `🔍`（按名称定位节点并高亮）· `上线自查`（域级：列出所有草稿节点的自查问题汇总）· 图例。

### 3.8 左侧清单

记录清单（点选=画布高亮定位；双击=打开详情页）+ 用户旅程列表（点开旅程查看/编辑）。域内全部记录无论草稿/上线都在列——"抽了暂不建"的概念在这里登记（状态：计划中）。

### 3.9 空态与异常

| 场景 | 表现 |
| --- | --- |
| 空画布 | "从一张数据表开始：登记一种记录" 大按钮 + 跳向导入口 |
| 无已上线数据集 | 引导去数据集上线，允许"先建概念后补数据" |
| 试连 0% | 边标红 + 提示，不阻断 |
| 绑定异常 | 节点角标红"对不上了 [去修复]"（重新绑定流程） |
| 节点过多 | 搜索定位 + 自动整理；虚拟化留待需要时 |

## 四、与既有动线的衔接（职责表）

| 界面 | 管 | 不管 |
| --- | --- | --- |
| **画布工作台**（域级） | 结构与关系：放名词、拉动词、看图走查、域级自查 | 字段级编辑（交给检查器/详情） |
| **建模向导** | 问题驱动的第一份记录（选数据→认字段→出指标） | 关系与全局结构 |
| **对象详情** | 记录级精修：字段含义深度编辑、指标、变更单 | 结构与关系（画布上查看/跳转） |
| **检查器** | 画布内的轻量字段核对 | 深度编辑（跳详情） |

- 资产视图三栏退役：记录清单并入画布左侧，业务过程流保留在画布工具栏入口（弹层或独立页签，v1 放画布左侧"旅程/流程"区）；
- 对象详情的"关联关系"分区改为只读视图 + "在画布中查看"跳转（数据同源）；
- 向导产物落地后自动在画布上生成节点（域内可见）。

## 五、上线自查（两级）

- **节点级**（记录）：字段全锚/身份证/事件有时间有累加/绑定正常——即现有发布预检；
- **画布级**（域级汇总）：草稿节点清单 + 各自问题 + "逐个去修"；孤立节点（没有任何关系连线的实体）提示"它和谁有关系？"（不是拦截，是提醒）；
- 全部人话文案，规则与后端发布闸同源。

## 八、明确不做（本阶段）

- 画布上的字段表单（字段含义只在检查器/详情编辑）；
- 边上的 join 条件编辑（v1 只删不改，编辑走侧栏）；
- 多域同画布、跨域关系连线（跨域引用后续随场景配方设计）；
- 层级可视化（类目树/地域树上卷展示，批次 2 随检修图）；
- 撤销/重做（react-flow 自带历史可后续打开，v1 不承诺）。
