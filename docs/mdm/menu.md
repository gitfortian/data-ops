# 主数据管理（MDM）—— 最终菜单设计

> 模块：`yak-ops-business-mdm`
> 版本：v1.0
> 状态：设计基线
> 核心原则：**主数据管理只做"特有"，通用能力复用 + 跳转**

---

## 一、设计原则

> **能复用就复用，只新建主数据特有的；通用能力通过跳转进入。**

- 平台已有：数据集成、数据开发、数据质量、数据消费、数据服务
- 主数据管理**不重复建这些菜单**
- 只新建"主数据特有"的 5 个菜单
- 通用能力通过**跳转**从主数据详情进入

---

## 二、菜单结构

```
主数据管理
├── 主数据总览      ← 入口，主数据视角
├── 主数据建模      ← 特有
├── 主数据识别      ← 特有
├── 主数据清洗      ← 特有（去重、合并）
└── 主数据审批      ← 特有
```

**从 9 个菜单减到 5 个。**

---

## 三、逐菜单说明

### 3.1 主数据总览

**定位**：主数据管理的入口，体现"主数据视角"。

**内容**：

```
主数据总览
├── 主数据实体
│     ├── 客户（10 万条）    [查看详情]
│     ├── 商品（1 万条）      [查看详情]
│     └── 供应商（500 条）    [查看详情]
├── 采集状态（跳数据集成）
│     ├── 客户：最近采集 2026-09-16 ✅
│     └── 商品：最近采集 2026-09-16 ✅
├── 质量概览（跳数据质量）
│     ├── 客户：98% 完整
│     └── 商品：95% 完整
├── 分发状态（跳数据服务）
│     ├── 客户：5 个系统订阅
│     └── 商品：3 个系统订阅
├── 变更概览
│     ├── 本月新增：1000
│     ├── 本月变更：500
│     └── 本月合并：50
└── 血缘概览（跳数据血缘）
      └── 主数据 → 数仓维表 → 报表
```

**要求**：
- 每个卡片可点击，跳转到对应功能
- 统计服务端聚合（遵循 home-overview-contract）
- 独立容错，"查不到"≠0

### 3.2 主数据建模

**定位**：定义主数据实体、属性、关系。

**内容**：

```
主数据建模
├── 实体列表
│     ├── 客户
│     ├── 商品
│     └── 供应商
└── 实体详情
      ├── 属性（名称、手机号、地址...）
      ├── 关系（客户→订单）
      └── 标准引用（类型、单位、码值、安全）
```

**要求**：
- 属性引用数据标准（复用 semantic）
- 支持关系定义
- 属性可标记必填

### 3.3 主数据识别

**定位**：从数据源发现主数据。

**内容**：

```
主数据识别
├── 扫描数据源
├── 识别候选
│     ├── CRM.customer → 可能是"客户"主数据
│     ├── 交易.order → 业务数据（不是）
│     └── 商品.item → 可能是"商品"主数据
└── [确认为主数据]
```

**要求**：
- 复用 datasource 的元数据读取
- 识别规则可配置
- 用户确认

### 3.4 主数据清洗

**定位**：去重、合并（主数据特有）。

**内容**：

```
主数据清洗
├── 去重
│     ├── 发现 100 组重复客户
│     ├── 规则：手机号相同 + 姓名相似
│     └── [合并/保留]
├── 合并
│     ├── C001（CRM）+ cust_001（交易）
│     └── → 合并为 C001
└── 标准化
      ├── 性别：M/F → 1/2
      └── 地址：浙江省杭州市 → 浙江杭州
```

**要求**：
- 去重规则可配置
- 合并策略可配置
- 标准化引用数据标准（复用 semantic）

**注意**：**质量检查**（完整性、格式）跳"数据质量"，主数据清洗只管"去重、合并、标准化"。

### 3.5 主数据审批

**定位**：主数据变更审批。

**内容**：

```
主数据审批
├── 变更申请
│     ├── 申请人：张三
│     ├── 主数据：客户 C001
│     ├── 变更内容：等级 普通 → VIP
│     └── [提交审批]
├── 审批流
│     ├── 一级审批：数据管理员
│     └── 二级审批：数据治理负责人
└── 版本管理
      ├── v1：2024-01-01 创建
      ├── v2：2024-06-01 等级变更
      └── v3：2024-12-01 地址变更
```

**要求**：
- 变更申请
- 审批流（可配置）
- 版本管理

## 四、通用能力的跳转关系

| 通用能力 | 菜单 | 跳转入口 |
|----------|------|----------|
| 采集 | 数据集成 | 主数据总览的"采集状态"、主数据详情页 |
| 质量 | 数据质量 | 主数据总览的"质量概览"、主数据详情页 |
| 血缘 | 数据消费 / 数据血缘 | 主数据总览的"血缘概览"、主数据详情页 |
| 服务 | 数据服务 | 主数据总览的"分发状态"、主数据详情页 |
| 标准 | 语义中心 | 主数据详情页的"标准引用" |
| 分析 | 数据消费 / 仪表盘 | 主数据总览的"变更概览" |

**跳转方式**：
- 总览页的卡片可点击，跳转到通用菜单
- 详情页的 Tab 可点击，跳转到通用菜单

## 五、主数据详情页设计

点"客户"进详情：

```
客户主数据
├── 概览
│     ├── 记录数：10 万
│     ├── 来源：CRM、交易、支付
│     └── 分发目标：5 个系统
├── 记录列表
│     └── 客户记录（master_id、名称、手机号...）
├── 采集配置 → 跳"数据集成"
├── 质量规则 → 跳"数据质量"
├── 分发配置 → 跳"数据服务"
├── 血缘 → 跳"数据血缘"
├── 标准 → 跳"语义中心"
└── 变更记录
```

**要求**：
- 详情页是主数据的"一站式"视图
- 通用能力通过 Tab 跳转
- 主数据特有内容（记录、变更）在详情页内

## 六、和数仓维表的关系

```
业务库 crm_db.customer
        ↓
        ├──► 数据集成 → MDM.customer（主数据）
        │                    ↓ 数据服务
        │              各业务系统
        │
        └──► 数据集成 → 数仓 dim_customer（引用主数据）
                            ↓
                      BI / 分析
```

**主数据和数仓都用"数据集成"，但产出不同**：
- 主数据：`MDM.customer`（统一实体）
- 数仓维表：`dim_customer`（引用主数据）
