# 03 · 端到端验收路线（发版前必跑）

> 状态：v0.1 草案
> 日期：2026-09-21
> 用途：把 02 的核心流程拆成**可执行的一步一步**。每次发版前按本跑一遍，全过才许发——这是“失控了吗”的回答工具，也是防复发机制的核心。
> 可信度标注：【已跑】= 本 agent 在测试环境实跑通过；【待跑】= 步骤据代码/文档整理，发版前首次执行时需校准（若步骤对不上，改本文档，不许改产品去迁就文档）。
> 配套：`scripts/backbone/check-backbone-modules.sh`（模块清单对账）随本一起跑。

---

## 怎么用

1. **发版前**：按顺序跑 R-1~R-5（每段一条，各 10 分钟内）+ F-1~F-3（跨段流程，按改动范围选跑）；
2. **任何一步对不上预期**：先记入《问题清单.md》，再决定是否阻断发版；
3. **路线本身过时了**（按钮变了、流程改了）：改本文档对应步骤——路线是描述现实的，现实不为路线改道；
4. 跑完在文末记录表打勾（日期+结果）。

## 一、每段最小验收路线（R 系列）

### R-1 接入段：数据源能用【待跑】

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 数据源管理 → 新建，选 MySQL，填连接信息 | 保存成功 |
| 2 | 点“测试连接” | 提示连通 |
| 3 | 打开该数据源的目录浏览，逐层点 库→表→列 | 列清单/类型/注释可见 |
| 4 | 预览表数据、看行数统计 | 有数据返回 |
| 5 | 在 SQL 执行里跑一条 select | 结果正常，执行记录进审计 |

守住：S1（所有模块经数据源模块取连接）。

### R-2 同步段：数据搬得进来【待跑】

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 离线同步 → 新建单表同步任务（源=测试数据源，目标=平台库） | 配置保存 |
| 2 | 手动执行一次 | 执行记录出现，状态成功 |
| 3 | 看对账结果 | 源行数=目标行数 |
| 4 | 元数据采集：对该数据源建采集任务并执行 | 表出现在元数据目录 |

守住：② 的产出是“落地表+数据目录”——这是后面建模的原料。

### R-3 标准与建模段：标准和指标闭环【已跑主干】

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 语义中心 → 数据标准 → 新建（命名类），填编码/名称/规则表达式 | 创建成功，列表可见 |
| 2 | 指标中心 → 新建指标：业务域选真域（如交易域）→ 业务过程下拉**有过程可选** → 选 DWD 模型/聚合/字段 → 创建 | 创建成功；编码自动生成；业务域列显示真域 |
| 3 | 指标详情 → 计算规则 | 显示创建时填的度量表达式（非空） |
| 4 | 指标血缘 → 选该指标 | 上游渲染来源模型节点；依赖表带版本快照 |
| 5 | 故意用已存在编码再建一个 | 字段下方报“指标编码已存在：xxx”，弹窗不关、不创建 |

守住：S2（标准只读语义）、S3（指标↔建模通道）、S9（编码一套机制）、S10（业务域一词一义，选真域有过程）。步骤 2/4/5 已于 2026-09-21 实跑通过。

### R-4 编排段：任务跑得起来【待跑】

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 数据开发 → 建 SQL 任务，保存草稿 | 草稿可存 |
| 2 | 发布该任务 | 进发布中心，任务目录可见（不可变版本） |
| 3 | 工作流 → 新建定义，从任务目录引用该任务，编排成单节点 DAG | 引用带版本号 |
| 4 | 手动触发一次运行 | 实例出现，节点状态成功/失败可见 |
| 5 | 实例运维：暂停/恢复/取消各点一次 | 状态随之变化 |

守住：S4（发布=不可变版本）、S5（引用锁版本）。

### R-5 消费段：数据被用起来【待跑】

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 数据集 → 从已发布任务/节点创建数据集 | 创建成功，字段目录可见 |
| 2 | 分析 → 基于该数据集建一个图表 | 有数据返回 |
| 3 | 仪表盘 → 把分析装上看板，发布 | 发布成功，版本+1 |
| 4 | 数据服务 → 从该数据集发布一个 API，看文档和调用记录 | API 可调，记录可见 |

守住：⑤ 的资产链（数据集→分析→仪表盘→API）与版本机制。

## 二、跨段核心流程（F 系列）

### F-1 一张业务表从外部进来到被看板消费（全主轴）【待跑】

```text
R-1 建数据源 → R-2 离线同步搬数+元数据采集 → R-3 逆向导入为 ODS 模型、
字段落标准、建 DWD、发布版本 → R-4 开发任务+工作流定时跑 →
R-5 数据集→分析→仪表盘 → 资产详情页看七格状态机随事实推进
```

通过标准：全程无断点；资产状态机随事实推进（采集=已发现、落标=已定标、质量规则=已稽核）；血缘每段都登记。注意两个当前口径：①「定标强制」只管“已定标”格且处只读观察期，**不拦上架**；②「已上架”需 ASSET_PUBLISH 审批流在审批中心配置后才能走（未配置发起即报 49007，属预期）。

### F-2 一个指标从定义到被看板使用（③→⑤）【已跑主干】

```text
语义定口径 → 建原子指标（R-3 步骤 2）→ 建派生/复合 → 血缘看上下游 →
仪表盘引用该指标 → 指标详情「使用情况」计数变化
```

通过标准：指标全生命周期无断点；依赖快照带版本。已于 2026-09-21 实跑通过（创建/血缘/详情/错误提示）。

### F-3 主数据从采集到提供服务（B 面小循环）【待跑】

```text
主数据建模（实体/属性）→ 采集落地（复用同步）→ 清洗去重 → 变更审批 →
分发 → 服务查询
```

通过标准：黄金记录可查、变更留痕。

## 三、与自动检查的配合

发版前除了跑路线，还要跑（都已就位，一条命令）：

| 检查 | 命令 | 不过意味着 |
|---|---|---|
| 模块清单对账 | `bash scripts/backbone/check-backbone-modules.sh` | 文档与代码模块不一致（对不上=失控信号） |
| 静默 catch 检查 | `node scripts/backbone/check-silent-catch.mjs` | 新增“出错不提示”代码 |
