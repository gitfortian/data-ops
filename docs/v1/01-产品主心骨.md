## 一、我们的产品是干什么的

**一句话：Yak Ops 帮客户把散落在各处的数据，变成能看、能管、能放心的资产。**

一条数据在我们平台里的旅程，就是产品的“主心骨”：

```text
① 接进来          ② 搬过来            ③ 定规矩、建模型           ④ 定期跑起来         ⑤ 用起来
┌──────────┐   ┌──────────────┐   ┌─────────────────────┐   ┌──────────────┐   ┌──────────────────┐
│ 数据源管理 │ → │ 离线同步       │ → │ 数据标准 → 指标 → 数仓建模 │ → │ 工作流编排      │ → │ 数据集 → 分析     │
│ 文件资源   │   │ 实时同步       │   │ (数仓分层可配置)      │   │ 任务目录        │   │ → 仪表盘/大屏     │
│           │   │ 元数据采集     │   │ 数据开发任务          │   │              │   │ → API/智能问数/首页│
└──────────┘   └──────────────┘   └─────────────────────┘   └──────────────┘   └──────────────────┘

同时有三件事，全程罩着上面每一步（不是某一步，是每一步都有）：

  A. 质量与安全  —— 每一步的产出都必须留质检结论；敏感数据必须分级、脱敏、管权限
  B. 治理        —— 资产台账、血缘、审批、审计、告警、数据保留策略、主数据：
                    全程看得见、管得住、查得到
  C. 项目空间    —— 不同客户的数据互相隔离（这条已定，不动）
```

每一段用一句说清：

| 段 | 干什么的 | 交给下一段什么 |
|---|---|---|
| ① 接进来 | 平台通往外部的门：数据库连接、文件上传 | 能用的连接、能引用的文件 |
| ② 搬过来 | 把数据和“数据的档案”运进来（批量搬、实时搬、自动收集数据字典） | 落地数据表、数据目录 |
| ③ 定规矩建模型 | 定义数据长什么样、怎么算：先立标准，再定指标，再建表，再写加工任务 | 标准、指标、表结构、可执行的任务 |
| ④ 定期跑起来 | 把定义变成每天自动运行的事实 | 运行记录、成功/失败状态 |
| ⑤ 用起来 | 数据被业务真正用掉的地方 | （终点） |

**本文与《平台业务主线：资产状态机》（docs/PLATFORM_CORE_FLOW.md）的分工**——两份文档不是竞争关系，是一体两面：

- **本文讲“数据怎么流”**：从接进来到用起来的工序，以及模块怎么分工；
- **状态机讲“一张表的可信度怎么涨”**：已发现→已描述→已定标→已稽核→已上架→运营中→**归档策略**七格（逐字用 PLATFORM_CORE_FLOW 与实现 `AssetStatusFlowService` 的定名），资产域独占账本；
- **两者共用同一套盖章方**（就是本文的模块）：元数据（②）盖章“已发现”、标准+建模（③）盖章“已定标”、质量+安全（A）盖章“已稽核”、审批（B）盖章“已上架”、生命周期（B）盖章“出口”。

状态机是 B 治理面的上位实现，M2-1~M2-5 已陆续落地；本文不重复其内容，只在治理处引用。

## 三、模块之间的十一条交接规矩

问题都发生在“交接”上。以下十一条就是国界：谁生产、谁消费、怎么交接。

| # | 规矩（说人话） |
|---|---|
| S1 | **要用数据源，必须走数据源模块**。不许别的模块自己私存连接信息。同名数据源在同一客户空间内不许重名。 |
| S2 | **要用标准（命名/类型/口径/单位…），只读语义中心的**。谁都不许抄一份到自己库里——抄了就是两份真相，早晚对不上。 |
| S3 | **指标和建模是“你中有我”的双向关系，但必须走规定通道**：建汇总表时听指标的（按指标反推表结构）；指标的数据来源来自模型。这条通道已经修好了，保持。（已定，不重问） |
| S4 | **开发任务发布后变成不可改的版本**。任务目录只是货架，负责展示，不负责决策。 |
| S5 | **工作流/质量/数据集引用任务必须锁版本**。任务升级要显式操作，不许悄悄换。 |
| S6/S7 | **模型和指标的关系必须登记，而且都要在血缘图上看得到**。 |
| S8 | **资产台账只记目录，不存内容**。数据内容实时去各模块取——这样台账永远不会和各模块对不上。 |
| S9 | **所有“自动生成编码”用同一套机制，各模块配自己的规则**（中文怎么处理、多长、项目内不许重复）。共用策略已落（CodeGenerator：字母数字直转、中文名附加稳定哈希后缀），域策略注册表是完整形态，当前一域策略够用。 |
| S10 | **一个词，全平台一个意思**。比如“业务域”在语义中心指“交易域”，在指标里现在居然指“订单”（那其实是业务过程）——这类一房两卖的词，发现一个宰一个。 |
| **S11** | **出错必须让用户看见，而且要说后端说的原话**。后端返回的错误码和话，必须一路透到界面；禁止前端吞掉不显示，也禁止拿一句猜测性文案（“保存失败，可能是编码重复”）替换后端的明确错误。每个提交动作失败必须有可见反馈。**自动检查：第 0 步 CI 约定测试——“任何 catch 不得吞 code+message”，违反即红。** |

## 五、砍还是并？——三条候选的结论

| 候选 | 结论 | 大白话理由 |
|---|---|---|
| 大屏 vs 仪表盘，要不要合成一个 | **先都留着，但附条件** | 一个是分析下钻、一个是大屏轮播，用法不同。但必须下轮核实：它俩的“草稿→版本→发布”是不是各写了一套代码？如果各写一套，就是重复建设，当场下沉成共用零件。 |
| 智能问数 agent 要不要并进分析 | **不合** | 它已经是 176 个文件的大模块了，动刀成本高；而且“分析”是拖拖拽拽配资产，“问数”是聊天，两种用法硬塞一个模块，以后更乱。但要补手续：只许读数据集，不许自己另开一条取数通道。 |
| 主数据 mdm 标注了两个位置 | **不是设计问题，是表没写清** | 它真正拥有的就一样东西：主数据档案。采集是借别人的道干活，不拥有同步能力。修正说法即可，不用拆模块。 |

**减法结论**：当前 28 个模块，没有一个够砍的标准。但“大屏/仪表盘”附了真实的合并触发条件——从此砍不砍看条件，不靠拍脑袋。

## 六、菜单和主轴什么关系

现网菜单是 **7 大业务域**，不是主轴的 1:1 投影——这是既成事实，而且没有错：**用户按业务心智找功能（“我要接数据”“我要治理”），主轴按数据生命周期描述架构**，两者本来就不是一个维度。规则：

> **每个一级菜单分组，必须能声明它对应主轴的哪些段/面；声明不了的分组，禁入导航。**

现网 7 域对照如下（新分组入导航照此表声明）：

| 现网一级分组 | 对应主轴 | 说明 |
|---|---|---|
| 数据接入 | ① + ② | 数据源/同步/资源 |
| 数据开发与编排 | ③ + ④ | 跨两段：开发任务（③）和工作流（④）同属“把事做出来” |
| 标准与建模 | ③ | 语义/指标/模型 |
| 数据治理 | A + B | 混装两面：质量/安全（A）+ 主数据/生命周期（B） |
| 数据资产 | B | 资产/血缘（元数据管理入口挂此组是 M2-2「目录三聚一」已拍板设计，实体视图已标注数据出处） |
| 消费与服务 | ⑤ | 数据集/仪表盘/大屏/API/问数/首页（指标中心入口 2026-09-21 已迁至「标准与建模」，随前端构建生效） |
| 审批中心 | B | 治理的审批一环 |

**首页 home 的定位**：home 什么都不拥有，是纯汇总——定位为**主轴的仪表盘**，不是新段，禁止以“工作台化”为名成长为第二个消费层或新真相源。
