## 一、① 接入：平台通往外部的门

### 数据源管理（/data-source）【实测+梳理】

用户能干什么：

| 功能 | 说明 |
|---|---|
| 数据源增删改查 | 按项目空间隔离；连接信息加密存储 |
| 连接测试 | 保存前/随时验证连通性 |
| 数据目录浏览 | 逐层看 库→表→列，支持预览数据和行数统计 |
| SQL 执行 | 在平台上直接对数据源执行查询，有审计记录 |
| 多类型数据源 | 内置 20+ 种：MySQL、Oracle、PG、达梦、Doris、ClickHouse、MongoDB、ES 等；新类型按插件扩展，不改主程序 |

产出：全平台公用的“可用连接”——后面所有模块都用它，不许自己私存连接（规矩 S1）。

### 文件资源（/resource-management）【梳理】

用户能干什么：目录树管理、上传文件、在线文本创建、版本管理（改文件产生新版本）、下载；文件可存本地/MinIO/HDFS。

产出：可被任务引用的文件（比如 Python 脚本、JAR 包）。

---

## 二、② 同步/采集：把数据和数据的档案运进来

### 离线同步（/sync/batch-link-up）【梳理】

用户能干什么：配置批量搬运任务（单表、多表、脚本三种配置方式）、设调度周期、看执行记录、增量同步（按游标）、搬运结果对账、失败重试、历史回填。

### 实时同步（/sync/realtime）【梳理】

用户能干什么：配置 CDC 实时任务（MySQL 等 → 目标库）、管理 Flink 计算环境、提交/启动/停止任务、看 Checkpoint 和运行指标、立即对账。

### 元数据采集（/data-metadata）【在建】

用户能干什么：配置采集任务（采集哪些数据源的库表结构）、先 dry-run 预演再正式采集、自动比对企业结构变化（指纹）、发现表消失（gone 检测）、全平台统一搜索（表/列/模型/标准跨类型搜）、维护元模型（类型和字段定义注册表）。

产出：统一数据目录——资产台账和建模的“事实来源”之一。

## 三、③ 标准与建模：定义数据长什么样、怎么算

本段是产品的“大脑”，顺序是：**先立标准（语义中心）→ 再定指标（指标中心）→ 再建表（模型工作台）→ 再写加工任务（数据开发）**。指标和建模是双向的：建汇总表时听指标的，指标的数据来源来自模型。

### 3.1 语义中心（/semantic）【实测】

用户能干什么：

| 页面 | 功能 |
|---|---|
| 数据标准 | 六类标准管理：命名/类型/码值/单位/口径/安全；码值标准带码值列表（码值+标签）；版本历史；预置标准一键初始化 |
| 业务域 | 业务域树（如 交易域 > 订单/支付/退款）——全平台“业务域”一词的唯一定义处 |
| 业务过程 | 业务过程挂在业务域下（如 下单、订单支付）——过程和粒度的事实来源 |
| 标准字段 | 全局字段库：字段必须引用标准（类型/单位/口径/码值/安全），不许自由填写 |
| 数仓分层 | 分层定义（默认 ODS/DWD/DWS/ADS 四层，可配置）；每层带“定标强制”开关（该层字段须 100% 绑定标准字段才算**已定标**；当前为只读观察期，不拦上架） |

### 3.2 指标中心（/metric）【实测】

用户能干什么：

| 页面 | 功能 |
|---|---|
| 指标管理 | 三类指标：原子（选 DWD 模型+聚合函数+字段）、派生（在原子指标上加工）、复合（公式编辑器组合多个指标）；统计周期（日/周/月）；版本管理；停用/启用；标签；负责人 |
| 指标详情 | 计算规则、口径、依赖清单（模型/口径/单位/子指标，带登记时版本快照）、版本历史、使用情况（被报表/仪表盘/API/大屏引用数） |
| 指标血缘 | 血缘图谱：上游（来源模型/上游指标）→ 当前指标 → 下游（派生/复合/消费方）；深度可调 |
| 影响分析 | 上游依赖变更检测：对比登记版本与当前版本，评估指标是否要重新校准 |
| 指标服务 | 标签管理；指标目录与统计 |

### 3.3 模型工作台（/modeling）【实测+梳理，模块未开发完】

用户能干什么：

| 功能 | 说明 |
|---|---|
| 模型列表 | 按业务域目录树/分层/状态/目标库筛选；列表+主线视图 |
| 新建模型向导 | 填名称/编码/分层/业务域/业务过程 → 设计表结构（字段/类型/主键/分区/注释） |
| 字段导入 | 三个来源：从源表导入（逆向）、从已有模型导入、从业务过程的标准字段导入 |
| 标准发现 | 按字段名/类型自动推荐绑定标准字段（如 order_id → 标识标准） |
| 建库脚本 | 生成 DDL（只生成不执行），可复制/下载 |
| 分层映射 | 模型列与标准字段的分层落地映射 |
| 血缘 | 模型上下游血缘（登记到统一血缘模块） |
| 版本与审批 | 模型发布为新版本、提交发布审批、版本历史、回收站（删除可恢复） |
| 逆向导入 | 浏览数据源表 → 批量导入为模型 |
| 派生建模 | 按业务过程/指标反推生成模型草稿 |
| 影响分析 | 标准字段/来源列变更的影响范围 |

### 3.4 数据开发（/data-development）【梳理】

用户能干什么：目录+节点树管理开发任务（SQL/Shell/Python/Java）、草稿编辑与保存、SQL 血缘预览、发布节点版本、运行记录（分页/取消/重试）、发布中心（下线/重新上线/切换线上版本）、Dataset 节点（执行 SQL 产出数据集）、Data Service 节点（把 SQL 发布成 API）。

产出：**不可变的任务版本**——发布后进任务目录货架，供工作流/质量/数据集锁版本引用（规矩 S4/S5）。

## 四、④ 编排执行：把定义变成定期运行的事实

### 任务目录（/api/v1/task-catalog，无独立页面）【梳理】

已发布任务资产的货架：只存投影（不可变 Revision + 项目归属），不决策。工作流编排时从这里挑任务。

### 工作流（/workflow）【梳理】

用户能干什么：可视化编排任务成 DAG、设调度（cron/周期）、并发与失败策略、实例运维（暂停/恢复/取消/重跑/单节点重跑/人工放行）、补数（按业务日期回跑）、触发记录（Trigger Ledger）、SSE 实时状态订阅。

产出：运行事实——每次执行的成功/失败/耗时，进运行记录和首页调度中心。

## 五、⑤ 消费与服务：让数据被用起来

### 数据集（/dataset）【梳理】

把任务产出包装成数据集：不可变版本、字段目录、查询性能诊断；数据集是分析/仪表盘/API/问数的共同原料。

### 分析与仪表盘（/data-analysis、/dashboard）【梳理】

分析：基于数据集拖拽配置图表与维度。仪表盘：把分析组装成看板，草稿→版本→发布，支持全局筛选器和图表联动。

### 数字化大屏（/digital-screen）【梳理】

大屏版式组装，绑定数据源/数据集/分析，适合监控大屏场景。

### 数据服务（/data-service）【梳理】

把数据发布成 API：从已发布来源（数据集/开发节点）一键发布、消费者与 API Key 管理、IP 白名单、限流、调用记录、自动文档。

### 智能问数（/ai-agent）【梳理，未深测】

对话式问数：提交问题→SSE 流式回答、会话历史、Skill 管理、分析报告。

### 首页（/home）【梳理】

一页看全平台：数据中心、工作台（待办/告警/质量健康）、资产总览、调度中心、快捷导航、资源中心、通知中心、快速创建入口。只读聚合——禁止成为新真相源（规矩：主页是主轴的仪表盘）。（注：“驾驶舱”是资产概览页的说法，不在首页。）

## 六、横切 A：质量与安全

### 数据质量（/data-quality）【梳理】

质量总览（通过率/趋势/维度报告）、数据表监控（按表挂规则）、规则模板库（内置+自定义 SQL 模板）、执行记录（规则级明细）、告警通知。

### 数据安全（/data-security）【梳理】

分级分类（分类树/等级/分级标签）、发现规则（扫描字段自动生成候选标签）、脱敏（内置算法+策略+试算）、权限管理（访问策略+审批）、访问裁决（放行/脱敏判断）、访问审计、合规管理（规则+体检）。

---

## 七、横切 B：治理

### 数据资产（/data-asset）【梳理，M2 系列已落地】

资产目录（一棵树看全平台数据资产）、台账一本账（多模块 Provider 自动对账）、标签与分配规则、健康度评分、360° 详情（**七格状态机：已发现→已描述→已定标→已稽核→已上架→运营中→归档策略**，各模块上报事实、资产域独占推进）、上架审批。

### 数据血缘（/data-analysis/lineage）【梳理】

全平台血缘统一视图：资产与关系、多跳上下游查询；血缘键全平台统一生成（规矩 S6/S7 的公共基础，M2-3 已落地 assetKey/metricId 参数化）。

### 审批中心（/approval）【梳理】

流程配置（模型发布/标准发布/权限申请/主数据变更/资产上架五类已定义）、待办中心、通过/拒绝/撤销、按业务对象查审批记录。（注：流程编码是代码常量，真实流程需在审批中心 UI 配置后才能发起；未配置即报 49007，属预期。）

### 其余治理件【梳理】

审计（谁何时做了什么，全模块记录）、告警（渠道配置：钉钉等，失败通知出口）、生命周期（数据保留策略：TTL 策略/模型绑定/SQL 生成与下发/存储统计）、主数据（客户商品等核心档案：建模→识别→采集→清洗去重→审批→分发→订阅服务）。

## 八、三条核心流程走查（用户视角）

### 流程一：一张业务表从外部进来到被看板消费（走完整条主轴）

```text
1. 接入    建数据源（连接源库），测试连通
2. 搬运    建离线同步任务，把源表搬进平台库（定时跑、可对账）
          （元数据采集自动把表收进目录）
3. 建模    模型工作台「逆向导入」把落地表变成 ODS 模型
          → 字段「标准发现」绑定标准字段（落标）
          → 建 DWD 模型（按业务过程派生或手工设计）
          → 发布模型版本（走发布审批）
4. 加工    数据开发写 SQL 任务（引用模型表）→ 发布成任务版本
5. 编排    工作流把任务编成 DAG、设每天定时 → 产生运行事实
6. 消费    开发 Dataset 节点执行 SQL 产出数据集 → 分析 → 仪表盘
7. 治理    全程：资产状态机七格随事实推进（采集=已发现、落标=已定标、
          质量规则=已稽核、上架审批=已上架）；血缘逐段登记
```

**今天的状态**：① ② 成熟；⑤ 资产链路（数据集→分析→仪表盘）完整、问数尚浅；③ 中语义/指标成熟、模型工作台在建（负责人确认未开发完）；④ 成熟；⑦ 资产状态机 M2-1~M2-4 已落地、M2-5 定标闸门只读观察期中（不拦上架）。

### 流程二：一个指标从定义到被看板使用（③→⑤）

```text
1. 语义中心定口径标准（如「支付率」的口径与单位）
2. 指标中心建原子指标：选 DWD 模型（下单表）→ 选聚合（COUNT）→ 选字段（order_id）
   → 引用口径标准与单位 → 保存（自动登记模型/口径/单位依赖快照，版本 v1）
3. 建派生/复合指标（在原子指标上加工，或用公式编辑器组合）
4. 血缘页看上下游；影响分析盯着上游变更
5. 仪表盘/API 引用指标 → 指标详情「使用情况」计数 +1
```

**今天的状态**：全链路已实测通过（含中文名编码自动生成、重复编码报错、血缘渲染模型节点、计算规则展示）。

### 流程三：主数据从采集到提供服务（B 面内部小循环）

```text
1. 主数据建模：定实体（如客户）/属性/识别规则
2. 采集：复用离线同步把业务库数据搬进主数据表（不另造同步）
3. 清洗：去重发现 → 合并预览 → 合并（黄金记录）
4. 变更走审批（主数据变更流）
5. 分发：把黄金记录分发回各业务系统；对外提供查询/检索 API
```

**今天的状态**：链路已通（CRM 客户 3060 行实测进平台），审批前端接入与记录版本化在修（见修复清单）。

## 十、这份文档怎么用

1. **新人上手**：按第八节流程一走一遍，就是对产品的完整第一印象；
2. **排优先级**：看第九节星级，弱项就是下一批投入方向（当前最弱：模型工作台、元数据、问数）；
3. **写验收路线（03）**：第八节每条流程拆成可执行步骤，就是发版前必跑的端到端验收路线——本文是它的素材库。
