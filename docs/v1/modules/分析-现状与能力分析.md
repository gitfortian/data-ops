## 1. 模块概览

| 项 | 内容 |
|---|---|
| 模块名称 | 分析（Analysis，图二 ANA 节点；前端历史名"图表分析/Chart Analysis"） |
| 在主脉与交互图中的位置 | ⑤消费与服务段，DST→ANA→DBH 中间环节：吃数据集契约，吐图表定义给仪表盘 |

| 一句话定位 | 后端只是"可复用图表定义资产"的登记簿（CRUD+校验+血缘+台账，**无查询执行**）；真正的自助分析能力（编码 shelf、11 种图型、计算字段、下钻联动）以**共享前端组件库 `components/analysis` + 仪表盘编辑器内嵌工作台**的形态存在，且该工作台**没有独立页面入口** |
| 当前实现状态 | **后端已实现但主用途空转**：Analysis CRUD API 完整有测试，但前端**只读不写**（`createAnalysis/updateAnalysis/deleteAnalysis` 零页面调用）；**前端能力已实现、寄生在仪表盘**：图表构建器/编码/渲染/缓存全量在 `components/analysis`，宿主是 dashboard editor（含高级图型，后端协议未扩展）；**独立分析入口已废弃**：`/data-analysis/chart-analysis` 只剩 redirect 壳 |
| 主要入口 | 无独立菜单入口。事实入口：仪表盘编辑器（`/dashboard/:id/edit` 等）内嵌图表工作台；legacy 路由 `navigation.ts:81`（hidden，重定向 `/dashboard`）；API `/api/v1/analyses`（`AnalysisController.java:28`）；Flyway `db/migration/yak-analysis/V1__baseline_analysis.sql`（1 张表）；模块内无定时任务；随 boot 构建（`yak-ops-boot/pom.xml:98`） |

特别说明（结构性事实）：图二把 ANA 画成"数据集→仪表盘"的必经边，代码现实是**两个半区错位**——后端半区（Analysis 资产）在 UI 上已无写入路径、仅剩消费存量；前端半区（分析工作台）根本不在本模块，而在 dashboard 页面目录与共享组件里。因此本盘点把"展现形式"列如实标注宿主位置。

## 3. 子功能逐个分析

### 分组 A：Analysis 资产后端（功能 1–7、17）

**A1 可复用图表定义 CRUD（功能 1–5）**
- 业务含义：把"一个数据集上的一组编码+图型+样式"沉淀成命名资产，供多个仪表盘复用、进资产台账、被血缘追踪——设计意图是"图表即数据产品"。
- 使用角色：设计上是分析师；现实中只有读方（仪表盘编辑器）与 API 调试者。
- 输入：`SaveAnalysisRequest`（name/datasetId/chartType/querySpec/visualConfig）；输出：`AnalysisViews.Analysis`。
- 依赖：dataset 绑定校验（唯一跨域写校验）、lineage/asset 外围。
- 必要性：**必要（作为概念）/ 过渡（作为现状）**。若共享图表是真实需求，这个资产本体不可省；但当前 UI 无创建路径，写入链已断，只剩存量读取与守卫——按代码现实只能判"过渡"。
- 理由：00 总表给 ANA 的职责"自助分析"实际全部在仪表盘编辑器里完成且默认产出 inline widget；共享 Analysis 是**双轨制图表资产**中失去入口的那一轨。
- 当前问题：①`fetchAnalyses` 仍每次打开仪表盘编辑器全量拉取，为空转协议付成本；②advanced chart type 协议缺口造成 inline 与 shared 两种 widget 能力不对等（`SHARED_ANALYSIS_CHART_TYPES` 白名单 5 种）；③后端无查询执行端点意味着 Analysis 资产无法独立预览/验证（离开 dataset API 它什么都不是——这本身合理，但和"资产"定位配套的分析体验缺失）。
- 建议：**二选一**（与决策方共同拍板，不擅自定）：(a) 恢复独立分析工作台页面（把 `components/analysis` 装回 `/chart-analysis` 路由）并接上"保存为共享分析/从共享分析创建图表"闭环；(b) 承认图表只在仪表盘内存在，退役 shared 轨（widget 全部 inline），Analysis 后端降级为"图表资产注册 API"或整体并入 dashboard。**当前状态（机制全有、入口全断）是最差的**。

**A2 绑定校验与删除守卫（功能 6–7）**
- 业务含义：Analysis 只准绑 ONLINE 且有当前版本的数据集、字段必须属于当前 schema；被仪表盘引用的不许删。
- 角色：全角色透明受益（S5/S8 规矩在⑤段的执行末端）。
- 必要性：**必要**，实现质量高（gateway+guard 接口反转，dashboard 侧实现，analysis 不反向依赖 dashboard）。
- 当前问题：字段契约演进无感知——数据集发布新版本删了字段，存量 Analysis 不会被校验或告警（校验只发生在 save 时）；下游破坏由 dataset 查询期才暴露。
- 建议：**保留 + 补齐**（版本切换时的引用扫描，可与 dataset 侧下线守卫合并设计）。

**A3 CHART 资产与血缘投影（功能 8–9）**
- 业务含义：可复用分析进台账（内嵌小图不进，边界口径清晰）；字段用益边进血缘。
- 必要性：**较必要**。台账"只记目录不存内容"规矩的模范执行者；但资产数量取决于 A1 写入链复活与否。
- 当前问题：血缘边是 dataset→analysis 还是 analysis 字段级？`AnalysisFieldUsageExtractor` 抽的是查询规格中的 fieldId 用益（字段级证据），正确；无问题。
- 建议：**保留**。

### 分组 B：分析工作台前端（功能 10、12–15）

**B1 可视化构建器 + 实时预览（功能 10、12）**
- 业务含义：拖字段进编码通道即出图的自助 BI 核心体验，spec 编译成 dataset 语义查询、结果喂 ECharts；带同参去重与 1.5s 微缓存。
- 使用角色：分析师/运营（仪表盘编辑者）。
- 输入：数据集字段契约（`PublishedDataset`）；输出：inline widget spec（或 A1 协议的 5 种 shared spec）。
- 依赖：`services/dataset` 查询 API；无本模块后端。
- 必要性：**必要**——这是"分析"能力的本体，全平台价值最高的前端资产之一（11 图型、编码语法、主题）。
- 当前问题：**产权错位**——它物理上住在 `components/analysis` 但路由/页面/保存全部归 dashboard；盘点 ANA 模块时只能"隔岸观火"。这不是代码坏味道（组件抽取干净），是**模块账实不符**：04 图 ANA 节点若指后端模块，则它只承载了分析能力的登记簿；若指能力，则能力主体在 dashboard 目录里。
- 建议：**保留**；在 05 清单层面做一次"分析能力记账归属"澄清（组件名 `components/analysis` 已埋了共享的伏笔）。

**B2 计算字段（功能 13）**
- 业务含义：图表级派生指标（公式 AST、可下推者编译进 dataset metrics、不可下推者前端逐行算）。
- 必要性：**必要**（自助分析的标配；且下推优先的设计避免了假计算列陷阱）。
- 当前问题：①只活在 widget JSON 里，不进数据集字段契约、不进血缘、跨图表不可复用（与 shared Analysis 同病）；②前端逐行求值的口径（如比率后算）与下推口径（先聚后算）混用风险无提示；③后端 `DatasetSqlSafety`/compiler 不认 calc 表达式。
- 建议：**保留 + 补齐**（沉淀到 dataset 字段契约或指标中心是唯一正解；短期至少在血缘证据中登记 calc 引用）。
- 说明：计算字段是否被问数/大屏复用——grep `calc:` 仅见于 dashboard/dataset 编辑器，判"图表私有机能"。

**B3 下钻/联动/全局过滤（功能 14）**
- 业务含义：分析交互三件套，运行时解析 JSON 行为配置。
- 必要性：**必要**（消费体验主菜），但全部是仪表盘宿主内的功能，本模块仅贡献 spec 协议字段。
- 当前问题：后端对 `dashboardBehavior/drill/hierarchy` 等零解析（grep 无），语义完全前端 all——校验不到、血缘不到、问数不可复用。属可接受的当前取舍。
- 建议：**保留**，与仪表盘盘点交叉引用。

**B4 历史入口死链（功能 16）**
- 业务含义：无——纯遗留。
- 必要性判定：**冗余**。数据集详情页与数据目录的"创建分析"主按钮（primary CTA）把用户导向 redirect 壳，最终落回仪表盘列表且丢失 datasetId 上下文。
- 当前问题：这是**用户找分析能力的最直觉路径**，现在是断的；且按钮 tooltip（"使用当前 Dataset 创建分析"）暗示存在独立工作台。
- 建议：**立即处理（P0 级体验账）**：要么把 CTA 改为"在仪表盘中基于该数据集建图"并真实带参直达编辑器，要么恢复 B1 工作台的独立路由。删壳不改语义会造成主脉图 ANA 节点彻底无宿主。

## 4. 真实功能定位

**问题：分析是 BI 工作台，还是仪表盘的前置草稿器？**

结论：**两者都不是当前现实——"BI 工作台"活在仪表盘肚子里，"草稿→资产"的沉淀链路已断，后端模块本身退化为一座无人出入的登记所。**

1. 作为 BI 工作台的分析能力（编码构建、预览、计算字段、下钻联动）**全部已实现且页面已展示**，但没有自己的页面：宿主是 dashboard editor，产出直接是仪表盘 widget。图二 `DST → ANA → DBH` 的"先做分析、再上板"两段式流程，在 UI 上已被"开板即分析、分析即上板"的一体式取代（inline widget 为主轨）。
2. 作为共享资产层的分析（yak_analysis 表 + CRUD API + CHART 台账 + 字段血缘 + 删除守卫）机制完整、测试齐备，但**写入口在 UI 上已拆除**（无创建/编辑/删除按钮），读路径仅剩渲染存量 linked widget 与"拆分"。`/data-analysis/chart-analysis` 只剩 redirect 壳，且数据集页面仍把主 CTA 指向这个壳。
3. 所以 ANA→DBH 这条边的真相不是"分析结果推给仪表盘"，而是"分析能力被仪表盘吞并后，留下的资产外壳偶尔被回头看一眼"。判断该外壳去留（恢复 vs 退役），是这次盘点给分析模块的唯一待决大事；从代码趋势看（inline 主轨、shared 图型协议未扩展、拆分方向单向 linked→inline），**退役并改图**与现状更一致，但若组织要做"图表复用/图表治理"，恢复入口是更省的路——机制一行都不用新写。
4. 后端不支持任意数据源直查、不含查询引擎（下推执行全在 dataset）、无 SQL 编辑器能力（自由 SQL 属 DEV 数据集节点）——这些不是缺陷，是分层正确；但意味着"分析"作为独立模块的可辩护性只剩"共享图表资产 + 治理投影"一件事。

## 7. 现状总结

1. **实现完成度：后端 100%（该有的都有）× 前端入口 0%（能写的都没按钮）；工作台能力 100% 但记账在仪表盘**。一个模块三截命运，是本次盘点里"图码错位"最严重的样本。
2. **与图二一致性：`DST→ANA` 真、`ANA→DBH` 机制真而主轨假（inline 直通取代两段式）**；图外补了 LIN/台账两条边但没画；还漏了一条 UI 现实边（DST 页 CTA→redirect→dashboard，且是断的）。
3. **前后端对称性：罕见地"反挂"**——没有"前端展示后端缺失"（除历史壳），倒是两处"后端完整、前端无入口"（Analysis 写链、linked widget 创建）+ 一处"前端能力驻留在别的模块目录"（工作台组件）。
4. **数据模型：小而正确**。一张 `yak_analysis`（dataset_id 逻辑引用 + 双 JSON 规格）+ dashboard 侧 `analysis_id` 列与索引；跨域全部逻辑引用无物理 FK，与仓规一致。
5. **代码健康度：高**。gateway/adapter 接口反转（dataset/dashboard/lineage 三方都干净）、守卫链（DeletionGuard SPI）、normalizer/policy/reader/manager 分层与架构测试齐备——机制质量对得起"被空转"的处境，也意味着无论恢复还是退役都无痛。
6. **职责过载信号：无**；相反，**职责空心化**是唯一信号——引擎在 dataset、工作台在 dashboard、资产在 asset，ANA 剩什么取决于定位决策。
7. **治理接入：全**（台账 CHART、字段血缘、删除守卫、绑定校验），是⑤段里治理姿态最端正的消费模块，尽管被治理的对象暂时进不来。
8. **对相邻模块的真实依赖（代码事实）**：dataset（binding 校验）、lineage（gateway）、asset（provider 实现）、common/core（项目空间/持久化）、dashboard 反向依赖本模块（AnalysisReferenceService/DeletionGuard 消费面）；pom 无 datasource/job/task-catalog。
9. **综合判断：先拍板，再动手**。P0 两项本质是同一个决策的正反面（入口死链 + shared 轨断头）；机制层**保留不动**，产品层必须在"恢复独立分析工作台（把 components/analysis 装回独立路由 + shared 资产 CRUD 页面 + 图型协议对齐）"与"正式并入仪表盘（退役 shared 轨、改图删壳、清表转档）"之间选一条——现状两头吊着，图、码、账三者对不上。
