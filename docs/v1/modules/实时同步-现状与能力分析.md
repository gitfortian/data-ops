> 依据：`docs/v1/04-主脉与模块交互图.md`（图二 RTS 节点）+ `docs/v1/05-模块交互与乱象清单.md` + 代码现实。
> 日期：2026-09-21。只描述盘点当日的实现现状；凡不确定处标注"当前无法确认"。
> 后端包：`data-ops-business/data-ops-business-sync/data-ops-business-sync-realtime`
> 前端：`data-ops-ui/src/pages/integration/realtime-sync`、`data-ops-ui/src/services/realtime-sync`、运行环境管理在 `data-ops-ui/src/pages/settings`

## 核心问题结论（先说答案）

**实时同步（CDC）不是页面占位、也不是接口骨架。** 它是一个 **约 10,904 行主代码 + 一整套前端页面** 的真实实现：具备计算环境注册与连通诊断、CDC Pipeline 定义（向导 + YAML 双编辑器）、定义版本化与发布、经 **Flink CDC CLI（本地或 SSH 提交）** 拉起长驻作业、经 **Flink REST** 做状态/停止/指标/Checkpoint 观测、状态机 + 对账协调 + 运行时租约 + 日志脱敏 + SSE 实时推送。它与离线同步**共用后端 Maven 聚合包但代码层零交集**。

它的"未完成/受限"不在"是不是骨架"，而在 **能力覆盖面窄**（源仅 MySQL、汇仅 JDBC mysql/postgres、语义仅 at-least-once）与 **重外部依赖**（须自备 Flink + Flink CDC 运行时）。详见第 6、7 节。

## 与离线同步共用后端包的边界说明

`data-ops-business-sync` 为 Maven 聚合父包，其下 `data-ops-business-sync-offline`（见《离线同步-现状与能力分析.md》）与 `data-ops-business-sync-realtime`（本文档）两子模块包路径独立（`...sync.realtime.*`）。全量 import 扫描确认两子模块 **互不引用**。交集仅为二者都依赖 `data-ops-business-datasource`。差异显著：离线经 `TaskProvider/TaskExecutor` 接入任务内核、经 `OfflineAuditBridge` 接审计、被 MDM 直连复用；**实时模块对上述四类均无依赖**（后端 import 仅 datasource + 自身，实测）。故两者边界清晰、可各自独立评估与演进。

## 3. 子功能逐个分析

### 3.1 计算环境管理（含诊断）
- 业务含义：登记 Flink 集群 REST 地址、Flink/Flink-CDC Home、提交方式（LOCAL/SSH）、凭据。角色：平台/数据工程师。输入：REST URL、版本、submitter、SSH 配置。输出：可用运行环境。依赖：无外部业务模块。交互：被实时任务绑定。必要性：**必要**。当前问题：入口藏在「设置」，与任务创建分离，用户易找不到。建议：**保留**，考虑在实时同步页给出入口引导。

### 3.2 CDC Pipeline 定义（向导 + YAML 双编辑）
- 业务含义：声明 source/sink 数据源、表路由、启动模式、汇端调优。输入：`CdcPipelineSpec`。输出：草稿 + `spec_json`/编译 YAML。必要性：**必要**。当前问题：向导对复杂 spec 会降级 YAML（`wizardCompatibility`），非全覆盖。建议：**保留 + 补齐**（扩大向导覆盖）。

### 3.3 版本化与发布（draft→publish）
- 业务含义：草稿与已发布不可变版本分离，运行时按发布版本拉起（`RealtimeDefinitionPublisher`、`DefinitionVersion`）。必要性：**必要**（S4/S5 锁版本精神）。建议：**保留**。

### 3.4 引擎提交（Flink CDC CLI / SSH + Flink REST）
- 业务含义：把 pipeline YAML 交给 Flink CDC 提交，REST 拉状态。输入：YAML + source/sink 密码（占位符 `${SECRET:*}` 注入，落盘即脱敏）。输出：`gateway_job_id`。依赖：外部 Flink 集群。必要性：**必要**（实时捕获真正发生处）。当前问题：① 强依赖外部 Flink + Flink CDC 运行时与本机/远端 CLI 可执行；② 仅 `at-least-once`。建议：**保留 + 补齐**（部署契约、健康前置）。

### 3.5 执行控制（start/stop/restart-execution/apply-published-version）
- 业务含义：长驻作业生命周期与滚动换版。必要性：**必要**。当前问题：`/restart` 为 `@Deprecated` 兼容入口仍在。建议：**保留**，兼容入口后续清理。

### 3.6 可观测（observability/events/logs/SSE）
- 业务含义：运行概览、Checkpoint、Metrics、异常历史、实时状态推送。必要性：**必要**（流式作业无观测即不可运维）。建议：**保留**。

### 3.7 对账与租约
- 业务含义：期望态 vs Flink 实测态收敛，`yak_realtime_runtime_lease` 保证单协调者。必要性：**必要**。建议：**保留**。

### 3.8 日志脱敏（`RealtimeLogRedactor` / gateway sanitize）
- 业务含义：提交/运行日志中密码等不落明文。必要性：**必要**（安全）。建议：**保留**。

### 3.9 连接器能力（`capabilities`）
- 业务含义：向前端声明可用 source/sink/语义。当前实现**硬编码** `sources=[mysql]`、`sinks=[yak-jdbc:mysql, yak-jdbc:postgres]`、`schemaEvolution=[evolve,ignore,exception]`、`deliverySemantics=at-least-once`、`checkpointConfiguration:false`、`restartConfiguration:false`。必要性：**必要**。当前问题：覆盖面窄且写死。建议：**补齐**（扩连接器、暴露 checkpoint/restart 调优）。

## 4. 模块真实功能定位

- **实际角色**：②段"CDC 实时"的独立执行子系统，自带运行环境管理与流式运维观测。
- **是否关键节点**：功能上关键，但 **未被其他模块强依赖**（后端无模块 import realtime，实测）。
- **被强依赖点**：无（与离线的 MDM/工作流/审计复用不同）。可独立上下线。
- **类型归类**：核心业务模块（**非占位、非过渡、非冗余**）。
- **真实边界**：真相 = 计算环境 + 实时任务定义/版本 + 部署(执行) + 事件/租约；不拥有连接、不拥有编排、不参与审计/资产对账。
- **职责问题**：与离线共用聚合包易被误认为"一套代码两种皮"，实则完全独立；连接器/语义覆盖窄使其适用范围有限。
- **下线影响**：仅影响 CDC 用户，无跨模块连锁（低风险）。

## 5. 交互关系

- 上游：数据源（`RealtimeDataSourceResolver` 经 `DataSourceRepository`/`DataSourcePluginRegistry` 取 source/sink 凭据；`RealtimeDefinitionValidator` 经 `DataSourceCatalogReader` 读目录）。
- 外部引擎：Flink 集群 REST + Flink CDC CLI（本地进程或 SSH）；工作目录 `./data/realtime-sync`。
- 下游：模型工作台——**代码层无 modeling/lineage/asset 依赖**，"落地表"是写入 sink 物理表的概念性数据流（当前无法确认是否自动登记为模型）。
- 横向：与离线同步/任务内核/工作流/审计/告警 **均无交互**（实测后端 import 无 `business.job`/`business.audit`）。
- 数据流：定义→版本→发布→编译 YAML→Flink 提交→REST 观测→对账收敛→SSE/事件/日志回流。
- 控制流：用户操作（start/stop/publish/reconcile）+ 后台定时对账协调器。
- 同步/异步：提交同步拿 jobId，运行异步，靠租约 + 状态机对账收敛。
- 共享存储：6 张 `yak_*`（realtime/compute）表 + 私有 Flyway `db/migration/yak-realtime-sync`（V1）。
- 风险：外部 Flink/CDC 不可达即全停；SSH 凭据与本机 CLI 权限；结果不确定态（`result_uncertain`）需人工核对 Flink UI。

## 6. 缺失能力表

| 缺失能力 | 为什么需要 | 影响场景 | 优先级 | 建议实现方式 | 依赖模块 |
|---|---|---|---|---|---|
| 连接器面扩展（source 仅 MySQL / sink 仅 JDBC） | 现实 CDC 需 PG/Oracle/SQLServer/Kafka/StarRocks 等 | 大量库无法实时接入 | P1 | 扩 `RealtimeConnectorCapabilityResolver`/`PipelineYamlCompiler` 连接器映射并去硬编码 | realtime、datasource |

| 血缘登记 | 同步边（source→sink）未入血缘 | 溯源断链 | P3 | 部署时登记血缘边 | realtime、lineage |

## 7. 现状总结（9 项）

1. 完成度：**中高**——核心链路（定义→发布→Flink 提交→观测→对账）真实闭环，非占位。
2. 与图二对齐：与数据源、落地表两条边有实证；审计/编排/MDM 三条边图二本就未连实时，代码一致。
3. 最大特征：**真实但窄**——连接器 MySQL→JDBC、at-least-once、依赖外部 Flink。
4. 页面-接口一致性：高；全部生命周期动作（validate/publish/start/stop/restart-execution/apply-published-version/reconcile）在 UI 可见（`RealtimeExecutionPanel`、`RealtimeSyncActionColumn`）；无"接口有界面无"的功能缺口；无死路由。
5. 遗留：`/{id}/restart` 为 `@Deprecated` 兼容入口，前端已用 `restart-execution`；`services/realtime-sync/legacy.ts` 与 `api.ts` 并存（同一后端端点的两套调用封装，建议后续收敛）。
6. 耦合：对外仅依赖数据源；不被任何模块依赖，边界最干净。
7. 数据层：6 张表，含版本化(definition_version)、部署快照、事件、全局运行租约，设计成熟。
8. 下游"模型工作台"为概念性数据流，非代码依赖。
9. 定性：**真实在用的核心模块，保留为主**；重点是"补齐连接器面/观测调优/审计与通知"，而非"从零实现"。原始假设"实时只是占位"**不成立**。

## 8. 掌握度自检

- 已确证：两 Controller 全端点、6 张表、Flink 提交与 REST 观测实现（本地/SSH）、计算环境设置面板已接线、前端全部动作可见、连接器能力硬编码、后端仅依赖 datasource。
- 未确证（标注不确定）：外部 Flink/Flink-CDC 是否已在目标环境部署可用；连接器硬编码是否掩盖 CLI 端更宽支持；落地表是否被下游登记。
- 结论可靠度：高。
