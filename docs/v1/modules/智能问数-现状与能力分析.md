## 1. 模块概览

智能问数是主轴⑤"消费与服务"段的**对话式取数入口**：用户用自然语言提问，LLM（AgentScope ReAct 循环）通过 7 个受控工具浏览在线数据集、以结构化 DSL 发起数据集查询、做 Python 辅助分析、反问澄清、保存分析报告；全程有轮次状态机、SSE 断线续播、trace/证据留痕与运行时动态配置。

- 后端：已入 reactor（`data-ops-business/pom.xml:37`）与 boot 装配（`data-ops-boot/pom.xml:142`）；**但运行时默认关闭**：`yak.agent.enabled=${YAK_AGENT_ENABLED:false}`（application.yml:65-67），全部 Bean 挂 `@ConditionalOnAgentEnabled`。**176 个 Java 文件 = main 141 + test 35**（R-6 所称"176 个文件直接进构建"含 1/5 的测试文件，其中架构/契约/E2E 测试 10+ 枚）。
- 依赖声明（pom）：`data-ops-common` + **`data-ops-business-dataset`（唯一业务依赖）** + 平台安全 starter + AgentScope 2.0.2 全家桶（model-openai/mysql/harness/studio/agui）。包结构 controller/conversation(+query)/runtime/toolset/catalog/gateway/report/repository/dao/domain/memory/telemetry/config，ARCHITECTURE.md 逐包定责并有 `AgentDependencyBoundaryTest` 静态执法（dataset 类型白名单仅 gateway 包、agentscope/reactor 仅 runtime 包）。
- 数据：自有 Flyway 两段迁移共 **10 张表**（V1 baseline：yak_agent_session/report/query_log/step/message/turn/turn_event/memory、yak_config、yak_agent_skill；V2 为 session/report/skill/turn/query_log 补 project_id 做项目隔离）。另借用平台共享 MySQL：官方 `MysqlAgentStateStore` 写 `agentscope_sessions` 表（消息/推理状态 truth，复用 `yakBusinessDataSource`，`AgentStateStoreWiring.java:21-24`）。
- 前端：**单页 `/ai-agent`**（导航树隐藏路由、`mode:'public'`，`navigation.ts:67`；入口为顶栏"智能助手"按钮 `layouts/SiteLayout/index.tsx:1064-1068`）。页内五 Tab：对话（会话列表+SSE 流+ThoughtChain 推理链）/查询审计/配置/分析报告/技能管理（按 `agent:skill:read` 显隐）；三个纯函数运行时模块（stream/skill/trace-runtime）各带 vitest。
- LLM 接入：`yak.agent.model.*`（provider 仅支持 openai 兼容协议，name/baseUrl/apiKey 任一为空即启动期 fail-fast——`AgentRuntime.java:111-125`）；llm 超时 120s/重试 3 次/ReAct 迭代上限 10/轮超时 300s/上下文窗口压缩（Compaction）。密钥只进 runtime 子系统（ARCHITECTURE"密钥不离开本子系统"）。
- 定性：**"数据集之上的问答壳"已经真实、完整、防御纵深良好地存在；"BI 替代品"远不是**。R-6 的三问（位置/概念/消费契约）在代码与模块文档里已有硬答案，缺的是第四问——平台级验收手续（03 路线无问数条目、对外接触面未入册、无菜单/权限种子 SQL）。

## 3. 子功能逐个分析

### 3.1 对话问数主链路（§2.1–4）
- **业务含义**：问数的全部价值所在——一句话变成一次受控取数与解释。
- **输入/输出**：自然语言+会话上下文→ReAct（≤10 迭代）→工具轨迹→答案+证据+可选报告。
- **实现度**：**必要，且是全模块最扎实的部分**。提交/执行分离（HTTP 线程不推理）、QUEUED 行即持久队列、CAS 认领幂等、事件先落日志再被尾随（断线可续）、取消路由、HITL 恢复带 toolCallId 防伪（`AgentChatService:78`）——多实例正确性与可恢复性都是真规则。`E2eAgentChatFlowTest`/`AgentResumeIntegrationTest`/`CompactionIntegrationTest` 等覆盖。
- **问题**：无任何平台级验收记录（03 路线零条目）；SSE 心跳/重连参数未见配置文档化。
- **建议**：优先补 03 端到端条目（见 §6 P0），其余不动。

### 3.2 取数链路（§2.7–9）——消费契约的命门
- 三道闸真实：目录闸（仅 ONLINE 数据集/字段）→ 白名单闸（`FieldWhitelistValidator` 在执行边界前置，拒绝路径也落 REJECTED 证据，不依赖工具层）→ 配额闸（limit 默认 200/上限 1000）。LLM 全程只见/只出结构化规格（dimensions/metrics/aggregation/filters/sorts），SQL 由 dataset 模块编译执行，证据回读实际 SQL。
- **必要性**：**必要**。这就是 D-4"只许读数据集，不许另开取数通道"的代码兑现，兑现质量好。
- **问题**：字段级授权继承的是 dataset 的可见面——若数据集本身无行级权限，问数也不会有（与数据集模块盘点共担，不另计）；无每用户/每项目问数配额（LLM 成本失控面，见 §6 P1）。
- **建议**：把 `[FIELD_WHITELIST_REJECTED]`/`[DATASET_OFFLINE]` 两类守卫事件接入告警（现仅落库）。

### 3.3 analyze_with_python（§2.10）
- **较必要（受限启用）**：给模型"算"的能力（统计/相关/画图数据），默认关闭、开关显式、并发/超时/临时目录强约束，数据只来自查询证据、产物只回文本。它不取数，不构成 D-4 违规；但它是**代码执行面**，与"只读 dataset"并列必须在准入契约里点名（§7.7）。
- **问题**：沙箱=无（本机 python3 进程，OS 用户权限内无隔离）；开启前需环境级评估。**建议**：准入登记条款中写明"仅限受控部署环境启用"。

### 3.4 报告（§2.11）
- **必要**：问数结论沉淀为可分享资产（Markdown+ECharts 块），生命周期独立。问题：报告不入资产台账（AssetProvider 无 agent，`AssetEnums` 无对应类型），"报告"是平台孤儿概念——**较必要→建议随 M2 资产覆盖统一收口**，不单独立项。

### 3.5 技能管理（§2.12）
- **必要**（把口径/黑话/常用分析套路沉淀为受控提示词，热生效免发版）。双写一致+乐观并发+热卸真实。
- **问题（本模块最大治理缺口）**：技能正文**无审批、无版本历史、无内容审计回放**，直进 System Prompt——拥有 `agent:skill:manage` 者等于握有"给全平台用户的大脑改写记忆"的钥匙，且 prompt 注入面在此处是合法通道。**建议**：技能变更接入审批中心（六类流补一类）或至少加版本快照+变更审计；01 文档"审批五类"需同步。
- **`SkillHotSwapE2ETest`** 证明热换真实可用。

### 3.6 trace/审计/观测矩阵（§2.13–16）
- **必要**：LLM 输出是输入不是真相（ARCHITECTURE 原则 6），trace+证据就是"对账面"。kind 单一注册表+单写者守卫（`StepSingleWriterGuardTest`）+采集边界守卫测试，记账体系干净。观测矩阵端点无页面（接口缺页面）；Studio/OTel 默认关且指向 localhost——**开发态配置，生产接入方案未定（当前无法确认有部署实例）**。
- **建议**：观测矩阵并入对话页或独立"运维"Tab；OTel/Studio 出站列入准入契约条款。

### 3.7 长期记忆（§2.17）
- **较必要，当前为过渡形态**：M1（提取+召回）已接线且 best-effort（失败不影响主链路、有 THROTTLED 闸与总开关），M2 巩固管线整段零调用者（ARCHITECTURE 如实自曝并指向 commit dea24fb5c）。**问题**：用户看不见记了什么、无法删除——个人数据治理欠账（GDPR 式"被遗忘"最小面：按用户清空）。**建议**：补"我的记忆"查看/清除入口后再考虑开启默认；M2 未接线部分明确排期或删除死代码。

### 3.8 动态配置（§2.18）
- **必要**：仅登记键可写、1s 微过期热生效、空值回退种子——小而正确。**问题**：`yak.agent.approval.query-execution`（查询执行人工确认）登记后**全模块零读取者**——页面上出现一个"看起来能开启审批"的开关而它什么都不控制，属**危险摆设**。**建议**：要么本期接线（run_dataset_query 首查过人工确认），要么从登记表摘除。

### 3.9 基础设施与装配（§2.19–2.22）
- 清障/扫描/每日聚合/条件装配（`AgentConditionalWiringTest` 保"关=零 Bean"）均**必要、达标**。权限注册的注释与事实不符（§2.22），实际生效路径推定为 starter `permission-registration.enabled=true` 的注解扫描（application.yml:94-95），**未在运行环境实证**。
- **建议**：修正注释；若注解扫描确为唯一途径，在 05/02 文档写明"问数无菜单种子，入口=顶栏公开路由"这一特例是拍板还是遗漏。

## 4. 真实功能定位

**问数：BI 替代品，还是 dataset 之上的问答壳？——代码给出的答案是后者，而且它自己清楚是后者。**

判据：①唯一的业务依赖是 dataset（pom + 依赖测试双锁），目录、字段、查询、SQL 编译、数据源连接全部经 dataset 公共契约，Agent 没有自己的图表引擎、看板对象、聚合缓存——产出是"对话+证据+Markdown 报告"，不是可视化资产；②它替代的是 BI 的"临时取数问答"象限（拖拽分析页做不了的自由提问），不替代仪表盘/大屏/分析三个已存在的可视化象限；③图二把它画在 `DST-->AGT` 上，代码兑现的恰恰就是这条边（与数据服务形成镜像：**图上该接数据集的两条边，SVC 零实现、AGT 全实现**）。

需要如实标注的三个"壳外附加面"：本地 Python 代码执行（默认关）、LLM 供应商出站（必选，openai 兼容）、OTel/Studio 观测出站（默认关）。它们不违反 D-4"不另开取数通道"（没有一个通向业务数据库），但超出了"只读 dataset"的字面消费契约——准入登记时应逐条入册（§7.7）。

**结论**：它是**数据集之上的问答壳 + 一层受控代码执行面**，不是 BI 替代品，也不应该变成 BI 替代品（那是 ⑤ 段另外三个模块的职责）。

## 7. 现状总结（九项）

1. **一句话定位**：智能问数=主轴⑤段"数据集之上的对话式问答壳"，取数三闸（ONLINE 目录/字段白名单/行数配额）+轮次状态机+证据 trace 真实落地，是 D-4 拍板（只许读数据集）目前唯一被代码兑现的⑤段消费者。
2. **最扎实的部分**：工程纪律近乎样板——提交/执行分离与 CAS 多实例语义、事件日志先持久后投递、dataset/agentscope 双重 import 白名单测试执法、"LLM 输出是输入不是真相"的证据对照面、模块文档七件套与代码自洽（含自曝未接线面）。
3. **最大空洞**：平台验收手续（03 路线零条目、无实跑记录）——模块内测试再多，也不能替代技术负责人拍板要的端到端证据；其次是技能/记忆/报告三块"自有真相"完全游离于治理横切之外。
4. **方法论未兑现点**："LLM 输出须经校验后才可使用"在 run_dataset_query 上兑现（白名单+DSL），但技能正文是 LLM 行为的无审输入、记忆是 LLM 生成的无审持久——同一条原则的两块盲区（§3.5/§3.7）。
5. **闸门现状**：取数有闸（机器闸：白名单+OFFLINE 拒）；执行无人工闸（审批键是空挂）；技能/配置变更无审批闸；发布闸不适用（无发布物）。
6. **前后端错位清单**：接口缺页面——观测矩阵、记忆管理（不存在接口）、PUT 无（配置有页面）；页面缺后端——无；假功能——配置 Tab 的审批键（P1 摘除或接线）；权限无 SQL 种子、入口仅顶栏（拍板状态待确认）。
7. **R-6 准入判定（四问体检结论）**：
   - **问 1 服务⑤段哪一段？** 合格。⑤段消费侧"问答入口"；01 文档已登记（第 77-78 行：段=⑤、真相=会话记录），00 总表第 18 行与图二一致。
   - **问 2 自有概念边界（会话/trace/技能?）** 合格。Session≠Turn≠Evidence≠Report 的边界在 ARCHITECTURE/DOMAIN 成文、包结构与 `AgentArchitectureTest/AgentFlywayContractTest` 执法；自有表 10 张全部 yak_agent_*/yak_config 命名空间。除会话/turn/trace/证据/报告/技能/记忆外未再扩张新真相。
   - **问 3 是否真的只读 dataset（有无旁路直连数据源/SQL 执行）？** **合格，附登记条款**。dataset import 仅 gateway 包（白名单测试锁）；无 SqlExecutionRuntime/数据源连接类 import；SQL 只能由 dataset 侧编译。需正式登记三个超字面契约的接触面：LLM 出站（必选）、本地 Python（默认关）、OTel/Studio 出站（默认关）+CORS 宽默认。
   - **问 4 验收现状？** **不合格——唯一欠票项**。03 端到端验收路线无问数条目；无实跑记录可查；权限注册生效途径未实证。
   - **判定**：**有条件准入通过**。票面三齐一缺，建议 05 清单 R-6 由"待评审"改"准入登记完成、验收补票中"，补票动作=P1 前两项（03 条目实跑+技能审批方案拍板）与 P2 权限途径实证，完成前**默认保持 YAK_AGENT_ENABLED=false 出厂**（现状即关，不构成既成事实倒逼）。
8. **前后端/文档一致性**：模块自述文档与代码高度一致（连未接线的 M2 都自曝），偏差在两处小字：权限注释指向不存在的 V2012；ARCHITECTURE Package Map 列有 `AgentEventPublisher/InvocationManager/TraceIdMiddleware/DynamicPromptMiddleware` 等名，当前源码文件清单中未见同名类（疑为角色职责改名至 Executor/中间件套件，**功能在、名字漂移**，逐一对应关系当前无法确认）。
9. **风险提示**：准入四问的"三问已过"依赖模块自身工程质量兜底，平台层参照系（图的边、验收步骤、治理台账）仍未真正接住它——若下个"176 文件模块"再来一次，不能指望每次都自动长出 ARCHITECTURE.md；建议把本篇 §7.7 四问模板固化为 05 清单第三节的新模块准入表。
