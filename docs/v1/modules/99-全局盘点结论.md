## 二、主脉是否成立

**结论：①②④段成立、③段半成立、⑤段名实分离、横切B 是叙事重心但兑现最薄。**

- 图一的"数据旅程"在**执行侧**是真的：接进来→搬进来→锁版本→定时跑，全链有代码有页面。
- ③段"标准→指标→建模"顺序**只在语义→建模真成立**；语义→开发断边、指标停在"定义台账"没有走到"算出来"，③→⑤的指标消费承诺为零。
- ⑤段宣称"让数据被用起来"，但四个消费出口里数据服务旁路数据集、大屏游离治理、分析无创建入口——**消费段内部就没连成一棵树**。
- 最要害的图-码矛盾集中三类：①方向反（CAT→QUA、MET→MOD 实为 MOD 供 MET）；②有边无码（WFL→AST、SEM→DEV/SEC、MTR→DBH/SVC、DST→SVC、DEV→AUD）；③有码无边（首页取数 13 线、SVC 直绑数据源、MDM 直连 sync）。**04 图需要一次"以码修图"，否则评审按图说话会指着空气吵架。**

## 三、哪些模块是核心（离了它主脉断）

1. **数据源**——全平台唯一外部门，8+ 模块引用其连接。
2. **数据开发 + 任务目录 + 任务内核 + 工作流**——④段执行机器，不可变 Revision 是平台最硬的契约。
3. **数据集**——⑤段事实消费根（除数据服务外都挂在它上面）。
4. **语义中心**——五域只读真源，一词一义的锚。
5. **数据资产 + 审批中心 + 血缘**——治理三角（状态机/闸门/溯源），定位核心、兑现半程。
6. 离线同步（有 Link-Up 时）、数据质量（真执行器）。

## 五、哪些模块职责不清（需一句话裁决）

- **分析**：独立工作台还是仪表盘的草稿器？（现状：寄生）→ 建议并入仪表盘产品面，代码留运行时。
- **首页**：总览还是第二推算源？→ 裁决"只读事实、禁止重算"。
- **安全 vs system 权限**：功能权限/数据权限分界书面定下。
- **建模 vs 指标**：汇总表属主（当前双向 SPI 健康，但"指标反推"覆盖率弱）。
- **元数据 vs 资产**：目录一本账的"账"归 asset，"核"（AssetExplorer）应搬家。
- **MDM**：平台治理件还是嵌入式产品？→ 先回答要不要继续养。
- **任务内核**：唯一执行引擎的名义 vs 路由壳的现实——要么收编 SQL/SYNC/QUALITY 三旁路，要么改口径。

## 七、收敛与补齐路线图（建议按序执行）

**第一步：修图不修码（0.5 天）** —— 04/05 文档以码修图：18 条交互边逐条标真/反/断，②③类乱象（本文件第二节三类）各归位。目的：先止住"按图评审指空气"。

**第二步：拆四个 P0 引信（1~2 周）** —— ④内核运行态持久化与 JAVA 白名单；③告警主链闭环；②生命周期删除守卫；①数据源删除引用守卫+凭证加密。全部是"事故型"缺口，不新增功能。

**第三步：治理三角合拢（2~4 周）** —— 资产 Provider 批量补齐（每域一天内的机械活）→ 消费发布链引用资产状态（闸门生效）→ 审批发起入口补齐（双轨归一）。完成后"M2 主线"才闭环。

**第四步：③段还债（1~2 周）** —— 指标消费接线（或产品裁决降级为"指标定义期"并在页面明示）；建模物理化对账（DDL 生成→执行→对表，决策 D3 重开）；分析写链裁决（并入仪表盘则删页面壳）。

**第五步：冗余合并（随版本滚动）** —— 第四节 10 项按"合并→下线→占名删除"顺序清；R-4 公共件下沉（版本快照/发布指针/查询运行器三件）与大屏治理投影同批。

**纪律建议（防复发）**：每个新域模块准入时强制交"复用清单"（用了平台哪些横切件、哪些自建+理由）——本次盘出 10 处重复的根因是 agent 各自为战造轮子；生命周期/审批 MDM 流可作正面样板写进 CODE_STYLE 或 01 主心骨。

## 八、总评（一段话）

这个平台**不是失控，而是"局部精装、连廊未通"**：单模块工程质量普遍超预期（不可变版本、统一网关、审批 SPI、七格只读聚合都是正确的设计），但模块间约三分之一声明边未接线或方向相反，横切治理"展示先行、执行垫后"（资产 7/24 在账、安全脱敏零执行、告警半接线、审计半覆盖）。真正危险的不是任何单点，而是**04 图的 ✅ 叙事与代码现实的落差正在被团队当作事实使用**。按上面五步收敛，代价小、路径清楚；再放任 agent 各建各的半年，才会到不可逆。
