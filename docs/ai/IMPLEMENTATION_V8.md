# Agent 第八版交付说明

日期：2026-10-07

实施权威：[F-016](../product/features/F-016-agent-history-evidence.md)，范围见 [第八版计划](./AGENT_V8_PLAN.md)。Feature 保持 IMPLEMENTING，工程交付与真实模型验收分开。

## 用户现在能做什么

重新打开会话时，有明确原轮次引用的已完成回答只展示该轮执行证据。旧消息或引用缺失/冲突仍显示正文，并提示“未能确定这段历史回答所属的执行轮次，暂不展示关联执行证据”。页面不会拿最新轮次或别轮的工具详情补到这段正文上。

失败/中断仍来自原轮次的独立记录，明确说明当前展示位置不代表它与前面回答的执行顺序。最新任务、活动状态跟随、精确停止和原澄清应答继续通过原 continuation 路径，不由历史关联缺失推断状态或改目标。

## 实现与边界

- Runtime 在新 START USER 消息 metadata 中写入原 turnId 引用，随官方 AgentState 保存。正文与 SDK 消息 owner 不变，不从模型正文/URL 接受身份。
- 原 USER 分组保留该引用，工具中间消息继续过滤；HITL 工具结果不创建新的 USER，回答仍归原分组。
- read-side 只对唯一分组引用、唯一完成记录且用户/项目/session 一致的回答读取原事件 trace。旧消息、未知/非法/重复引用或非完成轮不附 turnId/trace，不做序号、文本或时间猜测。
- 前端无确认 turnId 时不渲染返回的关联步骤，也不自动水合其他轮；独立失败直接持有原 ID。history HTTP JSON 形状不变。

继续使用 AgentScope Java 2.0.2。无新表、配置、状态机、权限、导航、模型调用或跨域依赖走廊。未接线消息树仍不作为正文来源，本版不为其补 append。

## 使用与限制

部署本版后新发起的问题可保存引用；旧消息不回填，所以旧会话正文可能没有可关联的执行详情。上下文压缩或旧状态丢失引用时也保守降级，不能宣称完整历史或完整时间线。消息与事件的并发读取沿用原只读一致性边界；活动状态与后续继续以最新 continuation 为准。

本版不支持活动全文重放、崩溃断点续跑、自动重新推理或自动源写入。准确关联证明“证据属于哪轮”，不证明模型结论语义正确或源事实仍然新鲜。
