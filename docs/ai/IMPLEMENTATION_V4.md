# 第四版：历史质量执行排查指引

日期：2026-10-07。实施契约 [F-012](../product/features/F-012-agent-quality-troubleshooting.md) 为 IMPLEMENTING，用户授权第四版工程实施。范围为 V4-0～V4-2；真实模型/账号试点 V4-3 待完成，V4-4 源证据扩展未立项。沿用 AgentScope Java 2.0.2。

## 用户如何使用

1. 在现有质量执行详情点击“AI 解读与排查”，进入绑定本次 executionNo 的现有对话。
2. 点击“解读与排查”或“补充排查信息”填写问题，再明确发送。进入页面或点击快捷按钮不会自动推理。
3. 系统按当前权限读取历史证据；回答围绕本次事实、关注规则、待验证假设/缺口、人工检查步骤和源页面下一步。业务背景或关注对象不明确时可使用原 HITL 继续同一轮。
4. 核对服务器事实卡和证据状态，通过“返回本次执行核对”或回答的证据回链进入原执行详情。
5. 如需修改规则，由用户在源页面选择当前监控，再独立发起已有规则建议。人工采纳、保存及显式执行保持原契约。

Quality 拥有历史执行、规则结果和当前监控定义，Security 拥有授权。Agent 只消费证据，排查文字不成为事故/处置事实。原 StateStore、轮次队列、预算、SSE/取消、源审计和证据协议继续复用。

## 可信程度与边界

关键状态/数值沿用 verify_governance_facts 和服务器事实卡。事实卡只证明特定字段，引用/链接守卫不证明整段自然语言或步骤语义正确；本批主要改进任务提示与表达，真实效果仍需专家评审。

当前 API 不提供原始错误、SQL、失败样本、冻结模板语义/失败策略或上游状态。因此 ERROR 不能确认连接/权限/SQL 根因；NOT_RUN 不确认本次 STOP 原因；未知模板语义时不将实际值换算为异常行数。当前定义不能替换历史；全 PASSED 不代表整表健康。

API 最大规则数、Gateway 文本及事实核验仍有现有上限，不能承诺全规则完整核验。用户口述背景不是源证据，字段缺失不能靠澄清补成历史值。证据不可读继续降级，不发布模型肯定诊断；固定核对提示也不会绕过源页面 live 权限。

显式历史任务继续禁止 Dataset 明细/Python/报告、其他对象读取、规则候选及业务写入/启用/重跑。跨执行比较、错误类别、RAG、多 Agent 和框架迁移不属于本批。
