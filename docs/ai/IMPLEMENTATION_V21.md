# V21 场景候选失效与停止恢复

用户于 2026-10-08 在 #348 合并后要求继续开发。当前实施依据为 IMPLEMENTING F-020/F-023/F-024/F-025/F-028/F-031 与 ACCEPTED PD-002/PD-003；本批修复既有合同中的失效与恢复行为。

User：建模与指标设计人员。Problem：标准/来源字段的检索词变化后旧候选仍可带入；停止请求等待期间能重复取消，且异步失败会显示任意服务异常；面板依赖调用方提供完整 key 才隔离目标/定义/权限变化。Capability：在原候选面板明确失效旧结果，串行核对精确轮次停止结果，保留当前输入及原会话出口。Journey：生成 → 核对候选或活动轮 → 修改检索条件/停止 → 只读核对原轮状态 → 明确重新生成或人工带入 → 原保存。Expected Outcome：不会将旧条件结果用于新输入，不因停止应答或传输结束误判终态，不自动重复生成。

Truth Owner：原 turn/Executor 持有生命周期，StateStore 持有消息，源域持有定义/权限/保存。Producer 是既有 submit/cancelTurn/continuation/history/源校验；Consumer 是既有四场景共用面板。复用原精确停止、完整目标比较、请求失效隔离与原编辑器。没有新增 API、业务状态、模块、导航或业务写入。

- 检索词变化立即撤下候选，刷新旧轮不得恢复到不同检索条件。活动/未知结果仍阻止新轮；完成核对后用户显式重新生成。
- 面板自身按目标、定义与 disabled 的完整作用域隔离生命周期；调用方继续拥有项目及表单作用域。权限失去后恢复也不能让旧校验回调带入。
- 停止冻结已确认的原 turnId，一次只允许一个停止/核对操作。停止回执丢失仍读取真实状态；核对失败保持不确定并阻止新生成。卸载或目标变化后迟到停止不刷新新面板，不重复取消后来轮次。
- 全量比较目标值，忽略对象键顺序与可空投影字段，不忽略字段、检索词、需求、版本或依赖。复用到原会话回看。
- 阶段失败显示固定可操作提示，保留检索输入与原会话链接。FAILED/CANCELLED/INTERRUPTED 明确区分；待答/缺失状态不开放新轮。场景面板未增加 HITL 执行能力，原会话仍按原 pending 应答。
- 指标解释及定义草稿准备上下文失败也使用固定提示；仅显式重试读取，保留定义草稿需求，不因重试自动提交推理。
