## 依据与旧规划冲突

这不是已观测的生产用户反馈。源码依据为 `GovernanceSuggestionPanel` 的局部 applied 索引在重新生成后清空，`MonitorEditorPage` 校验成功后直接追加，以及编辑器 save 与校验之间没有互斥。已有逐条采纳、源域校验和定义指纹必须保留，不重复建设。

[第四版规划](./AGENT_V4_PLAN.md) P1 原建议先完成真实 G 场景再识别断点。本次用户明确要求“继续规划下一版迭代 完成后开始实施”，新 F-013 授权提前修复上述可由确定性测试复现的工程缺口；不声称 G 场景通过，也不绕过真实试点开放门槛。V4-4 错误类别/跨执行对比仍受原门槛约束，未纳入本轮。

## 范围与切片

1. **V5-0 契约。** F-013 与 Agent/Quality Domain、Requirements 同步。无新业务对象、状态机、导航、数据库或跨域依赖，Architecture/Dependencies 保持原走廊。
2. **V5-1 核对。** 每条候选展示同模板 ID、同字段的当前表单规则（包含未保存编辑），显示名称、条件、启用状态；最多展示五条，超出明确标注。证据仍来自本轮证据卡，不把表单内容称作历史执行事实。
3. **V5-2 安全采纳。** 相同模板/字段/操作符/数值区间/枚举集合/自定义 SQL 的候选不重复带入，名称与启用状态不改变条件相同判断；不跨模板、大小写或字段别名推断等价。不同条件允许追加，绝不覆盖或合并现有规则。表单中删除已带入规则后可以再次带入。每次仍调用源校验，并在返回后按最新表单再次比较。
4. **V5-3 保存互斥。** 校验与人工保存相互排斥；保存开始即锁定本次待提交内容，校验期间保存明确阻止，源校验失败不改表单。切换目标或取消后的晚结果不追加；临时 UI 标识不入业务请求，不新增长期采纳库。
5. **V5-4 工程与收口。** 行为回归、完整前端测试、类型基线、构建、产品和架构护栏、PR CI。工程结果与真实验收分开记录，Feature 保持 IMPLEMENTING。

## 验收清单

| ID | 场景与期望 |
|---|---|
| RA01 | 已有同条件规则（名称/启用状态不同、枚举顺序不同也算），阻止重复；不同阈值允许新增，不覆盖旧规则 |
| RA02 | 两条候选独立采纳；重新生成仍按当前表单识别重复；删除后可重新带入 |
| RA03 | 校验未返回时尝试保存，不能调用更新 API；保存未结束时不能校验/采纳；正常保存仍携带原服务器指纹 |
| RA04 | 校验过程中用户改动表单，返回后以最新表单比较，不丢失其他编辑；拒绝/空校验结果不追加 |
| RA05 | 切目标、停止、晚返回、无更新权限，不产生采纳/保存/运行；HITL 仍恢复同轮 |
| RA06 | 人工保存成功后回原详情核对；冲突/权限拒绝保留未保存编辑，不能标为成功 |
| RA07 | 采纳后的规则停用，既有规则/过滤/调度/通知未被候选更改；生成与带入不产生源写入或执行 |
| RA08 | 对照卡显示表单来源、阈值单位、截断和本轮证据；真实模型是否有用由用户与专家核验 |

RA01～RA05、RA07 部分边界可由替身自动化证明；RA06、RA08 与真实保存/运行副作用必须在登录环境复核。继续保留 G1～G12、T1～T9、QP01～QP16，不换号消除待办。不声明准确率、采纳率、耗时或费用收益。
