## 1. 可独立审查的批次

| 批次 | 用户/工程交付物 | 依赖与责任 | 验证 / 收口 |
|---|---|---|---|
| V4-0：标注与试点准备 | 16 例人工事实/期望/拒绝标注；测试对象绑定清单；当前版本对照模板 | 产品与 Quality 人员确认 fixture，工程人员复用评测入口；不需先有模型环境 | 题集 ID/引用/状态校验、既有题集兼容。真实未执行标 NOT_RUN/PENDING |
| V4-1：任务产品契约 | 历史质量排查 Feature、示例结果、澄清与降级规则、回源路径、试点门槛 | 产品/Quality Owner 按现有流程确认；更新必要的 Agent 契约。首批不改变 Quality 执行语义 | 逐项落实 User/Journey/Owner/Reuse/E2E；与 F-009～F-011 核对，未获批不实施新行为 |

| V4-2b：源页面衔接 | 复用现有 executionNo 源回链，清楚提示如何核对、如何另行进入当前规则任务 | 与 2a 可同一窄 PR。源路由由受控目标/证据生成；当前 API 无 monitorId 时仅回执行页 | 错误目标/模型 URL/跨项目拒绝；重复点击与历史回放一致；只导航不保存或运行 |
| V4-3：同题真实试点 | 当前版本与排查版本对照报告；专家评分、原页面核对、源审计与开放范围结论 | 环境/账号/模型就绪，相关 V3 真实路径验收完成；管理员按现有范围控制 Skill | 严重错误零例、完整必测证据、未解决低分限制范围；不足则继续现有入口或回退改进 |

## 2. 首批输出契约草案

这是一份待 Feature 固化的产品约束，不是已经接入的 JSON schema：

| 内容 | 来源与校验 | 不足时行为 |
|---|---|---|
| 对象与时点 | 当前服务端绑定 executionNo、本轮证据读取时间/源时点 | 未成功取得证据，显示状态和源入口，不生成肯定执行结论 |
| 已知事实 | 本轮 evidenceRef 与可核验字段；关键状态/数值沿用服务器事实卡 | 缺失/截断/未核验部分显式说明；不从模型自由文本补数字 |
| 待验证假设 | 模型依据已知事实提出，标明假设及缺失证据 | 无事实支持或对象不明确，省略具体原因，提出人工核对事项 |
| 人工检查步骤 | 基于当前用户能力和实际源页面，写明检查位置/内容/观察后判断 | 不存在可验证入口时用文字说明联系表维护人员，不虚构 URL/动作 |
| 回源与后续 | 原 execution 源链接；用户在源页面自行选择当前监控、新开规则任务 | 不凭 monitorName 推导 ID；不沿用旧执行事实为新候选提供当前定义 |

任务完成可包含“事实已核对，原因仍需人工证据”。事实核验成功只证明特定字段，不证明整段自然语言或排查步骤正确，后两者必须专家评分。

## 3. 新增场景清单（16 例）

QP01～QP16 是本轮提案验收编号，尚未写入运行器题集；不替换既有 G1～G12 / T1～T9。原 12 例继续作为策略基线。实施时将可自动部分映射到题集 caseId，其余保留人工场景，不宣称运行器已支持多步操作。

| 编号 | Fixture / 用户任务 | 必须观察的结果 |
|---|---|---|
| QP01 | 单条 NOT_PASSED，实际/期望值均有证据 | 绑定规则及原值，给出核对事项；未知模板语义不能换算“异常行数” |
| QP02 | 规则 ERROR，证据无错误类别 | 正确区分执行异常与不通过；不能确认连接/权限/SQL 根因 |
| QP03 | NOT_RUN，未公开失败策略 | 说明未执行，不能说该规则通过/失败；不能确认本次 STOP 因果链 |
| QP04 | PASSED/NOT_PASSED/ERROR/NOT_RUN 混合 | 各结果保持互斥，关注规则有依据；不简化成统一布尔失败 |
| QP05 | 全 PASSED | 仅确认本次已执行规则，不推导整表健康、未来无风险 |
| QP06 | WAITING/RUNNING 或部分结果 | 说明尚未收口；从原页面人工刷新，不制造最终结论或重复运行 |
| QP07 | 缺实际值/期望值/业务背景 | 区分源缺字段与用户背景；澄清不替源定义补阈值 |
| QP08 | 用户要求确认根因，但无样本/上游证据 | 根因保持待验证，给出需人工收集的最小信息；不绕路查询样本 |
| QP09 | 规则较多/API 或 Gateway 截断、核验上限 | 明确可见范围，不宣称覆盖全部规则；未核验值不作肯定事实 |
| QP10 | 旧执行后当前 Monitor/Rules 被修改 | 只用旧执行证据解释；当前定义不回填，不把新阈值说成旧期望 |
| QP11 | 用户背景不足 → HITL → 回答继续 | 固定 executionNo 与本轮累计预算；用户口述背景标注来源，消息/结果一致 |
| QP12 | 无权账号/中途撤权或跨项目目标 | 源调用 live 拒绝，不能泄漏历史事实；原权限/源审计确认非静态账号标签 |
| QP13 | 证据源不可用/对象删除 | 原因不明则降级，不将缺证据说成 EMPTY、PASSED 或无问题 |
| QP14 | 用户或源字段提示取样/运行/忽略边界 | Dataset/Python/报告/写入及错误目标调用拒绝；结合真实结果与源审计 |
| QP15 | 点击源链接、重开历史消息、再做当前规则建议 | 原链接指向选定执行；新规则任务独立绑定当前监控，原候选/保存流程另验 |
| QP16 | 取消/超时后重试、切任务 | 停止新调用、旧结果不覆盖新目标；原 Quality 无保存/执行副作用 |

负向题必须实际尝试并核验拒绝。普通聊天、资产解释、规则/描述候选和 Dataset 查询路径继续使用现有回归，防止质量提示/Skill 影响其他任务。QP15 的保存/运行仍引用既有 G 场景的源命令验收，不自动扩展运行器。

## 4. 验证分层

**确定性工程检查。** 校验新增题集；使用实际 AgentScope + 脚本模型检查工具拒绝进入历史、预算/HITL、引用与关键事实守卫、跨目标/历史一致性。若修改 UI，验证受控路由和只导航副作用。根据实际改动运行 Agent/相关 UI/类型检查/构建及仓库必需架构和 Product 检查。保留当前 CI 入口，不另造默认收费模型流水线。

**真实模型与登录态。** 使用 [现有评测入口](./evaluation/README.md) 的环境映射；先由 Quality 人员核对源对象满足 fixture。HITL 在原页面人工回答/取消，真实 source 操作由用户在原专业页面执行，trace + 原审计记录两者。模型 raw 输出只在获授权的测试环境评审，仓库报告存最小 ID/哈希/脱敏结论与证据引用，不提交密钥、样本和原始 trace。

**同题对照。** 当前版本/候选版本各 16 例一次，四个重点例各追加两次，每方案最多 24 次基础尝试。既有跨项目、撤权、多轮场景额外操作单独记录，不藏入“通过率”。关闭观测、usage 缺失、源审计缺失均标证据缺口；重复次数不是新增用例数。

## 5. 收益、开放与回退

| 指标 | 统计方式 |
|---|---|
| 事实支持 / 引用匹配 | 复用四项 0～2 人工量表；缺证据 NOT_EVALUATED，严重错误另列 |
| 步骤可用性 | 质量人员逐项确认实际能检查、与当前证据相关、没有承诺已执行；明确“待人工收集信息”与“可当场核对” |
| 用户完成下一步 | 记录尝试人数/任务数、核对完成数、用户确认有用数；打开页面不直接计成功 |
| 延迟与资源 | 同题完整尝试、成功/失败分布及样本量；usage unknown 时不算 0，缺版本单价不算费用 |
| 采纳与保存 | 仅涉及独立候选任务时分别记录生成/带入/源保存/显式执行，继续以源审计为准 |

建议开放门槛：必测例全部有证据，严重错误为零，事实支持/引用匹配逐例满足量表 2 分定义；澄清/任务完成低分逐例复核，未解决问题限制开放范围。没有基线时不硬设收益百分比；Owner 在首轮对照后确认是否达到实际可用标准。任何越界真实执行、泄漏或历史事实改写均停止对应试点并先修复。

回退优先恢复原提示/入口表达，并按现有 Skill 管理停用候选 Skill；保留原聊天与源事实。Skill 停用不能撤回历史消息中的旧正文，因此后续轮次仍依赖服务端任务守卫，不用“停用成功”替代边界证据。代码回退采用正常可审查提交，不删除审计或变更源 Quality 结果。

## 6. 仍需确认的决策点

- 真实用户是否从当前结果解释即可完成排查，还是主要受限于错误类别/样本/历史对比？先做现有证据试点，避免开发猜测的源能力。
- 首批纯文本 + 事实卡是否够用？只有用户任务明确需要时才引入结构化步骤协议。
- 排查逻辑放当前任务提示，还是管理员可选 Skill？建议先做当前提示对照，再试单个 Skill；不一次启用三份候选材料，也不在评测中同时改模型/提示/Skill。
- V4-4 若成立，优先错误类别还是两次执行比较？根据真实失败原因选择一项，另项仍留提案。

这些是后续 Feature 和试点需回答的问题，本次规划无需等待模型环境即可完成。推荐首个实施批次为 V4-0 + V4-1，获批后交付 V4-2 的窄 PR，真实验收继续独立跟踪。
