# V16：模型来源字段映射 Skill

日期：2026-10-08。当前合同：[F-024](../product/features/F-024-skill-model-mapping.md)。这是框架复用调研推荐顺序的第二个场景；旧总纲中的版本号为候选排期，本次以当前 Feature 的单列来源映射范围实施，不表示已交付批量标准、模型多表映射或指标草稿。

入口在原来源映射编辑框。用户选定来源表后，可以补充业务说明、检索字段并生成最多三项候选；依据原持久化轮次完成状态与历史展示结果。采纳前重新核验 Skill、目标/映射指纹和 fresh 源目录指纹，只带入来源字段并清空旧表达式，仍需人工检查保存。

Modeling 提供授权 MappingSuggestionQueryApi；Agent gateway 只消费该 API。目录上下文最多 50 项、说明最多 512 字，显式提示截断。插件目前读取整张表的字段目录再筛选，未声称物理查询限额。没有行预览、密钥、连接参数或 SQL 执行。

第二个场景共用 V15 的 SDK 结构化调用装配和前端提交/停止/核对/采纳组件。业务匹配方法在独立 Skill 正文，工具集合、schema、源校验和业务保存规则由平台确定。请求仍独立 Agent/Toolkit/Middleware，共用原 StateStore 和 turn，不新增引擎、队列或状态机。

原编辑框读取单列编辑上下文，保存携带 If-Match。映射写路径先锁父模型，条件读取使用字段和映射 locking read，冲突先于写入。条件保存保留原标准字段关联，并用 fresh 元数据检查字段存在性；外部 DDL 与平台事务没有跨库原子保证。

代码与自动化记录见 [V16 验收](./acceptance/2026-10-08-v16/README.md)。真实模型/登录态试点继续 PENDING。V15 的实际 CI 测试已通过，汇总 gate 因 GitHub 账户计费限制未启动；未据此绕过合并检查。
