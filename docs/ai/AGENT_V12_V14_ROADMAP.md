# Agent V12～V14 连续建设路线

日期：2026-10-07
类别：实施计划；行为权威为各版 IMPLEMENTING Feature，历史计划仅作证据。

## 用户任务与结果

资产维护者、质量治理人员和分析用户需要完成“生成 → 核对 → 人工采纳或留存”。上一轮完善了聊天会话，本轮处理原编辑器候选生命周期、证据可读性和报告交付的可复现缺口。对应 J1/J4 及既有分析报告路径；不新增一级导航或跨域治理规则。

StateStore 拥有消息/pending，turn 拥有生命周期，源域拥有治理事实与条件保存，report 拥有已保存报告。源域公开 API、原会话读模型和报告详情是 producer；编辑器/证据卡/报告页是 consumer。复用原权限、Project、AgentScope Java 2.0.2、预算、HITL、精确取消与只读 continuation/history；无第二事实源。

## 顺序与切片

| 版本 | 用户问题与能力 | 实施权威 | 验收 |
|---|---|---|---|
| V12 | 编辑器候选还按会话取消、只凭 SSE 结束展示候选；改为原轮停止和持久化状态/唯一历史回答核对，异常可刷新或到原会话继续 | F-020 | SL01～SL08：完成、待答、活动、丢回执、取消竞态、重复提交、切目标/卸载、人工采纳 |
| V13 | 英文状态和歧义证据难以判断；展示五态含义、来源/读取时点/缺口、证据筛选，拒绝多块或重复引用，事实只关联唯一 OK 证据 | F-021 | EV01～EV06：五态、筛选、时间、重复/非法引用、事实关联、共享入口 |
| V14 | HTML 导出未经净化、依赖 CDN，报告详情可被晚响应覆盖；导出静态净化 HTML 和原 Markdown，图表保留配置供核对，列表/详情/导出有请求隔离与失败恢复 | F-022 | RE01～RE07：不可信内容、离线导出、图表配置、原报告一致、详情竞态、列表错误、重复导出 |

每版先形成 Feature 和 Domain/Requirements 约束，再实施及本地回归；前版本地通过后进入下一版。分别提交 PR，按 V12 → V13 → V14 顺序检查最终 CI 后合并。交付记录放各版 IMPLEMENTATION 与 acceptance 目录；最终 CI 结果以链接 PR 为准，避免提交记录晚于已验源码。

## 边界与开放门槛

不扩展数据源权限、工具矩阵、自动修复、质量跨执行比较、RAG 或多 Agent。V13 展示已有服务端投影，状态 OK 不代表业务健康；V14 导出文件不是新发布或共享权限，不内嵌远端脚本，图表以 JSON 配置而非交互图展示。报告仍是原分析报告，不开放治理报告写工具。

自动化证明工程行为与发行一致性；真实模型、登录态、源审计、专家语义评分全部独立 PENDING，旧 G/T/QP/RA/SC/AF/HE/NR/GP/LC 待办保留。各 Feature 保持 IMPLEMENTING，代码合并不能替代 SHIPPED 证据。未来问数澄清、质量比较、影响说明的源域契约/真实试点门槛继续沿用上一轮路线。
