# Agent V9～V11 连续迭代路线

日期：2026-10-07
授权：用户要求“这次多规划几个版本迭代的内容，然后依次完成”。
范围：三版依次完成工程实现、回归、PR 与 CI；真实模型验收独立待执行。各版先建立 IMPLEMENTING Feature，再修改行为。继续使用 AgentScope Java 2.0.2。

## 用户与结果

服务在原资产、质量页面进入 AI 的治理人员：先知道上一轮真实结果，再组织符合当前任务的问题，并在执行中安全核对或停止。Agent 不拥有源域事实或写入权；消息由 StateStore、轮次由 turn、源证据由各域拥有。沿用 J4 问题排查及 J1 可信资产判断路径，保留源页面回链。

| 版本 | 当前问题与能力 | 用户路径 / 期望结果 | 复用与生产消费 | 验收与依赖 |
|---|---|---|---|---|
| V9 | 终态缺一致说明，旧重试使用全局问题；提供终态说明与可证明的原问题草稿 | 读实际状态 → 填入原问题 → 核对编辑 → 明确发送新轮；无自动续跑 | turn 输入、StateStore 原引用 → 原 continuation / 输入框；原提交检查陈旧来源 | [V9 详细规划](./AGENT_V9_PLAN.md) NR01～NR10；先完成 |
| V10 | 原示例仅一句问题，容易遗漏背景且可覆盖编辑；提供按既有任务的提问准备表单 | 选当前任务问题 → 填已知背景、希望核对的点 → 预览 → 填入 → 发送；未填项不当事实 | 原 GovernanceTarget / governanceQuestions / 输入框；用户填写是口述背景，源域仍拥有证据 | GP01 场景匹配；GP02 无覆盖/自动发送；GP03 空项/长度/注入按不可信文本；GP04 pending/活动/切换失效；GP05 原工具矩阵不变；依赖 V9 |
| V11 | 实时停止仍用会话命令；断线/完成后缺一条稳定核对路径 | 实时停止确切 turn → 读实际 continuation；断线保留内容 → 手动刷新；完成/待答按实际展示 | 原 cancelTurn、continuation、事件订阅与跟随；无新服务端状态 | LC01 精确 ID；LC02 ACK 丢失不假报；LC03 完成/待答竞态；LC04 提交未确认不取消未知轮；LC05 晚回调/切换不污染；依赖 V9/V10 |

三版均不新增模块、导航、表、配置键、状态机或跨域读取。每版形成独立提交与 PR，前版通过再继续下一版。既有业务模型能够承载，故无需新跨域 Product Decision。

## 产品判断与边界

V10 是提问准备，不是确定性意图识别或源证据补全。仅覆盖已有的资产治理解读、资产描述候选、质量历史执行排查、质量规则候选；不按自由文本改 purpose，不在治理任务提供销售问数例子。普通对话保留现有示例。未发送输入保护、读取失败阻止填写、CHAT_RUN 权限与 HITL 优先贯穿三版。

V11 的停止只作用于提交回执确认的 ID；提交尚未确认时不推断正在运行哪一轮。SSE 断连不等于后台失败或停止。停止后必须读取真实状态；pending 不通过停止命令处置。保留已发生事实及原预算，不以客户端中断伪造 CANCELLED。

## 交付与成功信号

每版记录 Feature、实现说明、自动化检查和真实验收待办。工程验收包括权限/归属、竞态、SDK、页面、类型债务、依赖边界、发行及最终 head CI；不将替身模型测试记为真实语义通过。原 G/T/QP/RA/SC/AF/HE 待办保留。

成功信号分别是：用户能识别终态并重新完成任务；能表达核对目标而少遗漏背景；能确认停止或刷新后的实际状态。当前没有真实基线，试点记录具体任务与人工判断，不编造准确率或成本收益。

## 更后续的候选

| 候选 | 前置条件 / 原 Owner |
|---|---|
| 问数字段/时间/口径澄清 | 固定真实错题；Dataset 授权与版本、Metric 稳定引用；不直接生成 SQL |
| 两次质量执行比较 | V4 真实试点、Quality Owner 最小只读契约，不能拿当前定义代替历史 |
| 有限资产影响解释 | 所选对象、Lineage/Usage 授权与粒度得到确认 |
| 团队 Skill / RAG | ACL、版本与撤权、检索证据及同题评测 |
| 自动修复 / 多 Agent | 写动作幂等、审计与补偿，或明确同题收益证据，另行立项 |

这些候选没有进入本次实施范围。框架迁移需要已复现阻塞或同题对测收益，本次没有该证据。
