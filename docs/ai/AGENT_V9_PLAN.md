## 1. 建议与产品定义

建议 V9 补齐“本轮为什么结束、现在可以做什么、如何核对后重新提问”。接在 V7 的精确停止和 V8 的历史关联之后，在现有 Agent 页面完成，不增加任务中心。

| 必答项 | 本轮提案 |
|---|---|
| User | 停止、失败或中断后返回会话的质量治理、资产维护及问数用户 |
| Problem | 恢复页只有状态，缺少一致的终态说明；原重试依赖页面内存中的最后问题，刷新后丢失，也不能证明按钮对应所见轮次 |
| Capability | 最新轮次的可信终态说明、原问题草稿恢复、用户核对后明确发起新轮 |
| User Journey | 打开/停止原会话 → 读取实际状态 → 看说明和下一步 → 点击填入原问题 → 核对范围与补充信息 → 明确发送新轮 |
| Expected Outcome | 用户知道何时只需刷新、何时回答原澄清、何时可以重新提问；不会误以为旧轮正在续跑或已经回滚 |
| Truth Owner | turn 拥有生命周期/错误码/提交输入；StateStore 拥有消息/pending；Quality/Asset/Dataset/Security 保持源事实与权限归属 |
| Producer / Consumer | 原 read-side 生产授权终态与草稿投影，原页面消费；新发送仍经 AgentChatService 和原 Runtime |
| Reuse | 当前项目/RBAC、continuation、TurnInput、V8 原消息引用、原提交/单飞、HITL、预算、trace 与受控回链 |
| E2E evidence | NR01～NR10，代码/CI 与真实模型/登录态验收分列，旧 G/T/QP/RA/SC/AF/HE 待办保留 |

成功信号是实际用户能区分“停止、失败、中断、等待澄清”，并在核对后完成有用的新提问。当前没有真实基线，先记录任务是否继续完成和是否误触重复发送，不承诺成功率、时延或成本收益。

## 2. 已有能力与可复现断点

以下是源码证据，不是生产故障或用户收益证明：

| 已有能力 / 位置 | 当前事实 | 本版需要补的路径 |
|---|---|---|
| [V7 停止说明](./IMPLEMENTATION_V7.md) / `AgentChatService.cancelTurn` | 固定 turnId 停止；请求应答不代表 CANCELLED，须重新读取；WAITING_INPUT 拒绝取消 | 停止核对后给出下一步，不能直接提供“继续执行旧轮” |
| `SessionContinuation` / `AgentSessionQueryService.continuation` | 已恢复最新状态、任务范围、反问和阻止原因，没有结构化终态错误说明或问题草稿 | 以最新已校验轮次生成只读投影，读取不推理、不写状态 |
| `index.tsx` 的 `lastUserMessageRef`、`presentError` 与“重新生成” | 存在错误文案及再次发送动作，但使用页面全局最后问题；选择会话时清空该值 | 动作绑定最新所见轮次，先恢复草稿供核对，不从历史按钮直接重发全局问题 |
| `stream-runtime.ts` / Executor.classify | 已有 TIMEOUT、USER_ERROR、PROVIDER_ERROR、GUARD_REJECTED、GENERIC | 复用已持久化码；USER_ERROR 不能一概确认为模型配置异常，GUARD_REJECTED 不能一概确认为指标口径问题 |
| `requeueForResume` | HITL 后 kind 改为 RESUME、payload 被工具反馈替换，原问题不在最新 payload 中 | 不能把恢复反馈当原问题；必要时只按 V8 的唯一原 USER 引用读取，否则不给草稿 |
| [V8 历史说明](./IMPLEMENTATION_V8.md) | 新消息有原 turnId 引用，旧/缺失/冲突引用保留正文并不猜配 | 草稿也不得用最近一条 USER、文本相似、消息下标或旧标题猜测 |

当前已有“手工输入新问题”能力，本版是核对和填写体验的完善，不新建服务端自动重试系统。`AgentTurnExecutor.safeMessage` 并不是通用脱敏保证；新终态投影不直接透传原始异常文本。

## 3. 首批范围

### 3.1 一处最新轮次说明

原页面显示最新轮次状态及固定、保守的下一步。状态和错误码来自服务器；说明是展示映射，不成为新的业务状态机。

| 实际状态 / 证据 | 提议展示与下一步 |
|---|---|
| QUEUED / RUNNING | 沿用有界跟随、刷新和按所见轮次停止；不提供重新提问草稿入口 |
| WAITING_INPUT | 回答原澄清，保持原 turnId/目标/预算；缺反问则阻止继续，不把它当失败重试 |
| CANCELLED | 已停止本轮后续生成；已经发生的调用和事实保留。可核对后填写新问题 |
| INTERRUPTED | 本轮中断，不能原地续跑；保留历史，核对后新提问 |
| FAILED + TIMEOUT | 推理达到时限，可缩小问题后再问；不能承诺旧调用回滚 |
| FAILED + USER_ERROR | 请求被拒绝或模型调用遇到不可继续错误；核对权限/服务配置等，具体原因未确认 |
| FAILED + PROVIDER_ERROR | 模型调用未完成，建议核对服务后稍后新提问；没有次数证据不展示“已重试 N 次” |
| FAILED + GUARD_REJECTED | 执行条件校验未通过，核对任务范围/输入；不推断具体质量或语义问题 |
| FAILED + GENERIC / 缺失 / 未知码 | 无法确定具体失败原因，核对本轮记录或联系管理员；不展示裸异常作为结论 |
| COMPLETED | 本轮推理结束；不等同于质量通过或治理问题已解决。可编辑原问题后再问 |
| 读取失败 / 身份不匹配 / 停止未确认 | 只提示刷新核对；不宣称已停止，不自动重新提交模型 |

仅已有模型配置读取权限的用户能得到对应管理入口；普通用户得到联系管理员的指引，不自动授予权限或输出密钥、鉴权头、连接信息、堆栈、SQL。Agent 推理失败与 Quality 历史执行的 ERROR / NOT_PASSED / NOT_RUN 仍是不同事实。

### 3.2 “填入本轮问题”，随后明确发送

1. 仅对当前最新、已确认的终态轮提供入口；点击后先重新核对所见 session/turn，状态或身份变化就刷新，不使用旧草稿覆盖新任务。
2. START 可用已持久化提交输入生成草稿；它是原命令的输入建议，不替代官方历史正文。若同时存在原 USER 引用且内容冲突，不默选一份。
3. RESUME 仅在原 StateStore USER 分组有唯一、精确的该 turnId 引用时恢复原问题。旧消息、压缩丢引用、重复引用或读取失败明确不给草稿；用户仍可手动整理新问题。
4. 不把 toolResults 当新问题，不复制旧 toolCallId/pending，不拼接为“已补全的原输入”。澄清背景请用户重新核对和补充，不能承诺完整复现旧轮。
5. 草稿包含原问题及已恢复任务范围的可见提示，只在用户点击后填入输入框。已有未发送输入时禁用覆盖并说明，保留编辑。
6. 草稿投影建议上限 8000 字符，仅用于该辅助功能；超限不给草稿并提示手工整理，不静默截断发送，也不据此修改现有通用消息上限。Feature 阶段冻结该上限。
7. “填入本轮问题”没有模型或源工具调用；用户修改后点击原“发送”，才创建新的 START / turnId，重新授权读取、重新冻结当前执行预算。旧轮状态、证据和预算保持不变。
8. 将原失败“重试”和“重新生成”的直接发送行为统一为上述草稿核对路径；仅为最新确认轮提供该动作，历史旧气泡不再用全局最后问题代发。

### 3.3 陈旧草稿和重复点击保护

建议原新轮提交兼容增加可选 `expectedLatestTurnId`，仅由本次草稿路径携带。服务器在既有提交互斥区内核对最新轮次、终态、归属及恢复目标，再插入新轮；变化则拒绝并要求刷新，不能只靠点击前客户端读取防竞态。核对失败不启动推理，旧客户端普通发送保持兼容。

前端同步锁定发送，双击不连续建轮；提交应答丢失后保留输入并阻止重复发送，先读取实际状态。此处是陈旧来源保护，不是通用幂等提交协议；多节点分布式提交互斥仍未解决，不能宣称集群下具备强并发保证。

## 4. 拟议实现边界与治理

| 边界 | 拟议变化 |
|---|---|
| API | continuation 兼容增加白名单错误码及可选草稿/不可用说明；字段名在 Feature 冻结。不返回完整 TurnInput、原始异常或工具反馈 |
| Query | 在既有 AgentSessionQueryService 内组合原 turn 与必要的原消息只读证据；活动/待答轮不为草稿增加 StateStore 读取 |
| Command | 原 SubmitTurn 增加可选来源版本核对；无独立 retry/resume-failed 命令，HITL 原 resume 不变 |
| Domain | 使用现有 Session/Turn/Input/Evidence，无新生命周期；新增展示与陈旧输入核对需求需先更新 Requirements/Domain |
| Persistence | 原 turn / StateStore，预计不改表、不回填、不建立草稿或重试记录表 |
| UI | 原最新轮次提示与输入框；切换、新建、卸载后草稿和异步结果失效，旧提示不能更换任务范围 |
| 权限与观测 | 读取本人/当前项目、发送 CHAT_RUN、每次源调用重验权限；沿用新轮原 trace/审计，不以草稿点击伪造运行事实 |

预期无新增 package 走廊、反向依赖、业务模块、一级导航、启动配置或动态配置键。沿用已安装的 AgentScope Java 2.0.2；本轮没有新的框架阻塞证据，不另开迁移工程。

本提案不修改 F-014/F-015/F-016 的当前规则。历史计划提到的“重试/继续”不能解释为 FAILED/CANCELLED/INTERRUPTED 原轮续跑；当前 Domain 仅允许 WAITING_INPUT 同轮恢复。V8 也未解决完整历史重建，本提案不假定所有旧问题都可恢复。

## 6. 验收场景

| ID | 场景与关键断言 |
|---|---|
| NR01 | 最新终态、已知/未知错误码展示一致；未知/恶意异常不泄密、不推断具体根因 |
| NR02 | 停止后必须读取真实 CANCELLED 才展示停止说明；完成/待答竞态按真实状态，无自动重试 |
| NR03 | START 原问题/范围准确生成草稿；点击填写零模型/源工具调用，不覆盖已有输入 |
| NR04 | RESUME 只从唯一原 USER 引用生成原问题；不重发反馈或旧 pending，不重置旧预算 |
| NR05 | 旧/缺失/冲突/压缩/超限草稿明确不可用；正文仍可读，不回扫猜测旧问题 |
| NR06 | 编辑后发送创建新 turnId / START，旧轮状态/证据/预算不变，新轮重新授权及初始化预算 |
| NR07 | 草稿加载后另一标签创建新轮、状态变化或目标变化，服务端来源核对拒绝，零新推理 |
| NR08 | 双击、提交应答丢失、停止未确认保留输入并核对，不能重复自动提交或假报成功 |
| NR09 | 本人/当前项目、CHAT_RUN、模型配置入口权限有效；切换/卸载旧结果失效 |
| NR10 | 原普通问数、显式治理范围、HITL、跟随、精确停止、历史关联和完整构建发行不回归 |

真实验收需要固定部署、模型/Skill 哈希、账号/项目、session/turn、停止/失败前后记录、源审计和用户完成下一步的证据。当前 NR01～NR10 均为待执行；不因代码测试关闭旧验收待办，也不将新轮“执行完成”计为原问题已经解决。
