## 1. 建议与下一版目标

**继续使用仓库现有 AgentScope Java 2.0.2，下一版围绕“可信解读 → 可审核建议 → 原页面人工采纳”交付。主场景选择质量规则建议，资产描述辅助作为较轻的并行场景。**

先收口首版真实环境验收，同时完善证据展示和回答事实校验；再把质量模板、字段和历史执行证据转换成候选规则。用户看清建议依据与缺口，将选中的内容带入现有编辑器，经过原校验和权限检查后自行保存。发布范围以独立 Feature 的批准结果为准。

本阶段不迁移框架、不建设新 AI 一级入口、不开放 Agent 直接修改规则/定级/治理状态，也不把知识库、多 Agent 和自主巡检作为交付前置。现有框架已有 ReAct、工具、StateStore、SSE、HITL 和取消，本次问题主要位于证据与源域契约，选型依据沿用[框架调研](./FRAMEWORK_RESEARCH.md)，不声称做过新版本或性能对测。

旧规划中的“身份未接通”“治理工具待开发”已被首版实现覆盖，下一阶段不重复立项。Agent 文档仍有 Skill/记忆“规划中”与源码已接线的差异：以领域约束决定允许行为，以代码核对实际接线，在相关切片中收口文档；不默认把全部记忆行为视为已验收。

## 4. 交付顺序

| 阶段 | 交付结果 | 退出条件 |
|---|---|---|
| A：可信解读收口 | 首版真实 E2E、事实/假设/建议分层、证据卡片、固定评测集、有效配置与耗时记录 | 首版正负场景有真实证据；硬安全失败清零；明确下一阶段批准范围 |
| B：质量规则辅助 | 注册物理表上的模板候选、字段/参数校验、用户澄清、原编辑器带入、并发保护 | 一条真实“生成 → 人工保存 → 显式运行 → 结果复核”旅程通过，无隐藏调度或执行 |
| C：资产描述辅助 | 台账描述候选、对比和原表单采纳；试点反馈与成本调优 | 有权限用户可人工保存；无权限/来源故障/旧值冲突处理正确；试点结果可测量 |
| D：评审扩展 | 按价值和契约准备敏感分类、标准映射或血缘影响解读的下一份方案 | 依据试点结果只选择一个后续场景，来源契约与产品治理先就绪 |

A 的环境准备和 B/C 的已批准契约工作可以并行；真实发布必须通过对应门槛。优先完成 B，C 可独立灰度，不要求等待所有治理域补齐。

## 5. 三条用户旅程

### 5.1 可信解读完善

资产/质量执行详情 → 现有 AI 对话 → 明确目标与问题 → 展示读取进度 → 结果按“已知事实、可能原因、建议行动、证据缺口”组织 → 点证据查看来源/状态/读取时间/适用范围 → 回原页面核对。

- 数值、执行状态、对象身份与对应证据核对；“质量未纳管”不能扩写成“质量健康”，“有脱敏配置”不能扩写成“当前用户查询已脱敏”。
- 旧执行结果明确 executionNo 和时间，不能因当前规则已修改就改写历史解释。
- 来源更新时间未知时明确未知；不可用、未授权、不适用与确认没有数据保持五态。
- 语义支持仍需专家评测。校验引用 ID、字段和数值不能保证任意自然语言结论正确，不把模型自评视为安全裁决。

### 5.2 质量规则建议：本阶段主场景

默认在现有监控编辑器的规则区域提供“AI 建议规则”。从执行结果进入时，先回到所属监控，再读取当前规则/字段；历史 execution 只解释过去，当前建议基于当前目标与模板。物理表尚未注册时引导既有注册流程，不由 Agent 创建 TableAsset。

每次建议最多 5 条，用户逐条选择、编辑和带入。首批允许 TABLE_ROW_COUNT、COLUMN_NOT_NULL、COLUMN_UNIQUE；COLUMN_RANGE、COLUMN_ENUM 仅在用户提供或授权证据明确给出合法范围/枚举时生成。CUSTOM_SQL、正则、跨表一致性、自动阈值调优后置；当前枚举没有的能力不能凭空生成。

候选内容包含目标、模板、字段、比较方式、参数、依据、解释和待确认项。缺少主键/允许空值/有效范围等业务信息时反问，不根据字段名猜出必须唯一、不为空或具体阈值。质量比例单位按模板的百分比语义处理，不能把 0.95 与 95 混用。

历史执行统计只代表对应时点、规则与检查范围，不能自动当成当前全表画像或推荐阈值。已有监控存在筛选条件时，建议明确沿用该检查范围；用户改变范围必须重新取证，AI 不生成或修改 whereClause。

**“带入表单”只改变未保存的编辑内容。** 不替换整套现有规则，不修改目标、负责人、调度、通知、失败策略或启用状态；新增候选默认不启用，用户在原页面自行决定。取消生成、关闭建议或放弃编辑不能写源域表。

人工保存仍由 Quality 原命令校验并执行。保存可能同步 Schedule 和 Task revision；已有启用监控的规则启用/修改可能影响下一次自动运行，必须在原编辑器展示实际变更及影响。手动运行是单独动作，执行权限、单 active Execution、冻结计划和 after-commit dispatch 保持原语义。现有代码未证明存在“草稿规则试跑”接口，因此本阶段承诺的是无副作用定义校验与保存后的显式运行；新增试跑需另定 Quality contract。

### 5.3 资产描述辅助

资产详情现有快照编辑区 → “AI 建议描述” → 读取授权台账与适用分区 → 展示当前描述和候选 → 用户编辑/选择 → 带入现有描述输入 → 点击原保存按钮 → 回读并核对审计。

仅建议 Asset 拥有的台账描述。没有业务用途证据就保留“用途待确认”，不从表名编造指标口径、SLA、合规或责任人。源域注释、字段定义、业务标准、Owner、标签、目录和访问入口均不在自动修改范围。SOURCE_GONE 或来源事实缺失时提示缺口，停止基于不存在源对象生成确定描述，是否允许普通台账编辑继续由 Asset 原规则决定。

## 6. 来源与采纳边界

| 内容 | 来源 Owner | AI 可做 | 采纳与生效入口 |
|---|---|---|---|
| 历史质量结论 | Quality Execution / RuleExecution | 解释真实历史数值、状态；给出待核实假设 | 只读，不修改旧结果 |
| 当前模板/规则/注册表与字段 | Quality + Datasource typed Catalog | 生成模板支持的规则候选 | 原 Monitor 编辑器与 Manager；启用、调度影响由用户核对 |
| 资产台账描述 | Asset | 起草并显示前后差异 | 原台账编辑与审计 |
| 技术字段/注释 | Metadata / Datasource | 在授权范围内作为依据 | 本阶段不写物理注释或元数据事实 |
| 分级/策略/访问结论 | Security | 解释获准读取的现有事实 | 本阶段不生成生效策略，不代办审批 |
| 消费数据 | Dataset / Security | 保留已有受治理问数 | 不为规则建议绕过 Dataset 读取原始样本 |

不引入通用“AI 建议管理中心”、新业务审批流程或候选状态机。建议是本轮模型输出与表单临时内容，业务真相从原命令成功后成立。若需要长期保存建议、批量待办、自动应用或后台巡检，单独进入产品决策流程。

## 7. 暂缓范围与启动条件

| 后续能力 | 为什么暂缓 | 启动条件 |
|---|---|---|
| 敏感分类辅助 | 影响候选/确认与权限治理；现有 Discovery 只识别元数据，不做内容扫描 | 先批准独立 Feature；复用 Security CANDIDATE/ACTIVE/REJECTED，不覆盖已确认/驳回事实；等级来自源域字典 |
| 标准映射与指标口径辅助 | 语义版本、验证、发布边界较复杂 | 核验 ACCEPTED PD-003 与相关 Feature/域契约，给候选而非自动发布 |
| 血缘影响与根因定位 | 静态依赖不能证明运行影响与真实根因 | 有界读取、覆盖/时间/方向声明；补对应 E2E 后再扩大 |
| 文档 RAG | 当前主要问题是已有事实读取与采纳；检索还需文档 ACL、版本与删除处理 | 真实问题证明业务术语/规范检索有价值，明确文档 Owner 和权限，不建第二份标准 Truth |
| 多 Agent / 图编排 | 本阶段单轮读取与建议已有运行时可承载 | 出现长时跨域动作、恢复/幂等或可测量并行收益，再单独验证；不由复杂场景数量直接推导迁移 |
| 自动修复/主动巡检 | 涉及自主执行主体、触发、审批、幂等与停止边界 | ACCEPTED Product Decision + APPROVED Feature + 可重复恢复/撤权/停止验收 |

## 8. 验收与试点价值

先执行[首版待验收场景](./acceptance/2026-10-05/SCENARIOS.md)，再增加下一阶段固定题集：可信回答 20、规则候选 25、描述辅助 10、权限/故障/注入/漂移 15，共建议 70 个用例。来源必须包含真实脱敏业务案例，自动化固定响应测试与真实模型结果分开；非确定性生成建议每例运行 3 次。

发布硬门槛：没有越权、凭据/原始 SQL 泄露、隐藏业务写入；非法模板/字段/参数不能进入可带入候选；无证据不能声称健康/合规；并发旧建议不能静默覆盖当前定义。硬门槛按逐例结果核对，不以平均准确率抵消失败。

候选产品目标（待试点基线确认，不是已达成指标）：专家判定事实支持率 ≥95%、候选规则服务端校验通过率 ≥95%、真实任务中位耗时减少 ≥30%。带入前合法性检查必须 100% 执行。分别统计生成、合法候选、带入、保存、修改后保存和显式运行，不能把“点了带入”算作规则有效或价值达成。

采集 p50/p95 首次进度和最终回答延迟、token、超时/引用拒绝、取消效果。价格来自实际供应商与账单；缺 usage 时标未知，不能计为零。具体费用与延迟 SLO 由 A 阶段实测制定。面向试点先按现有用户/项目准入方式开放；若平台不能做到细粒度开放，明确部署范围，不把 UI 隐藏当服务端授权。

## 9. 立项与下一步

本次仅新增规划文档，不新增已批准 Feature、不修改业务代码与运行配置。A 中首版收口沿用既有 AI Feature；新增回答形态、建议和采纳需补相应产品范围并批准后实施。

建议按两份 Feature 拆分：“可信解读完善与质量规则辅助”“资产台账描述辅助”。沿用 PD-001/002 的事实归属；新增跨域治理规则、直接写工具或长期建议流程时，先形成 Product Decision。实施切片、依赖和验收见[交付清单](./NEXT_PHASE_BACKLOG.md)，边界与数据契约见[技术方案](./NEXT_PHASE_TECHNICAL_PLAN.md)。

当前 `docs/product/features` 同时有 AI 与审批两份 `F-009` 文档，编号有冲突；正式分配下一份 Feature ID 前应先核对并修复索引。本规划使用 A/B/C 和 N 编号作为临时工作切片，不新增同号正式契约，也不改动另一项审批工作。
