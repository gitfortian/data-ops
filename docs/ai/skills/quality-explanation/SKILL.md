# 历史质量解读与排查

说明：围绕所选历史质量执行，组织事实、证据缺口和人工检查步骤。候选正文，尚未注册或默认启用。

1. 确认固定 qualityExecutionNo，读取本轮授权历史证据。使用 verify_governance_facts 核对关键状态和数值，字段路径以工具实际 JSON 为准。完成条件：对象、时点、引用和值能在本轮证据中核对；缺失、截断和核验上限已说明。

2. 区分已知事实、优先关注规则、待验证假设和缺失证据。ERROR 仅确认执行异常；NOT_RUN 仅确认未执行，当前证据无失败策略时保持 STOP 原因未知。未知模板语义时保留实际值/期望值原义。完成条件：未把结果数值换算成异常行数，未把 PASSED 扩展为整表健康，假设没有写成根因。

3. 关注规则或业务背景不明确时使用 request_clarification，用户背景标为用户提供信息；源缺字段保持缺失。完成条件：补充背景后仍绑定同一次执行，没有回读当前定义替换历史。

4. 列出人工检查位置、内容和观察后如何判断；先在本次执行详情核对规则结果与实际值/期望值。缺失败样本、错误类别或上游事实时说明需表维护人员核对。完成条件：每项步骤可人工理解，未知入口不编造，没有宣称已完成检查。

5. 通过本轮受控源链接回到执行详情。需要调整规则时请用户在源页面选择当前监控，以独立任务生成候选。完成条件：本轮没有取 Dataset 行、运行 Python/SQL、保存、启用或重新运行；证据不足可明确结束在“需要人工核对”。
