**继续使用 AgentScope Java 2.0.2，下一批优先建设任务工具边界、回归评测和运行配置可追溯，再深化质量问题的处置指引。** 不需要为了增加治理场景先更换框架或增加一组 Agent。

| 产品验收 | 自动化与数据库 CI 有记录，真实模型/登录态待完成 | 补真实环境证据、专家评分与任务耗时；缺环境可继续代码和离线评测建设，不制造上线结论 |

这次对工具范围的判断来自上述调用路径检查，尚未执行真实模型越界复现。已有身份校验仍有效；缺口是“用户有源域权限时，该任务是否应允许调用该工具”，不能把它等同于已证实的越权漏洞。

## 3. 建设顺序

### P0：先完成任务约束和评测底座

**A1 任务工具边界。** 根据持久化的 GovernanceTarget/purpose，在本轮服务端确定允许的工具。模型、Skill、用户文本和源注释不能扩大这个集合。显式治理轮次只允许所需只读证据、事实核验、澄清与对应候选工具，禁止 Dataset 取数、Python 和报告保存。普通问数维持现有 Dataset 授权查询路径；普通对话混合问数/治理的规则单独明确，不能靠关键词或模型分类授予权限。

首先保护已有入口，再决定是否需要新的用户任务选择。详细工具矩阵和兼容边界见 [实施清单](./AGENT_NEXT_STAGE_BACKLOG.md)。新用户行为按 Feature 流程确认，未知工具默认拒绝；不能运行时修改共享 Toolkit 的全局激活状态来实现会话隔离。

**A2 有界执行与错误处理。** 复用已有超时/迭代约束，增加每轮工具调用与重复失败约束。授权/策略拒绝不自动重试；源不可用不能推导为空或健康；字段/版本变化只能有限重新发现；候选参数错误沿用有限修正。并发调用在真实执行前原子预占预算，取消后不得继续发起新调用。

预算首先按调用数和时间形成可证明的硬约束。模型 token usage 缺失时标记 unknown；token 预测和费用估算不能假装已经构成精确费用拦截。HITL 新执行段如何累计同一业务轮次预算必须先写清楚，不能恢复一次就无限重置额度。

**A3 两层评测。** CI 使用固定输入、源域替身/隔离数据库和脚本化模型，验证执行副作用、拒绝、候选、证据及历史一致；真实模型通过独立、显式启动的验收执行器验证工具选择、澄清和语义质量。普通 PR 不调用收费模型。复用既有 G1～G12 和上一阶段建议的 70 例题集，完善标注，不复制成另一套互不关联的清单。

真实模型的环境准备是一条独立待办；A1～A3 的代码与 CI 可先完成。正式试点仍要求对应真实 E2E 通过。

### P1：形成可复现的运行配置与治理 Skill

**A4 配置与版本证据。** 继续以 application-ai.yaml 作为所有 AI 启动默认值的入口，已有动态配置覆盖对应默认值。管理界面说明当前值、来源、是否需重启；不把模型密钥搬入业务库。记录实际调用时设置，而不是显示未使用的配置。新增预算配置也必须集中到该文件，名称与启动/热更新语义在实施契约中冻结。

扩展现有 effective-config/步骤观测，记录任务策略版本、真实可用工具集合哈希、实际加载 Skill 内容与启停哈希、预算及配置来源。Skill 或动态设置在轮次中变化时，记录发生变化的执行段/调用；如果选择冻结，需证明作用于框架真实加载路径。只记录哈希和非敏感语义，不持久化密钥、端点鉴权、完整提示词或私人样本。

首批保持当前 OpenAI-compatible 接入，覆盖流式结束、tool call、HITL、usage 缺失、错误分类和超时。没有真实 provider 需求时不扩展供应商清单。费用可后续按管理员提供的版本化单价估算；缺单价/usage 显示 unknown，不填 0，也不提供没有测量的 P95 和成本承诺。

**A5 少量治理 Skill。** 首批候选是资产解读、历史质量结果解释、质量规则建议和描述建议，复用现有启停/管理入口。Skill 负责检查步骤、业务澄清和结果表达；权限、工具策略、参数校验与候选保存边界仍由服务器拥有。只有同题评测证明有收益的 Skill 才进入试点。

现有 Skill 仓储读取没有项目过滤参数。首批按已存在的管理员维护范围使用，不宣称已具备用户/项目私有 Skill 隔离，也不通过复制表自动增加范围。若需要团队 Skill、审核发布或版本回滚界面，先定义其 Owner、可见范围和产品契约。对热启停与重启还原做行为验证后，再决定是否修复现有路径。

### P2：只深化一个用户任务

推荐试点任务：**质量执行结果 → 有依据的排查步骤与下一步指引**。首版已经提供结果解释，这里衡量的是用户能否完成下一步，而不是再新增一个“解释结果”按钮。

继续绑定同一个 executionNo，按已有历史证据解释未通过规则、实际值与期望值、ERROR/NOT_RUN 和证据缺口。输出“已知事实、待确认的业务条件、可人工检查的步骤、原页面下一步”；原因只能表达为待验证假设。解释历史运行不使用当前定义替换旧规则；需要新规则时明确结束该历史任务，由用户进入现有当前监控编辑器重新发起规则建议。

首批只使用现有公开证据。若真实题集表明缺少跨执行对比、执行环境分类或血缘关联，先由 Quality/Lineage Owner 提供明确的只读契约与适用范围，再立 Feature；Agent 不查源域 DAO、不执行排障 SQL、不自动启用/运行/通知。仅有资产分区摘要时，不能承诺完整字段血缘、全链路影响或根因定位。

只有 P0/P1 和当前真实验收达到门槛后，才以试点反馈选择深化本任务或改为 Dataset 问数口径澄清。两者不同时铺开。

## 4. 暂缓的建设与启动条件

| 方向 | 启动条件 |
|---|---|
| 文档 RAG / 业务术语检索 | 证明现有源域事实与 Skill 不能解决具体问题；确定文档 Owner、项目/对象 ACL、版本、撤权/删除和引用回链。检索片段不能代替实时授权事实 |
| 记忆巩固 M2 / 自学习 | 先核验 USER/GLOBAL 记忆与项目边界、用户可见/删除/更正、隐私和失效规则；不能将治理事实或模型建议自动学成真相 |
| 标准映射 / 敏感分类 | 由对应源域定义候选、人工确认及业务事实归属；新增长期跨域规则走 Product Decision。PD-005/006/007 仍是 PROPOSED，不能据其启用业务规则 |
| Agent 自动写入 / 后台自主治理 | 完整 command Owner、明确动作授权、幂等与不确定提交恢复、人工确认及审计契约；不能用聊天中的“确认”通用解锁所有写入口 |
| Multi-agent / Workflow | 单 Agent 在固定真实任务中持续失败，且拆分职责能够改善同题结果；不复制 turn、StateStore 或源业务状态机。长事务业务优先复用平台已有流程边界 |
| Python 开放或任意 MCP | 确定必要用户任务、执行隔离/网络/凭据边界与授权协议；Python 当前默认关闭，超时强杀不等于完整沙箱 |
| 框架迁移 | 在相同题集和权限/恢复/成本约束下，现框架边界有可复现阻塞，窄适配无法解决，替代方案对测有收益且迁移风险可接受 |

框架复评只在出现上述证据时启动。当前版本号来自仓库，不代表外部最新版本，也没有做新一轮性能排名或供应商能力推断。

## 5. 阶段完成标准

| 维度 | 完成标准 |
|---|---|
| 安全与事实 | 固定负向场景中，禁止工具零源域调用、零业务副作用；目标/权限/项目/版本检查有效；原始 SQL/样本/密钥不进入治理回复 |
| 任务可完成 | 对应真实 Golden Journey 完成；候选生成、带入、保存、运行分别有证据；失败/取消后不能提供可采纳候选 |
| 质量 | 标注事实支持、时点、单位、澄清充分性、候选合法性与下一步可执行性；专家复核，严重错误单列。引用、合法性与语义正确分别计分 |
| 运行治理 | 按实际模型调用/工具调用/执行段追溯配置与 Skill；未知 usage/来源时间诚实；关闭观测不改变安全守卫 |
| 体验与收益 | 比较同一任务人工耗时和 AI 辅助耗时；统计生成、合法候选、人工采纳/保存各自分母。没有客户端/审计证据不推断采纳率 |
| 回退 | 关闭建议后仍可用原编辑器；停止新推理不伪造完成；数据保存/调度回退继续由源域负责 |

推荐在实际试点题集内要求严重错误为 0 次，再讨论范围受限的开放；这只是验收样本门槛，不是对所有输入的零错误承诺。成功率、延迟和费用阈值应在真实部署基线采集后由任务 Owner 确定，不能用当前未测数据填目标达成率。

## 6. 契约协调与落地入口

现有文档存在需要显式协调的差异：Agent DOMAIN/REQUIREMENTS 仍把 Skill/记忆写成未接线，而当前源码和 ARCHITECTURE 已有运行路径；DOMAIN 的 SSE 断连仅停止订阅与后文“断连取消上游”、REQUIREMENTS 的断连停止推理表述冲突；Skill Service/SDK 适配与早期架构白名单表述也需核对当前守护测试。应由模块 Owner 按实际行为和现行产品契约修正文档，不能从历史计划推导要重新实现或更改断连语义。

本轮仅产出规划，不改这些长期契约。实施前按 [产品变更流程](../product/PRODUCT_CHANGE_PROCESS.md) 区分：既有约束修复、纯工程评测、用户行为变化、新跨域规则。中型产品变化建立正式 Feature 并确认实施范围；新增跨域规则另走 Decision。不得直接把本提案标为 APPROVED，或顺手改 F-009/F-010 为 SHIPPED。

可独立交付的 PR、工具矩阵、评测结构与验收用例见 [下一阶段实施清单](./AGENT_NEXT_STAGE_BACKLOG.md)。建议第一批先完成 **A0 契约与回归基线、A1 任务工具策略**，随后 A2/A3；真实模型验收始终保留为单独的未完成项。
