# Agent V22 规划：指标发布前的版本变更解释

日期：2026-10-08
分类：DOCS / PROPOSED
状态：规划提案，未批准实施；不改变当前 Product / Domain Contract。

后续记录：用户于 2026-10-08 确认规划并授权实施。本文保留提案快照；当前实施指令与具体首版覆盖边界以 IMPLEMENTING [F-032](../product/features/F-032-metric-change-review.md) 为准。

## 1. 推荐结论与当前基线

下一版建议服务指标设计与审核人员：在原指标详情中，解释“当前已保存草稿相对当前生效发布版本改了什么、已有验证证据指出什么问题、有哪些已登记关系需要人工核查”。交付可回源的变更说明与检查清单，用户仍在原流程修改、验证、发布。

当前已有标准匹配、批量字段辅助、来源映射、指标口径解释、定义草稿及 J2 原页面交接；V20 补齐原会话只读回看，V21 修复候选失效与停止恢复。2026-10-08 规划核对时，[V21 PR #354](https://github.com/gitfortian/data-ops/pull/354) 的 Product Guard / Architecture Checks 均成功，PR 仍 OPEN、未合并。后续开发从合并后的 main 新建分支，不在旧 PR 中叠加本版实现。

真实模型、登录态、源保存/发布和 J2 全程验收按用户要求继续 PENDING。本规划不要求现在提供环境，也不据工程检查宣称业务收益已达成。

## 3. 与现行合同及历史路线的关系

当前依据为 ACCEPTED [PD-002](../product/decisions/PD-002-governed-consumption-contract.md)、[PD-003](../product/decisions/PD-003-business-semantic-metric-contract.md)，APPROVED [F-005](../product/features/F-005-business-semantic-metric-productization.md)，以及 IMPLEMENTING F-025/F-027/F-029/F-031。它们允许原专业路径及事实复用，不等于已经批准本版新的 AI 输入和交付行为。

- [F-027](../product/features/F-027-metric-version-review.md) 已有精确版本解释、原 diff 和治理证据展示。本版增量是**把版本对及获授权治理事实作为受控上下文，生成引用可核对的变更说明**，不重新实现版本列表或发布面板。
- [F-025](../product/features/F-025-skill-metric-caliber.md) 的当前解释投影明确不输出校验和发布状态。不能直接给旧场景塞入新事实；立项时需独立 Feature 冻结新场景及最小源域投影，旧解释与业务说明采纳行为保持原合同。
- [F-031](../product/features/F-031-agent-scenario-history.md) 的历史卡保持只读。本版结果也只供阅读，不增加历史候选带入、未保存表单恢复或自动源调用。
- [AI 总纲第 11 节](AI_MASTER_PLAN.md#11-建议的后续路线先业务深度再覆盖与主动化) 曾把 V22 列为“告警/事件主动检查建议”。这是未批准的候选编号，且总纲当时列出的首批场景已有后续工程实现。本规划明确调整候选顺序：先深化现有指标任务；主动化另行立项，不能依据旧编号自动启用调度、通知或自主执行。

本提案不新增一级入口、默认跨域路径、生命周期或 Truth Owner；预计沿用现有 PD。若立项后出现这些变化，先按 [Product Change Process](../product/PRODUCT_CHANGE_PROCESS.md) 完成适用的产品决策。

## 4. 首版边界与用户交付

### 固定输入

- 仅一个当前项目内的已有指标；以**已保存当前草稿版本**为对比版本，以读取时的 **active published version** 为基准。固定双方 version ID / versionNo / snapshot digest 和 publication event identity。
- 用户可填最多 512 UTF-16 units 的核对重点；口述背景不能改变指标、版本、权限或事实。
- 未保存编辑不参与比较；没有 active publication 时明确提示“暂无生效发布版本可比较”，沿用单版本解释/首次发布流程，不猜测一个历史基准。
- 双方相同版本或白名单定义无差异时显示确定性说明，不为“无变化”自动调用模型。任意历史版本对、多指标批量和跨指标比较不纳入首版。

### 用户看到的结果

1. **明确的版本对与原差异。** 以源域白名单定义生成确定性差异；保留 before/after、缺失值与引用版本。公式、限定条件和组成 token 不靠模型重写。
2. **AI 变更说明。** 至多 5 项，每项至多 512 units，引用本次实际差异或事实 key。引用标签和值由服务端事实重新装配，不能由模型生成对象 ID、数值或链接。
3. **发布前证据核对。** 展示对比草稿精确版本的现有 Validation 和 readiness，区分未验证、验证失败、provider 不可用及读取禁止；仅解释已有结果，不触发新的 Validation，也不把 readiness 读取变为发布授权。
4. **已知关系与人工检查。** 分开呈现依赖健康、直接血缘、声明引用和实际消费覆盖；说明读取时点、版本未知及范围限制。关系存在仅表示需要核查，不证明计算结果已经改变或消费者将受损。检查步骤至多 5 项、待确认问题至多 3 项，每项至多 512 units。

结果不生成可直接执行的修复命令、公式替换或“允许发布”决定。页面下一步复用原编辑、版本差异、验证、影响及消费入口；只有源域已有稳定映射才给消费回链。

## 5. 事实、授权与失败约束

- 权限及当前项目来自服务端可信主体。源域公共投影在执行线程重新检查权限；不能因已有 Controller 注解就假设 Agent 内部调用已获授权。无 Metric READ 时不得读取或泄露对象/版本是否存在。
- 两份不可变定义与当前治理/关系事实分开。当前依赖状态、今日名称、当前验证和发布指针不能补写进历史快照；ID 本身不证明业务含义。
- 准备及交付前核对当前草稿、active publication identity、双方 digest、Skill 活版本和权限。任一漂移使本次说明不能继续作为当前发布前核对结果；保留历史含义并要求用户显式重新准备，不自动重跑。
- 组合读取不承诺跨域原子快照。每类事实保留自身 evidence identity、读取时点与覆盖范围；变化无法核对时返回缺口。证据身份/结果用于一致性核对，不能只比较每次都会变化的读取时间。
- 保留 READY / EMPTY / UNAVAILABLE / FORBIDDEN / NOT_APPLICABLE 的源含义。非 READY 分区只输出固定状态及下一步，不向模型发送原异常、连接信息、执行 SQL 或数据行。历史未知版本不升级为精确引用。
- 输入预算在源读取/投影边界生效。双方复用现有每份快照 65536、单事实 4096、事实总计 16000 units 的上限；新场景另设总上下文预算，不把双份上限直接当作模型可承受量。公式/定义超限拒绝解释；关系清单可有界分页并明确“仅所示范围”，禁止先无界读取再截断冒充有界能力。具体分区上限由实施 Feature 固定。
- 不新增取数、SQL、业务写工具或依赖递归遍历。停止/断线/未知终态继续复用原精确轮次核对；修改输入、切换对象/项目/版本/权限立即隔离旧回调。场景问题清单是完成轮交付，用户补充后明确开新轮，沿用现有规则。
- 结果与原会话都展示生成时依据；只有唯一关联已完成轮及完整新目标一致的历史结果才可呈现结构化只读交付。新场景必须显式扩展 parser/目标比较，不能套用旧场景 JSON 猜配。

## 6. 已有实现、最小缺口与开发切片

| 能力 / 证据 | 已有部分 | 本版必要增量 |
|---|---|---|
| `MetricExplanationQueryApi` / Adapter | 授权当前/历史版本，白名单事实及 digest；不含治理状态 | 复用快照事实；提供源域拥有的新场景只读上下文，不修改旧接口语义 |
| `MetricVersionComparisonDrawer` | 原详情已有两份快照的确定性字段对比 | AI 使用服务端白名单差异，不能信任客户端提交的 diff；与原展示核对一致 |
| `MetricGovernancePanel` / 原 publication、validation 读取 | 精确版本验证、readiness、active publication 和显式命令 | 在只读边界核验身份和版本，明确证据缺失，不让 Agent 调用命令 |
| `MetricImpactContextService` | 分开组合依赖、depth=1 血缘、声明引用及 observed provider | 复用 owning facts；审查每个内部读取的授权、有界性和异常投影。现有完整 impact 返回不等于可直接送模型的安全投影 |
| scoped Skill / 原场景执行与回看 | 持久化轮次、结构化输出、源复核、精确停止和只读历史关联 | 新场景方法、最小事实协议及结果 schema；不迁移 SDK 或开启资源/工具自动加载 |

建议一个独立 PRODUCT PR，按以下顺序完成，所有切片共同验收：

1. **产品与源域投影。** 新建并批准 Feature，更新 Agent/Metric 必要契约；实现或复用授权、有界、只读上下文与漂移复核。若某关系 provider 没有安全有界读取，保留真实覆盖缺口和原页面出口，不顺带补齐整个关系模块。
2. **Skill 与原详情交付。** 固定新目标、输入/输出白名单和事实引用；沿用原执行底座；在原版本/治理上下文显式生成、阅读、返回源步骤，补原会话只读回看。
3. **反例与交付证据。** 完成下表工程回归、类型/构建、架构与 Product Guard；提交独立 PR 等用户手动合并。真实模型题集和登录态证据继续单独 PENDING。

依赖方向沿用 `Agent runtime → toolset → gateway → metric.api`，Metric 内部复用自己的版本、验证、发布与影响边界；源域不依赖 Agent。不新增业务表、长期建议库或跨域任务状态机。

## 7. 计划验收矩阵

以下均为**待执行验收项**，不是本次规划已通过的测试。

| 编号 | 场景 | 必须得到的结果 |
|---|---|---|
| MR01 | ATOMIC / DERIVED / COMPOSITE 的发布版本与已保存草稿 | 版本对、公式/限定/组成差异和精确引用一致，AI 说明能回源 |
| MR02 | 首次发布、相同版本、白名单无变化 | 不猜历史基准；无差异不调用模型；原路径可继续 |
| MR03 | 有未保存编辑 | 不把表单草稿当已保存快照；明确先处理编辑 |
| MR04 | 旧版本验证通过，当前草稿未验证/失败 | 不借用旧通过结果；原验证/发布仍显式执行 |
| MR05 | 声明引用、depth=1 血缘、未知版本、无 observed provider | 类别及范围独立，不宣称真实调用、完整影响或零风险 |
| MR06 | provider 失败/撤权、跨项目、账号权限变化 | 固定降级，无敏感载荷；禁止读取在授权校验之前发生 |
| MR07 | 当前草稿更新、发布切换/撤回、Skill 更新、迟到回调 | 当前说明失效；不接纳旧结果或自动生成新轮 |
| MR08 | 缺失/损坏/超限快照、超量关系、未知事实引用、重复回执 | 拒绝不可信交付或明确有界缺口，不截断定义后解释 |
| MR09 | 断线、停止完成竞态、未知状态、重复点击、原会话刷新 | 精确轮次核对与唯一历史关联成立，无重复或误停 |
| MR10 | 读取/生成/回看全流程 | 不触发源保存、Validation、publish/withdraw 或取数；原命令权限与门禁保持 |
| MR11 | 真实登录用户与真实模型，人工评审三个指标类型 | 记录误解/遗漏/检查项有效性、完整核对耗时、调用成本及原证据；按用户要求 PENDING |
| MR12 | 真实 J2 中发布后编辑再核对、人工验证和发布 | 旧发布与已保存下游引用不漂移；源审计及真实结果一致；按用户要求 PENDING |

工程测试保护事实协议、权限、漂移和生命周期；MR11/MR12 才能证明真实任务行为。收益基线尚未采集，不预先声称准确率、节省时间或放量条件已达成。

## 8. 后续候选顺序

本版之后优先依据真实错题选择下一项：问数字段/时间/口径澄清、两次质量执行比较、或有限影响解释扩展。分别需要 Dataset 授权与稳定引用、Quality 历史冻结证据、关系覆盖及源 Owner 合同；不按模块“不完整”自动补齐。

团队私有 Skill、主动告警建议、后台调度与自动业务动作保留独立提案。当前工程可继续推进获批范围；扩大任务覆盖、主动化和效果结论需适用产品合同及真实验收证据。
