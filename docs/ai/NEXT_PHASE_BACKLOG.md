## 2. Golden E2E 与负向场景

| 场景 | 操作链路 | 必须观察的结果 |
|---|---|---|
| G1 可信资产解读 | 真实用户 → 资产详情 → AI 解读 → 证据卡 → 原分区 | 同一对象、项目、Owner、时点与五态；未知来源时间不伪造 |
| G2 历史质量解释 | 运行 E1 → 修改当前规则 → 解读 E1 | 历史状态/数值保持 E1；解释区分 NOT_PASSED/ERROR/NOT_RUN；当前建议单独读取当前定义 |
| G3 规则建议闭环 | 注册物理表/现有监控 → 当前字段与模板 → 澄清业务约束 → 合法候选 → 带入 → 人工保存 → 有权限时显式运行 | 生成/带入零业务写；保存影响可见；原 admission 与冻结计划；执行结果可回链 |
| G4 描述辅助 | 资产快照编辑 → 候选与旧值对比 → 带入 → 人工保存 → 回读审计 | 只修改台账描述；不清空名称/入口，不写源表注释，不编造用途 |
| G5 权限与撤权 | 只读用户、可编辑用户、无运行权限用户分别操作；生成过程中撤销项目/权限 | 源读取/保存/运行分别拒绝；生成权限不能替代保存/运行权限 |
| G6 并发修改 | A 生成建议，B 修改相同定义并保存，A 再保存 | 原子比较失败并要求重读；不覆盖 B；规则/Settings 子项修改也能识别 |
| G7 字段/目标漂移 | 生成后删字段/变类型/取消注册/换表/切 Project | 校验拒绝或使候选失效；不能沿用旧证据静默保存 |
| G8 非法输出与注入 | 注释内恶意指令、假模板/引用、SQL、异常阈值、HTML/外链 | 服务端校验拒绝、内容有界；合法事实仍按数据读取；无越权或业务执行 |
| G9 来源故障 | provider 未装配/超时/无权限/确认无数据 | 状态诚实；部分证据可用时回答有范围；没有字段就不给可采纳规则 |
| G10 重复与切换 | 重复点击带入、重新生成、HITL 恢复、切会话/目标 | 不重复追加同一候选；恢复不能伪造目标；旧候选不可作用于新对象 |
| G11 取消与重启 | 排队/生成时取消、SSE 断连、进程重启 | 原轮次语义保持；不隐藏写入；INTERRUPTED 不伪称断点续跑；回放不能触发采纳 |
| G12 自动运行影响 | 已启用定时监控采纳新规则，检查保存前提示与下一次触发 | 新增候选默认不启用；用户决定后的变更有明确影响；计划冻结与历史结果不变 |

证据应记录环境版本/提交、用户角色与 Project、对象 identity、执行时点、模型与有效配置指纹、允许的来源快照、trace、截图或录屏、期望/实际结果和失败原因。禁止记录密钥、连接凭据、原始敏感样本；来源 SQL 不进入模型回复。自动化与真实环境证据分目录标识，不混算通过率。

## 3. 评测与发布门槛

| 检查 | 门槛/规则 | 证据 |
|---|---|---|
| 身份、安全与隐式动作 | 每个正负样本正确；无越权、秘密泄露、隐藏保存/执行 | 源域拒绝、审计、trace 与登录态走查 |
| 可带入候选 | 每条均执行服务端定义校验；非法项不可带入；并发更新不降级 | Policy/集成测试 + G3/G6/G7/G8 |
| 事实支持 | 试点候选目标 ≥95%；报样本/分母/失败类型，关键误导样本逐项修复 | 专家标注与固定题集；模型 judge 仅辅助 |
| 生成有效性 | 首次生成的规则校验通过率候选目标 ≥95%；区分自纠后通过与主动澄清 | 校验报告；被拒绝样本不能从分母消失 |
| 任务价值 | 中位耗时减少候选目标 ≥30%；记录人工基线和试点同类任务 | 用户实际任务；带入/保存/修改率作为辅助 |
| 成本与延迟 | N0/N8 实测后冻结 SLO；配置/模型变更复跑 | p50/p95、token、超时、取消与实际费用，unknown 不计零 |
| 回退 | 关闭新增服务端能力及 UI 入口可恢复普通编辑；已保存事实保留 | 操作记录与回退演练 |

首版缺真实 E2E 时可以记录开发通过和环境阻塞，但不能将对应 Feature 宣布为 SHIPPED。新增能力按独立批准范围灰度，质量与描述不互相拖住发布。

## 4. 投入估算与依赖风险

以下是基于当前源码的工作量区间，不是排期承诺；按 2 后端、1 前端、0.5 QA，并有领域 Owner 持续参与估算。范围冻结、模型环境就绪后，建议预留 **4～6 周** 完成该阶段开发、联调和试点；单人推进应按总工作量与外部依赖重新排期。

| 工作组 | 粗估投入（人日） | 主要不确定性 |

| 证据/质量读取/校验 N2/N3 | 7～11 | 当前证据投影结构、字段类型与模板语义覆盖 |

| 描述辅助 N7 | 3～5 | 原请求部分字段兼容、描述长度、源事实缺口 |

## 5. 首个开发批次

立项通过后第一批交付 N2/N3 的最小纵向切片：**一张已注册物理表 → 授权字段/模板 → 生成一条非空规则候选 → Quality 无副作用校验 → 带依据展示**。先证明建议合法且无隐式写入，再接 N4/N6 的保存链路；阈值没有业务证据就请求用户确认。

该切片复用 AgentScope 与原源域角色，不引入新 Maven module。完成后用 G3/G5/G8/G9 形成第一份真实证据，决定是否扩展到唯一性、范围、枚举和描述辅助。
