# Agent 第七版交付说明

日期：2026-10-07

实施权威：[F-015](../product/features/F-015-agent-session-follow.md)，范围见 [第七版计划](./AGENT_V7_PLAN.md)。工程交付与真实验收分开，Feature 保持 IMPLEMENTING。

## 用户现在能做什么

重新打开排队或推理中的会话后，原页面自动检查状态。结果完成或出现澄清问题时，会重新加载原历史与最新任务，用户可以继续追问或回答原问题，无需反复刷新。跟随只读取状态，不启动推理、工具调用或全文重放。

有 `agent:chat:run` 权限的用户可点击“停止本轮”，停止当时看到的排队/推理轮。请求固定原 turnId，晚到或重复请求不会选择同会话的新轮。请求处理后页面重新读取真实状态；若本轮已经完成或转为待答，以实际读取为准，不直接报已停止。

自动检查每次完成后间隔 3 秒，最多 20 次。隐藏页面暂停调度，重新可见可以立即检查但不重置预算；失败或达到上限则保留历史并停止自动检查，可手动刷新重新建立有界检查。切换、新建、卸载及主动停止后的旧响应不能覆盖当前会话。

## 实现与边界

- 原 `continuation`/history API、StateStore、HITL、预算和受控回链继续复用；局部 `useSessionFollow` 只管理读取调度。完成/待答/轮次身份变化时停止本轮检查，再走原会话恢复。
- 兼容新增 `POST /api/v1/agent/chat/turns/{turnId}/cancel`，使用 CHAT_RUN 与 PROJECT_REQUIRED，先验证轮次及会话的本人/当前项目。响应是命令处理应答，不是取消终态。
- 排队轮精确 CAS 到 CANCELLED，与本机 `claimAndRegister` 使用同一锁；运行轮使用原 finalizer → dispose 顺序与 Executor 收尾。终态幂等无操作，WAITING_INPUT 明确拒绝，不删除 pending 或预算。
- 停止未确认时明确禁止继续并要求刷新，页面不能从网络失败推断执行失败，也不能从 HTTP 成功推断 CANCELLED。原会话级停止接口保持兼容。

继续使用 AgentScope Java 2.0.2，无新业务状态、数据库、配置、导航、后台任务、通知或源写工具。源定义/权限仍由 Quality/Asset/Dataset/Security 拥有；依赖矩阵与走廊不变。

## 使用与限制

打开原会话后检查任务范围与最近状态。页面可见时自动等待结果；活动轮也可手动刷新，或在有权限时停止本轮。自动检查暂停后点击“刷新会话”核对，历史证据仍只供回看，追问重新经过授权读取。

等待澄清时请回答原问题或新建会话，本版不新增取消 pending 转移。多节点运行句柄路由不在本版：若运行句柄不在处理请求的节点，不假装已停止，重新读取仍可能显示运行中。进程崩溃仍使用 INTERRUPTED，不能断点续跑。

本版没有补齐消息与轮次的完整身份关联，因此继续不自动重放活动全文。隐藏暂停不代表停止后台执行，停止自动检查也不取消推理；3 秒是读取间隔，不是结果延迟承诺。跨标签并发结果可能在读取后变化，提交/应答/取消仍由服务端裁决。
