# AI 治理辅助第二版交付

日期：2026-10-05。产品契约：[F-010](../product/features/F-010-ai-governance-suggestions.md)，状态 IMPLEMENTING。用户已授权代码、CI、提交 PR 和合并；真实模型与登录态产品验收单独待完成。

## 用户可用能力

现有质量监控编辑器的规则区域增加“AI 建议规则”：输入业务约束，Agent 读取当前已注册物理表字段与内置模板，必要时沿用现有 HITL 澄清。最多五条候选经 Quality 源域校验，逐条带入未保存表单，新增规则默认不启用。人工核对后点击原“保存配置”；原调度、任务版本同步与运行入口仍负责后续行为。

资产详情快照编辑增加“AI 建议台账描述”：生成、查看当前描述与候选、带入 description，再人工保存。名称、Owner、访问入口、源表注释与治理状态不由建议修改。来源消失不提供可采纳候选。

实际聊天页面及候选面板显示服务器证据卡，含来源、状态、读取时间、源更新时间和内部回链。`verify_governance_facts` 按本轮证据 ID 与字段路径复制服务器已读取的标量值；用户可核对关键状态和数值。引用校验与事实卡不能证明全部自然语言语义正确，专家评测仍待执行。

## 实现与保护

- 保留 AgentScope Java 2.0.2、原 StateStore、轮次队列、SSE、取消、HITL 与执行线程身份/Project 守卫。Agent 新工具只有当前监控读取、规则候选校验、描述候选生成和事实值核验，没有治理写 API。
- 候选结构、模板、字段、类型、百分比/行数/区间/枚举参数和存储精度由源域校验。禁止 CUSTOM_SQL 与未知参数；候选尝试最多三次（首轮加两次修正）。监控上下文最多 200 个字段、12000 字符，截断明确标识。
- 带入规则时重新核验字段和监控定义；带前置条件的人工保存再次绕过 Datasource 发现缓存读取当前字段。源域事务内锁定当前对象并比较定义指纹，拒绝旧编辑状态。Quality 指纹涵盖 Monitor、Rules、Settings，排除执行结果和 nextRunTime；Asset 指纹涵盖名称、描述与入口，条件写只更新快照字段。
- 用户切换对象、取消或组件卸载后，迟到结果不再生效；同一候选不能重复带入；失败/中断轮次不暴露采纳按钮。候选不写表单外的业务，页面保留原保存权限与服务端命令校验。
- 显式治理目标轮次禁用长期记忆召回及提取；普通轮次调用治理读取/候选工具后也不提取记忆。历史聊天不能代替当前授权证据。候选正文由服务器生成，模型自称已保存/已启用不发布，伪造保留 JSON 块被移除；验证结果写回同一 StateStore 消息。
- 首次推理通过已有 TURN_SUMMARY 观测保存 `effective-config`：框架/候选契约版本、模型、启动迭代与超时/重试设置、建议开关、实际提示词和工具契约哈希。只保存哈希和非敏感设置，不记录模型密钥、端点或提示词原文。动态 LLM 超时仍以每次调用的原观测为准。

## 配置与使用

AI 全部启动配置位于 `data-ops-boot/src/main/resources/application-ai.yaml`，由主 application 引入。使用环境变量配置 `YAK_AGENT_ENABLED=true`、模型名称、端点及密钥；密钥只在环境变量中设置。新增 `YAK_AGENT_SUGGESTIONS_ENABLED` 对应 `yak.agent.suggestions.enabled`，默认 true；关闭后源域不会生成建议。

需要 `agent:chat:run` 和相应资产/质量读取权限。规则上下文还需要模板与数据源读取权限；带入与保存需要原资产/监控编辑权限；显式运行需要原运行权限。生成权限不授予保存或运行权限。

原更新 API 兼容不带指纹的旧调用；本次接入的编辑器保存携带服务器前置条件。物理库 DDL 与平台定义无法跨库原子提交：带入/保存前会重新读取，检查后继续发生的外部 DDL 仍由后续真实执行报告。元数据读取失败会阻止带前置条件的质量保存。
