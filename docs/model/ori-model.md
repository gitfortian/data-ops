# 数据平台数仓建模需求规格说明书

## 1. 功能概述

本模块面向数据平台数仓建模场景，提供可视化建模能力，涵盖数据模型管理、模型加工任务管理、正向与逆向建模、元数据驱动建模及模型资产统一视图等核心功能，支撑业务人员与开发人员高效完成数仓模型的设计、构建与治理。


## 2. 功能需求详述

### 2.1 可视化建模

**需求描述：**
提供图形化界面，支持用户以拖拽、配置等方式在线完成数据模型的设计与构建。

**功能要点：**

| 序号 | 功能项 | 说明 |
|------|--------|------|
| 1 | 模型在线编辑 | 支持数据模型的在线创建、删除、查询操作 |
| 2 | 实体对象编辑 | 支持对模型关联的实体对象及其属性信息进行编辑与维护 |
| 3 | 来源数据映射配置 | 支持在线配置物理模型的来源数据映射关系 |
| 4 | 逻辑模型转物理模型 | 逻辑模型配置完成后，系统自动生成对应的物理模型 |


### 2.2 元数据驱动建模

**需求描述：**
系统通过对接数据库元数据信息，自动完成物理模型的生成，减少人工录入成本。

**功能要点：**

| 序号 | 功能项 | 说明 |
|------|--------|------|
| 1 | 元数据自动加载 | 从目标数据库读取元数据信息（表结构、字段类型、约束等） |
| 2 | 物理模型自动生成 | 基于加载的元数据自动生成对应的物理模型 |


### 2.3 源端系统集成与变更感知

**需求描述：**
与源端各业务系统建立集成机制，支持自动生成建库脚本，并对源端表结构变更进行动态感知与提示。

**功能要点：**

| 序号 | 功能项 | 说明 |
|------|--------|------|
| 1 | 建库脚本自动生成 | 根据模型定义自动生成数据库建库（DDL）脚本 |
| 2 | 表结构变更动态感知 | 实时或定时监测源端业务系统表结构变化，发现变更时及时向用户发出提示 |
| 3 | 变更同步建议 | 源端表结构发生变更后，提示并引导用户对关联模型进行同步调整 |


### 2.4 模型资产统一视图

**需求描述：**
构建全域数据模型的集中化管理视图，实现模型资产的统一管理、全局可视与多维度检索。

**功能要点：**

| 序号 | 功能项 | 说明 |
|------|--------|------|
| 1 | 全域模型集中化视图 | 提供统一视图展示全域范围内的全部数据模型 |
| 2 | 模型资产统一管理 | 实现模型资产（表结构、关联关系、血缘链路等）的集中管理与维护 |
| 3 | 多维度统一视图 | 支持从业务域、数据域、主题、层级等多个维度查看和筛选模型 |
| 4 | 关系可视化 | 支持表结构关系、模型间关联关系、数据血缘链路的图形化展示 |


### 2.5 正向建模与逆向建模

**需求描述：**
同时支持正向建模与逆向建模两种方式，兼顾新模型构建与存量模型治理场景。

**功能要点：**

| 序号 | 建模方式 | 说明 | 适用场景 |
|------|----------|------|----------|
| 1 | 正向建模 | 从业务需求出发，自上而下进行模型设计（概念模型 → 逻辑模型 → 物理模型） | 新模型构建 |
| 2 | 逆向建模 | 解析现有数据库表结构，自动识别并生成数据模型 | 存量系统模型梳理与治理 |


## 3. 功能需求汇总矩阵

| 功能模块 | 核心能力 | 优先级建议 |
|----------|----------|------------|
| 可视化建模 | 在线编辑、映射配置、逻辑→物理自动转换 | 高 |
| 元数据驱动建模 | 元数据加载、物理模型自动生成 | 高 |
| 源端集成与变更感知 | 建库脚本生成、表结构变更动态提示 | 中 |
| 模型资产统一视图 | 集中化管理、多维视图、血缘/关系可视化 | 中 |
| 正向建模 | 业务需求驱动的模型设计流程 | 高 |
| 逆向建模 | 存量库表解析与模型生成 | 中 |


## 4. 术语释义

| 术语 | 定义 |
|------|------|
| 逻辑模型 | 从业务视角描述数据实体、属性及实体间关系，与具体数据库实现无关 |
| 物理模型 | 面向具体数据库实现的模型定义，包含表结构、字段类型、索引、约束等信息 |
| 元数据 | 描述数据的数据，本需求中特指数据库中表结构、字段、约束等结构性元数据 |
| 正向建模 | 从业务需求出发，按“概念模型→逻辑模型→物理模型”的顺序逐步细化的建模方法 |
| 逆向建模 | 从现有数据库表结构出发，反向解析并生成数据模型的方法 |
| 数据血缘 | 描述数据从源端产生、经过加工处理、到最终消费的全链路流转关系 |
| 建库脚本 | 用于在目标数据库中创建表结构的DDL（数据定义语言）脚本 |


## 5. 非功能性需求建议

| 维度 | 建议要求 |
|------|----------|
| 性能 | 元数据加载与模型生成操作响应时间 ≤ 3秒（常规规模表结构）；大规模批量建模任务支持异步执行 |
| 可用性 | 可视化建模界面操作直观，支持撤销/重做、操作校验提示；血缘关系图谱支持流畅缩放与拖拽 |
| 兼容性 | 至少适配主流关系型数据库（如 MySQL、Oracle、PostgreSQL、Hive 等）的元数据读取与DDL生成 |
| 扩展性 | 支持接入新的数据源类型；模型元数据接口开放，便于与数据资产平台、数据质量平台等系统集成 |
| 安全性 | 模型编辑操作需记录审计日志；支持按角色控制模型查看、编辑、删除权限 |
