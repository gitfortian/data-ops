### 一、背景

我在做数据平台的数据建模功能。当前问题是：所有模型新建都需要从零手填全部字段信息，重复劳动多、效率低、跨层不一致、业务人员门槛高、模型无法沉淀复用。

我期望的优化方向是：**模型不是被"创建"出来的，而是从上游"派生"出来的**，按数据层级逐层继承，每层只做本层增量。

请你基于以下已有方案，**修正计划或重新规划最新内容**，输出一份更完善的需求文档 + 设计方案。

### 二、最重要的一条原则

**所有功能必须是业务闭环，而不是一个个单独的功能点。**

具体要求：
- 每个功能都要能回答"谁在什么场景下用它、用完产出什么、产出如何被下游消费"
- 模块之间要形成闭环链路，而不是孤立的能力堆砌
- 例如：数据标准 → 被业务过程引用 → 被字段映射引用 → 被建模引用 → 产出模型 → 回流为资产 → 反哺标准优化，这是一条闭环
- 设计时先画闭环链路，再拆功能点；不能只列功能清单
- 如果一个功能无法嵌入任何闭环，要么砍掉，要么说明它属于哪个闭环的哪一环

### 三、已有方案的核心内容

**1. 分层派生建模**
```
ODS  ← 源表结构复制 + 技术字段
DWD  ← 依赖 ODS，做清洗/规范化/退化
DWS  ← 依赖 DWD，选维度 + 度量
ADS  ← 依赖 DWS/指标，面向应用反推
```

**2. 数仓分层模型管理**
定义每层对应哪个库、哪个数据源、什么命名规范、默认分区、存储格式、生命周期，建模时自动定位。

**3. 业务域与业务过程管理**
- 业务域：按主题划分（交易、用户、商品等），挂载业务过程
- 业务过程：业务动作（下单、支付、退款等），关联标准字段集、源表/上游模型、常用维度度量
- 作为建模主线，贯穿各层

**4. 数据标准管理**
独立成全局规范层，在业务过程之上，包含：命名、类型、码值、单位、口径、安全。为业务过程和字段提供约束与默认值。

**5. 标准字段集**
业务过程下的标准字段，分三种角色：业务过程、维度、度量。类型/单位/口径/码值/安全均引用数据标准，不自由填写。

**6. 字段分层映射**
标准字段在各层的落地映射，记录该层字段名、类型、来源字段、转换表达式。是逐层继承的载体，血缘自动建立。

**7. 关键支撑能力**
字段级血缘、元数据管理、映射可视化编辑、规则引擎、变更影响分析。

**8. 建模交互流程**
```
选业务域 → 选业务过程
     ↓
自动带出标准字段集 + 关联源表 + 已建各层模型
     ↓
选数据层级（自动定位库/数据源/规范）
     ↓
自动带出该层字段映射（字段名/类型/转换预填）
     ↓
用户勾选/增删/调整
     ↓
校验 → 生成模型 + 血缘
```

**9. 整体架构**
```
数据标准（全局规范层）
        ↓ 被引用
业务域 / 业务过程 / 标准字段集（业务语义层）
        ↓ 被引用
数仓分层管理（技术配置层）
        ↓ 被引用
字段分层映射（逐层继承载体）
        ↓
分层派生建模（操作层）
        ↓ 支撑
血缘 / 元数据 / 规则引擎
```

**10. 核心原则**
- 数据标准定义"规矩"
- 业务过程在规矩下定义"要什么"
- 字段分层映射在规矩下定义"怎么落"
- 建模时逐层派生，只做本层增量

**11. 落地路线**
- 第一阶段：业务域 + 业务过程 + 标准字段集 + 分层管理；ODS 反向生成 + DWD 继承
- 第二阶段：数据标准（命名、类型先行）；字段分层映射；字段级血缘
- 第三阶段：码值/单位/口径标准；DWS/ADS 建模；变更影响分析
- 第四阶段：安全标准；AI 辅助建模
