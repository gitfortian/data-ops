# 02: 物理化状态回填（模型↔物理表对账）

**对应需求:** 模型工作台盘点 §6 缺失能力（P0）| 阶段: P0

**What to build:** 平台对目标库真实表**零感知**：DDL 仅生成不执行（决策 D3）、发布=元数据快照盖章、无任何"建表已执行/表已存在"回写，`ModelStatus` 无 landed 类状态——"PUBLISHED"与物理世界可能长期背离且不可见。本单**不内嵌执行器**（盘点 §4 裁决：物理化闭环留待 DEV 承接），走"检测感知 + 人工确认回填"：模型已绑定数据源时，经 `DataSourceCatalogReader` 只读 introspection 对账"目标表是否存在/列数是否一致"，产出落地状态徽标与最近对账时间。

**模块归属:** **跨模块**——modeling（对账服务+详情页徽标） + datasource（只读 SPI，现成）

**Blocked by:** 无；与 04（source-diff 界面）共用对账展示面，建议 04 先行或合流设计

**硬性约束(不可打破):** 遵守 [dev-plan.md《硬性开发约束》](../dev-plan.md)；**严禁新增任何 DDL 执行通道**（D3 决策不破）；对账只读、幂等、可失败降级（数据源不可达时显示"未知"而非报错阻断）；落地状态不侵入 `ModelStatus` 三态机，独立字段/派生标记。

- [ ] 先立裁决：盘点结论落 05 乱象清单（"已发布≠已建表"的可见性方案定稿）
- [ ] 后端：模型级对账接口（表存在性+列数一致性+对账时间），只读经 datasource SPI
- [ ] 前端：详情页/列表出"物理表：存在/不一致/未对账/未知"徽标与手动"立即对账"
- [ ] 资产状态条（M2-1 七格）是否增列"已落地"一并裁决并落文档
- [ ] 单测：数据源不可达、表不存在、列数漂移三分支
