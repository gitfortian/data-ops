# 09: 发布自动血缘登记

**对应需求:** 模型工作台盘点 §6 缺失能力（P3）| 阶段: P3

**What to build:** 现状血缘登记是"用户确认后"引导式，仅 graph 查询时自动触发登记（M-3 修复口径）。发布动作=元数据盖章时刻，正是登记时机：`ModelVersionService` 发布成功（含 01 单审批回调路径）后自动调 `ModelingLineageRegistrationService` 幂等登记表/列资产，去掉手工步骤。登记失败不阻断发布（fail-open，血缘 Tab 可手动重登）。

**模块归属:** modeling（+ 血缘域现有 upsert 接口，无契约改动）

**Blocked by:** 无；若 01 后合入，需覆盖"审批回调发布"路径

**Status:** backlog(待排期)

**硬性约束(不可打破):** 遵守 [dev-plan.md《硬性开发约束》](../dev-plan.md)；复用现有幂等 upsert，不新建登记通道；血缘键沿用 `PhysicalTableAssetKey` 归一（防裂节点，见 MDM↔血缘复用契约）；登记异常只记日志+徽标提示，禁止回滚发布事务。

- [ ] 发布成功钩子触发自动登记（直发与审批回调两路径）
- [ ] 重复发布幂等：资产不重复、列变更增量更新
- [ ] 登记失败 fail-open 验证（血缘域不可用时发布仍成功）
- [ ] 血缘 Tab 文案从"登记"调整为"已自动登记/重新登记"
