## 真实样本验收步骤

使用当前项目有模型/标准读取和修改、Metric 读取和创建/修改/发布、Agent 运行与会话读取及消费访问权限的用户。由 Skill 管理人员导入并启用 standard-match、model-field-mapping、metric-caliber-explanation、metric-definition-draft 的已审阅材料。记录真实身份、项目、Skill 版本/摘要、模型配置标识及精确对象 ID；不要记录 API key。

1. 在真实 DWD 模型原编辑器选择 2–5 个字段，生成批量标准候选；保留各独立 session/turn ID。只采纳明确选择的 TYPE 引用，说明勾选后才覆盖该字段。未选择字段及字段名、类型、默认值不变。原 CAS 保存并回读。
2. 用原 model-field-mapping 核对来源字段映射，人工采纳与原保存回读。变更来源/项目/权限或晚响应时不能覆盖当前草稿。
3. 点击模型页“继续设计指标”，在原指标新建页明确“使用来源模型”；目标重新读取当前项目 DWD、业务域和过程，不以 URL 声明作为事实。模型无权/删除/跨项目/非 DWD 应失败而非预填。
4. 原子指标明确需求和来源模型，生成/审核定义草稿，确认无任意 SQL、仅来源字段。人工保存，进入保存回执对应详情。重复派生（所选原子上游+限定）与复合（明确选择非复合上游+结构 token）路径；依赖/结构/Skill 版本变化要拒绝旧候选。
5. 在详情选择历史版本并解释；说明只读，事实为该不可变快照。原版本差异、当前影响、当前验证/发布分别核对。编辑器当前版本说明采纳仍走原 expectedVersion 保存。
6. 在原详情对精确保存版本显式验证与发布，保留验证证据、发布事件、snapshotDigest；草稿/启用不等于发布。
7. 在真实 Dataset 原配置登记对已发布精确版本的引用。刷新指标消费引用，进入 canonical DATASET productKey；消费页重新判权限及可发现性。进入原 Dataset 查询，保留真实运行结果/审计与 Consumption 证据，再用回链返回指标详情复核原发布版本。
8. 核对未知版本、另一版本、API 未映射、无目标、provider 不可用、权限拒绝、批量部分失败、提交未知与关闭后晚回执：明确缺口，保留成功项与原轮，不重复提交、不声称执行成功。
