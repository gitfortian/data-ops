## 1. 状态口径：分离五个不能混淆的事实

- `MERGED`：可检索到 PR 已合入；不证明环境部署。
- `CI_RECORDED`：可定位工作流结果；不证明当前产物或用户验收，本台账未重新运行 CI。
- `STATIC_REVIEWED`：已核对当前默认分支源码/契约；不等于运行时已执行。
- `E2E_PASS`：相同构建的真实角色、项目、API、浏览器、审计和后端持久化证据齐全，且经 QA/Owner 签收。
- `BLOCKED_EVIDENCE` / `PENDING_RECHECK`：分别表示必要实测证据未归档或还未完成当前代码核对；**不推断已测试失败，也不伪称已通过**。

不能以 Issue Closed、脚本存在、Mock/Jest/CI、历史 R1/R2 成功或部署提交未知的环境数据替代当前 E2E。

## 3. Golden 真实环境阻塞解除条件（必须逐场景记录）

以下缺任一关键前提，不得标记 P0 Golden 验收 PASS：

1. **版本与部署身份**：记录待验 main SHA、构建流水线/后端 JAR/前端静态包 SHA-256、实际部署 commit、构建与部署的映射；无法确认则部署版本记 `UNKNOWN`。
2. **环境与身份**：专用可清理合成项目 A/B、隔离数据源与数据库；真实管理员、普通读写、受限/跨项目账号，以及独立 Consumer/API Key。记录脱敏角色、权限快照、Project ID，不存 Token/Cookie/原始 Key。
3. **实际消费正反例**：Dataset 真实 Query、Data Service 真实 Invoke、拒绝场景（无权、跨项目、无效/撤回 Key、IP 限制如适用）。应核对真实持久化 Source Success Audit、精确不可变 sourceVersion/revision、Consumer、Usage 与审计 ID；拒绝路径不得产生伪成功。
4. **浏览器与回链**：至少真实浏览器完成 Consumption → Dataset/Service → Asset/Producer → 原上下文往返，复核项目切换、403/404/500、成功 EMPTY、单 Provider 失联、刷新重试及旧请求竞争返回。
5. **故障恢复**：真实触发可恢复故障/拒绝再恢复，比较恢复前后实际成功 Usage/来源审计，保留精确版本；仅 HTTP 200 不构成证据链。
6. **R3～R8**：按既有工具和 R8 严格报告门禁归档输入/输出；缺真实运行报告就记 `BLOCKED_EVIDENCE`，不使用 Mock/Jest 输出替代。
