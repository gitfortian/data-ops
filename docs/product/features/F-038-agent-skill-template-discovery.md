# F-038 — 已交付 Skill 模板的页面发现与人工注册

Status: IMPLEMENTING
Product basis: 现有 Skill 管理及 F-023/F-024/F-025/F-028/F-032 场景合同。
需求来源：用户在技能列表为空时追问已开发的 Skill 在哪里；本切片补齐现有材料到管理页面的发现与注册路径。

## 用户、问题、能力与结果

User：Agent 使用者与技能管理员。Problem：仓库已有技能正文，但页面只列出 DB 已注册条目，空表无法解释材料位置与下一步。Capability：在原技能管理页面查看交付模板，并由管理员带入既有注册表单。Journey：技能管理 → 模板用途与登记状态 → 查看正文 → 管理员核对并明确注册 → 刷新原列表 → 原启停与编辑。Expected Outcome：无需翻查仓库、手工复制正文即可找到模板；没有注册的模板仍明确保持模板身份。

成功信号：管理员能找到场景对应模板并完成原注册路径；真实模型效果与业务收益继续沿原场景验收，不用模板数量或工程测试代替。

## 事实归属与复用

原 docs/ai/skills 正文与已有 register.json 生产模板材料；前端只消费构建时生成的只读副本。yak_agent_skill 仍是登记、版本及启停的唯一 Truth Owner；模板不被框架直接加载，不伪造运行版本或启用状态。复用原 READ/MANAGE、Project Space、注册/编辑/详情/启停、冲突与热生效路径。无新业务模块、一级导航、状态机、审批或注册库。

## 范围与失败

展示已有五份场景注册材料和三份治理方法候选；不声称真实模型验收已通过。只读用户可看正文，管理员在原表单核对并提交，原接口的“注册即启用”语义明确展示。已登记的同 ID 模板不可重复注册，不覆盖管理员编辑；仍可在已注册列表查看、编辑或启停。

模板标识由对应场景引用，带入登记时只读；名称、说明、正文与元数据可人工调整。自定义登记沿用原可填写标识的表单。

列表加载中或失败时登记状态保持未确认，禁止从模板发起登记；失败可重试，不把失败显示成“尚未注册”。空表明确显示当前项目暂无已注册技能以及模板下一步。模板切换或返回自定义注册时必须清掉旧表单值。缺 MANAGE、重复注册、列表刷新失败均沿原权限与冲突处理，不自动批量写入。

## 验收

空列表仍能发现八份材料；查看或带入表单零写入；显式保存才调用原注册接口并刷新。验证正文、固定 ID 和元数据与原材料一致，手工编辑被保留，已有同 ID 不覆盖，取消/切换不串值，只读无登记动作，加载失败状态区分，生成副本漂移被检查发现。既有编辑、启停、冲突及原场景回归须通过。真实模型验收继续按用户要求延后统一执行。

## 长正文在线编辑与阅读

用户与问题：技能管理员在窄弹窗的小输入框里难以核对长正文、Markdown 层级与代码/表格。原技能阅读者也需要完整排版与定位。能力与旅程：原模板预览/详情/注册/编辑入口 → 宽屏 Markdown 工作区 → 阅读或源码核对、标题目录定位 → 管理员编辑并实时预览 → 明确保存至原接口。成功信号是能阅读完整正文并核对编辑结果，不以字符数或模板数代替。

编辑区支持源码、分屏、预览，全屏切换、Markdown 语法着色、行号、查找与常用格式插入；基础信息置于独立侧栏。窄屏改为上下布局。模板和详情默认阅读，可切源码，长文标题目录定位在本阅读区内。开头 YAML front matter 只在阅读投影中折叠展示，不转换成管理字段、不修改源文。原 Markdown 字符串仍是保存载荷，预览/布局/格式切换不自动保存、执行正文或推理；显式格式操作才修改草稿。

复用现有 Monaco、marked、DOMPurify 与原表单/权限/版本冲突处理，无新增依赖、运行时事实或注册路径。技能文档预览静态净化，代码围栏按代码显示，不执行图表或 HTML 脚本，不自动加载远端资源。编辑器加载失败可重试或编辑原始源码，不隐藏现有草稿；取消或切模板仍清除未提交内容。

验收证据须覆盖长 Markdown 标题/列表/表格/代码与 YAML 展示、目录定位、模式/全屏切换不串值、原文回传（含换行/空格/front matter）、格式插入及撤销、原登记/编辑版本路径、只读不可修改以及预览脚本/远端资源隔离。真实模型与 J2 验收继续独立待办。
