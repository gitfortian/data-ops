# F-015 — 活动会话状态跟随与停止

Status: IMPLEMENTING
Approval: 用户于 2026-10-07 指令“继续规划下一步迭代规划 并开始实施”，授权第七版规划后实施。
Product basis: ACCEPTED PD-001/PD-002、IMPLEMENTING F-011/F-014。

## 用户任务与结果

质量治理、资产维护和问数用户重开正在执行的会话后，需要看到执行完成或澄清，并可主动停止所见的本轮。第六版只提供手动刷新，恢复页面没有停止入口。沿用原页面，提供有限只读状态跟随和按所见轮次 ID 停止，减少重复刷新，避免旧页面停止新轮。

旅程：重开原会话 → 用户/项目校验 → 自动检查原活动轮状态 → 完成/待答时重新读取历史与上下文 → 明确继续或回答；也可明确停止所见排队/推理轮 → 重新读取真实状态。

StateStore 拥有消息和 pending，Agent turn 拥有生命周期，源域/Security 拥有事实与权限。continuation 是 producer，原页面是 consumer；停止仍由 AgentChatService、现有 Registry/Executor 与仓储 CAS 执行。无第二份运行真相。

## 行为与边界

- 恢复 QUEUED/RUNNING 后每隔 3 秒只读 continuation，最多 20 次请求，不重放活动全文、不自动发起模型、工具或应答。单次请求完成后才安排下一次，隐藏页面暂停调度，重新可见可检查但不重置次数预算。
- 原轮达到 WAITING_INPUT 或终态、最新轮身份变化时停止跟随，重新读取历史与最新上下文；期间仍锁定提交。历史和上下文完整恢复后才能继续，缺失证据不伪造成功。
- 读取失败、身份/投影无效或次数用尽后停止自动检查，保留历史、阻止继续并提供手动刷新。显式刷新可重新建立有界检查。切会话、新建、卸载、开始推理或停止请求使旧读取结果失效。
- 兼容新增按 turnId 停止接口，先校验轮次与会话的当前用户/项目。只能取消该 ID 的 QUEUED/RUNNING；与认领串行，以已有 CAS 和终态收尾裁决。已终态幂等无操作，不取消同会话后来轮次；WAITING_INPUT 明确拒绝，不改 SDK pending。
- 停止按钮需 agent:chat:run，读取沿用 agent:session:read；后端权限与归属为最终裁决。发送停止请求不等于停止成功：无论应答或不确定结果，都必须重新读取真实状态；失败提示核对重试，不显示虚假已停止。

无新状态机、数据库、配置、导航、后台任务、通知、源读取、业务写入或框架迁移；原会话级停止和原连接续播保持兼容。多节点运行句柄路由不由本版解决，未确认的运行状态不得假装已停止。
