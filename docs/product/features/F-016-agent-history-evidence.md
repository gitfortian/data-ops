# F-016 — 历史回答与执行证据准确关联

Status: IMPLEMENTING
Approval: 用户于 2026-10-07 再次指令“继续规划下一步迭代规划 并开始实施”，授权第八版规划后实施。
Product basis: ACCEPTED PD-001/PD-002；IMPLEMENTING F-011/F-014/F-015。

## 用户、问题与结果

返回治理或问数历史的用户，需要确认一段回答对应哪次执行，避免把别轮的工具或配置证据用于判断本轮结论。现有历史按 assistant 序号配对 COMPLETED 轮次；失败、部分回答、上下文压缩或旧消息可使序号失去对应关系。提供可证明的轮次关联，无法证明时保留正文并明确不展示关联执行证据。

## 旅程、归属与复用

原会话 → 本人/当前项目校验 → StateStore 正文 → 通过服务端写入的原轮标识与归属一致的 turn 关联 → 原 trace/工具详情；缺失关联时显示说明，仍可按最新 continuation 明确继续。

StateStore 拥有消息，turn 拥有生命周期，step/query_log 拥有各自执行证据；元数据仅引用原 turnId，不复制状态或源事实。Runtime 是原消息引用的 producer；原会话 read-side 与页面是 consumer。复用原会话权限、官方 StateStore 消息 metadata、turn 仓储、trace、history API 与恢复路径，不使用未接线消息树替代正文。

## 行为与范围

- 新 START 的 USER 消息由服务器附带原 turnId 引用，随官方状态序列化保存；HITL 不新建 USER，沿用原分组与轮次。文本/模型/URL 不得提供这个引用。
- 历史按原 USER 分组保留正文和中间工具过滤；组内回答继承该 USER 的引用，不用回答文本、问题相似度、时间或数组位置猜测。
- 仅当引用唯一、归属/项目/session 一致且对应 COMPLETED 轮时，为回答关联原 turnId 与原 trace。重复引用、未知/非完成/跨范围引用、旧消息无引用都保留正文、返回空关联，且不读取其他轮 trace。
- FAILED/INTERRUPTED 继续来自原 turn 的独立失败记录，并保留其真实 turnId；不把失败记录顺序当作消息发生顺序，不据它关联正文。失败记录明确标识为独立记录。
- 页面对无法关联的历史回答明确提示，不自动水合别轮 trace；不影响最新 continuation 的目标、状态、澄清与预算恢复。旧 API JSON 形状不变。

无新数据库、状态机、配置、权限、导航、跨域读取、模型自动重试或框架迁移。不迁移/回填旧消息，不承诺完整历史时间线、压缩后完整消息恢复、活动全文重放或崩溃断点续跑。

成功信号：真实用户回看时能区分有明确轮次证据的回答与缺少关联的正文，不将别轮 trace 误认为本轮证据。当前无真实基线，自动化不证明结论语义正确或用户收益。
