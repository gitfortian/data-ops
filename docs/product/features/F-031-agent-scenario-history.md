User：建模与指标设计人员。Problem：从原候选面板进入原会话后，四类交付显示原始 JSON，难以回看候选和待确认项；指标定义草稿标题误入质量执行兜底。Capability：在原会话提供只读场景交付卡和准确任务说明。Journey：原编辑器生成 → 原会话读取本人当前项目历史及 continuation → 核对最新完成轮唯一关联交付 → 回看候选/依据/待确认项 → 返回原页面重新核验处理。Expected Outcome：能理解本轮交付及下一步，不把生成或轮次完成当成业务保存/发布成功。

Truth Owner：原 turn/StateStore 拥有生命周期和消息，Semantic/Modeling/Metric 拥有定义及保存/验证/发布，Security 拥有访问裁决。Producer 是既有授权 history/continuation；Consumer 是原会话只读展示。复用四场景 parser、目标规范化、原页面回链与现有请求失效隔离；无新增 API、源读取、业务状态、导航或事实库。

- 只呈现由 history 读取、与最新 COMPLETED continuation 的 session/turn/完整目标一致、且唯一关联的 assistant 交付。SSE 文本、活动/失败轮、旧轮无当前目标证据、缺失/重复引用、重复/跨类型回执、坏格式不升级为交付卡；保留正文与固定核对提示，不猜测来源。
- 展示标准候选/字段说明、来源字段及类型差异、指标说明及原事实、三类定义草稿及依赖版本、待确认项、Skill 版本与截断说明。文本按普通 React 文本转义。内部 JSON 默认由可读卡替代，仅唯一有效块被替换，历史正文不重写。
- 卡片不做采纳/复制进表单/保存/推理或自动源调用。回链由已核对目标的稳定 ID 派生，目标页面重新判权；历史快照明确只读，新指标草稿返回原列表继续选择/新建，不自动恢复未保存表单。
- 刷新/切项目/切会话/新轮/权限失去/读取失败后旧交付不能继续展示为已核对。最新完成后的 SSE 只读状态核对仍不把流文本当历史，用户刷新读取后才呈现交付。
- 准确区分四种场景标题及指标当前/历史视图；旧资产、质量、普通问数路径保持。
