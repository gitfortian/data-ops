## 1. 目标、用户与结果

主要用户为数据工程师、指标 Owner、治理人员、数据消费者、审批用户和平台管理员。
当前治理入口分散、消费目录隐藏、审批任务与配置混放，折叠侧栏又将页面平铺成大量图标。
用户应能按任务选择已有能力，沿 J1～J6 进入当前页面，并在详情深链中保持所属菜单与项目上下文。

能力沿用 Capability Map 的五个业务域：数据接入与集成、标准、指标与建模、开发与运行、数据资产与治理、数据消费与服务。
首页和我的待办是工作入口；平台设置是横切管理入口；MDM 保留专业方案定位。

## 2. 成功信号

现有基线为七个业务顶级组，消费目录隐藏。目标为五个已有能力域，消费目录可直接发现，审批用户直接进入我的待办。
通过登录态任务走查观察用户能否直接选对入口、是否需要在资产与元数据之间猜测、折叠菜单是否可用。
菜单/权限契约测试是交付证据，不等同于真实用户效果或各业务旅程已经闭环。

## 3. 事实归属、生产与消费

业务定义、运行、治理、质量、安全、血缘、生命周期、审批、消费关系继续由原域持有。
前端 navigation 拥有名称、路径、排序、分组与高亮；Yak Security 拥有数据库菜单目录与角色授权。
源域生产事实，现有页面、Asset 与 Consumption 投影消费事实。此次只变更导航呈现，不增加业务实体、状态机或第二份真相。

## 4. 方案与范围

- 接入：数据源、离线同步、实时同步、文件资源、SQL 执行记录。去掉只有文件资源一页的冗余资源分组。
- 标准建模：业务语义（业务域→业务过程→数据标准→标准字段→数仓分层）→模型工作台→指标。
- 开发运行：开发工作台→发布中心→开发运行记录→工作流定义/实例。
- 资产治理：资产目录优先、资产概览、资产管理（盘点上架/目录与标签）、技术元数据、血缘、质量、安全、生命周期、专业方案：主数据管理。
- 消费服务：数据产品目录优先、数据集管理、API 服务、分析展示（仪表盘/数字大屏）。
- 工作入口：首页、我的待办。平台设置：项目空间优先、用户、部门、角色与权限、审批流程配置、操作日志；保留资源授权和系统配置 feature gate。
- 名称统一：指标标签与统计、调用方与密钥、数据访问策略、质量检查记录、生命周期策略等。
- 指标血缘与影响分析支持跨指标/模型/标准排查，保留专业菜单和旧授权；指标管理仍是首个主要入口。
- 菜单按 route 与 subgroup 的共同排序展示，避免始终先显示页面而破坏用户任务顺序。
- 默认仅展开当前路由所属一级组与子组。折叠显示一级组图标，通过可点击、可悬停的浮层进入子菜单；隐藏组内链接不能被键盘误聚焦。

本 Feature 是已有五域的导航呈现收敛，不合并/拆分业务能力、不创建新顶级产品域、不改变默认业务动作路径。
不实现统一 Integration 对象、不补齐模块、不新增搜索/收藏/运行入口、不调整 API 数据安全或审批状态语义。

## 6. 复用、权限与兼容

复用 navigation、RouteAccessBoundary、Project Space、RBAC、Approval、Asset、Consumption、Flyway 与 Ant Design 菜单交互。
原 URL、叶子菜单码、业务权限码保持稳定。隐藏详情沿 parentId 继承权限和高亮。
将现有隐藏 Consumption 路由纳入同一 navigation 元数据，使用稳定新菜单码 `consumption-catalog` 和 API 既有 `data-asset:read`；详情继承目录。
迁移给已有有效 `data-asset:read`（显式权限或已授权菜单隐含读取权限）及 root 角色补齐新目录授权；不新增操作权限。
分组重排保留叶子行 ID 和角色叶子关系，仅补齐已有叶子的父链。退役 resources/data-approval 容器而保留历史关系，不删除授权。
框架拥有 system-* 菜单，仅按 app_name 对现有 system 标题/项目排序更新，不在业务迁移复制框架目录。

无权限过滤空组；拒绝直达 URL。菜单迁移未部署时，新目录对已暴露 menuCodes 的旧后端用户保持拒绝；需要先部署迁移并刷新登录态。
加载、空态、FORBIDDEN、UNAVAILABLE 继续由现有专业页面与后端表达。
智能助手入口还须消费后端部署开关：未开启时隐藏顶部入口，直达 URL 显示未开启说明且不挂载 Agent 页面；状态加载失败单独提示并可重试，不冒充关闭或无权限。开关由原 `yak.agent.enabled` 拥有，Boot 提供只读投影，不新增业务状态或授权；Agent 业务接口和 SSE 保持原直连传输。
跨域回链与稳定对象/版本由原页面负责，菜单不重写项目上下文或业务身份。

## 7. 验收场景与证据

1. 全权限用户看到五个业务组；语义→模型→指标、目录→专业治理、消费目录→专业供给顺序正确；每个可见页面仅有一个菜单归属。
2. 已有叶子授权用户迁移后仍能进入原页面；待办 read 用户无流程配置，manage 用户流程配置在平台设置；无权限无空组。
3. 数据产品目录与详情均要求 data-asset:read 及新目录菜单授权，Dataset/API 操作仍使用原域权限；菜单改组不扩大操作权。
4. 直接进入质量监控详情、资产详情、消费详情、模型与指标详情时，正确高亮并仅展开所属组；旧编辑器、重定向继续可达。
5. 展开/折叠侧栏、打开浮层、点击叶子、键盘关闭；折叠时没有叶子图标平铺，展开时关闭组内链接不可聚焦。
6. Flyway 有效菜单目录与前端父子关系、名称、顺序、路径、类型、读取权限一致；角色关系与框架目录所有权保持。
7. Agent 关闭时无顶部入口，直达页面只显示未开启说明且不挂载业务页面；开启后入口可点击；读取失败可重试，身份切换后的旧响应不能覆盖当前状态。复用 `HeaderDropdown.test.tsx`、`AgentAvailabilityContext.test.tsx` 与 Boot `ApplicationFeaturesControllerTest` 验证。

自动化：导航/目录契约、权限边界、侧栏交互、迁移集成验证；真实部署 J1/J2/J3/J4/J5 场景复用 #289 清单。
执行结果与环境限制记录在 `docs/product/acceptance/task-oriented-navigation.md`。未执行的登录态业务链路不得标记已通过。
