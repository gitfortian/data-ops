# F-019 — 实时轮次停止与状态核对

Status: IMPLEMENTING
Approval: 用户于 2026-10-07 授权多版本规划并依次完成；本版为 V9/V10 后的 V11。
Product basis: ACCEPTED PD-001/PD-002；IMPLEMENTING F-014/F-015/F-017/F-018。

## 用户、问题、能力与结果

实时使用 Agent 的治理及问数用户需要停止眼前这一轮并知道实际结果。恢复页已按 turnId 停止，实时 Sender 仍用会话级 cancel；断开订阅后不能证明后台已停止，晚回调还可能污染后续会话。统一实时精确停止与有界只读核对，保留事实及已有文字。

## 旅程、归属与复用

原发送 → 回执确认 turnId → 实时进度 → 明确停止该轮 → 重读 continuation/历史 → 按实际终态、待答或活动状态继续。断线不能当失败或停止；传输结束也不能替代 turn 状态。turn/Executor 拥有生命周期，StateStore 拥有消息/pending；客户端 generation 只过滤陈旧响应。复用原 CHAT_RUN、cancelTurn、continuation/history、有限跟随、原工具审计/预算/权限，未增加事实 owner。

## 冻结行为

- 仅用服务器提交回执确认的 turnId 停止，不使用会话级 cancel 选择当前轮。提交未确认/无 ID 时不发送取消，保留进行中提交并提示等待回执或核对，不猜测其他轮次。
- 精确停止前冻结 ID，阻止重复停止并使该订阅的晚事件/回调失效，再断开订阅；只取消该 ID。请求处理后重新读实际 continuation/history，不能先显示 CANCELLED。应答丢失阻止新提交并提供刷新核对；完成/待答竞态按实际读取，pending 不经停止取消。
- 正常流结束或连接错误后沿用只读最新状态核对，不从传输事件伪造生命周期；连接错误明确提示“连接结束，正在核对”，不是持久化推理失败事实。核对失败保留已收到文字/输入并禁止新发送；手动刷新仍保留编辑。
- 当前订阅的事件/完成/错误/重连回调均检查原 generation 与 AbortSignal。新提交、停止、切换、新建、卸载使旧回调失效；水合也须核对 generation。读到 active 后仅沿用原有限跟随，不自动重新推理或全量重播。
- 实时停止与填写需要 CHAT_RUN，服务端仍重验归属/项目；pending 恢复保持原 ID/目标/预算。旧会话级 API 为兼容保留，但新页面不再调用。

## 架构、影响与边界

原前端页面内管理已确认 ID 和订阅 generation，原 AgentChatService / Query / Executor / StateStore 不变；无新 API/状态机/表/配置/权限/导航/依赖走廊。Domain/Requirements 增补客户端投影纪律。无源域写入、回滚、活动全文重播或多节点保证，继续 AgentScope Java 2.0.2。
