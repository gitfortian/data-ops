# F-018 — 治理提问准备

Status: IMPLEMENTING
Approval: 用户于 2026-10-07 授权多版本规划并依次完成；本版为 V9 后的 V10。
Product basis: ACCEPTED PD-001/PD-002；IMPLEMENTING F-009/F-010/F-012/F-017。

## 用户、问题、能力与结果

资产/质量治理人员在已有带范围 AI 入口，需要表达希望核对的点、已知背景和期望结果。原快捷问题只有固定句子，直接填入还能覆盖未发送编辑；治理任务的空状态却展示销售问数例子，容易误解能力范围。提供当前任务的提问准备表单和可核对预览，明确发送后再推理，保留编辑且不扩大工具范围。

## 旅程与归属

原资产/质量页面 → 带 GovernanceTarget 的对话 → 选择原任务问题 → 可选填写背景/核对重点/期望结果 → 看预览 → 填入原输入框 → 编辑并明确发送 → 原证据与源回链。turn 拥有冻结任务，用户填写仅为口述背景，StateStore 拥有实际发送后的消息，源域拥有证据。前端确定性组装问题是 producer，原输入框/提交是 consumer；未发送表单只在内存，不入库、不拥有第二份真相。

## 冻结范围与交互

- 仅现有四种任务：资产解读、资产描述候选、所选历史质量执行排查、监控规则候选。以 GovernanceTarget/purpose 选择原 governanceQuestions，不从自由文本切换任务。普通问数保留原例子。
- 在原页面展示可折叠“准备治理问题”。原问题为必选模板，已知背景最多 2000、核对重点与期望结果各最多 1000 UTF-16 units；全部可留空，不自动生成阈值/样本/根因。超长明确阻止填写，不静默截断。
- 预览区用纯文本，不渲染 HTML/脚本。补充部分统一标记“用户提供，尚待源证据核对”，不把口述提升为已证实事实；不承诺提示注入检测。
- “填入准备的问题”零 API/模型/源调用；原输入非空禁用并说明，现有快捷按钮同样保护编辑。填写后仍由用户点击原发送。
- 活动/pending/读取失败/恢复加载/无 CHAT_RUN 时禁止填写。会话/目标/轮次变化重置表单，切换/新建不泄露旧背景。HITL 继续回答原问题，不被本表单替换。
- 治理空状态仅展示本任务说明，不再显示普通销售问数例子；源页面回链、任务策略、授权、预算、证据校验、候选人工采纳保持原规则。

## 架构与复用

复用 Project/RBAC、GovernanceTarget、governanceQuestions、原 Sender/提交与源回链。仅原前端页面内组件和纯组装函数，无新服务端 API/表/状态/配置/权限/导航/跨域走廊；不需新 Product Decision。Domain Gap 由本规格及 Requirements/Domain 补充收敛，源域 owner 不变。
