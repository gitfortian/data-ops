## 用户、问题、能力与旅程

质量治理、资产维护和 Dataset 问数用户需要各自在合适的工具范围内完成任务；管理员需要区分模型、源域和配置问题。当前共享注册不能表达显式治理任务的禁止取数边界，配置/Skill 变化缺少固定评测。

沿用原页面 → 现有对话/澄清 → 授权证据和候选 → 原编辑器人工保存。增加服务端任务工具约束、有限调用/重复失败预算、实际配置与 Skill 哈希及离线/真实评测执行器；不新增导航、源域事实或 Agent 写工具。

## 事实归属与复用

源域拥有业务定义/结果，Security 拥有权限；Agent 消费公开 API。StateStore 继续拥有消息与框架状态；执行预算作为同一 StateStore 中的辅助执行状态，单会话只保留当前轮预算，不成为第二轮次状态机或业务事实。生命周期仍由 yak_agent_turn 拥有。

复用 AgentScope Java 2.0.2、Toolkit、StateStore、SSE、HITL、取消、UserExecutionScope、源域候选校验、动态配置、Skill 管理与现有 trace。

## 当前实施范围与规则

- 资产解读/描述任务读取所选资产及分区；首批不自动读其他关联对象。历史质量任务只读所选 executionNo；规则任务只读所选 monitorId。事实核验、日期、澄清及管理员维护的只读 Skill 加载可用；仅对应 purpose 可生成候选。
- 显式治理任务禁止 Dataset 发现/字段/取数、Python、报告保存和其他任务候选。普通对话保持现有工具/授权行为，不依关键词自动切任务；其治理记忆隔离限制继续明确。
- 未登记工具不能执行；静态业务工具和框架 Skill 辅助工具分别登记。工具执行边界与运行时检查共同保护，不用全局 Toolkit 激活状态隔离会话。
- 工具预算默认每轮 32 次，单工具 ERROR/异常累计默认 3 次后拒绝继续执行；两者为启动配置，初始执行冻结。入口预读、澄清与只读 Skill 加载计入。HITL 使用同一 turnId 恢复已消费额度；历史挂起轮缺新预算时仅首次初始化并留记录。预算持久化失败必须阻止后续真实工具调用。
- 模型调用输入字符预算默认 120000，按实际 system/messages 的文本与工具参数上下文检查；超限明确失败，不伪造完整读取，也不作为 token/费用精确闸门。所有新增启动项集中 application-ai.yaml。
- 撤权仍在每次源调用检查；取消后停止新工具调用，已经发生的事实保留。SSE 断连仅结束订阅，沿用当前异步执行契约。
- 现有 Skill 启停/重启还原与乐观更新需要行为回归；运行时只能加载当前启用的管理员维护 Skill，不新增项目私有范围。治理 Skill 先提供可评测材料，通过真实评测前不默认注册开放。
- trace 记录实际任务策略、工具集合、Skill 内容/启停哈希和预算。观测关闭/故障不改变强制守卫；密钥、端点鉴权和完整私人提示不落配置证据。
- 配置列表展示当前启动默认/动态覆盖来源；仅已接入键支持调整，未接入预留键在页面与管理 API 明确拒绝，避免“保存成功即生效”的误导。
