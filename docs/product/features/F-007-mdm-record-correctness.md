# F-007 — Master Data Record Correctness & Governance Persistence

Status: IMPLEMENTING  
Feature ID: F-007  
负责人：Product / MDM  
目标版本：MDM correctness follow-up  
创建日期：2026-09-30  
关联产品决策：无（沿用现有 MDM / Approval / Data Service 边界）  
关联 Issue / 设计材料：[#281](https://github.com/gitfortian/data-ops/issues/281)

> 本 Feature 收敛现有主数据行为中的数据正确性问题，不新增主数据产品域、导航或业务真相。

## 1. 目标与价值

**功能：** 让主数据加工、治理变更和下游查询共享一致、可追溯的记录事实。

**主要用户：** 主数据管理员、数据治理人员和负责来源加工任务的数据工程师。

**用户问题：** 来源任务重跑可能覆盖审批/清洗后的人工值、重复累积来源标识并无意义地增加版本；并发治理写入可能静默覆盖；删除属性/实体可能留下不可解释引用；停用实体仍可能被查询或发布。

**期望结果：** 来源刷新只更新来源管理字段；经审批或显式清洗的字段可持续保留并能逐字段恢复来源值；重复加工幂等；治理写入有并发保护；身份字段不可被清洗改写；停用实体不对服务消费者可见。

**为什么现在做：** Issue #281 的代码核对已发现这些问题落在已有的主数据加工、审批、清洗和分发路径中，会损害已审批数据的可信度与审计能力。

## 2. 成功指标

| 指标 / 信号 | 当前基线 | 目标状态 | 如何验证 |
|---|---|---|---|
| 已审批字段在来源重跑后的保留率 | 当前加工 SQL 可覆盖人工值 | 受治理字段重跑后保持审批值，单字段恢复后下次重跑接收来源值 | Golden E2E 前后记录值与 override 元数据 |
| 同一来源重复加工的记录版本 | 当前每次命中都会增加版本 | 属性及该来源原始 ID 均未变化时版本不变 | 重复执行加工 SQL并比较记录版本 |
| 停用实体的对外可见性 | 服务 API / 已发布分发缺少统一阻断 | API 离线或拒绝请求，运行查询返回零行 | 发布解析、API 查询与服务 API 场景 |

## 3. 产品上下文

**所属产品能力：** 主数据建模、记录治理、审批、加工和分发。

**用户旅程：** 定义实体与属性 → 配置来源并运行主数据加工 → 审批修改或执行清洗/合并 → 再次加工 → 检查记录、版本和来源归属 → 通过已发布 Data Service 消费。

**入口：** 既有主数据实体详情的记录、清洗和审批入口，以及既有 Data Service 发布入口。

**前置步骤：** 实体及属性已定义，来源落地并已生成加工任务。

**下一步：** 检查治理后的记录，或在实体生效且分发配置有效时由既有 Data Service 发布和查询。

## 4. 假设与验证

| 假设 | 为什么这样判断 | 如何验证 | 当前结果 |
|---|---|---|---|
| 审批和清洗产生的值应覆盖来源刷新 | 审批是已存在的 MDM 事实所有权路径；来源任务属于外部事实生产方 | 审批后重跑来源任务并检查记录值 | 本 Feature 实现并待 E2E 验收 |
| 恢复来源值属于需审批的治理变更 | 人工值由审批产生，移除保护标记也会改变后续记录事实 | 审批恢复申请，再运行加工任务 | 本 Feature 实现并待 E2E 验收 |

## 5. 事实归属与所有权

**Truth Owner：** MDM 拥有实体、主记录、记录版本、变更审批与合并事实；来源系统拥有来源值；Data Service 拥有服务发布和运行事实。

**事实生产方：** 来源落地任务提供输入值；MDM 审批、清洗和合并产生治理决策与受治理字段。

**消费方：** MDM 页面读取记录和审批状态；Data Service 消费生效实体中的 ACTIVE 主记录。

**真相来源：** `yak_mdm_record`、既有审批/变更/版本与合并日志；属性来源保护元数据保存在记录行内。

是否新增第二份业务真相：否。保护元数据是记录当前值的治理来源标记，不复制另一份记录或审批状态。

## 6. 方案与范围

### 已选择方案

- 为记录增加逐属性来源保护元数据；批准的 UPDATE 和实际改变属性值的清洗/合并写入保护值。
- 加工 SQL 对保护字段保留 MDM 值，对未保护字段刷新来源值；来源 ID 按数据源键覆盖写；无有效变化不增加版本。
- 审批申请可通过保留键 `$useSource` 逐字段清除保护，随后一次来源加工才刷新这些值。
- Repository 写入按当前版本 compare-and-set；拒绝清洗改写 PK；补齐删除引用与停用实体服务边界。

### 本次范围

现有 MDM 记录加工、人工 UPDATE 审批、去重合并、标准化/补全、属性/实体删除校验，以及现有服务查询与分发 API。

### 明确不做

不新增实体类型、状态机、顶级导航、订阅或 Usage Truth；不接管 Data Service、Asset、Quality、Lineage 或 Sync 的事实；不重写加工执行引擎。

## 7. 复用要求

- 复用现有 Approval Center 流程承载字段修改和来源恢复申请。
- 复用现有 Audit、主数据记录版本、合并日志与 Data Service 发布能力。
- 复用数据开发已注册的主数据加工 SQL 任务；不创建新的调度或执行引擎。

## 8. 用户体验

**正常路径：** 记录页标出“人工修正”字段，用户为字段提交审批变更；审批通过后来源重跑仍保留该值。用户可逐字段提交恢复来源申请。

**空状态：** 无受保护字段时不显示恢复来源操作。

**异常 / 阻断状态：** 版本竞争、无效属性、PK 修改和停用实体查询给出明确失败；未审批的申请不改变记录。

**无权限状态：** 沿用既有 MDM / Approval / Data Service 权限检查。

**加载与长耗时：** 加工仍由数据开发任务执行，MDM 页面只显示读取结果。

**跨域回链：** 沿用现有审批中心和 Data Service 路径，不新增跨域导航契约。

## 9. 治理影响

不更改跨域事实所有权。记录修改继续经过 Approval 与 Audit；版本保留有效记录快照；合并日志继续保留规则来源；停用实体不会被服务消费者查询或解析为在线分发来源。

## 12. 架构影响

- API：沿用变更申请 API，UPDATE 内容新增保留键 `$useSource`。
- 数据库：`yak_mdm_record.attribute_overrides` 保存当前受治理字段值；Flyway V17。
- Domain：record 更新按版本 CAS；PK 是稳定 `master_id` 的身份材料，禁止通过审批、合并或标准化/补全改变；已有引用后不可在 PK 与普通属性间切换。
- Events：复用现有 Approval / Audit 事件。
- 兼容性：旧记录的空保护元数据按 `{}` 处理；旧加工 SQL 需通过现有生成入口重新生成，才具备新的幂等和保护语义。

## 13. 验收标准

### E2E 场景

**Given / 前置条件：** 生效实体有一个 PK 属性、一个普通属性及一条 ACTIVE 记录，记录由数据开发主数据加工任务维护。

**When / 用户动作：** 用户通过 Approval 提交普通属性变更并获批，运行一次来源重加工，再提交并批准该字段恢复来源值并再次运行加工；同时重复执行一次未变化的来源任务。

**Then / 期望结果：** 第一次重加工保留已审批值；恢复来源审批后下一次重加工采用来源值；未变化重跑不增加版本；来源 ID 不重复累积；PK 不可由审批、合并或清洗改写；停用实体对服务 API 不可见。

### 验收证据

- UI / API：记录页显示字段受治理标记；恢复来源申请进入既有 Approval Center；服务 API 对停用实体拒绝查询。
- 持久化事实 / Event：`attribute_overrides` 与 `attributes` 一致更新；记录版本仅在有效变化时增加；旧版记录空值按 `{}` 兼容。
- Audit：审批、清洗、合并沿用既有审计事件。
- Observability：代码审查、模块编译、CI 和上述登录态 Golden E2E；本地 PR 阶段仍需 CI / 运行态 E2E 证据。
