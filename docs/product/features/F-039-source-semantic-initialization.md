## 用户任务与完成定义

实施人员选择一次授权业务范围，输入背景，审查计划与分片理解，集中确认候选和依赖，然后明确保存。只有 Semantic 返回正式对象、状态、版本/引用与可回读证据，首期才算完成；仅生成答案/候选不算完成。

- 入口：原 Datasource / Metadata 已采集结果中的关联 Agent 工作；不新增一级导航。
- 结果：可关联的业务域、过程、标准字段、必要 TYPE / UNIT / CODE、过程字段与来源证据。
- 下一步：原 Semantic 专业编辑器、Modeling/Metric 路线（仅回链/交接，不批量生成、验证、发布）。
- 成功信号：与同一业务范围人工查阅、填写、核对、返工基线对照；语义准确性需专家独立判断，不能凭 JSON 合法率代替。

## 典型风险和用户可见错误

| 情况 | 用户看到什么 | 禁止的行为 |
| --- | --- | --- |
| 采集不完整 | 来源覆盖、缺字段、返回采集入口 | 将省略范围当全部覆盖 |
| 关系/单位/码值证据不足 | 带依据的问题与需要补充的信息 | 从物理样例猜标准 |
| 计划未确认/退出被拒 | 保留 Plan 修订，等待用户决定 | 等同正式保存授权 |
| 预算耗尽/写入失败 | 已交付片段与阻断原因 | 无预算继续调用 |
| 刷新/停止/重启 | 从已落事实核对，未交付片新 turn | 伪造继续同一推理 |
| 来源版本变化/撤权 | 失效旧候选/预检并重新授权 | 继续持旧 token 写入 |
| 重复保存/丢回执 | 源域幂等回执或待核对 | 盲目生成重复正式对象 |
| 标准待审批 | 已创建但未生效及原审批入口 | 自动批准或字段引用未生效标准 |

## 复用清单与依赖防线

- 沿用 AgentChatService / AgentTurnDispatcher / AgentTurnExecutor、官方 StateStore、AgentRuntime 的既有轮次、trace、SSE、Skill 守卫和额度机制。
- Agent 只经 outbound Gateway → Metadata/Semantic **公共契约**，不得调用源域 Mapper/Repository；源域不反向引用 Agent。
- Metadata 保留物理结构 Truth，Semantic 保留正式语义和审批 Truth，Modeling/Metric 保留各自版本事实。
- AgentScope PlanMode 的 Plan Markdown 属 workspace，不等于 StateStore 已持久化；新增任务级总额度不能替代/重置 turn 级预算。

## 规模和留存待定

可作为待验证的起点：每任务最多 20 表/500 列，具体字符、轮次、时间、模型令牌、候选保留时长由真实试点确定。当前**不是性能承诺、默认配置或可上线指标**。文件后端必须证明同一 user 不同 task 的隔离且支持重建；删除/清理依源域保留与用户可核对流程。
