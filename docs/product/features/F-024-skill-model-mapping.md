# F-024 — 模型来源字段映射 Skill

Status: IMPLEMENTING
Approval: 用户于 2026-10-07 要求按框架复用调研的推荐顺序逐个完成，授权首个标准场景后复用到模型映射。
Product basis: ACCEPTED PD-003，APPROVED F-005，IMPLEMENTING F-011/F-023。

## 用户、问题与结果

User：建模人员。Problem：面对源表大量字段，人工查找字段及判断业务含义重复耗时。Capability：在原来源映射编辑框，为一个已保存的目标字段推荐已选源表中的字段。Journey：选择目标字段 → 选择源数据源/库/表 → 填业务说明/字段检索词 → 原 Agent 轮次加载 `model-field-mapping` Skill → 核对至多三项候选 → 再校验并带入 → 人工检查表达式 → 原条件保存 → 回读。

Expected Outcome：缩短来源字段定位时间、减少仅凭同名误配。成功信号是试点同题准备时间与返工率下降；尚无真实基线，不以自动化通过代替收益。

Truth Owner：Modeling 拥有目标字段及来源映射，Datasource 拥有项目内数据源和目录元数据，DB Skill 管理拥有方法版本，原 Agent turn 与 SDK StateStore 各自拥有轮次和消息。Producer / Consumer：Modeling 授权只读 API 组合模型和目录上下文，Agent 消费，原映射编辑器消费候选；AI 不写映射、不执行 SQL，不新增模块、导航、状态机或业务定义库。

## 场景合同

- 固定模型 ID、已保存目标字段、用户选定的单个来源表、业务说明和检索词。目标字段类型/说明由源域读取；用户补充说明单独标为输入。未保存的模型结构需先保存。首期仅推荐来源字段，不生成转换 SQL 或自动断言类型兼容；显示两侧类型，由用户按原表达式校验处理。
- 生成前、交付前和采纳前核验 Agent、Modeling READ、Datasource READ 与项目范围。仅读取目录，不读取行样本、密钥或连接配置。目录读取失败是不可用，不能当无匹配。读取使用已有 fresh 目录方法；外部 DDL 无法与平台保存建立跨库原子事务，明确验证时间边界。
- 给模型最多 50 个字段，按名称/说明检索及稳定排序，显式返回截断；底层插件当前返回一张表的全部字段，限制的是模型上下文，不宣称物理目录查询被限制。字段名/类型/说明单项有界。
- 必须加载管理员启用的 `model-field-mapping`；复用 F-023 的请求隔离、Skill 版本/hash、SDK 结构化 call、预算、取消及历史一致保障。最多三项候选、三项待确认问题，每项理由/问题最多 512 字；来源字段只能选本轮实际提供集合，最终从源域重新装配标签和类型。
- 带入只改原表单的来源字段并清空旧转换表达式，避免旧表达式继续引用别的来源字段；不自动保存。项目/模型/目标/来源表/表单变化、权限撤销、晚响应和重复采纳需要隔离。原会话可回看，不从其自由文本直接写业务。
- 编辑上下文绑定目标字段定义及当前单列映射指纹。原编辑框保存携带 If-Match；所有映射写路径先持有模型行锁，当前字段和映射使用 locking read，冲突在写入前拒绝。保存仍运行原源字段存在性与表达式校验，条件路径使用 fresh 元数据，保留原标准字段关联；原兼容 API 仍可用。编辑框保存完成关闭并回读，不自动发布。

## 复用、边界与缺口

复用原映射编辑框、数据源目录、项目/RBAC、结构事务锁、原 Agent 提交/SSE/停止/历史、SDK Repository/SkillFilter/Middleware/结构化输出。缺口限定为 Modeling 的授权有界映射上下文 API 与单列条件保存；Agent 仍仅 gateway → modeling.api，不直接消费数据源内部组件。第二个真实场景提取共用结构化调用与前端轮次交接，不创建新推理引擎或第二队列。

## 验收与失败

自动化覆盖：授权失败前零读取；源字段集合/截断；未知/重复字段、超量/畸形结果拒绝；目标/映射/源目录漂移；条件保存冲突前零写、保存回读；原 SDK 回退/预算/并发与历史；表单变化/晚响应不带入；保留人工保存。缺 Skill、源权限、目录失败、格式失败和冲突显示真实原因。

真实 E2E：登录用户选择实际模型字段和源表，生成、核对、带入、人工保存并回读映射，记录 Skill/模型/映射/源目录指纹、trace；反例含撤权、外部 DDL 和并发编辑。沿用户已有确认保留 PENDING，代码与 CI 完成也不标 SHIPPED。
