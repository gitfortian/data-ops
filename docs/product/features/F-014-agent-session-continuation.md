# F-014 — 治理会话恢复与继续

Status: IMPLEMENTING
Approval: 用户于 2026-10-07 指令“ok 继续 第6版迭代规划 并开始实施”，授权本轮规划后实施。
Product basis: ACCEPTED PD-001/PD-002；复用 IMPLEMENTING F-009～F-013 的源事实、任务范围、预算与原页面边界。

## 用户、问题与期望结果

质量治理、资产维护及等待澄清的问数用户，需要重新打开原会话继续工作。当前历史入口清空任务并丢失待答状态，刷新无会话定位。提供服务端恢复最新任务/状态/反问的原页面体验，用户辨认范围后明确发送；失败不悄悄变为普通问数，活动轮不重复提交。

## 旅程、归属与复用

原会话或 sessionId URL → 本人/当前项目校验 → 原消息与最新轮次投影 → 显示任务/状态 → 原 HITL 应答或明确追问 → 原受控源回链。

StateStore 拥有消息与 SDK pending，yak_agent_turn 拥有轮次状态与 TurnInput；Quality/Asset/Dataset/Security 保持原归属。仓储/历史为 producer，原页面为 consumer。反问事件只重现问题，不成为新的 pending truth；恢复仍由原服务和 SDK 校验。复用原 read-side、HITL、budget、trace、工具矩阵和回链，无新审批/记忆/采纳库。

## 行为与失败

- 兼容新增只读 continuation API，原 history JSON 保持不变；本人和当前项目校验先于读取。仅输出 session/turn identity、真实状态、已持久化目标、可重现反问或阻止原因，不返回原始 payload。
- 任务仅来自最新提交轮次；不得从历史标题、回答、证据卡或更旧轮次推断。target 为 null 保持普通任务；损坏输入不得当作 null。
- WAITING_INPUT 才显示原反问。缺帧或工具身份非法则阻止继续并可刷新/新会话；应答仍发 toolResults，不由客户端更换 target，不重置 turnId/预算。过期或并发恢复由原 CAS/SDK 拒绝。
- QUEUED/RUNNING 阻止新提交，显示状态和刷新入口；本批不自动重放活动全文，避免现有历史关联不完整造成重复。不承诺 mid-turn 崩溃续跑。
- URL sessionId 优先请求服务端上下文；其中额外目标参数不能覆盖历史任务。加载时禁止提交，读取失败可重试；切换/新会话/卸载忽略晚响应。新会话清除 task、pending、旧 URL。
- 正常追问携带恢复目标；仍是新轮次、重新授权读取，不把历史证据视为本轮已验证事实。原候选需要在源编辑器重新生成/校验，不从历史一键写源。

## 范围、验收与信号

无新业务状态机、数据库、导航、源契约、自动写入、框架迁移、跨执行比较或记忆权限扩展。Query 继续只读；必要的项目隔离校验覆盖该旅程的历史/trace 读取，不能由界面隐藏替代。

按 [V6 计划](../../ai/AGENT_V6_PLAN.md) SC01～SC08 验证。自动化证明读取归属、状态投影、澄清恢复请求和页面竞态，PR CI 验证既有运行契约；真实部署/模型/源审计仍单列 PENDING，保留 G/T/QP/RA 待办，Feature 不标 SHIPPED。

成功信号是实际用户重开后完成有效追问/澄清，并正确辨认任务范围。当前没有真实基线，工程通过不证明收益或恢复成功率。
