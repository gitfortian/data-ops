# F-012 — 历史质量执行排查指引

Status: IMPLEMENTING
Approval: 用户于 2026-10-07 指令“ok 开始实现第四版功能实现”，授权第四版 V4-0～V4-2 工程建设；真实模型与登录态验收沿用既有确认独立待完成。
Product basis: ACCEPTED PD-001/PD-002、APPROVED F-001-A、IMPLEMENTING AI F-009/F-010/F-011。

## 用户、问题、能力与结果

质量治理人员和表维护人员需要从某次历史执行知道下一步检查什么。当前已有证据解释，但没有真实任务效果基线；只有结果状态时容易将推测说成根因。本批将已知事实、待验证假设/缺口、人工检查步骤及原执行页面核对组织为现有任务结果。成功结果也可以是明确指出缺证据，供人工继续核对。

## 旅程、入口与下一步

原质量执行详情 → “AI 解读与排查” → 现有对话中固定 executionNo、用户明确发送 → 按当前权限预读历史证据 → 必要 HITL → 本轮事实卡与排查文字 → 受控源链接核对本次执行。需要修改规则时由用户在源页面选择当前监控，独立发起现有 QUALITY_RULES 任务；不在历史任务内切换权限或自动保存/运行。

空数据、源不可用、无权限和截断显式说明，无法证实原因时保持待验证。加载/取消/历史回放沿用当前契约；SSE 断连不取消执行。

## 事实归属、生产消费与复用

Quality 拥有历史执行及规则证据、当前定义和命令；Security 拥有权限。公开授权 API 为 producer，Agent 与现有页面为 consumer。用户背景标为用户提供信息，不升级为源事实。官方 StateStore 拥有消息，Agent turn 拥有生命周期；排查文字不增加业务事实表或处置状态机。

复用 AgentScope Java 2.0.2、GovernanceTarget、工具策略/预算、UserExecutionScope、QualityEvidenceQueryApi、证据台账/核验、回答守卫、HITL/SSE/取消、现有源回链、管理员 Skill 管理和评测执行器。没有新 top-level 依赖走廊，不改变 Quality 契约。

## 实施范围

- 服务端只为显式 qualityExecutionNo 任务追加排查表达约定；普通对话、资产和候选任务保留原行为。输出使用原文本/事实卡/证据协议，不新增结构化步骤 schema。
- 回答按“本次事实、优先核对规则、待验证假设与缺口、人工检查步骤、源页面下一步”组织；关键状态/数值通过本轮 verify_governance_facts 核对。事实卡核验不代表整段文字语义已验证。
- 保留 PASSED/NOT_PASSED/ERROR/RUNNING/NOT_RUN。实际值的业务含义须有源证据；不从数值推导脏数据行数，不将全 PASSED 推导整表健康。
- 当前证据无错误类别/SQL/样本/冻结失败策略/上游状态；ERROR 不确认具体技术根因，NOT_RUN 不确认本次 STOP 因果，历史不使用当前规则回填。
- 背景或关注规则不明确时复用 HITL；源字段缺失不能靠用户澄清补成历史证据。恢复保持原 executionNo 与同轮预算，显式治理不读写长期记忆。
- 最终回答附固定人工核对提示，继续通过同一 StateStore 消息保存，当前输出与历史一致；源链接仅来自受控目标或本轮登记。
- 质量入口和上下文提示明确排查范围、快捷提问及返回本次执行；快捷按钮只填写问题，用户明确发送。既有监控候选入口正确显示当前监控身份。
- 增加独立 16 例 QP 标注题集与离线检查；单请求执行仅供初步观察，多步验收明确保留人工步骤。离线 NOT_RUN，真实输出始终待专家/源审计评审。
- 更新质量 Skill 候选步骤，保持材料未注册/未默认启用；先比较当前任务提示，再按管理员现有范围做 Skill 对照。

## 非目标与治理

V4-4 错误类别/跨执行对比、RAG、多 Agent、MCP、框架迁移与自主修复不在本批。历史任务不取 Dataset 明细、不执行 Python/SQL、不写报告、不生成其他任务候选、不自动改规则/运行/通知。没有新导航、权限、配置键、业务状态机或第二份 Truth。

## 验收与成功信号

自动化：实际 SDK 中的显式任务提示、当前授权历史证据/核验值、拒绝结果与历史一致；无证据降级、模型链接移除；HITL/预算与取消沿用现有回归；受控目标回链和快捷问题不自动发起操作；新题集有效、旧 12 例兼容、手工多步题不自动运行。脚本模型不评分自然语言根因或步骤正确性。

真实：QP01～QP16 逐例记录源 fixture 核对、账号/部署/模型/Skill 哈希、trace、专家四项评分、原页面和审计；保留 G1～G12 / T1～T9 待办。相关旧路径和本批必测证据齐全、严重错误零例、低分限制范围后由 Owner 确定试点开放。没有环境保持 IMPLEMENTING，代码/CI 完成不等于 SHIPPED。

成功信号与验收分开：记录用户能否完成有效人工核对及对照耗时，打开页面不能计为解决；费用缺 usage/版本单价为 unknown。当前真实基线未建立，不承诺收益比例。假设“现有证据足以提供有用步骤”由试点验证，失败时记录最小源契约缺口，另行立项。
