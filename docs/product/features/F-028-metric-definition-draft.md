# F-028 — 指标定义草稿与原编辑器交接

Status: IMPLEMENTING
Approval: 用户于 2026-10-08 授权下一批开发，明确包含指标定义草稿及完整任务串联。
Product basis: ACCEPTED PD-003；APPROVED F-005；IMPLEMENTING F-023/F-025/F-027。

User：指标设计人员。Problem：业务需求转为聚合/限定/组合定义反复手填。Capability：用户在原新建或编辑表单选定类型和依赖后，明确输入需求，通过固定 `metric-definition-draft` Skill 准备类型适配草稿与待确认问题。Journey：选类型/模型或上游 → 输入业务需求 → 授权有界上下文 → SDK 结构化候选 → 核对依赖与定义 → 重新核验带入 → 人工原保存 → 原精确版本验证/发布 → 回读。Expected Outcome：减少准备/返工，真实质量和耗时待试点。

Truth Owner：Metric 拥有定义及保存/验证/发布，Modeling 拥有字段，Semantic 拥有业务域/过程与标准；Agent 只消费只读 API。源域授权上下文/草稿校验生产材料，原编辑器消费。复用原 SDK 场景骨架、会话/预算/停止、Skill 版本/hash、Project/RBAC、原 expectedVersion 保存与审计。不新建业务表或第二推理队列。

固定用户选择的类型、模型/上游集合（最多 5 个）及已存指标版本（新建为 null）；不让模型搜索任意对象。原子草稿仅从授权有界模型字段选聚合函数/字段；派生草稿只对明确选定原子指标组织结构化限定；复合草稿只对明确选定上游组织有界 token。名称/说明/周期及类型相关表达为候选；域/过程、单位/口径、身份、编码、对象 ID 和保存版本始终由原表单/源域拥有，不由模型新增授权。信息不足返回问题，用户补充后新轮；不增加 pending 状态。

生成前、交付前、带入前核验 Agent/Metric、必要 Modeling READ 与当前项目；源版本/结构指纹、Skill 变化拒绝陈旧产出。所有候选经过源域只读检查，不能用 JSON 可解析代替领域校验；展示 AI 草稿与原依赖版本，源读取失败明确不可用。表单/对象/项目变化失效；带入只更新白名单定义字段，不保存/执行 SQL/验证/发布。原保存和 Definition Validation 仍是最终裁决，不承诺自然语言或数据执行正确。

验收 MD01–MD10：三类草稿正常路径、缺项问题、未知字段/依赖/token、无权限零源读、版本/结构/Skill 漂移、超界/坏输出、停止及历史一致、表单/项目晚响应、原人工保存版本冲突、精确验证/发布回读。真实模型与登录 E2E PENDING。
