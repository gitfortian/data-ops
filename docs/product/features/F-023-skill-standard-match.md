# F-023 — 场景 Skill 与字段标准匹配

Status: IMPLEMENTING
Approval: 用户于 2026-10-07 明确要求“按照推荐实施顺序与交付标准逐个完成”，授权框架复用调研第 11 节的逐项实施；本 Feature 为首个场景切片。
Product basis: ACCEPTED PD-001/PD-002/PD-003，APPROVED F-005，IMPLEMENTING F-011。

## 用户、问题与结果

User：建模人员。Problem：现有规则推荐难以理解字段业务说明，候选难以核对其实际版本。Capability：在原标准助手生成类型标准匹配候选。Journey：原字段草稿 → 输入业务说明/标准检索词 → 现有 Agent 轮次 → 按需 Skill 与结构化输出 → 查看候选和不足 → 实时核验 → 带入草稿 → 原建模保存 → 回读。

Expected Outcome：减少逐字段查找标准的时间与误选；首期单字段、TYPE 类型标准，后续类别和批量单独切片。成功信号是同题人工对照下准备时间与返工下降，当前真实基线未知，试点采集，不以工程测试数代替。

Truth Owner：Semantic 拥有标准定义、类别、启停与版本；Modeling 拥有模型和保存结果；AgentScope StateStore 拥有推理消息；现有 Agent turn 拥有生命周期，DB Skill 管理拥有方法版本。Producer / Consumer：源域授权只读 API 生产上下文和校验结果，Agent 消费，原编辑器消费候选，保存仍由 Modeling 生效。不新增业务定义表、一级导航、审批流或第二份事实。

## 场景合同

- 原标准助手显式发起，目标固定模型 ID 与单字段当前草稿（字段名、类型、业务说明、检索词）；草稿明确为未保存用户输入，不能当已存源事实。会话与目标原样绑定。首期待确认项是完成结果的问题清单；补充后发起新轮，不新增 SDK 外部 HITL 或状态。
- 继续复用提交、持久化轮次、SSE、准确停止、历史与身份作用域；不新增同步 HTTP 推理路径或第二套队列。
- 首期搜索当前项目启用 TYPE 标准，SQL 限制 20 项并给出截断标识，检索词为空为有界目录。模型只能选择实际提供的 ID/版本；最多 3 项；候选理由和待确认项均有长度限制。无匹配或信息不足可返回空候选和问题，不能伪造标准。
- 只加载管理员管理的 `standard-match` Skill，缺失/停用/来源故障明确失败。默认不激活未经真实评测的候选 Skill；提供可导入材料，沿现有管理面启用。不建立第二 Skill 注册库。
- 优先 SDK RuntimeContext + SkillFilter + DynamicSkillMiddleware。请求独立 Toolkit/Middleware，固定同轮 Skill 快照及真实版本/目录/正文 hash；加载前及最终交付重查当前启用和版本，变更时拒绝陈旧结果。正文资源、脚本和额外工具激活继续关闭。
- 使用 SDK 结构化 call（原生 response_format 或 call-scoped generate_response），不让模型输出 fenced JSON 决定候选。原有任务不放宽未知工具规则；此场景仅允许只读上下文、Skill 正文与框架结果工具；所有真实调用受预算、身份、取消和时间限制。候选校验与历史存储文本由服务端编码。
- 生成前及最终交付核验 Agent/Modeling/Semantic 读取权限；带入再次核验模型定义、标准启用/类别/版本及 Skill 版本。不把源调用失败当“无匹配”。未通过校验的模型产出不可采纳。
- 用户带入仅改当前字段的标准类型引用，不修改其它字段或自动保存。字段/项目/模型切换、草稿变化、晚响应和重复带入需要隔离。保存继续走原方言/标准规则和审计，增加源域条件保存以拒绝覆盖其它用户的新结构；不执行 DDL。保存回执在同一事务读取新的结构基线，保存期间的后续草稿保留，不能用稍后读取的别人修改冒充本次保存回执。

## 复用与架构影响

复用原 Project/RBAC、标准助手、建模校验/结构事务锁/审计、SDK 状态与 Skill 仓储、现有 Agent 运行与事件通道。仅 gateway 可消费新增 Semantic / Modeling 授权只读 API；runtime 经 toolset 预读/校验，conversation 仍经 runtime，依赖单向无环。SDK 结构化调用在独立 Agent 实例中使用原 StateStore 和原轮次上下文，避免共享工具组变化。

## 体验与失败

显示“当前未保存字段草稿”、来源版本、候选范围和限制；候选可读解释不代表业务结论已批准。无候选保留业务说明，允许调整检索词/补充信息。Skill 未启用、模型配置缺失、读取无权限、源漂移、格式失败分别显示真实失败，可回原会话核对；等待时展示原轮次状态，停止后重新读取实际状态。返回原模型路径使用稳定 ID。

## 验收

自动化必须覆盖：授权前零读取、项目隔离、候选 SQL 上限/截断、未知 ID/版本/类别/停用、Skill 范围与热编辑/禁用、两请求并发、SDK 合成工具预算与未知工具拒绝、畸形/空/超量结果、取消及历史一致；原字段带入、草稿/目标变化和晚响应隔离；保存前置条件冲突及回读。

真实 E2E：已登录测试用户在实际模型字段上生成、核验、带入、手工保存并回读标准绑定，记录模型/Skill/源版本、trace、保存审计；反例含撤权与并发修改。真实模型/登录态验收按用户已有确认单列 PENDING，未完成前保持 IMPLEMENTING。
