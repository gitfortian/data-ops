# J1 工作台统一产品视觉整改 / 真实页面验收

2026-10-14，基于用户对 #569 合并版本真实截图的评审结论：**产品验收不通过**。此文档说明当前修正 PR 的具体范围、与主站的一致性设计及可手工验证步骤；不拿设计原型或 mock 测试截图代替正式页面。

## 原因与合同

#569 把 IA-550 v0.8.2 的原型布局当成了主产品视觉模板：在 DataSource 中新建左导航 4 步栏、右侧两张教学卡，使用 #14796f 一套陌生的青绿交互色；ODS 也另建左身份/中字段/右操作三栏和英文大字标签。真实 screenshot 显示大量无业务价值的辅助面积挤压最重要的源表、字段表。这不是 data-ops 商业化样式，也不是高效工作台。客户验收结论：**拒绝这版视觉**。

标准以实际项目已有代码为准：
- `src/styles/brand.ts` 全局品牌主色 `BRAND_COLOR = rgba(254,44,85,1)`；不得在局部工作台再定义青绿色主按钮。
- 已有 `data-source/index.less` 页面、`data-metadata/overview` 与 `data-asset/overview` 采用中性色文字、白色卡片、灰色边框及简洁操作栏；沿用原 Ant / Yak 组件的主次操作、焦点及响应式规则。
- v0.8.2 只作为**业务任务关系**和后端交接基线，不作为 UI 主题、三栏装饰和英文标签的复制源。

## 本次实际代码整改（单 PR）

### DataSource 正式页面
- 取消占用页面宽度的左侧步骤教学栏 + 右侧解释栏；桌面主工作区最大 1320px，实际 Drawer 最大 1360px。
- 顶部只保留数据源自身身份、简短标题与返回；下方是连接状态以及单一的库/Schema/源表和字段详情卡片，采集信息作为现有 Tab。
- 原有即时探查、同名 Schema 区分、字段刷新、采集任务复用、连接测试/编辑及 RBAC 一项不删。
- “打开或创建 ODS”回归源表标题旁的**紧凑主要操作**，不再是分割字段表的 100% 宽横幅；无列结构证据不能点击。
- 移除自造 `#14796f` 主题及英文视觉装饰，使用项目默认颜色、表格、边框、字号。

### ODS 正式页面
- 删除顶部四张流程卡、左右辅助侧栏、英文标签及独立青绿色主操作主题。只保留“简短标题 / 精确来源一行 / 字段映射主体 / ODS 草稿配置 / 底部真正的保存动作”。
- 来源坐标始终保留并可回源；已同源 ODS 优先打开，空目标才允许实时列预览、逐列映射、空草稿与原子提交。
- 保留真实服务端 `SAVED_AND_VERIFIED` 回执、未保存提醒、未知结果恢复、权限保护。布局改变不添加新的真实性推断。
- 列结构占据页面主要宽度，320~1440 视口只有字段表的容器内部可横向滚动。

## 验收流程（请直接在代码启动后检查）

1. 数据源 → 产品库：标题应是主站惯用中文、白色灰边工作区，不再有左侧绿色四步菜单、右侧两张教学面板或英文 SOURCE/NEXT ACTION。
2. `mkt_db / mkt_coupon`：库/Schema 选择和表列表/字段表应成为主要内容。确认「打开或创建 ODS」是源表标题右侧的紧凑按钮，不是铺满字段表上方的大色块；原字段、主键、类型和备注不缺失。
3. ODS：应只有一行精确来源和中央字段映射/目标配置，动作与其后状态位于页面底部；不能再出现左身份、右英文帮助卡两条装饰栏目。
4. 检查现有 ODS 复用、新建 ODS（实时列→空草稿→原子保存→成功回源），同名不同 Schema/撤权/超时/无 Asset 权限等负例，旧能力均不可倒退。
5. 对照元数据/资产目录中现有的顶部标题、卡片边框、字号、按钮与 focus 规范，检查 390 / 768 / 1366 px；电脑截图第一眼不得再像嵌入了另一个设计系统。
6. 单元测试和 TS 门禁需全绿；**真实浏览器布局截图与体验必须由用户手动签收，不能用 CI Green 宣称视觉验收通过**。
