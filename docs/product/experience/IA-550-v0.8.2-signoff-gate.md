## 1. 本次签收边界与未决事实

1. **已可评审冻结的体验原则**：首页按建设/消费/异常的首要任务呈现，同时展示项目规模和运行态；保留指标/安全/MDM/J1 Agent/J6 问答的独立入口。原页面功能先组合再逐域替换，不允许静默删去管理、审计和专业入口。
2. **ODS 例外**：源表 → 采集/核对 → 精确寻找/新建 ODS → 保存 → 返回来源；ODS 不强迫提前建立逻辑模型、标准字段或 Asset WRITE。资产纳管属于平行治理路径。
3. **业务模型主线**：Semantic 过程/粒度/标准 → Logical 实体/属性/关系/独立版本 → DWD/DIM Physical；DWS 由指标与统计粒度导向，ADS 由消费输出导向。逻辑关系和物理 Join 不能凭名称推断；精确物理模型 ID，不以“DWD 层”作为唯一模型身份。
4. **交付门禁**：保存设计≠发布设计≠部署≠创建 DataDev 任务≠执行≠质量验证≠消费≠Usage。未获 Owner 契约的写操作保留只读审阅与“需完善”的提示。
5. **IA V3.1 设计事实**：106 条 appRoutes、按功能开关 62 条可见配置/44 条隐藏、54 业务叶子；4 条旧 Metadata 地址。20 个候选默认任务入口不能靠删路由/菜单码/RBAC 达成。[#550](https://github.com/gitfortian/data-ops/issues/550) D1–D5 尚未作为最终产品签署。
6. **分支与证据**：v0.8.2 在设计分支（PR #554 堆叠合并），与 main 尚有版本差异。正式纳入 main 应在最终签收、解决冲突和完整 CI 后单独进行；不得因为 #554 的“merged”就当作 main 已有该原型。
