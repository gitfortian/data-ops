## 授权与范围

用户在本轮明确要求“规划模型拆子菜单出来”。沿用 ACCEPTED PD-003、IMPLEMENTING F-029 及 Modeling 领域合同。现有导航实现作为当前事实；不使用 PROPOSED PD-010 或 DRAFT F-040 授权新行为。

- 本轮优先落实菜单和页面职责。模型详情中的版本核对、恢复草稿及开发交接继续使用既有能力，后续可以围绕这些对象内交互单独迭代。
- 保持现有一级导航域及双栏布局，在模型设计分组直接展示五个子入口，不叠加折叠层级。不是新增五份数据库菜单或权限。
- 子入口仅投影已授权的 modeling-workspace 路由及其既有子页面，继承同一菜单/RBAC 检查；不添加虚构菜单编码，不改 Flyway 历史目录、不绕过原页面授权。
- 建模总览关注五层与过程的整体情况；逻辑模型负责实体/属性/关系；物理模型负责原列表及按层筛选；过程覆盖复用原主线矩阵；变更影响复用原只读查询。
- ODS、DIM、DWD、DWS、ADS 是模型属性/筛选条件，不拆成五个重复一级入口。单模型字段、来源/分层映射、版本、生命周期和开发交接继续留在模型详情。
- 数据源与数据标准分别由原域维护；模型导航不复制它们。原 URL、过程回链、查询参数与对象内未保存保护保留。
- 列表和总览分别显示任务标题与说明，移除把主要导航藏在工作台分段切换中的做法。页内需要上下文切换时仍通过明确动作进入原页面。

## 验证记录

- 自动化：7 个套件、64 项测试通过，覆盖五入口的原路由授权继承、缺权限/缺菜单时隐藏、查询参数与模型详情精确选中、折叠菜单、移动端点击回调、原导航与数据库菜单合同，以及逻辑设计/物理草稿取消保护回归。
- 生产构建 `npm run build` 通过；8 个相关生产文件的 Biome lint 无错误或警告；`git diff --check` 通过。
- TypeScript 类型债务门禁通过（131 项既有基线诊断）。本次重写折叠菜单投影时显式使用 `MenuProps['items']`，消除了该函数原先 `flatMap` 分支推断产生的 TS2322；未修改或放宽类型基线。
- 登录态浏览器实际打开五个入口：建模总览读取 ODS 2 / DWD 3 / DWS 0 / ADS 0 / DIM 0；物理模型读取原有 5 条记录；过程覆盖读取下单与购买商品两个过程；逻辑模型读取原“下单 / order”草稿；变更影响打开原只读查询页。
- 总览 DWD「查看模型」进入 `view=list&layerCode=DWD`，显示 3 条 DWD 模型并高亮物理模型；打开订单模型详情仍高亮物理模型，浏览器返回保留 DWD 筛选。
- 实际收起侧栏后，弹出菜单保留五入口并可直接进入逻辑模型；完成后恢复原展开状态。移动抽屉由组件回调测试覆盖，未进行真实窄屏端到端验证。
- 最后返回建模总览并刷新，五入口、当前选中及真实五层统计均正常读取；交付页面停留在总览。
- 浏览器没有新建、修改、冻结、恢复或发布业务模型，没有触发数据开发任务。跨角色真实端到端、影响查询完整结果和用户查找效率改善仍待业务验收。
