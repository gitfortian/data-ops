## 范围和边界

依据 ACCEPTED PD-003、IMPLEMENTING F-029 与 Modeling 领域合同。用户明确授权按原型继续重构；原型作为体验参考，不将 PROPOSED PD-010 / DRAFT F-040 升格为实现命令。

当前逻辑关系命令只接受实体端点、基数与描述。Domain 的目标说明提到属性对，但当前 API 没有属性对写合同。本轮只展示真实实体关系，不增加隐式外键、JOIN、角色维度或精确维度版本引用，不按拓扑猜测事实/维度身份。

- 画布拖动、缩放、自动排列、对象选择与视图过滤是当前会话布局，不写业务数据或新增进度状态。
- 属性、实体与关系复用原表单和 `expectedRevision` 保存；未知基数、待关联标准是提醒，不新增冻结门禁。
- 卡片可仅摘要展示部分属性，但明确剩余数量；完整属性在属性面板/表格查看。大图超出预算时明确要求聚焦邻接或使用表格，不截断后宣称全图。
- 冻结仍生成 DRAFT 快照；标准有效性、历史差异、物理复核沿用原证据入口，不将当前属性列表伪装成历史快照。
- 只读权限允许浏览和定位；写按钮按现有 CREATE / UPDATE 权限显示能力，服务端授权仍为最终裁决。
- 编辑取消保护本地输入；保存失败保留输入；重复点击、切换项目和对象后的晚响应不能覆盖当前工作区。

## 走查发现的身份精度问题

真实项目读取中发现：草稿目录可读，但打开首个草稿报“不存在”。目录的 Java Long 身份超过 JavaScript 安全整数范围，原 JSON 数字解析会舍入后再构造详情 URL。此问题直接阻断新工作区，因而纳入本轮修正。

修正在逻辑建模前端请求边界进行：原有鉴权、项目头、错误处理仍走统一 request；读取响应原始文本并在 JSON 解析前保护大整数。安全范围内的旧 ID 保持数字，大整数保留精确十进制字符串。实体、属性、关系、快照证据、原治理定位及逻辑/物理导航同步保持精确身份；路径拒绝已舍入的数字、非法字符串与超出 Java Long 的坐标。没有修改全站 JSON 解析或后端接口，也没有改写既有数据。

同时修正草稿读取的局部容错：一个已授权草稿的详情失败时保留目录与所选对象，让用户重试或选择其他草稿；不把局部读取失败显示为整个项目没有逻辑模型。

## 验证记录

- 自动化：17 个相关套件、86 项测试通过。覆盖视图投影、对象检索/定位、画布与表格共用对象、真实回执刷新、原修订号单次提交、冲突保留/取消保护、项目切换后隔离晚响应、目录局部失败恢复、只读能力、大图预算、Long 身份解析与原物理回链。包含前两版创建/派生/全景/未保存结构返回回归。
- `npm run build` 通过并生成前端构建清单；12 个相关生产文件的 Biome lint 无错误或警告，`git diff --check` 通过。
- `node scripts/check-type-baseline.mjs` 仍失败，唯一未纳入基线的诊断是既存 `src/layouts/SiteLayout/SidebarNavigation.tsx` 的 TS2322。本轮逻辑建模、身份兼容和测试文件没有新增类型诊断，未放宽类型基线或修改侧边栏。
- 登录态真实读取：通过工作台“从逻辑设计开始”进入当前项目，原来无法打开的“下单 / order”草稿在 ID 修正后读取成功，修订 0、实体/属性/关系均为 0，界面显示真实空设计状态。当前项目数据不含可走查的实体关系，没有补造业务记录。
- 登录态表单验证：在真实空草稿打开添加实体表单，填写临时编码/名称，取消后显示未保存保护，继续编辑仍保留输入；最终显式放弃，实体数量保持 0，没有点击保存。
- 隔离浏览器验证：用真实 `LogicalDesignStudio` 组件、项目主题和测试样例单独打包，在本机临时服务验证 3 实体、9 属性、2 关系。已验证 SVG 关系选择、基数方向、节点拖动及布局保持、属性卡片/对象检索定位、摘要外第 6 个属性的准确编辑回调、完整表格、视图切换保留选择和直接邻接聚焦。样例明确标为“不连接业务接口”，不会发出创建或保存请求。
- 浏览器没有保存真实实体、属性、关系或冻结快照；写入、修订冲突和权限行为由组件模拟服务验证。真实跨角色/并发写入全程 E2E、物理生成、发布、加工运行和用户收益仍待实际样本验收，不能根据本轮测试宣称这些已经完成。
