## 1. 评审结论

**方向成立，尚不具备全产品设计冻结条件。** 五域导航、逻辑/物理分离、ODS 贴源例外、依赖批量载入、指标版本与发布区分，以及协作回链应保留。最大的风险是：局部任务能点击完成，用户却容易把它理解成整条业务交付已完成。

应把原型从“展示工作台有哪些功能”推进到“不同角色怎样完成一次有证据的任务”。v0.8 已修正可定位的状态与交互缺陷，补入消费者的独立合同样例；它仍然是设计演示，不能用于宣称 SQL、DDL、权限、数据质量或真实消费已经通过验收。

### R01 的具体复现

v0.7：进入模型 → 冻结 LM-016 → DWD → 从 PM-701 载入字段 → 生成映射候选 → 仅保留 order_id 对 LA-101 → 确认映射 → 核对并保存。`v7MappingReview` 只判断非空选项数量大于 0，剩余 item_id、etl_time 等缺口不会阻断“本次映射一致”。[源代码](https://github.com/gitfortian/data-ops/blob/f3e1d9b0028e830c39f01c9fd7f75367be9cb92b/docs/product/experience/prototypes/IA-550-task-flows-v0.7.html#L1648)。

v0.8：生成候选后，item_id 未对应属性会显示一项待说明，不能直接确认。选择“业务映射待补充”并说明商品粒度标识问题，可以保存 `DEMO-DWD-V1`；“准备数据开发交接”保持禁用。**允许设计不完整，但完成提示必须准确。** 原型的本地准备条件不构成正式发布/标准豁免规则。

### R02 的具体复现

v0.7：ODS 载入→检查→保存→准备交接，再修改目标列名；按钮只检查 `saved.length`，旧引用和新草稿可以同时显示。[源代码](https://github.com/gitfortian/data-ops/blob/f3e1d9b0028e830c39f01c9fd7f75367be9cb92b/docs/product/experience/prototypes/IA-550-task-flows-v0.7.html#L1985)。

v0.8：字段输入同步撤销检查/交接显示，保存快照与当前设计指纹一致才可准备。快照保留，不以新输入改写历史；草稿输入焦点和光标位置保留。

### R03/R04 对专业建模的建议

逻辑模型可以包含多个实体，实体有属性和关系；物理模型代表具体技术目标。推荐工作区保持三层身份：**逻辑模型/实体 → 选定版本 → 一个或多个物理目标**。模型列表允许按层筛选，但编辑、差异和映射必须始终围绕当前 target ID。

关系编辑至少表达：来源实体 ID、目标实体 ID、两端属性对、基数、业务解释、是否已确认。订单商品明细不能因为 order_id 字段存在就被当作订单级事实；DWS 的 COUNT DISTINCT 也不能由“字段角色=度量”自动推导。

这部分属于已有 Modeling 能力的完整专业交互，需与原域合同对照，不建议在首页引入一个新建模对象或强制所有 DWS/ADS 都新建逻辑实体。

## 5. v0.8 的交互安排

### 首页

第一屏回答当前目标，提供“建设可信数据 / 使用已有数据 / 处理异常”选择。每次只突出一项建议动作，并显示对象身份。接着是当前职责相关待办；未匹配时显示诚实空态。设计、部署/运行、消费分别解释证据。草稿续接和风险放侧区；项目规模保留在页面下部。

取消以冻结次数增加“项目进度”的做法。首页仍是只读组合视图，不能创建统一跨域完成状态。演示目标选择不改变用户权限或业务角色。

### 建模与交接

来源依赖先于字段设计；ODS 直接走贴源路径。非 ODS 逐列确认逻辑属性、来源版本、映射方式、依据/表达式。技术列用途不代表已批准的标准豁免。保存是设计快照；准备交接还要求当前草稿匹配保存版本、没有本次待补映射。

完整逻辑建模尚需补多实体、关系属性对和业务键；完整物理建模尚需补 target ID、方言、环境、多输入转换和真正的预检结果。v0.8 没有把它们伪装成已完成。

### 消费

沿用现有“数据产品目录”入口。Dataset 展示 schema/粒度；Service 展示接口、参数和版本。发布、运行、访问、质量、订阅和 Usage 各自单独表达。运行未知、访问拒绝或访问判定不可用时，不生成模拟消费回执。Usage 不可用显示数量未知，不抹掉已保存的本地操作历史。

演示结果明确标为固定样本和 `DEMO-` 回执，不从它产生真实 Usage。新页面不提供自由 SQL、自动授权或新的消费产品对象。
