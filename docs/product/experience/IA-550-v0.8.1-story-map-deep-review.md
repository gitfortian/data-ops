## 审查方法

严格按每条故事的 **谁/入口→决策→正式 Owner/版本→下一步→失败态→可验证完成证据**核对，而非菜单能打开就算覆盖。状态说明：

- `SIMULATED`：目前静态原型有一段可操作路径，不能说明该功能生产可用。
- `NEW_SIMULATED`：v0.8.1 增加了模拟人机交互；无真实 AI/Provider。
- `PARTIAL`：仍缺重要正式环节。
- `ENTRY_OR_PLANNED`：仅有入口/提示/既有静态专业页或已规划，**不是完整用户故事**。
- **真实 E2E = 0**：没有查询真实部署环境、权限、真实执行、质量、Source Audit、Usage 或正式产品合同。

## 三、首页信息架构修订（任务先行，不再堆模块数）

上方仍是 **建设 / 使用已有数据 / 处理异常** 三个主任务；其他「定义指标 / 安全授权 / AI 协助建设 / 可信问答 / MDM」按需展开。主任务不因当前用户没有建设权限强推进入建模。切换入口后显示独立旅程：**来源和对象身份 → 需要谁确认 → 下一步专业入口 → 无权/无证据时何种行动**。

建设模式若存在未保存物理草稿，主要 CTA 自动改为**精确恢复模型 ID**，而不是无条件重新打开逻辑模型；其余草稿显示为续接卡。首页只消费各领域状态、没有跨领域“总完成率”或所谓真实进度百分比。正式上线前需验证首页不同项目、不同授权、空事项/服务超时/读接口部分失败状态。

## 四、各专业域职责与阶段

- **Semantic** 负责业务过程/标准/标准字段 `stdFieldId`；逻辑模型是 Modeling，不能创建第二标准库。
- **Modeling** 负责逻辑实体/关系/逻辑版本、具有稳定 ID 的多个物理目标、字段/来源/逻辑映射及设计版本；源证据仍来自 Metadata。
- **DataDev** 有自己的 TaskRevision/Workflow/Execution 与真实配置及回执。模型交接上下文只引用设计 ID，不写第二任务表。
- **Metric** 保存 MetricVersion/Validation/Publication，标记已确认口径不等于真实数据验证成功。
- **Dataset/Service/Consumption** 保存生产合同、访问裁决、订阅及真实 Usage；模拟预览回执不能冒充真实查询。
- **Asset/Quality/Security/Lineage/MDM** 的专业状态与通知、审计必须由 Owner/平台提供，首页/协作只做关联视图。
- **PD-010 仍 PROPOSED、F-040 仍 DRAFT**：不在设计 PR 内设置或改变正式非 ODS 标准字段发布阻断规则。#513 R-01/R-02 仅确认规划范围与两条优先验收轨。

## 五、回归与验收、还需要什么证据

本 PR 添加 `ia550-v081-prototype.test.mjs`，继承 v0.8 既有 17 项脚本并添加 12 项：主任务/更多任务、J1 Agent 与 J6 拒答区分、同层两个目标隔离/映射不可串用、精确 DataDev 交接（包含拒绝缺口）、Dataset/Service 精确投诉来源、首页精确恢复、只读画像和专业入口。需要 GitHub CI 静态检查通过且人工复核代码与实际结果。

**此次未新增真实浏览器实屏证据**；原有 v0.8 的 320/390/768/1024/1366/1440 布局结果只适用于旧提交，不能自动继承为 v0.8.1 的视觉验收。仍须在新版本重新走查、键盘/读屏、长字段/多模型切换、对话框焦点和模态边界。真实 E2E 仍全部待验收。

**结论**：v0.8.1 为有边界的 UX 深审优化，不是 75/75 完成，不是 G1/G2 SHIPPED。PR 保持 Draft，先评审这版综合原型，再决定 F08/F09 和真实任务/消费合同的正式产品阶段；没有用户授权则不改正式业务页面或合并。
