## 二、补回被 IA 页面合并遗漏的标准字段库

上一轮核对 `main` 的 `/semantic/standards` 和 `/semantic/fields` 后，确认两者原本分别存在，不应该用一张「数据标准字段示例列表」冒充两种身份。[IA V3.1 菜单与页面组合规划](IA-V3.1-navigation-page-composition-plan.md) 明确「数据标准 + 标准字段组合」且「不要把标准字段藏到单一业务过程详情」。

当前 v0.5.1 **仍只有一个「数据标准」主导航入口**，但内部有明确两个工作视图：

- **标准目录**：NAMING / TYPE / CODE / UNIT / CALIBER / SECURITY 六类规则、稳定标准身份/编码/状态、按类筛选及反向查看字段引用；只作示例目录，不冒充真实有效发布。
- **标准字段库**：独立 `stdFieldId` 身份（非物理列）、PROCESS / DIMENSION / METRIC 角色、字段类型快照及引用；类型 TYPE 必填，METRIC 单位 UNIT 必填、CALIBER 可选，DIMENSION 可选 CODE / SECURITY；绑定需选择已启用的标准，明确草稿与本地绑定修订，并保留模型映射「选目标→确认变更」的原有流程。
- **不会隐式执行**：在标准字段库更改标准引用不自动改写业务过程/模型；浏览和只读角色不能提交绑定；模型的保存与 Semantic 标准引用的保存分开。实际审批、发布、更新 SQL、权限和标准生效仍归原 Semantic/Approval/Modeling Owner，不在本次新造第二套事实。

这部分是对**既有功能呈现的缺口补全**，不代表已实现全部数据标准 CRUD、审批、标准字段生命周期或真实标准绑定 API。旧路由 `/semantic/standards`、`/semantic/fields` 与子权限继续保留，生产代码未修改。
