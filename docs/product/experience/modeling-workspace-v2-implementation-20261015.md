## 权威与边界

复用 ACCEPTED PD-003、原 Modeling Domain、现有 DWS/ADS 与 DIM 派生合同，以及 F-029 的稳定回链。无后端或 schema 修改，不增加一级菜单、审批或第二份业务真相。原型仅用于组织交互；不将 DRAFT PD-010/F-040 或原型中的新持久合同当作实现指令。

明确历史材料冲突：旧 Requirements 的统一创建段曾描述“先建空模型再进入派生页”，但当前派生 Controller 不接收已有模型 ID，服务会在一个事务里创建模型、字段与映射，并阻断同过程同层已有模型。先创建空模型会与当前防重合同冲突。本轮直接调用既有原子派生命令，不执行旧的两次创建路径，也不修改现有防重规则。

## 交互合同

- 手工物理草稿仍可用；选择“从上游设计”需要当前项目正式业务过程、配置层和方言。进入设计前不写模型。
- DWD/DIM 展示真实过程源表/ODS 就绪情况；DIM 支持 SCD1/SCD2 的结构约定，拉链加载归数据开发。
- DWS 选择同过程 DWD，上游多选，配置周期、分组字段和白名单聚合。ADS 支持 DWS/DWD 来源与应用编码/名称。
- 预览与配置绑定；改配置后阻止使用旧字段提交。重新读取前确认替换已编辑字段，Project/对象变化隔离晚响应。显式清空上游不能被序列化成服务端“默认全选”。
- 字段来源与目标类型来自真实预览；纳入、改名、分组/度量、聚合与表达式由用户确认。技术列与维度约定不伪装成业务度量，标准引用保持正式 ID。
- 提供可解释结果粒度/主键预览，明确周期并未实现日期分桶、多上游并未实现 JOIN、AVG/COUNT_DISTINCT 等需核对可加性。设计的配置不是加工 SQL 或运行证据。
- 先复核再显式创建，禁止连击重复提交。后端按提交时上游重新校验，当前接口没有预览冻结/CAS 合同；预览不冒充冻结版本。
- 同过程同层已有模型时显示真实冲突与已有模型入口。成功回执使用实际 modelId 和计数，进入原结构/分层映射页面；写入失败保留草稿，不能在无成功回执时声称已创建。

## 验证记录

- 自动化：5 个相关测试套件、29 项通过。覆盖派生请求白名单/业务粒度与聚合校验、单次显式创建与真实回执、失败后保留设计、切换配置/项目后隔离晚响应、清空上游不回退全选、已有模型冲突、返回基本信息的种子保留，以及第一版全景/来源返回回归。
- 页面走查：在当前登录态和真实后端中从“下单”过程进入 DWD / DWS / ADS。DWD 显示真实 `dwd_orders` 冲突和 MAIN 来源的 ODS 未准备；DWS 正确显示 `dwd_orders` 的 0 个业务字段并阻断复核；ADS 可从 DWS 切到 DWD，修改应用参数后必须重新读取当前配置。旧配置的错误和来源标签不再作为当前证据展示。
- 本轮修正真实走查发现的层级显示问题：聚合/应用上游按 DWD/DWS 标示，不能将接口历史字段名 `odsModelId` 直接解释为 ODS 来源。ADS 的无分组主键提示与 DWS 分开。
- 退出保护同时覆盖字段编辑和已读取预览的用户配置；读取预览不等于保存模型。当前项目没有 DIM 分层配置，未为走查擅自添加配置；DIM SCD 结构分支由自动化覆盖。
- `npm run build` 成功，生成前端构建清单；本轮 6 个生产文件的 Biome lint 通过，仅报告 `api.ts` 原有未使用参数警告；`git diff --check` 通过。
