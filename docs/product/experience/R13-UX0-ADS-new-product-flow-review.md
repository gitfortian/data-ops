# R13 UX-0 / ADS｜全新应用数据建模产品流程与逐屏评审稿

> 2026-10-17 · 状态 `ADS_UX0_REVIEW_REQUIRED`。**必须单独签收**，不能复用 DWS 高保真或老 IA 原型。本文件独立从消费方目标出发，不用已开发的应用派生代码反推界面。关联 [#593](https://github.com/gitfortian/data-ops/issues/593)、[#513](https://github.com/gitfortian/data-ops/issues/513)。

## 1. ADS 的真正用户成果

**ADS 不是「DWS 字段再复制一遍」**，而是面向一个实际应用目标、具有明确输出结构与生命周期的数据交付模型。先回答「谁使用、用于什么、每行是什么、需要多新、允许看哪些字段」，再选择 DWS/DWD 上游，不让来源选择代替应用需求分析。

**主要用户**：应用/报表需求负责人定义输出合同；数据建模人员选择来源和映射；Metric/Semantic 审核业务口径；安全/消费平台负责人审核访问；DataDev/Runtime 提供后续真实构建、刷新和回执。ADS ModelVersion 只证明**设计**，不生成真实 Dataset/Service 授权，也不证明消费者能够 Query/Invoke。

### 1.1 两个必须分离的黄金故事

**汇总型：订单经营日报**。
- 使用者：订单运营负责人；用途：看每天/每地区订单数、支付金额、趋势。
- 目标粒度：一个 `业务日 × 地区` 一行。默认选**已发布 DWS** `dws_order_daily` 的准确版本。需要已审的 Metric/标准字段、输出列名、过滤/排序/时效要求。
- 目标：`ads_order_overview` 设计版本，可供后续 Dataset/BI 正式引用；**不可**因已创建 ADS 而在页面上宣称看板已经更新。

**明细型：订单明细 API**。
- 使用者：有许可的订单查询应用；每行是**订单明细行**，不是订单/业务日。
- 允许显式改选**已发布 DWD** `dwd_order_detail`，保留订单明细业务键；需确认敏感字段、过滤范围、分页排序、数据新鲜度和最小访问授权。
- 此路径不能悄悄套用「日报汇总」的统计粒度或从指标名称生成去重后的订单级事实。

## 2. 应用输出合同（建立在原域事实之上）

| 决策域 | 建议必须保存的设计信息 | 边界与风险 |
|---|---|---|
| 应用身份 | 项目/业务过程、ADS 模型 ID、唯一 appCode、应用名称、业务负责人、用途与消费类型（报表/数据集/API/分析） | `appCode/appName` 不是自动批准的消费产品；消费方 Owner 保持独立 |
| 输出粒度/业务键 | 每行代表什么、业务键/唯一行组合、是否汇总或明细，期望记录范围 | 聚合 DWS 和明细 DWD 不可无提示互换 |
| 上游版本 | 来源层明确 `DWS` 默认，`DWD` 必须手动选择用途；锁定 ModelVersionId/No/SHA | 不能在已编辑时自动切换为 latest 或从草稿读取 |
| 输出映射 | 展示名/技术列名、类型、标准字段/敏感分级、源列和表达式、必填/NULL、逐列去重冲突 | 同名列自动先到先得、推断类型不能直接签发 |
| 使用语义 | 固定过滤条件、默认排序、页面/结果稳定性、时效需求、是否存在敏感行级限制 | 过滤及排序不等于数据库即有索引/性能 SLA |
| 指标引用 | 已发布 MetricVersion ID 和当前口径核验、无指标时的业务含义声明 | ADS 不复制指标中心的指标定义，不代替其发布 |
| 消费交接 | 期望 Dataset/Service 类型与关联意向、消费者和权限申请、刷新要求和运行证据入口 | 只有 Dataset/Service 原域发布并通过授权、Usage 才是可消费事实 |

**关键边界**：ADS Modeling 保存的是“应用输出设计”，Dataset/Service 所持有的服务授权、数据权限、查询/调用和使用记录均来自各自原域。模型设计可以展示只读关联，不能新建假消费回执或自动授予权限。

## 3. 用户目标主线与状态

### 3.1 从应用需求而非从来源表开始

`建模工作台／创建 ADS` → `选择应用目标与消费方` → `明确输出粒度和业务键` → `推荐并确认已发布 DWS（或显式切 DWD）` → `设计输出字段、指标口径、过滤/排序` → `治理安全和刷新预检` → `保存 ADS 设计草稿` → `发布设计版本` → `查看 Dataset/Service 后续交接状态`。

**现有工作台原位完成**：单个 ADS 对象有唯一入口、浏览器深链和返回业务过程路径。只有有权用户可编辑；消费者无 Modeling Write 也应能在授权范围内查看发布摘要。不能为一条 ADS 交付再开六个左侧菜单。

### 3.2 状态必须分开，不用“已发布”混淆

- `APP_REQUIREMENT_DRAFT`：消费目标和业务键已记录，但来源/字段可不完整。
- `ADS_DESIGN_DRAFT`：已有上游草稿映射，仍可有明确的 blockers。
- `ADS_REVIEW_READY`：来源、字段、口径、安全审阅条件在当前版本均满足，**尚未发布**。
- `ADS_MODEL_DESIGN_PUBLISHED`：形成不可变 Modeling 设计版本，可交接给 DataDev/Dataset/Service。
- `DELIVERY_NOT_CONFIGURED / DELIVERY_PENDING / RUNTIME_UNKNOWN / QUALITY_BLOCKED / DATASET_OR_SERVICE_AVAILABLE`：**另一个维度**，由相应 Owner 真实回执决定。不可从 ADS ModelVersion 状态自动计算。

任何来源版本、MetricVersion、权限或消费者目的改变均显示明确的 `REVIEW_STALE`、差异影响和恢复操作。历史已发布版本只读。

## 4. 全新低保真逐屏定义（独立于 DWS 的流程）

| 屏 ID | 主要用户问题 | 主区 | 证据区 / 弹层 | 主动作 |
|---|---|---|---|---|
| ADS-01 应用目标 | 谁将消费这份数据？ | 应用类型、appCode/名称、责任人、使用目的、预期消费方 | 当前项目/业务过程/已有 ADS 草稿 | 保存应用需求草稿 |
| ADS-02 粒度与来源 | 一行代表什么？应从哪一层取？ | 汇总/明细模式明确选择；DWS 已发布候选默认，DWD 明细为显式例外；目标业务键 | 上游版本、源数据粒度和切换来源字段差异 | 确认目标行粒度和精确来源 |
| ADS-03 输出合同与验证 | 交付字段、业务键、过滤后是否仍符合原业务目标？ | 字段映射/业务键/敏感级别/过滤/排序 + 当前场景下「验证输出（原型模拟）」 | 预期与输出样例对比、行键重复、过滤范围、指标和上游同口径对比、受限字段屏蔽 | 修改映射/过滤 → 静态校验 → 可选样本预演并重验 |
| ADS-04 业务口径/时效 | 指标数据或查询结果意味着什么、多久刷新？ | Metric 引用/口径证据、刷新目标、数据有效性/保留范围、分页和结果稳定性 | Metric 已发布版本/质量与能力缺口、不同消费类型的特殊要求 | 保存应用合同 |
| ADS-05 安全审核与设计发布 | 设计是否符合消费契约，样本/真实运行证明了什么？ | 输出唯一键、来源/Metric 版本、静态合同检查 + 样本预演/真实数据对账状态各自独立 | 汇总基线与过滤后结果、偏差、权限与敏感字段风险、未发布服务状态 | 保存草稿 / 修复并重验 / 发布 ADS 设计（仅建模域） |
| ADS-06 回读与交接 | 新版本之后谁去运行、怎么给消费者？ | 应用设计版本、精确版本依赖、后续 DataDev/Dataset/Service 原域状态（只读） | 返回来源/应用、对比历史版本、异常恢复和变更影响 | 发起合法交接（若原域支持）、继续编辑新草稿 |

ADS-01 和 ADS-03 是**应用产品体验中心**，不是 DWS 的「业务时间/维度/度量」面板换皮。ADS-02 必须在每次 DWS↔DWD 切换时展示：
1. 目标粒度变化（业务日×城市 vs 订单行）；
2. 会失去/新增的输出字段与指标含义；
3. 已编辑草稿有无危险覆盖；
4. 操作人必须选择「确认重新配置映射 / 保留旧模式 / 取消」，不能默默替换。

## 5. 分屏分支与恢复行为（必须进可点击低保真）

| 失败/异常/权限场景 | 页面表达 | 恢复动作 | 不能做的事 |
|---|---|---|---|
| 无已发布 DWS | 来源选择保留目标需求，不可生成字段 | 回到 DWS 审阅/发布；或者经用户确认改选明细型 DWD | 自动退化为 DWD |
| DWS 与 DWD 切换且字段已编辑 | 展示粒度、业务键、字段及公式差异 | 保留/迁移/放弃编辑三选一，并保留旧草稿版本 | 悄悄覆盖字段、继续展示旧 Metric 的汇总含义 |
| Metric 未发布/变更 | 标识引用状态及当前冻结版本，阻断受影响字段 | 转 Metric 原域、审阅新旧口径、保存明确的缺口草稿 | 在 ADS 自行发布新 MetricVersion |
| 高敏/受限字段 | 字段级分级与消费者可见性提示，严禁展示无权内容 | 去安全授权申请、缩减输出字段 | 基于“有页面权限”自动放行实际 Query |
| 输出业务键重复或粒度改变 | 表格显示冲突和可能重复行 | 更换键、过滤/去重规则、放弃当前设计 | 把列名相同当作行粒度相同 |
| 固定筛选或排序不可证明 | 表达式/类型/参数化检查结果为待审 | 修正规则或只保存草稿 | 宣称 SQL 性能/注入防护已完成 |
| 未保存的页面跳转 | 弹窗显示具体修改对象/字段 | 保存/明确放弃/取消返回 | 静默关闭 |
| 保存超时、结果不确定 | 显示对象身份、设计 revision、只读回查状态 | 继续原草稿/安全重试（原域幂等成立时） | 在未知状态反复创建同名应用 |
| 发布模型但任务还未跑 | 显示 `设计已发布／运行未配置` 两条状态 | 跳到有权 DataDev 交接入口 | 显示“API 已可调用”“数据已经更新” |
| 取消授权或跨项目查看 | 当前资源无权限/被撤销 | 退出、申请访问、改选有权来源 | 暴露敏感字段或以旧缓存执行 |

## 6. 专业交互的明确取舍

### 6.1 ADS 不应该变成小型数据开发工具

- 聚合应在 DWS 处理。ADS 主要做**有治理依据的输出投影与受控过滤**；如果 ADS 需求里有新的跨粒度聚合/多表 Join，默认提示「返回 DWS 设计」而不是让用户随手写一个隐含 SQL 表达式。
- DWD 明细直出是**使用场景例外**，用于明细型 Dataset/API，不是“实时”性能保证。仅凭来源是 DWD 不能承诺时效或稳定性。
- 指标定义应引用 Metric Owner 的不可变版本；消费者授权、导出审批、调用日志由安全/消费 Owner 决定。

### 6.2 数据源多样性应如何在首版体现

推荐 UX v1 只允许**同一业务过程、同一来源粒度的一份明确发布模型作为主要事实来源**；多消费对象可以共用 ADS 设计版本，但一份 ADS 里多主题 Join、计算表达式、跨过程输出和嵌套服务视为高级后续能力，待领域模型/权限与真正执行可证明时评审。该限制需要用户决定，并非已批准实现规则。

### 6.3 不能简化为「选择消费类型即开通消费」

- 报表：展示统计口径、时间范围、维度解释及刷新状态。
- Dataset：展示数据集输出字段、稳定主键、权限类型、发布者/消费者的关系。
- API：展示查询参数、分页/排序、敏感字段、访问策略、调用 SLA **需求**（不是已兑现的 SLA）。
- 以上都是设计视图和未来交接**意向**，实际发布需调用 Dataset/Service 原域并有成功回执。

## 7. 设计验收（用用户可理解的效果衡量）

- H-ADS-01：从应用目标进入，不要求用户先懂 DWS/DWD 术语才能表达「订单经营日报」。
- H-ADS-02：默认 DWS 汇总，在明细用途改选 DWD 时有明确身份/粒度/字段差异和人工确认。
- H-ADS-03：应用业务键、输出字段/排序/筛选和消费者意向可保存为同一个对象草稿，再打开同一对象/设计版本。
- H-ADS-04：能说明每个 Metric 引用的版本与业务口径归属；未批准的指标变化不自动传播。
- H-ADS-05：无输出字段/冲突、无权限、Metric 漂移、来源被撤销、变更后旧草稿均有明确阻断/恢复。
- H-ADS-06：支持查看历史已发布 ADS 设计版本，但不能用历史版本的截图宣称当前 Dataset/Service 已上线。
- H-ADS-07：Project + BusinessProcess + ModelId + VersionRef 身份保持，浏览器刷新后能找到同一合同；异常保存有状态核对。
- H-ADS-08：安全/消费侧给出的授权状态是独立证据，不能由 Modeling UI 中的状态模拟“已批准”。
- H-ADS-09：1440/1024/768/390 宽度、键盘与屏幕阅读顺序、长字段列表/敏感提示/差异弹窗必须在**后续高保真阶段真实浏览器验证**，本稿不预填 PASS。
- H-ADS-10：低保真至少走通汇总日报、明细 API、来源切换草稿、Metric 漂移、无权字段、运行未知六个不同业务分支。

## 8. 现有代码核查与应补的能力（不是做旧 UI 的微调）

- `DeriveLayerPolicy` 中 ADS 模式 `APPLICATION` 默认 DWS；`ModelDeriveService` 可以显式覆盖为 DWD，但主要继承字段和应用编码/名称，还没有完整的消费者身份、输出合同版本和安全预检事实。该事实证明 ADS UX 不应受当前 DTO 所限。
- `ModelDeriveService` 存在“多个候选源同名先到先得，再加冲突标记”的行为；正式 ADS 输出设计需要**逐列来源和字段冲突裁决**，不能仅凭生成成功通过发布。
- DWS 的 `DwsGrainDesignService` 已在 R13-B 合并，但不是 ADS 专用消费合同；不能直接加一张 ADS 选项面板就认为 ADS 产品完整。
- `MetricQueryApi` 的只读启用指标可以用于候选，但引用正式语义/版本必须由 Metric Owner 提供真实证据；不能复制指标库或从字段名反推消费者已批准口径。
- 不实现原型假 Runtime、假 Dataset/Service 发布、假 Usage/Access/审计。此 UX-0 的实现差距仅做后续前后端合同清单，不在低保真评审之前开发。

## 10. 新增 UX-0 核心能力：ADS 输出数据与指标对账（待评审）

ADS 验证要证明**按特定消费者合同投影、过滤后交付的数据**符合预期，而不是重算 DWS 的一套独立指标。嵌在 ADS-03 输出字段合同中、ADS-05 审核汇总中，不增加“验证专业工具”菜单。

| 验证层 | 检查依据 | 状态与动作 | 边界 |
|---|---|---|---|
| V0 静态应用合同 | ADS 输出键/字段/标准/类型、上游冻结版本、过滤/排序合法性、正式 Metric 引用和字段级授权 | `STATIC_PASS/STATIC_BLOCKED`，定位缺失业务键、字段重复或无权字段；发布设计前必过 | 仅证明结构/引用，不证明 Dataset/API 可用 |
| V1 授权只读预演 | 相同来源快照、时间范围和过滤口径下，对比上游 DWS 与 ADS 预计输出的行键唯一性、指标合计、过滤前后差异和敏感字段曝光 | `NOT_RUN/UNAVAILABLE/SAMPLE_MATCH/SAMPLE_WARNING/STALE`，必须标记行数/时间窗/过滤条件/采样策略 | 汇总数字不同**不一定错误**，应优先解释过滤范围差异；只读授权+脱敏+审计 |
| V2 真实交付对账 | DataDev/Runtime 真正的 ExecutionId、目标 ADS 表数据、Metric/Dataset/Service 原域真实状态 | 输出键唯一性、目标聚合/明细记录和上游可比范围、差异阈值、新鲜度与消费授权 | 设计模型发布不能自动标为可查询/可调用 |

**ADS 合成数据交互**：DWS 上游按「同一天×地区」两行：上海 `order_count=2, paid_amount=450`，北京 `order_count=1, paid_amount=120`；ADS 默认投影两行，合计订单 **3**、金额 **570**。若用户增加 `city_id=上海` 的固定过滤，ADS 应仅一行、订单 **2**、金额 **450**；与全范围 DWS 相比减少不是错误，必须解释「过滤范围不同」。若选择不存在的字段/业务键、重复键、无权受限列或尚未审阅 MetricVersion，显示失败/需核对原因。DWD 明细来源不应套用 DWS 日汇总公式。

**预演结果必须绑定**：`projectId + adsDraftRevision + upstreamModelVersionRef + metricVersionRef + outputFields + businessKey + filters + timeWindow + accessScope`。以上任何一项变化必须 `STALE`，不可拿上一版 PASS 直接发布新设计。无 READ 权限则 `UNAVAILABLE`，结果区不能回显敏感值。样本验证只能帮助设计评估，不代表正式运行或消费授权。
