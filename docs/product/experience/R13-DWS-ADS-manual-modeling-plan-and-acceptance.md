## 1. 共同原则与领域所有权

DWS 是「可复用的主题汇总事实表」，ADS 是「应用/报表/数据集交付表」；两者**不等于 Metric 的正式指标定义**。上游模型/层级/字段/结构版本由 Modeling 负责；标准字段和过程由 Semantic 负责；指标的口径版本由 Metric 负责；数据加工 Runtime 由 DataDev/Job 负责；最终 Query/Invoke/Usage 由 Dataset/Consumption 负责。任何页面和后端不复制第二套事实库。

**建议主线**：
1. 选择业务过程与 DWS 目标 → 选择一个或多个**已发布**的同过程 DWD 精确版本 → 明确时间周期/时区、维度（分组粒度）、度量（聚合公式）、去重/NULL/迟到数据策略 → 关联已启用且有有效数据标准的标准字段 → 预览冲突和来源版本 → 保存 DWS 草稿 → 审核/发布设计版本 → DataDev 独立执行/数据质量。
2. 选择应用场景与 ADS 目标 → 默认基于已发布 DWS；若确属订单明细、临时报表或时效要求，显式选择**已发布 DWD** → 选择消费字段、业务过滤、应用唯一键、时效与权限策略 → 绑定独立 Metric/Dataset 引用（不自动替它发布）→ 保存 ADS 草稿 → 审核发布设计 → 交接正式开发/消费。
3. 设计、部署、执行、质量对账、受治理消费必须分别呈现不同证据。只有实际 Query/Usage 才能称为业务可用。

## 2. DWS 与 ADS 不能混为一谈

| 维度 | DWS（汇总层） | ADS（应用层） |
|---|---|---|
| 目标 | 提供多个场景复用的稳定聚合表 | 满足一个明确应用/报表/服务的输出契约 |
| 默认上游 | 同过程已发布 DWD，适当 DIM | 同过程已发布 DWS |
| 显式例外 | 无；DWD 上游不可由浏览器覆写 | 明细/时效可明确改为 DWD，不允许静默变更 |
| 粒度 | 必须有维度集合、统计周期与至少一个度量 | 必须有应用代码、输出实体/业务键、消费字段；不可静默重聚合 |
| 指标关系 | 可基于 Metric 提供建议，不代替指标口径审批 | 可引用正式 Metric/Dataset；发布物理表不等于消费获批 |
| 标准治理 | 所有业务字段须有效标准字段+标准角色（草稿可显示缺口，正式发布强约束） | 同左，不得因应用层而绕过 |
| 输出证据 | 上游精确版本、维度/度量、粒度、周期、校验、设计版本 | 上游精确版本、应用身份、消费模式、字段合同、设计版本 |
| 失败态 | 未发布 DWD、粒度/度量不完整、标准缺失、来源版本变化 | 未发布 DWS/DWD、应用身份缺失、跨过程、指标定义漂移 |

订单黄金故事：`trade_order` → `ods_order` → `dwd_order`（订单/订单明细粒度已确认）→ `dws_order_daily`（**明确指定业务日、统计时区、分组维度、COUNT DISTINCT order_id/支付金额口径**）→ `ads_order_overview`（面向订单运营看板）；`Metric` 里的「日下单订单量」与 `Dataset` 消费权限是独立引用。上述对象名是验收样例而非已落地数据或确认的指标口径。

## 3. 代码基线核查：已有能力与真实缺口

已存在：`DeriveLayerPolicy` 把 DWS=AGGREGATE(DWD 上游)、ADS=APPLICATION(DWS 默认/DWD 显式覆盖)；`ModelDeriveService` 提供 preview/derive、维度/度量与聚合函数白名单、statPeriod、appCode/appName、MetricDraft；`ModelVersionService` 支持物理设计版本；页面已有「按指标反推」入口。**不再重新造这些功能。**

必须修复或分阶段审查的缺口：
- **P0**：现有聚合解析直接调用 `ModelPublishedStructureReader.publishedStructure`，此方法对未发布模型会回落读取活草稿，对失效指针甚至可能自动补发版本；DWS/ADS 绝不能视草稿为已发布可信上游。也不应因未勾选的候选模型未发布而阻断已选择的好模型。
- **P0**：提交非法、重复、跨过程或不存在的 upstreamModelIds 会被当前过滤逻辑静默忽略；必须可解释拒绝，避免悄悄改变聚合来源。缺上游不许保存伪空表。
- **P1**：DWS `statPeriod` 与时间字段、统计时区、度量口径尚未形成完整版本绑定；当前 DWS primaryKey 默认是所有 DIMENSION，可能把 `order_id` 保留成日订单级而不是日汇总粒度。需要独立的粒度确认合同，不能仅靠命名建议通过正式发布。
- **P1**：ADS appCode/appName 目前属于松散元信息；需要应用身份/输出字段/消费者引用合同及对 DataDev/消费侧的精确版本交接，不能把模型创建视为应用已发布。
- **P1**：非 ODS 的标准字段完整性应在正式发布统一把关；不能因草稿可保存或 derive 可带 null 就宣称满足治理。
- **P2**：上游精确 ModelVersionId/No → 目标 DWS/ADS 草稿的**持久关联**与漂移治理目前不足，不能把页面显示「发布」作为正式可追溯加工血缘。
- **P2**：生产 SQL、真实 Runtime、质量与消费 E2E 另走 DR-07 跨域授权，不在首轮凭空开放生产写。

## 4. R13 本轮实际实现范围（一个可审 PR）

**Slice R13-A：DWS / ADS 已发布上游读隔离**
- 引入严格只读、**无自动发布/无活表回退**的 Modeling 上游结构读取方法。只有项目可见模型实际拥有有效 publishedVersionId 且版本行属于该模型时，才取确定的物理快照。
- 聚合/应用层的预览和建草稿统一使用严格上游来源；只读预览不制造发布版本，未发布选中来源提示明确阻断；未选中的未发布候选不拖累有效所选项。
- 校验模型选择必须来自当前过程/指定层，客户端明确传的不存在或不合法 ID 必须拒绝，不可无声改为全选。
- 测试覆盖：未发布草稿、发布指针悬空、已禁用、错误/跨过程选择、未选择来源、合法发布旧版与当前新草稿并存时快照不被污染、ADS DWD 来源例外。
- 既有 DWD/ODS 发布、UI、SQL 运行协议不因本 PR 改写。

**交付门槛**：Product Guard、Architecture、Modeling 后端现有测试及新增负例、前端回归无阻断；至少有可人工复核的 DWS/ADS 一步只读预览和保存草稿的可靠性证明。此交付只是 **DESIGN_DRAFT_READY**，不是 `PRODUCTION_DATA_READY`。

## 5. 后续两段纵向切片（非本轮伪交付）

- **R13-B DWS 专业工作台与发布合同**：明确分组粒度/业务时间/时区/周期/度量/聚合函数与标准字段，原域持久冻结上游 ModelVersionRefs，预演 SQL 仅在合法的环境与方言进行；双向保存/重新打开；黄金订单按日用例和负例全覆盖。
- **R13-C ADS 应用契约与受治理消费**：应用唯一身份/字段输出/筛选与排序/消费对象/敏感权限，DWS/DWD 合法切换但必须显式重新确认，指标引用和物理模型版本解耦，完成 Dataset/Service 受治理预检。真实执行/对账/消费须受原 Owner 授权，不能用建模草稿伪造。
