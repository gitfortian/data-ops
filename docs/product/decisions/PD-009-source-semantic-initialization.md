## 1. 用户、问题和结果

**用户**：数据治理负责人、数据架构师、来源库接入实施人员。  
**问题**：物理表已采集后，仍需逐表阅读、推敲业务概念、跨表去重、寻找标准、填写定义、手工建立关联。现有 F-023/F-026 主要辅助局部字段，不能将一次业务系统范围初始化成成套语义基础。  
**预期**：从已授权的 Schema 与人工背景出发，分片生成带源证据的业务理解，汇聚域、过程、标准、字段和来源关联候选；人工统一复核后，由 Semantic 真正保存，返回正式 ID，并回到原 Modeling/Metric 专业入口。

旅程：原来源入口 → 范围和覆盖核对 → Plan 确认 → 多原 turn 分片理解 → 概念问题确认 → 候选与依赖预检 → 人工明确保存 → 正式回执/审批 → 原专业页。

## 2. 待批准的产品选择

1. **无新一级产品能力**：继续属于 J1 来源接入与 J2 标准/指标/建模；Asset 仍承担资产治理发现。不得新增独立业务目录或第二审批中心。
2. **分离三次确认**：计划确认仅批准分析计划；候选核对决定本次选择；保存确认才授权 Semantic 的正式写操作。Plan 不是业务写授权。
3. **保留人工业务判断**：跨表同义归并、同名异义、TYPE/UNIT/CODE、过程粒度与关键关系必须显示来源与不确定性。缺乏证据时提出问题，不臆造规范、码值、精确血缘。
4. **Agent 仅拥有有限任务辅助材料**：范围、计划修订、step→turn 绑定、候选快照、累计预算和审阅选择可有界持久化；原 turn、消息、pending、正式业务定义由原 owner 持有，绝不复制。
5. **正式保存只能发生在 Semantic**：用户显式提交后，Semantic 自行校验项目权限、指纹、引用、版本、标准生效以及事务幂等；没有 Agent 业务写工具。部分成功要逐项回读，不得以候选成功冒充保存成功。
6. **交接不冒充发布**：首期到语义对象与来源关系回读；跳转原 Modeling/Metric 以真实稳定 ID 重查。批量生成 Model/Metric、自动发布与实际使用证据留作单独提案。
7. **可恢复不等于中途续推**：多个有界原 turn 串行推进。刷新可读取已提交的真实片段；启动恢复依既有 RUNNING → INTERRUPTED，未交付片段需要新 turn 重新核对后重做。
8. **保存不确定有独立含义**：网络丢回执、权限撤销、并发冲突和源漂移不得当作失败后直接重复写入；先按 Semantic 正式回执核对。

## 3. 唯一 Truth Owner

| 事实 | 拥有者 | 其他方只能做什么 |
| --- | --- | --- |
| 数据源身份、Schema、采集时点、覆盖、对象指纹 | Datasource / Metadata | Agent 通过授权、有界只读投影引用 |
| Session / 执行轮次 / 消息 / pending | Agent 既有 turn / 官方 StateStore | F-039 任务只保留绑定和观测 |
| Plan Markdown | 隔离 workspace 的文件后端 | StateStore 仅保留 plan mode/path，不代表文件内容存在 |
| 候选、证据、审阅选择、总额度 | Agent 有限任务产物 | 只读工作材料，不成为第二语义目录 |
| 域/过程/标准/字段/关联及生效/审批/幂等回执 | Semantic / 原 Approval | Agent 只发起受权用户独立采纳命令和读取回执 |
| Model/Metric 版本/验证/发布/使用引用 | Modeling / Metric 等原域 | 回链原页面，禁止推断已发布或已消费 |

来源目录 API 与保存 API 的准确接口由 #494 技术评审冻结；不得先制造 Agent → 各源域 DAO 的新依赖路径。

## 4. 安全与异常必须被产品承认

- 当前项目、本人与对象级读写权限各自重新核验；跨项目输入、过期的 Skill 或 Schema 指纹不能直接沿用。
- 源事实分页不完整、未采集、字段注释缺失、无外键必须展示覆盖缺口；来源行数据、任意 SQL、Python 与 DDL 均非首期能力。
- Task/turn 额度包含规划、读取、重试、HITL；耗尽与持久化失败阻断新调用，但保留已有交付。
- 标准创建 ≠ 启用。需要原审批时显示待生效，不能自动审批；已启用引用按源域规则重新核对。
- 取消只阻止后续步骤；成功的正式写操作不得擅自反向删除。
- 用户可看每项：已新增、复用、待生效、失败、未执行、待核对；不能把未知折叠到成功或失败。

## 5. 非目标

不升级 AgentScope SDK、不移植 Python PlanNotebook、不建新通用 Workflow/队列/审批引擎、不直接读取业务数据行、不批量变更既有定义、不创建模型/指标、不自动启用发布、不写猜测血缘、不重写旧 Flyway、不扩散生产数据访问。
