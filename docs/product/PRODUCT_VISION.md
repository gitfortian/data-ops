# Product Vision

## 一句话

**DataOps 帮助团队把分散的数据，持续生产成可信、可治理、可运行、可消费的数据资产。**

## 我们解决什么问题

数据团队真正的问题不是缺少某一个调度器、同步工具、元数据页面或 BI 页面，而是：

- 数据接入、加工、调度、治理和消费彼此割裂；
- 同一份业务定义在多个系统里重复出现；
- 运行状态、质量、安全、血缘和消费关系无法串起来；
- 平台功能很多，但用户必须自己理解系统边界并手工拼流程；
- AI 能力缺少可信数据、语义和证据支撑。

DataOps 的价值是把这些上下文重新放回一个统一控制面。

## 核心产品主张

~~~text
接入数据
 -> 标准化与建模
 -> 开发与运行
 -> 形成可治理的数据对象与业务事实
 -> 通过稳定消费契约被使用
 -> Dashboard / API / Agent / downstream
~~~

质量、安全、血缘、审批、审计、生命周期贯穿整个过程，而不是作为孤立后台存在。

## 我们不以什么为中心

- 某一个调度引擎
- 某一个同步引擎
- Maven 模块数量
- CRUD 页面数量
- 后台管理菜单数量

## 核心对象

当前产品围绕这些对象建立一致体验：

- DataSource
- Semantic
- Model
- Metric
- Task / Workflow
- Dataset
- Asset
- Evidence

“哪个对象成为跨域默认 Hub”属于 Product Decision，不由 Vision 直接拍板。

## 北极星

用户应能从核心数据对象出发理解：

- 它是什么；
- 谁负责；
- 来自哪里；
- 是否可信；
- 是否敏感；
- 当前是否正常；
- 被谁使用；
- 变更影响谁；
- 下一步可以做什么。

当这些问题仍需用户自己跨多个孤立后台拼接答案时，产品仍未完成。
