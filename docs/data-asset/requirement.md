# 第一部分：需求文档

## 一、背景

### 1.1 现状

平台的数据治理要素已经分散建齐，但"数据资产"没有统一的门面：

- **血缘**已有跨类型统一资产节点表 `yak_metadata_asset`（TABLE/COLUMN/SQL_TASK/DATASET/DATASET_FIELD/CHART/DASHBOARD/METRIC 八类），但只服务图谱，不承担编目。
- **task-catalog** 已验证"source-neutral 资产目录 + Reconciler 对账"范式（`yak_task_asset`），仅覆盖任务一类。
- **modeling** 有模型目录树与标签（`yak_modeling_directory/tag`），**metric** 有指标标签，但各域目录/标签互不相通、只在本域生效。
- **security** 拥有资产分级标签（对象↔等级/分类），**quality** 有表资产注册与质量分，**lifecycle** 有模型 TTL 状态——都是资产的一个侧面。
- **首页**"数据资产"区只做只读聚合（`/home/assets/overview`），契约明确"不做新的真相中心"。

### 1.2 问题

治理人员回答不了三个基本问题：

1. **家底**：全平台到底有哪些数据资产？各层/各域/各类型分布如何？谁负责？
2. **找到并用上**：分析师想找一个"订单明细"数据，该去模型、数据集、指标还是报表里找？没有统一搜索与目录。
3. **管住**：资产有没有描述、有没有负责人、质量可不可信、敏感字段定没定级？没有状态、没有评分、没有待办。

### 1.3 本功能解决什么

**平台管目录，不管内容。** 资产中心是跨域资产的统一编目、盘点、上架与发现层：

- 各源域（模型/指标/数据集/报表/任务）保持自身事实的唯一真相源；
- 资产中心只拥有：目录结构、上架状态机、统一负责人、跨域业务标签、编目规则、健康度评分、检索快照；
- 详情页以"聚合视图"呈现源域 + 血缘 + 质量 + 安全 + 生命周期的全貌。

一句话：**把分散在各治理域的资产侧面，编成一本可盘点、可上架、可搜索、可评分的资产账本。**

## 二、需求目标

| 目标 | 说明 |
|---|---|
| 摸清家底 | 跨域统一资产台账：类型/分层/域/负责人/状态一目了然 |
| 盘点闭环 | 源域自动对账：新发现、变更、源消失全部留痕待确认 |
| 上架管控 | 资产发布上架必经编目前置检查（负责人/描述/目录/分级），可批量 |
| 找得到 | 统一搜索 + 目录树 + 多维过滤（类型/层/域/等级/健康度/标签/状态） |
| 看得全 | 资产 360° 详情：基本信息 + 字段 + 血缘 + 质量 + 安全 + 生命周期 + 使用 |
| 评得准 | 健康度评分（完整性/可信度/活跃度），治理缺口变成待办清单 |

## 三、核心需求

### 3.1 资产自动编目与盘点（对账）

- 每个源域实现统一 `AssetProvider` SPI（复用 task-catalog Reconciler 范式），资产中心定时（每日）+ 手动触发对账。
- 对账产出三类记录：**NEW**（源域新对象自动登记为"待上架"）、**META_CHANGED**（源域名称/描述/结构指纹变化，需人工确认）、**SOURCE_GONE**（源对象消失，资产自动降级归档）。
- 快照字段（名称/描述/分层/域/content_hash）只服务检索与过滤；详情页事实一律实时读源域 SPI。
- 对账分批拉取（单批有上限），禁止无界 list（遵守 home-overview-contract）。
- 无法自动接入的存量对象（如未建模的物理表、外部报表）支持**手工登记**（source_type=MANUAL，自维护描述与访问入口）。

### 3.2 上架状态机与发布管理

- 资产状态：`PENDING 待上架 / PUBLISHED 已上架 / OFFLINE 已下架 / IGNORED 已忽略（抑制）/ SOURCE_GONE 源已消失`。
- **上架前置检查**（可一键补齐默认值）：负责人已设、描述非空、已入目录、安全定级（建议）。定级项仅对物理对象类资产（表/数据集）适用——security 只对 DATASOURCE/DATABASE/TABLE/COLUMN 定级，指标/报表/任务类为 N/A 不算缺口。未满足项红色列出，允许"带风险上架"（留痕）。
- **忽略（IGNORED）**：待上架池/已下架可"忽略"，台账行保留但对账不再复活为待上架（仅刷新在场时间）；源对象指纹再次变化时自动回到 PENDING 并重新记 NEW——否则"忽略"会在下一轮对账中被无限重登记。
- 批量操作：批量上架（逐个预检汇总结论）、批量下架（必填原因 + 预览确认）、批量移目录。
- 上架是**治理门面状态**，不改源域业务状态（模型草稿也可上架为"预生产资产"）；源域删除 → 自动 SOURCE_GONE 并出现在盘点待办。

### 3.3 统一负责人（Owner）

- 资产负责人唯一事实源在资产中心；自动登记时从源域创建人/负责人继承（带出，不手填）。
- 负责人变更需选人（复用平台用户选择器），全程审计留痕。
- 概览与盘点页暴露"无负责人资产"数量并支持一键认领/批量指派。

### 3.4 资产目录与自动编目规则

- 目录树由资产中心拥有（跨域视图），提供**预置模板一键初始化**：按数仓分层（ODS/DIM/DWD/DWS/ADS）+ 业务域两级生成。
- **编目规则**：条件（类型 / 分层 / 名称前缀正则 / 关键字）→ 动作（归入目录 / 打业务标签），带优先级；支持 **dry-run 试跑**（展示将命中资产数与前 N 个样例）后才可启用。
- 新登记资产自动套规则预归目录/预打标签（可改）；规则变更可"重新应用"（预览确认受影响资产数）。
- 源域自身目录/标签（modeling 目录、指标标签）**不回迁、不打通**，在详情页"源域标签"分区只读回显。

### 3.5 跨域业务标签

- 标签字典（编码自动生成、名称手填、颜色可选预置）+ 资产打标（多选）。
- 定位：面向消费侧的业务语义标签（如 `核心资产` `高频引用` `待退役`），与安全分级、源域标签三套体系并列展示、互不覆盖。

### 3.6 资产搜索与发现（资产目录页）

- 统一搜索：名称 / 描述 / 负责人 / 标签，前端单输入框；匹配快照字段；默认排序 = 健康度 ×0.6 + 活跃度分 ×0.4（固定公式见 design §6.5，输入列全为台账派生列，列表零跨域调用）。
- 过滤维度：资产类型、分层、业务域、安全等级、健康度等级（A/B/C/D）、上架状态、标签、目录。
- 卡片/列表双视图；卡片含：名称、类型图标、分层 Tag、安全等级色标、负责人、健康度环、近 30 天浏览数。
- 点击进资产 360° 详情页。

### 3.7 资产 360° 详情

| 分区 | 内容 | 来源 |
|---|---|---|
| 概览 | 基本信息（名称/编码/类型/分层/域/负责人/状态/上下架时间）+ 源域实时属性 | 资产中心 + 源域 SPI |
| 字段 | 表/数据集类字段清单（名/型/注/安全等级） | 源域 SPI + security |
| 血缘 | 上下游血缘局部图 + 跳转全屏血缘图谱 | lineage SPI |
| 质量 | 质量分、规则通过率、最近执行 | quality SPI |
| 安全 | 安全等级/分类、脱敏策略摘要（只读） | `SecurityClassificationQueryApi`（已实现） |
| 生命周期 | 生效 TTL 策略、下发状态（只读） | lifecycle SPI |
| 使用 | 近 30 天**资产页浏览**趋势（本模块流水）+ **数据消费**事实（表类读 lineage 1 跳下游计数、指标读既有 `MetricUsageApi`）——两类语义分列展示不混算 | 资产中心 + lineage/metric SPI |
| 变更 | 上架流水 + 盘点变更确认记录 + 操作审计 | 资产中心 + audit |

- 各分区独立容错：某域 SPI 失败显示"暂不可用"，不伪造为空、不阻塞整页（对齐 home 契约语义）。

### 3.8 健康度评分

- 三部分加权（满分 100）：
  - **完整性 40**：描述(10) · 负责人(10) · 已入目录(5) · 业务标签(5) · 字段注释覆盖率(10)
  - **可信度 40**：质量监控覆盖与通过率(15) · 血缘已登记(10) · 安全已定级(10) · 变更已确认(5)
  - **活跃度 20**：近 30 天浏览(10) · 更新新鲜度(5) · 下游引用(5)
- 不适用项做 **N/A 归一**：得分 = Σ(实得分) / Σ(适用项满分) × 100——非物理对象类无"质量监控/定级"项、MANUAL 无"血缘登记"项等，N/A 项在明细中展示但不进分母，避免结构性不公平（如指标类永远达不到 100）。
- 等级：A ≥85 / B ≥70 / C ≥55 / D <55；评分为纯函数派生，每日定时重算（`YakScheduleNamespaces.ASSET`），不可手改。
- 详情页展示评分明细（每项得分与缺口），治理动作 = 补哪个字段一目了然。

### 3.9 资产概览（治理驾驶舱）

- KPI：资产总数、已上架、待上架、近 30 天新增、负责人覆盖率、已定级率、A/D 级数量。
- 分布：类型分布、分层 × 目录分布、健康度分布、上架状态漏斗。
- 待办区（每项可点击直达处理页并带过滤上下文）：待上架 N、源变更待确认 N、无负责人 N、D 级资产 N、SOURCE_GONE 待归档 N。
- 最近上架/下架动态（有上限 LIMIT）。
- 全部指标服务端聚合 + 固定查询预算，禁止无界加载。

## 七、关键决策

| # | 决策 | 说明 |
|---|---|---|
| D1 | 管目录不管内容 | 资产中心不复制存储业务事实；快照字段仅供检索过滤并标注来源与时间，详情永远实时读源域。资产中心拥有的是：目录、状态、负责人、业务标签、规则、评分 |
| D2 | 复用对账范式 | `AssetProvider` SPI 直接沿用 task-catalog 的 source-neutral + Reconciler 已验证模式，不发明新协议 |
| D3 | 上架 ≠ 源域发布 | 资产上架是治理门面状态，与模型发布/指标生效等业务状态正交；源对象消失自动 SOURCE_GONE |
| D4 | 负责人唯一事实源在资产中心 | 回写源域会制造双源冲突；源域自身创建人仅在登记时作为默认值带出 |
| D5 | 不新建任何字典 | 分层/业务域引用 semantic，安全等级引用 security，均为快照展示与过滤，源头不改 |
| D6 | 不动 `yak_metadata_asset` | 血缘图节点表归 lineage 拥有；资产详情内嵌血缘局部图并按 assetKey 跳转全屏图谱，双向可去不互写 |
| D7 | 健康度是派生值 | 纯函数 + 定时重算 + 明细公开，杜绝人工"改分" |
| D8 | 本期无审批流 | 具备 `data-asset:update` 权限者可直接上架（预检留痕）；审批对接 workflow 列入范围外 |
| D9 | 搜索走 DB 索引 | 名称/描述 LIKE + 组合索引起步；ES/向量检索列入范围外，接口预留 `searchText` 抽象 |
| D10 | 交互原则强制 | asset_key/编码自动生成、登记从源域带出全部已知信息、上架预检支持一键补默认、危险操作（批量下架/规则重应用）必经预览确认 |
| D11 | project 隔离 + 统计预算 | 全表 `project_id` 取服务端可信上下文；所有概览/排序查询固定次数 + LIMIT，遵守 PROJECT_SCOPE 与 home-overview-contract |
| D12 | 无行级权限 | 资产中心只有功能权限（`data-asset:*`）；负责人是**治理联系人**而非访问权限主体——数据级"谁能读什么"仍归 security（其 D2 分层），本模块不建 ACL 表、不做行级过滤 |

## 八、和现有模块的关系

| 模块 | 关系 |
|---|---|
| modeling / metric / dataset / dashboard / task-catalog | 资产**来源域**：实现 `AssetProvider` 供对账；详情属性经其 Query SPI 实时读取 |
| lineage | 详情血缘 Tab 读其查询服务；assetKey 对齐其节点键实现跳转 |
| quality / security / lifecycle | 详情对应 Tab 的只读数据源；security 等级同时是目录页过滤维度（读快照） |
| semantic | 分层/业务域字典来源（目录模板、过滤项预置） |
| datasource | 范围外能力的未来入口（物理表自动编目需元数据采集，见九） |
| home | 首页契约不变；未来资产视角 KPI 经 `AssetCatalogApi` 消费，不直连表 |
| yak-security / audit / yak-schedule | 权限注解与用户选择器 / 操作留痕 / ASSET 命名空间定时任务 |

| 数字大屏资产 | digital-screen 当前为浏览器 localStorage 实体（见 home-overview-contract），无服务端真相源可盘点，具备服务端持久化后再接入 |
| 收藏夹 / 个人工作台 | P2 视反馈再排 |
| 跨 project 资产共享 | 与平台隔离模型一致，不做 |

# 第二部分：方案总览

> 详细实体、流程与契约见 [design.md](./design.md)，此处只给一页骨架。

## 1. 整体架构

```
 ┌─────────────────────────── data-ops-business-asset ───────────────────────────┐
 │  provider   AssetProvider SPI 聚合 + 每日/手动对账(分批游标)                   │
 │  item       台账 CRUD + 快照 upsert + 状态机(PENDING/PUBLISHED/OFFLINE/GONE)  │
 │  catalog    目录树 + 编目规则(条件→动作, dry-run) + 业务标签                    │
 │  health     健康度纯函数评分 + 每日重算 + 明细                                  │
 │  discover   搜索/过滤/排序 + 360°详情聚合(SPI fan-out, 分区容错)               │
```

## 3. 闭环

```
① 对账: 源域扫描 ──② 登记: 自动入台账(套规则预编目) ──③ 预检: 负责人/描述/目录/定级
      ▲                                                        │一键补齐
      │                     ④ 上架: 单个/批量(风险留痕) ◀───────┘
      │                                │
      │                     ⑤ 发现: 搜索/目录/详情360° ──▶ 消费
      │                                │
      ⑧ 归档: SOURCE_GONE ◀── ⑦ 评分: 健康度每日重算 ──⑥ 盘点: 变更确认/下架/移目录
```

## 4. 一句话总结

> 数据资产中心：源域留事实，此处留账本 —— 自动对账登记，规则预编目，预检即上架，搜索即发现，评分即治理；**平台管目录，不管内容**。
