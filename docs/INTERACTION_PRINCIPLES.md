# Yak Ops Interaction Principles

本文件定义 Yak Ops 全平台的交互设计原则。

目标不是堆功能，而是让用户在操作时"少填、少选、少记"。

核心原则：**能默认就默认，能选择就不填写，能引用就不重复，能自动就手动。**

## 1. 核心原则

> 能默认就默认，能选择就不填写，能引用就不重复，能自动就手动。

四个层次，优先级从高到低：

| 层次 | 做法 | 用户负担 |
|------|------|----------|
| 1 | 自动生成 | 零 |
| 2 | 默认值 | 零（可改） |
| 3 | 选择 / 引用 | 低 |
| 4 | 手填 | 高 |

规则：能用 1 就不用 2，能用 2 就不用 3，能用 3 就不用 4。

## 2. 每个字段自问四句话

1. 能不能自动生成？
2. 能不能给默认值？
3. 能不能用选择 / 引用？
4. 只有都不能，才让用户手填。

## 3. 编码类字段：优先自动生成

| 字段 | 自动规则 |
|------|----------|
| 分层库名 | `{layer}_db` |
| 分层命名标准 | `naming_table_{layer}` |
| 码值标准编码 | `{码集编码}_{码值}` |
| 业务过程编码 | 从名称生成（可选） |
| 标准字段编码 | 从名称生成（可选） |

## 4. 配置类字段：优先默认值

| 字段 | 默认值 |
|------|--------|
| 存储格式 | `Parquet` |
| 默认分区 | `dt=yyyyMMdd` |
| 生命周期 | ODS=永久、DWD/DWS=365、ADS=180 |
| 排序 | 自动递增 |
| 统计周期 | `DAY` |
| 状态 | `ENABLED` |

## 5. 引用类字段：优先选择 / 引用

| 字段 | 来源 |
|------|------|
| 类型标准 | 从标准库选，按字段名推荐 |
| 单位标准 | 从标准库选，按类型推荐 |
| 口径标准 | 从标准库选，按类型推荐 |
| 码值标准 | 从标准库选，按字段名推荐 |
| 依赖模型 | 从建模工作台选 |
| 业务域 | 从业务域树选 |

禁止让用户手填标准编码。

## 6. 名称类字段：唯一需要手填

| 字段 | 说明 |
|------|------|
| 名称 | 业务名称，无法自动 |
| 描述 | 可选 |
| 负责人 | 可选 |

## 7. 推荐机制

| 场景 | 推荐规则 |
|------|----------|
| 字段名含 `amount` | 推荐类型"金额"、单位"元"、口径"GMV" |
| 字段名含 `status` | 推荐类型"状态"、码值"订单状态" |
| 字段名含 `time`/`date` | 推荐类型"时间" |
| 选类型"金额" | 推荐单位"元" |
| 选类型"数量" | 推荐单位"件"、"个" |

推荐不是强制，用户可改。

## 8. 禁止事项

| 禁止 | 原因 |
|------|------|
| 让用户手填标准编码 | 应引用标准 |
| 让用户手填库名 | 应按分层生成 |
| 让用户手填存储格式 | 应下拉 |
| 让用户手填枚举值 | 应引用码值标准 |
| 让用户重复输入已知信息 | 应自动带出 |
| 让用户填写可从其他字段推导的字段 | 应自动推导 |

## 9. 例外：必须手填的字段

| 字段 | 理由 |
|------|------|
| 名称 | 业务语义 |
| 描述 | 业务语义 |
| 负责人 | 组织信息 |
| 自定义计算规则 | 口径标准未覆盖时 |
| 自定义 SQL | 复杂逻辑 |

即使是这些，也要给示例、给提示、给校验。

## 10. Review Checklist

设计表单时确认：

1. 每个字段能否自动生成？
2. 不能自动，能否给默认值？
3. 不能默认，能否用选择 / 引用？
4. 只有都不能，才让用户手填。
5. 手填字段是否给了示例、提示、校验？
6. 是否让用户重复输入了已知信息？
7. 是否让用户填写了可从其他字段推导的字段？
