# P0 · Data Service 集市与 API 详情读取真实性（#180 / #336）

## 主线核查（2026-10-09）

#454 已合并。其真实改动仅覆盖运行概览、最近调用记录、API Console Debug；本批不重复修这些页面。

本批经最新 main 确认的缺陷：
- 集市将主 API 列表、可选数据源名称、最近调用日志 `Promise.all` 绑成一体。任一可选调用失败导致整个集市加载失败；失败后保留旧列表或旧 Project 的 API；仅 toast，无显式错误/重试；统计不可用易误判为零次调用。
- API 详情将主 getDataService 与可选数据源名称捆绑，运行状态 / Keys 的任何失败会让页面只 toast，却可能显示已取到的主对象和伪零指标；主请求失败可能留下前一次 API 信息，或被空态归为“未找到 API”。
- 集市和详情自身未以 Project/权限码为组件生命周期边界，旧请求归属可能跨页面上下文。

## 批量修复的四个相互关联的场景

1. **主列表真正失败**：请求开始清理之前读到的 API 列表、详情导航目标、辅助统计；只有主列表成功才显示真实 EMPTY。403 明示不可读，500/超时明示不可用，提供重试。加载中不显示“没有 API”的假空态。
2. **辅助来源隔离**：数据源名称与最近调用统计采用 `Promise.allSettled`，单一来源故障不阻断集市主体。源名称降级到 ID 且警示，调用统计不可用显示破折号及警示，不得显示 0 / “暂无调用”。业务没有授予观察权限则不发出调用日志请求。
3. **详情主对象正确性**：重新读取/切换后清理前一对象和所有 runtime/key/log/source 缓存。API 读取 403 展示 FORBIDDEN，404 仅展示“可能不存在或当前 Project 无权查看”，不据 404 自证真实删除；网络失败独立显示 UNAVAILABLE + 重试。
4. **详情局部故障**：数据源名称、运行指标、Key 列表分别失败时保留真实 API 主对象，警示并阻止将未知 Key/指标显示为成功空值。Key 来源不可用时不将未核实密钥列表作为合法管理依据。来源审计 / Invocation / Usage、权限判断依然由后端所有权域负责。

所有入口按当前 Project ID 和 permissionCodes 重挂载，旧请求由单调 epoch 及 effect cleanup 废弃。没有修改 API Key 授权逻辑、Consumption 持久 Usage 或 Data Service SourceRevision/Invocation Audit。

## 验收级别

新增 Jest hook 反例：可选来源失联、无调用统计权限、真实主列表 403 与恢复、异步旧结果覆盖、新 Project 卸载；API Detail 反例：403/404、只读辅助失联、不同 Project 旧响应不得伪装成功，以及分类纯函数。CI 结果以本 PR 的**最终 HEAD**为准。
