## Standards：展示规范问题

### S1 · P2 · 内部故事编号进入用户页面

- `HomeTaskStarter.tsx:42` 展示 `entry.story`；`homeJourneyEntries.ts:38/44/50` 对应 `GM-J1/GM-J3/GM-J4`。这是故事映射编号，没有任务名称、状态或实际业务对象身份，无法帮助用户行动。

依据：`PRODUCT_STYLE.md §4.3`“用户按任务完成工作，不应该学习 Maven module 结构”。建议不渲染故事编号，内部映射留在测试、代码元数据或文档。

### S2 · P2 · 研发语言成为页面说明

- `HomeTaskStarter.tsx:87/120` 将“不创建新的业务流程或事实”“分别由原域管理”等研发合同写成首页说明。
- `homeJourneyEntries.ts:43/76` 将“不经过生产者 Dataset 管理”“仍须原域授权和真实证据”等实现边界写进入口描述。
- `HomeProjectPulse.tsx:149–154/165` 将 `Home / DataSource`、`Modeling`、`Home Cockpit`、`Run`、领域事实归属和未知值处理规则直接展示。

依据：`PRODUCT_STYLE.md §4.6`“不把内部机制暴露成用户心智”。实现说明属于明确应收敛的内容。字数与布局选择属于设计判断。

建议：删除研发声明，保留用户用途。统计范围改为中文业务口径，集中到可点击、可键盘访问的帮助说明，避免仅悬停可见。

### S3 · P3 · 同一统计重复出现且状态表达不一致

`HomePage.tsx:24/29` 同时呈现旧 `HomeHeader` 和新增 `HomeProjectPulse`。数据源、运行中数量在页头与项目概况各出现一次。页头不可用显示 `--`，新卡显示“暂不可用”；新卡未知显示 `—`。重复信息新增了比较成本，也让同一事实看起来像两套统计。

依据：用户本次要求“简洁、规范、统一”；这是新增概况与保留旧首页组合后的体验问题，不是认定原页头在本 PR 被修改。

建议：计数集中在项目概况，页头保留简短品牌与项目上下文。统一加载、未知、不可用状态。保留数字 `0` 的真实零值含义。

## Spec：名称与实际行为不一致

### P1 · P2 · “实时读模型”承诺了当前不存在的持续更新

`HomeProjectPulse.tsx:167` 展示“实时读模型”。该组件在 scope 变化时请求统计，`useHomeCockpit.ts:18–35` 在挂载或项目变化时请求，没有轮询或订阅，也没有展示逐统计观测时间。页面保持打开时，用户可能将旧数值理解成持续更新的现状。

依据：Home `REQUIREMENTS.md`“无法证明的指标不使用其他字段替代”；本 PR 要求读取真实 Owner 事实。更新时效同样需要证据，不能由来源是读模型就推导为实时。

建议：删除该标签。若以后展示更新时间，应绑定真实的对应统计时间，不能用单一 Cockpit 时间代表六个独立读取的领域。本次无需为文案治理新增轮询功能。

### P2 · P2 · 建设入口的固定说明不符合权限落点

`homeJourneyEntries.ts:37–39` 的建设说明固定从来源、ODS 开始，但同一入口可按授权直接落到建模工作台。只有建模权限的用户看到的说明与可进行的下一步不一致。

依据：F-008“用户应能按任务选择已有能力”，其范围“不增加业务实体、状态机或第二份真相”；PR #560 的结果要求是“直接到已有真实 Owner 工作台”，不新增跨域任务事实。

建议：用途说明表达该类工作的目的，CTA 继续取实际目的地名称。避免承诺当前落点并不直接提供的完整建设或恢复流程。

### P3 · P2 · 运行统计范围缺少用户可理解的解释

`HomeProjectPulse.tsx:154` 用“Home Cockpit 汇总，非统一 Run”解释“运行中任务”，用户仍无法判断其覆盖范围。`HomeCockpitReader.java:43–48` 实际仅合计离线同步、工作流、质量检查，不包含 DataDev。

依据：PR 要求保留原统计语义，`PRODUCT_STYLE.md §4.6` 要求“不把内部机制暴露成用户心智”。建议在统计帮助中明确三个业务来源。这一项关注口径可理解性，与 Standards 轴的内部措辞问题分别记录。

另有命名优化建议：`HomeTaskStarter.tsx:84` 的“从当前任务开始”下方是静态入口，建议改为“开始工作”；此处不构成要求新增任务列表的功能缺陷。

## 统计口径保留方案

默认统计卡保留名称、数值/状态、合法跳转提示。统计口径的具体内容建议如下；不改变既有读取或计算。

| 名称 | 帮助说明 |
| --- | --- |
| 数据源 | 当前项目的数据源数量。 |
| 物理模型 | 当前项目的物理模型数量，不代表已部署表数。 |
| 指标定义 | 指标定义总数，不等同于已发布指标数。 |
| 表资产 | 表资产数量，不等同于已上架数量。 |
| 今日质量异常表 | 今日质量检查发现异常的表数量。 |
| 运行中任务 | 离线同步、工作流与质量检查的运行中数量汇总。 |

运行口径依据 `HomeCockpitReader.java:43–48`，不应误称为 DataDev 执行数或全部业务域执行数。保留现有卡片名称时，帮助必须让范围可发现。

建议页面统一使用“加载中”“暂不可用”“—”（未知）和真实 `0`。未知占位可补充无障碍名称“暂无统计数据”。不要为了视觉统一将失败、未知和真实零合并。

## 页面级收敛与实施范围

1. 第一批：移除故事编号、研发声明、统计来源标签；修正区块标题和“实时”；缩短用途说明。
2. 同一批核对：统计口径可发现、按授权回退的 CTA 与说明相符、空态提供下一步。
3. 页面组合：项目概况承载唯一主要统计；页头只保留简短身份/品牌。原有快速创建和快捷导航保留功能，其默认展示层级另做页面走查，不在静态审查中自动删除。
4. 统一文案沿用现有 locale 体系；新组件的中文硬编码与旧首页 `useIntl` 混用，后续替换时应同时核对中英文，避免语言切换后局部仍为中文。

不将 PROPOSED PD-010、DRAFT F-040 或历史原型转换为实施合同。保持现有工作入口、菜单码、API、项目和角色边界，避免把内容治理扩大为新任务中心或新统计能力。

## 验收清单（待实施后执行）

- 首屏和“更多工作入口”展开后，不出现 `GM-*`、内部模块来源或研发合同声明；任务详情、定位链接和日志仍保留真实对象身份。
- 三张主卡各有清楚的工作目的、简短用途和对应实际落点的动作；无额外研发页脚。
- 只有建模权限、只有质量/执行权限、无主入口、无项目时，说明与能做的操作一致；隐藏入口不扩大授权。
- 同一计数有一个主要展示位置；加载、未知、失败和真实 `0` 可区分；统计帮助可通过鼠标、键盘和触屏访问。
- 页面停留不会被未经证实的“实时”标签误导；口径明确区分模型/部署、指标定义/发布、表资产/上架。
- 中英文及 390/768/1440px 视口检查标题、单句说明、按钮名称和项目上下文；点击仍进入原专业页。
- 若只调整展示，复用现有权限/菜单/项目范围回归与适当的前端检查，不新增仅比对文案常量的测试；真实浏览器结果单独留证。

本次结论：Standards 三项（两个规范问题、一个体验判断），Spec 三项，最高均为 P2。前者主要问题是内部信息进入首屏；后者主要问题是名称、说明与实际行为不一致。两轴存在交集，不将六项解释为六个互不重叠的缺陷。当前没有治理后的验收证据。
