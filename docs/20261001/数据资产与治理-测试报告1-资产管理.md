## 二、缺陷清单

### A1-01 (P2)【已修复】资产目录点击资产行无任何详情反馈
- **复现**：资产目录 → 点击任意资产行（如"订单聚合天表"）。
- **实际**：仅行选中高亮，无详情面板/抽屉/跳转；用户无法查看资产详情（负责人、健康度构成、标签、血缘入口等），只能看行内展开的治理建议摘要。
- **建议**：行点击打开详情抽屉（"管目录不管内容"理念下，至少应展示台账字段全量与源域跳转）。
- **证据**：![点击行后无详情](screenshots/a1_catalog_asset_detail.png)
- **修复（2026-10-01）**：`catalog/index.tsx` 表格增加 `onRow` 点击跳转 `/data-asset/detail/{id}`（行内链接/按钮/勾选框/文本选择不触发），并加 `cursor-pointer`。回归：点击"订单表"行 → 跳转 `/data-asset/detail/15` ✅

### A1-03 (P2)【已修复】手工登记的资产无删除路径
- **复现**：资产目录 → 手工登记一个测试资产 → 尝试删除。
- **实际**："待上架"状态下"删除"按钮禁用；点击"忽略"（确认忽略成功，忽略按钮转为禁用）后"删除"仍禁用。错误登记的记录无法从台账清除，只能永久留痕（仅可忽略）。
- **建议**：为手工登记（manual:* 编码）资产提供"撤销登记"入口；或忽略态允许删除。物理表/模型等源域资产保持现有防误删策略合理。
- **证据**：![删除始终禁用](screenshots/a1_catalog_delete_disabled.png)、![忽略确认](screenshots/a1_catalog_risky_shelf.png)
- **修复（2026-10-01）**：
  - 后端 `AssetAppService.delete`：新增 `MANUAL_DELETABLE_STATUS`（PENDING/OFFLINE/IGNORED）——手工登记无源域对象、不参与对账，不存在"源域仍存在"的误删风险；已上架仍须先下架。新增单测 4 项（PENDING/IGNORED 可删、PUBLISHED 须先下架、非手工 PENDING 仍拦截）。
  - 前端 `catalog/index.tsx`：删除按钮按 `isDeletable`（源类型+状态）判断可用，并补充删除确认弹窗（与忽略/下架的确认模式一致）。
  - 回归：MANUAL+IGNORED 资产删除成功（toast"已删除台账行"），测试残留数据一并清理 ✅

### A3-01 (P2)【已修复】变更确认"差异摘要"列显示空对象 "{}"
- **复现**：盘点上架 → 变更确认 tab。
- **实际**：差异摘要列全部显示字面量 `{}`，无任何差异信息；确认框文案"将用快照新值覆盖…展示字段"也无法说明具体变了什么。
- **建议**：渲染结构化差异（字段级 before → after），空差异显示"无字段变更（快照刷新）"。
- **证据**：![差异摘要为{}](screenshots/a3_inventory_changes.png)
- **根因**：后端对 NEW/REAPPEARED 不落 diff（存 null），但 API 序列化把 null 归一成空对象 `{}`，前端空对象为 truthy 直接 `JSON.stringify`。
- **修复（2026-10-01）**：`constants.ts` 新增 `formatChangeDiff(changeType, diff)` 纯函数——按变更类型给出语义说明（NEW→"首次登记，无对比基线"、META_CHANGED 空 diff→"内容指纹变化，展示字段无差异"），有 diff 时渲染字段级"中文字段: 旧值 → 新值"（previousStatus/goneAt 走状态/时间翻译）；`inventory/index.tsx` 差异摘要列改用该函数 + Tooltip。新增单测 4 项。回归：新登记/元数据变化行均显示可读摘要 ✅ ![修复后差异摘要](screenshots/fix_a3_01_diff_summary.png)

### A2-01 (P3)【已修复】概览分布图颜色语义不一致
- **实际**："按状态分布"四个状态条全部使用品牌粉色；而同页"按健康度分布"使用语义色（未评分=灰、D=红、B=蓝）。状态本身有语义（待上架=黄、已上架=绿、已忽略=灰），统一粉色削弱可读性。
- **证据**：![状态分布全粉色](screenshots/a2_overview_bottom.png)
- **修复（2026-10-01）**：`constants.ts` 新增 `ASSET_STATUS_BAR_COLORS`（待上架橙/已上架绿/已下架灰/已忽略浅灰/源已消失红，与状态标签口径一致）；`overview/index.tsx` 状态分组改用语义色，类型/分层（无语义的分类维度）保留品牌色。新增单测 1 项。回归通过 ✅ ![修复后语义配色](screenshots/fix_a2_01_status_colors.png)

### G-A3 (P3)【复测撤项：非产品缺陷】搜索框编程清空后不触发刷新
- **初测现象**：脚本 `fill("")` 清空 + 点击搜索后仍显示旧关键字结果；使用输入框自带的 close-circle 清空按钮正常。
- **复测（2026-10-01）**：在资产目录实测四种方式——
  - `fill("")`：输入框值不变（自动化工具对 React 受控输入的清空限制）；
  - **逐字符退格 + 搜索按钮**：值清空、列表恢复全量（21 行）✅；
  - **allowClear X 按钮**：触发 onSearch 刷新，列表恢复全量 ✅；
  - antd Search 源码确认：X 清空走 `onSearch('', {source:'clear'})`，搜索按钮读取输入框实时值，两条用户路径均正确。
- **结论**：真实用户清空路径（X 按钮 / 键盘清空）均正常，初测观察为自动化工具限制。撤销该项，不修改产品代码。
