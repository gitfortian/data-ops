## 一、总体结论

**功能整体完成度和稳定性较好**：10 个页面的主流程（列表展示、筛选搜索、新建、编辑、删除、引用保护）全部走通，未发现阻断性（P0）故障；引用保护、软删除、版本管理等治理机制运转正常。

共发现 **22 个问题**：**P1 功能缺陷 2 个、P2 体验缺陷 7 个、P3 打磨问题 13 个**。另有 9 条面向商业产品迭代的体验改进建议。

最需要优先处理的三件事：
1. **T1-01**：编辑业务域时清空必填"名称"仍提示"已更新"——必填校验在新/编辑两种模式不一致，且反馈误导用户（P1）。
2. **T7-03**：指标验证执行失败（FAILED）后，失败原因完全不可见——用户被发布门禁 BLOCKED 卡住却无法知道如何修复，验证闭环断裂（P1）。
3. **G1 全局**：多个列表页在 1280px 宽度下表格横向溢出，"操作"列不可见；且搜索/筛选触发后页面横向滚动位置错乱、标题被截断（P2）。

> 说明：本次测试工具不支持读取浏览器 console 日志，错误证据均来自页面可见表现（toast、错误通知、空白、布局异常），已在相应条目标注。

> **修复完成（2026-10-02）**：22 项中 **17 项已修复并回归验证**，**3 项复测确认为误报/已满足予以撤项**（T1-01、T2-03、T7-04），**2 项受损于产品范围而未实现、已转为改进建议**（T10-01 的分布维度需要后端聚合、T9-01 的术语表沉淀）。明细见第七节「修复记录」。

## 三、缺陷清单

### P1 — 功能缺陷（建议本迭代修复）

#### T1-01 业务域"编辑"缺少必填校验，空名称保存仍提示成功
- **复现步骤**：业务域 → 选中"订单"节点 → 详情面板点"编辑" → 清空"名称" → 点"保存"。
- **实际结果**：对话框关闭，弹出绿色成功提示"业务域已更新"；但树与详情中名称仍为"订单"，数据实际未修改。
- **预期结果**：与"新建根域"对话框行为一致——前端拦截并显示"请输入名称"（新建模式校验已验证正常，见截图 t1_domains_new_empty_submit.png），或后端返回明确错误。
- **影响**：用户以为改名成功，实际未生效；新/编辑校验不一致会让用户对系统信任度下降。
- **证据**：![编辑清空名称后仍提示成功](screenshots/t1_domains_edit_empty_name.png)

#### T7-03 指标验证失败后失败详情不可见，验证闭环断裂
- **复现步骤**：指标管理 → 打开"优惠占比（discount_rate_1d）"详情 → 点"验证当前版本 v3" → toast 提示"v3 验证完成：FAILED" → 点"刷新证据"。
- **实际结果**：页面始终显示"当前版本尚无验证证据"，门禁保持 `metric-definition-validation-gate/v1: BLOCKED (DEFINITION_VALIDATION_PASSED_EVIDENCE_REQUIRED)`；无任何位置展示失败原因、失败检查项列表或验证历史。
- **预期结果**：失败后应展示验证报告（哪个检查项失败、缺什么证据、如何补齐），或至少在"发布历史/证据"区域记录本次 FAILED 记录。
- **影响**：指标发布门禁 BLOCKED 后用户无法自助修复，流程卡死。
- **证据**：![验证FAILED后页面无失败详情](screenshots/t7_metric_validate.png)、![刷新证据后仍无变化](screenshots/t7_metric_refresh_evidence.png)

### P2 — 体验缺陷（建议排入近期迭代）

#### T2-01 列表页搜索/筛选后页面横向滚动位置错乱
- **复现**：业务过程页（其他筛选列表页同样）→ 在搜索框输入关键词点击搜索。
- **实际**：主内容区整体横向偏移，页头标题"业务过程"被截断为"过程"，编码列不可见；第二次筛选时复现（截图 t2_processes_filter_pay.png 同样偏移）。筛选、清空等操作后偶发。
- **预期**：内容区横向滚动独立于页头，或搜索后滚动位置复位。
- **证据**：![搜索后标题被截断](screenshots/t2_processes_search.png)

#### T3-02 版本=1 的数据标准没有"版本"入口
- **复现**：数据标准 → 新建一个码集（版本1）→ 查看其操作列。
- **实际**：操作列只有"编辑/停用/删除"，无"版本"按钮；只有版本≥2 的记录（如 order_status v3）才显示。用户无法查看初始版本内容。
- **建议**：版本按钮常显，v1 显示单条记录。
- **证据**：![v1记录无版本按钮](screenshots/t3_standards_created.png) 对比 ![v3记录有版本按钮](screenshots/t3_standards_initial.png)

#### T4-01 创建成功后无法定位新记录
- **复现**：标准字段页（共149条）→ 新建标准字段 → 保存成功 → 列表仍停留在第一页。
- **实际**：新字段不在当前页，也无提示；只能靠搜索找到。对比：指标管理页创建后新记录置顶显示、统计卡片实时+1（体验正确）。
- **建议**：创建成功后跳转/滚动定位到新记录并高亮，与指标管理行为对齐。
- **证据**：![创建成功但列表无新记录](screenshots/t4_fields_created.png)

#### T6-01 模型列表行点击仅选中，无详情预览
- **复现**：模型工作台 → 点击"下单表"行或名称。
- **实际**：仅行高亮选中，无任何详情反馈；查看模型必须经"更多 → 详情"或"编辑"。
- **建议**：行点击进入详情页（与"详情"菜单一致），名称做成链接。
- **证据**：![行点击后仅选中](screenshots/t6_model_detail_panel.png)

#### T6-05 主线视图无返回列表控件
- **复现**：模型工作台 → 切换"主线视图"。
- **实际**：进入独立页面"业务过程主线视图"后，页面无"返回列表"/视图切换控件，只能通过左侧导航重新进入模型工作台。
- **证据**：![主线视图无返回控件](screenshots/t6_modeling_mainline_view.png)

#### T7-02 验证失败（FAILED）使用绿色成功样式提示
- **复现**：同 T7-03 步骤。
- **实际**：toast 为绿色成功图标 + "v3 验证完成：FAILED"，语义矛盾——失败结果用成功样式呈现。
- **预期**：验证失败应使用警告/错误样式，或区分"执行完成（结果为失败）"两种信息层级。
- **证据**：![FAILED却显示绿色成功](screenshots/t7_metric_validate.png)

#### T7-04 聚合函数仅有 SUM / COUNT
- **复现**：新建指标 → 原子指标 → 展开度量表达式聚合函数下拉。
- **实际**：只有"求和 SUM""计数 COUNT"两项；缺少 AVG、MAX、MIN、COUNT(DISTINCT) 等常用聚合，无法表达"人均""客单价""最高价"类指标（现有 atv_1d 客单价等指标应无法通过界面新建）。
- **证据**：![聚合函数仅两项](screenshots/t7_metric_form_filled.png)（下拉截图见测试过程记录）

#### G1 多页表格在 1280px 视口下操作列不可见
- **涉及**：业务过程（10列）、数据标准（10列）、数仓分层（14列）、指标管理（15列）。
- **实际**：操作列（编辑/删除等）被挤出视口，需横向滚动才能操作；数仓分层页新建分层对话框也超出 720p 高度（T5-01，见 t5_layers_new_dialog.png）。
- **建议**：操作列固定右侧（sticky），次要列默认折叠（配合已有"列设置"能力）。
- **证据**：![业务过程操作列被截断](screenshots/t2_processes_initial.png)、![数仓分层14列](screenshots/t5_layers_initial.png)

## 四、面向商业产品迭代的改进建议（按优先级）

1. **统一"创建后定位"体验**（T4-01 vs 指标管理的正确示范）：所有列表页创建成功后定位并高亮新记录。
2. **表格横向空间治理**（G1）：操作列 sticky 右固定；宽表默认隐藏低频列；1280px 作为最低支持分辨率做一轮回归。
3. **验证/门禁结果人性化**（T7-01/02/03 一揽子）：中文展示门禁结论，FAILED 给出失败项与修复指引，成败样式区分。
4. **校验一致性专项**（T1-01）：新建与编辑共用同一套表单校验规则；建议对全部表单做一次"编辑模式清空必填项"回归。
5. **危险操作与确认策略统一**（T3-04 vs 解绑无确认）：为确认弹窗制定规则——影响已持久化数据的操作需确认，表单内未保存变更不确认；删除与编辑按钮保持间距或收纳进"更多"。
6. ~~**血缘/影响图布局优化**（T6-02）：分层 DAG 布局替代单列堆叠~~ **已修复（2026-10-01）**：共享布局组件增加行距压缩 + 重心排序，三处血缘整图可读；后续可对超宽扇出增加节点聚合。
7. **文案本地化专项**（T2-02、T7-01、T9-01、T10-03）：建立中文术语表（标准/业务过程/指标等），清理英文残留与技术串直出。
8. **指标表达式能力**（T7-04）：补齐 AVG/MAX/MIN/COUNT DISTINCT/去重计数，这是指标体系的基础能力。
9. **无障碍细节**（T6-03、T10-03）：图标按钮补充 aria-label 与 tooltip；操作元素使用语义化 button。

### P1 — T7-03 校验失败详情不可见（根因：只读「最近通过」）

面板原先只调 `GET /versions/{v}/validation/latest-ready`，该接口按定义只返回 **PASSED** 证据，于是失败的那次对 UI 完全不可见——页面永远显示「当前版本尚无验证证据」。改为读取完整证据历史 `GET /versions/{v}/validations`（后端按 `checkedAt DESC` 返回），取第一条作为「最近一次尝试」另单独推导「仍持有的通过证据」。

- **为什么保留两者**：门禁是按「存在 PASSED 证据」放行的，只显示最近一次会让用户以为门禁在乱拦；反之只显示通过证据又会把失败藏起来。
- 代码：`data-ops-ui/src/pages/metric/detail/MetricGovernancePanel.tsx`
- 回归：优惠占比 v3 现在显示「最近一次校验 v3 · 未通过 · 校验源就绪」并列出 4 条失败项（必须指定指标负责人 / 必须绑定口径标准 / 必须绑定单位标准 / 复合指标必须固化至少一个操作数），各带 code 与字段名。

### P2 — G1 + T2-01 宽表横向溢出（一处改法，四处受益）

实测发现真实情况比报告描述的更糟：业务过程表内容宽 1290px、容器 950px，祖先带 `overflow-hidden` **直接裁掉**操作列且无法滚动（`document.scrollWidth == 视口宽`，页面根本没横向滚动）。而搜索后位置错乱（T2-01）正是因为聚焦元素时浏览器把那个 `overflow-hidden` 容器滚动走了。

修法：给表格 `scroll={{ x: 'max-content' }}` 让宽表在表内滚动，并把「操作」列 `fixed: 'right'` 钉住。五个页面对齐：业务过程、数据标准、数仓分层、标准字段、指标管理（指标管理本是唯一做了 `scroll={{x}}` 的，本次补齐其余四处）。

- 回归：5 页均 `document.scrollWidth == 视口宽`、仅 `.ant-table-content` 自身滚动、`.ant-table-cell-fix-right` 数量 > 0；横向滚动后操作列保持吸附。
