## 二、缺陷清单

### Q2-03 (P2)【已修复】注册数据表后无"注销/移除"入口
- **复现**：数据表监控 → 注册数据表（选 crm_customer）→ 注册成功 → 查看该行操作。
- **实际**：操作列只有"新增监控 / 规则管理"，无注销/移除；误注册的表无法从监控列表移除。注册产生的监控与规则同样无删除入口（规则管理页仅见"测试运行/···"）。
- **影响**：测试或误操作产生的监控配置永久残留，长此以往监控列表会成为垃圾场（本环境已残留 1 表 + 1 监控 + 1 规则 + 1 条执行记录）。
- **建议**：提供"注销数据表"（级联确认其监控/规则）与监控/规则的删除能力。
- **证据**：![注册后无注销入口](screenshots/q2_table_registered.png)
- **根因**：后端 `DELETE /quality/table-assets/{id}`（`QualityTableAssetManager.unregister`，含"已被监控使用则拒绝"保护）与前端 API `deleteQualityTableAsset` **均已存在，但从未被任何页面调用**——纯前端漏接线。
- **修复（2026-10-02）**：
  - 数据表监控操作列新增"取消注册"，接线到已有 API；`monitorCount > 0` 时按钮 hover 提示并给出引导 toast（"该表已配置 N 个监控，请先删除监控后再取消注册"），避免让后端抛错；成功后刷新列表。
  - 监控删除入口经核查已存在（监控详情页"更多操作 → 删除质量监控"，带确认框"删除后将保留历史执行记录"）；规则删除已存在（编辑监控 → 规则行"删除"）。初测未发现，属入口较深，非功能缺失。
- **回归**：crm_customer（含 1 监控）点击取消注册 → 正确拦截并提示；删除监控后再次取消注册 → 成功（toast"已取消注册「crm_customer」"），列表回到空态。测试残留数据一并清理 ✅
- **证据**：![取消注册入口](screenshots/fix_q2_03_unregister_entry.png)、![监控引用保护](screenshots/fix_q2_03_guard.png)、![注销成功](screenshots/fix_q2_03_unregistered.png)

### Q2-02 (P3)【已修复】添加规则后"已选择 N 条"计数不刷新
- **复现**：新增监控 → 添加规则 → 选择"表行数"模板 → 确定添加。
- **实际**：规则表格已显示 1 条规则，但上方计数仍为"已选择 0 条"。
- **证据**：![计数未刷新](screenshots/q2_rule_added.png)
- **根因**：该计数绑定的是表格勾选框 `selectedRowKeys`，而勾选列**没有任何批量操作消费它**（无批量删除等），因此计数永远与"已添加规则数"无关，语义误导。
- **修复（2026-10-02）**：移除无语义的勾选列与该计数，改为显示真实的"共 N 条规则"（随增删即时更新）。抽屉内"已选择 N 条规则"计数保持不变。
- **回归**：编辑监控 → 规则区显示"共1条规则"（与实际 1 条一致）✅ ![修复后](screenshots/fix_q2_02_rule_count.png)

### Q2-01 (P3)【已修复】规则模板树展开时文本出现蓝色选中高亮
- **复现**：新增监控 → 添加规则 → 双击/点击展开"完整性"分类。
- **实际**：模板节点"表行数 TABLE_ROW_COUNT / 字段非空 COLUMN_NOT_NULL"文字出现浏览器默认的蓝色选中样式（文本被拖选），视觉异常。
- **证据**：![模板文字选中高亮](screenshots/q2_rule_templates_expanded.png)
- **修复（2026-10-02）**：规则模板 `Tree` 根节点加 `select-none`（`user-select` 可继承，覆盖全部节点标题）；先试的 per-node 任意变体类未生效（Tailwind 未生成该组合类），故改用根节点方案。
- **回归**：展开分组后双击叶子节点 → 选中文本为空（无高亮）✅ ![修复后](screenshots/fix_q2_01_tree_select.png)

### Q1-01 (P3)【已修复】五维雷达图在数据稀疏时退化
- **实际**：当前仅"完整性"有执行数据（100%），其余四维"暂无执行数据"——雷达图退化为单点，五个维度卡片四个显示"--"。
- **建议**：无数据维度从雷达图中淡出或虚线示意；卡片聚合为"2/5 维度已启用检测"之类摘要。
- **证据**：![雷达图单点](screenshots/q1_quality_overview.png)
- **根因**：`hasCompleteRadar` 要求五维齐全才绘制面积——该约束本身合理（缺维度按 0 会误读为"质量差"），但缺少"为什么没有面积"的解释，界面看起来像坏了。
- **修复（2026-10-02）**：保留"五维齐全才画面积"的诚实语义，补齐可解释性与视觉区分——
  1. 有数据的维度轴点用品牌色实心高亮，无数据维度保持灰色空心；
  2. 图例下方按情况给出说明："仅 N/5 个维度有检测数据，五维齐全后展示雷达面积"或"暂无任何维度的检测数据…"。
- **回归**：质量总览显示"仅 1/5 个维度有检测数据，五维齐全后展示雷达面积"，完整性轴点高亮 ✅ ![修复后](screenshots/fix_q1_01_radar.png)
